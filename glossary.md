## 0–9

- <a id="hvdc-800v"></a>**800 V DC power architecture** — NVIDIA's plan (from 2027) to distribute 800-volt direct current to racks, cutting conversion steps and copper so a single rack can draw up to about a megawatt. *See also:* [Liquid cooling](#liquid-cooling).
## A

- <a id="abf-substrate"></a>**ABF substrate** — The multilayer organic base (made with Ajinomoto Build-up Film) on which a GPU package sits and which routes thousands of connections to the board; supplied by firms such as Ibiden and Unimicron. *See also:* [Advanced packaging](#advanced-packaging), [Interposer](#interposer).
- <a id="acie"></a>**ACIE (AI clouds; industrial and enterprise)** — The non-hyperscale half of NVIDIA's Data Center revenue since Q1 FY2027: AI clouds and neoclouds, sovereign projects, industrial and enterprise buyers. *See also:* [Neocloud](#neocloud), [Hyperscaler](#hyperscaler).
- <a id="acquihire"></a>**Acquihire** — A deal that hires a target company's team, usually with a technology licence, instead of buying the company outright. It is faster than an acquisition and can avoid merger review; NVIDIA's Groq and Enfabrica deals used this structure.
- <a id="activation"></a>**Activation** — An intermediate result produced by a layer during the forward pass and kept for the backward pass. Activation memory grows with batch size and sequence length; recomputation trades it for extra compute. *See also:* [Forward pass](#forward-pass), [Backward pass (backpropagation)](#backward-pass).
- <a id="active-electrical-cable"></a>**Active electrical cable (AEC)** — A copper cable with retimer chips in its connectors that extend reach to several metres at 100-200G per lane, cheaper and lower-power than optics for in-rack and adjacent-rack links. Credo is the leading supplier. *See also:* [SerDes](#serdes).
- <a id="activist-investor"></a>**Activist investor** — A shareholder that builds a sizeable stake and presses management for change (board seats, cost cuts, a sale). Starboard's 2017-18 campaign at Mellanox preceded the company's auction.
- <a id="adam"></a>**Adam optimizer** — The standard optimizer for large models. It keeps two running averages per parameter (momentum and variance), which is why training needs about 16 bytes per parameter in mixed precision. *See also:* [Optimizer](#optimizer), [Mixed-precision training](#mixed-precision).
- <a id="adaptive-routing"></a>**Adaptive routing** — Choosing the path for each packet (or group of packets) based on live queue depths instead of a fixed hash, steering traffic around hot spots. InfiniBand has it natively; Spectrum-X and Ultra Ethernet add it to Ethernet. *See also:* [ECMP (equal-cost multipath)](#ecmp), [Packet spraying](#packet-spraying).
- <a id="amx"></a>**Advanced Matrix Extensions (AMX)** — Matrix-multiply units added to Intel Xeon CPU cores from Sapphire Rapids (2023) onward; each core can do up to 1,024 BF16 operations per clock, 16 times its vector units. *See also:* [Tensor core](#tensor-core).
- <a id="advanced-packaging"></a>**Advanced packaging** — Techniques that join several dies and memory stacks in one package with far denser wiring than a circuit board, such as TSMC's CoWoS (2.5D) and SoIC (3D stacking). For AI accelerators it has become a capacity bottleneck and a major cost item. *See also:* [CoWoS](#cowos), [Interposer](#interposer).
- <a id="agent-sandbox"></a>**Agent sandbox** — An isolated environment (typically a container or small virtual machine pinned to a CPU core) in which an AI agent's generated code, browser session or tool call runs, or in which reinforcement-learning attempts are executed and scored. *See also:* [Agentic AI (agents)](#agentic-ai), [Reinforcement learning (RL)](#reinforcement-learning).
- <a id="agentic-ai"></a>**Agentic AI (agents)** — Systems in which a model plans, calls tools, reads results and iterates over many steps to complete a task. One task can consume hundreds of model calls and millions of tokens. *See also:* [Test-time compute](#test-time-compute), [Inference](#inference).
- <a id="ai-blueprint"></a>**AI Blueprint** — NVIDIA's reference applications (for example a research agent or a retrieval pipeline) built from NIM microservices and NeMo tools, published as starting code for enterprises. *See also:* [NVIDIA NIM](#nim), [NeMo](#nemo).
- <a id="ai-factory"></a>**AI factory** — NVIDIA's term for a datacenter built and run mainly to produce AI tokens, designed as one system from power and cooling to racks, networking and software. *See also:* [Rack-scale system](#rack-scale-system), [800 V DC power architecture](#hvdc-800v).
- <a id="ai-head-node"></a>**AI head node** — The general-purpose server CPU that schedules work, runs agent logic and feeds data to accelerators in an AI system. Qualcomm pitches its Dragonfly C1000 for this role. *See also:* [Host CPU](#host-cpu).
- <a id="ai-ran"></a>**AI-RAN** — Running AI workloads and radio-network signal processing on the same accelerated servers at mobile base stations. NVIDIA's $1B Nokia stake targets this market.
- <a id="aiter"></a>**AITER** — AI Tensor Engine for ROCm: AMD's library of tuned LLM operators (attention, MoE, GEMM) written in Triton, Composable Kernel and assembly; the default attention backend for vLLM on ROCm. *See also:* [ROCm](#rocm), [Composable Kernel](#composable-kernel).
- <a id="alexnet"></a>**AlexNet** — The 2012 neural network by Krizhevsky, Sutskever and Hinton that won the ImageNet image-recognition contest by a wide margin. It was trained on two GeForce GTX 580 gaming GPUs using CUDA. *See also:* [CUDA](#cuda).
- <a id="all-gather"></a>**All-gather** — A collective in which each GPU contributes a slice and every GPU ends up with all the slices concatenated. *See also:* [All-reduce](#all-reduce), [Reduce-scatter](#reduce-scatter).
- <a id="all-in-power"></a>**All-in power per GPU** — A GPU's share of everything a datacenter must provision to run it: the GPU, its host CPU, switches and NICs, plus cooling and conversion losses. Per-MW metrics divide by this, not by GPU TDP. *See also:* [PUE (power usage effectiveness)](#pue), [Tokens per second per megawatt](#tokens-per-megawatt).
- <a id="all-reduce"></a>**All-reduce** — A collective operation in which every GPU contributes a set of numbers (e.g. gradients) and every GPU receives the combined result. Its speed depends on the network between GPUs. *See also:* [NCCL](#nccl), [Scale-out](#scale-out).
- <a id="all-to-all"></a>**All-to-all** — A collective in which every GPU sends a different piece of data to every other GPU at once; the communication pattern of mixture-of-experts layers and the hardest for a network. *See also:* [Expert parallelism (EP)](#expert-parallelism).
- <a id="allocation-ratio"></a>**Allocation ratio** — The share of installed GPUs assigned to some job at a given moment. It says nothing about whether the assigned GPUs are busy; it is the first and loosest utilization measure. *See also:* [MFU (model FLOPs utilization)](#mfu), [SM utilization](#sm-utilization).
- <a id="amd-helios"></a>**AMD Helios** — AMD's first rack-scale AI system (2026): 72 Instinct MI455X GPUs, EPYC Venice CPUs and Pensando NICs in a double-wide rack joined by UALink over Ethernet, positioned against NVIDIA's Vera Rubin NVL72. *See also:* [Rack-scale system](#rack-scale-system), [UALink over Ethernet (UALoE)](#ualoe), [NVL72](#nvl72).
- <a id="sev-snp"></a>**AMD SEV-SNP** — AMD's confidential-VM technology for EPYC CPUs (Secure Encrypted Virtualization with Secure Nested Paging): encrypts each VM's memory and blocks the hypervisor from tampering. SEV-TIO extends it to PCIe devices via TDISP. *See also:* [Trusted execution environment (TEE)](#trusted-execution-environment), [TDISP](#tdisp).
- <a id="amdahls-law"></a>**Amdahl's law** — The rule that the part of a job that cannot be sped up (in AI clusters, usually communication that cannot overlap with compute) caps the total speed-up from adding processors. *See also:* [Scale-out](#scale-out).
- <a id="annapurna-labs"></a>**Annapurna Labs** — Israeli chip-design start-up Amazon bought in 2015 for a reported ~$350-370M; it designs AWS's Nitro, Graviton, Inferentia and Trainium chips. *See also:* [AWS Nitro](#aws-nitro), [Trainium](#trainium).
- <a id="annual-cadence"></a>**Annual cadence** — Shipping a new flagship data-center GPU generation every year instead of every two. It raises the bar for rivals and second sources, which must match a moving target rather than a fixed one. *See also:* [NVL72](#nvl72).
- <a id="apache-spark"></a>**Apache Spark** — The most widely used open-source engine for large-scale data processing and SQL across clusters of servers. *See also:* [ETL (extract, transform, load)](#etl), [cuDF](#cudf).
- <a id="architecture-licence"></a>**Architecture licence** — An Arm licence that lets a company design its own cores implementing the Arm instruction set, rather than using Arm's core designs. Apple, Qualcomm and NVIDIA (for Vera's Olympus cores) use this route. *See also:* [Arm (instruction set)](#arm-isa), [Neoverse](#neoverse).
- <a id="arithmetic-intensity"></a>**Arithmetic intensity** — FLOPs performed per byte moved from memory. Work below a chip's ratio of peak FLOPS to memory bandwidth (its ridge point) is memory-bound; decode at small batch sizes is far below it. *See also:* [Decode (generation phase)](#decode), [Memory wall](#memory-wall).
- <a id="arm-isa"></a>**Arm (instruction set)** — A family of instruction sets licensed by Arm Holdings to chip designers, who pay licence fees and per-chip royalties. Grace, Vera, Graviton, Axion and Cobalt are Arm CPUs. *See also:* [ISA (instruction set architecture)](#isa), [Neoverse](#neoverse), [IP royalty](#ip-royalty).
- <a id="arm-cca"></a>**Arm CCA** — Arm Confidential Compute Architecture: Armv9 'Realms' that isolate a VM from the host software, Arm's counterpart to SEV-SNP and TDX. *See also:* [Trusted execution environment (TEE)](#trusted-execution-environment).
- <a id="asic"></a>**ASIC** — Application-specific integrated circuit: a chip designed for one workload. In AI it means custom accelerators such as Google's TPU or AWS Trainium, trading flexibility for efficiency. *See also:* [GPU (graphics processing unit)](#gpu).
- <a id="asic-design-partner"></a>**ASIC design partner** — A company (e.g. Broadcom, Marvell, MediaTek, Alchip, GUC) that turns a customer's chip architecture into manufacturable silicon, supplying physical design, high-speed SerDes, packaging and foundry access. Hyperscalers use them to build custom accelerators without hiring a full chip team. *See also:* [ASIC](#asic), [XPU (custom accelerator)](#xpu).
- <a id="at-the-money"></a>**At the money** — An option or warrant whose strike price equals the share price when it is granted. It has no intrinsic value at grant and pays only if the shares rise above the strike, unlike a penny warrant with a near-zero strike. *See also:* [Intrinsic value](#intrinsic-value), [Warrant](#warrant).
- <a id="attach-rate"></a>**Attach rate** — How much of one product a customer buys alongside another, e.g. dollars of networking per dollar of GPUs. A rising attach rate means a vendor captures more of each cluster's budget. *See also:* [Installed base](#installed-base).
- <a id="attention"></a>**Attention** — The part of a transformer layer where each token compares itself with earlier tokens to pick up context. Its cost and its memory (the KV cache) grow with sequence length. *See also:* [Transformer](#transformer), [KV cache](#kv-cache).
- <a id="attestation"></a>**Attestation** — Cryptographic proof, signed by keys burned into the chip, that a TEE is genuine hardware running approved firmware and settings. A customer checks it before sending secrets such as model weights. *See also:* [Trusted execution environment (TEE)](#trusted-execution-environment), [Hardware root of trust](#root-of-trust).
- <a id="autotuning"></a>**Autotuning** — Automatically benchmarking many versions of a kernel (tile sizes, pipeline depths, thread counts) on the actual hardware and shapes, then keeping the fastest. Used by cuBLAS heuristics, Triton and TorchInductor. *See also:* [GPU kernel](#gpu-kernel), [Triton (OpenAI)](#triton).
- <a id="aws-nitro"></a>**AWS Nitro** — AWS's family of in-house offload cards and hypervisor that run EC2 networking, storage, management and security off the host CPU; it grew out of the 2015 Annapurna Labs acquisition. *See also:* [DPU (data processing unit)](#dpu), [EFA (Elastic Fabric Adapter)](#efa).
- <a id="azure-cobalt"></a>**Azure Cobalt** — Microsoft's in-house Arm server CPU for Azure: Cobalt 100 (128 Neoverse N2 cores) and Cobalt 200 (132 Neoverse V3 cores, 2025). *See also:* [Maia](#maia), [Neoverse](#neoverse).
## B

- <a id="back-end-network"></a>**Back-end network** — The dedicated GPU-to-GPU fabric (InfiniBand or AI Ethernet) used for training and large-scale inference collectives, separate from the general-purpose network. *See also:* [Front-end network](#front-end-network), [Scale-out](#scale-out).
- <a id="backside-power-delivery"></a>**Backside power delivery** — Routing a chip's power wires underneath the transistors instead of through the signal layers above them, freeing space and reducing voltage loss. TSMC calls its version Super Power Rail and introduces it with the A16 node. *See also:* [Process node](#process-node).
- <a id="backward-pass"></a>**Backward pass (backpropagation)** — Walking the layers in reverse to compute how each parameter should change to reduce the error (the gradient). Costs about twice the forward pass, so training totals about 6 FLOPs per parameter per token. *See also:* [Forward pass](#forward-pass), [Gradient](#gradient).
- <a id="bare-metal"></a>**Bare-metal instance** — A cloud server rented with no provider hypervisor underneath: the tenant controls the whole operating system. The provider's control software must then live somewhere the tenant cannot reach, such as a DPU. *See also:* [Multi-tenancy](#multi-tenancy), [DPU (data processing unit)](#dpu).
- <a id="base-command-manager"></a>**Base Command Manager** — NVIDIA's cluster-management software (from the 2022 Bright Computing acquisition) that provisions, configures and monitors the servers, OS images and schedulers of a GPU cluster; now part of Mission Control. *See also:* [NVIDIA Mission Control](#mission-control), [Slurm](#slurm).
- <a id="baseband-modem"></a>**baseband modem** — The chip (or block) that handles a phone's cellular radio protocols; NVIDIA bought Icera in 2011 to supply one and wound the business down in 2015. *See also:* [system-on-chip](#system-on-chip).
- <a id="batching"></a>**Batching** — Serving many requests in the same GPU step so one read of the weights is shared by all of them. Raises throughput per GPU but slows each individual user. *See also:* [Continuous batching](#continuous-batching), [Throughput-interactivity Pareto frontier](#pareto-frontier).
- <a id="behavioural-remedy"></a>**Behavioural remedy** — A merger condition that governs how the combined company behaves (for example no bundling, keep supplying rivals, stay interoperable) instead of forcing it to sell assets. *See also:* [SAMR](#samr).
- <a id="behind-the-meter"></a>**Behind-the-meter generation** — Power plants (often gas turbines, engines or fuel cells) built on or next to a datacenter site and feeding it directly rather than through the utility grid, used to start before a grid connection arrives. *See also:* [Time to power](#time-to-power), [Interconnection queue](#interconnection-queue).
- <a id="bf16"></a>**BF16 (bfloat16)** — A 16-bit (2-byte) number format with the same range as 32-bit floats but less precision; the default format for training and much inference on current GPUs. *See also:* [FP8](#fp8), [Mixed-precision training](#mixed-precision).
- <a id="bill-of-materials"></a>**Bill of materials (BOM)** — The list and cost of every component that goes into a product. For a GPU package: logic dies, HBM, packaging, substrate and test. Analyst estimates put a B200's at roughly $6,400.
- <a id="bin-packing"></a>**Bin-packing (scheduling)** — A placement policy that fills one server or rack before using the next, keeping whole units free for large jobs. The opposite, spread placement, improves resilience but fragments capacity. *See also:* [GPU fragmentation](#gpu-fragmentation).
- <a id="binary-translation"></a>**Binary translation** — Converting a program's machine code from one instruction set (or form) to another while it runs. NVIDIA's Denver cores used a related 'dynamic code optimisation' scheme. *See also:* [ISA (instruction set architecture)](#isa).
- <a id="bionemo"></a>**BioNeMo** — NVIDIA's framework and model collection for training and serving biology and chemistry foundation models (proteins, molecules, DNA). *See also:* [Parabricks](#parabricks).
- <a id="bis"></a>**BIS (Bureau of Industry and Security)** — The US Commerce Department agency that writes and licenses export controls, including the AI-chip rules aimed at China. *See also:* [Export controls](#export-controls).
- <a id="bisection-bandwidth"></a>**Bisection bandwidth** — The total bandwidth across the narrowest cut that splits the network into two equal halves. A non-blocking fat tree has full bisection bandwidth: half the endpoints can talk to the other half at line rate. *See also:* [Fat tree (Clos network)](#fat-tree), [Oversubscription](#oversubscription).
- <a id="blended-token-price"></a>**Blended token price** — One price per million tokens that averages input and output prices, commonly weighted 3 input tokens to 1 output token. *See also:* [Token price deflation](#token-price-deflation).
- <a id="blind-mate-connector"></a>**Blind-mate connector** — A connector that mates automatically when a tray slides into the rack, without anyone plugging cables by hand. NVL72 trays use them to join the NVLink spine, which makes trays swappable and cabling errors rarer. *See also:* [NVLink spine](#nvlink-spine), [NVLink switch tray](#nvlink-switch-tray).
- <a id="bluefield"></a>**BlueField** — NVIDIA's (originally Mellanox's) DPU family: a ConnectX network adapter combined with Arm CPU cores that offloads networking, storage and security work from the host CPU. *See also:* [DPU (data processing unit)](#dpu), [ConnectX](#connectx).
- <a id="bmc"></a>**BMC (baseboard management controller)** — A small service processor on a server or switch tray that monitors health, power and firmware over a separate management network, even when the main chips are off. *See also:* [NVLink switch tray](#nvlink-switch-tray).
- <a id="bounce-buffer"></a>**Bounce buffer** — A staging area in CPU memory where data lands before being copied on to its real destination (for example from a NIC or SSD into GPU memory). Each bounce costs host memory bandwidth, CPU time and latency; GPUDirect removes it. *See also:* [GPUDirect RDMA](#gpudirect-rdma), [GPUDirect Storage](#gpudirect-storage).
- <a id="brook"></a>**Brook** — A C-like stream-programming language for GPUs from Stanford (2004), led by Ian Buck. It proved general code could be compiled to graphics hardware and was the research precursor of CUDA. *See also:* [GPGPU (general-purpose GPU computing)](#gpgpu), [CUDA](#cuda).
- <a id="burn-in"></a>**Burn-in** — Running new hardware at full load for days before accepting it into production, to flush out early failures in GPUs, cables, cooling and power before customers rely on them. *See also:* [Compute tray](#compute-tray), [NVL72](#nvl72).
- <a id="bus-bandwidth"></a>**Bus bandwidth** — The metric NCCL's benchmark reports: the data rate each GPU's links actually sustain during a collective, normalised so it can be compared with the hardware link speed. *See also:* [NCCL](#nccl), [All-reduce](#all-reduce).
- <a id="busbar"></a>**Busbar** — A thick copper bar running the height of a rack that carries DC power from the power shelves to every tray. At ~50 V a 132 kW rack draws about 2,600 A, which is why higher voltages are coming. *See also:* [Power shelf](#power-shelf), [800 V DC power architecture](#hvdc-800v).
- <a id="bytes-per-token"></a>**Bytes per token** — The data a GPU must read from memory to generate one token: roughly the model's weights (read once per decode step and shared by the batch) plus each user's KV cache. Dividing memory bandwidth by it gives the decode ceiling. *See also:* [Decode ceiling](#decode-ceiling), [Memory-bound](#memory-bound), [KV cache](#kv-cache).
## C

- <a id="cache-coherence"></a>**Cache coherence** — Hardware that keeps every processor's cached copy of shared memory consistent, so a CPU and GPU can read and write the same data with ordinary pointers instead of explicit copies. *See also:* [NVLink-C2C](#nvlink-c2c).
- <a id="cann"></a>**CANN** — Huawei's Compute Architecture for Neural Networks: the driver, compiler and kernel layer for Ascend NPUs, Huawei's CUDA equivalent; open-sourced in 2025. *See also:* [CUDA](#cuda).
- <a id="capacity-allocation"></a>**Capacity allocation** — How a supplier such as TSMC or an HBM maker divides scarce output among customers, usually favouring the largest, earliest and most reliable buyers. In AI hardware it can matter more than having the better design. *See also:* [CoWoS](#cowos), [HBM (high-bandwidth memory)](#hbm), [Purchase obligations](#purchase-obligations).
- <a id="capacity-backstop"></a>**Capacity backstop** — A promise by a third party (here usually NVIDIA or Google) to buy, or pay for, data-center capacity that the operator fails to sell to customers. It lowers the operator's financing risk and borrowing cost. *See also:* [Circular financing](#circular-financing), [Neocloud](#neocloud).
- <a id="capacity-market"></a>**Capacity market** — An electricity market in which a grid operator pays generators (in $ per MW-day) to be available years ahead; PJM's auction price is a public gauge of how scarce firm power is in the largest US data-center region. *See also:* [Interconnection queue](#interconnection-queue).
- <a id="capital-recovery-factor"></a>**Capital recovery factor** — The share of an investment that must be earned each year to repay it with interest over its life: r / (1 - (1 + r)^-n). Used to turn capex into an annual cost. *See also:* [TCO (total cost of ownership)](#tco).
- <a id="capital-for-capacity"></a>**Capital-for-capacity deal** — A deal in which a chip vendor gives a customer money or equity (cash stakes, warrants, backstops) in exchange for a commitment to deploy a stated amount of its compute, often measured in gigawatts. *See also:* [Circular financing](#circular-financing), [Warrant](#warrant).
- <a id="captive-silicon"></a>**Captive silicon** — Chips a company designs for its own use and does not sell (for example AWS Nitro or Microsoft's Azure Boost DPU), as opposed to merchant silicon. *See also:* [Merchant silicon](#merchant-silicon).
- <a id="cdna"></a>**CDNA** — AMD's data-center GPU architecture family (Compute DNA), separate from its RDNA gaming line. CDNA 3 powers MI300X/MI325X, CDNA 4 the MI350 series; MI500 is reported as CDNA 6. *See also:* [ROCm](#rocm), [AMD Helios](#amd-helios).
- <a id="channel-partner"></a>**Channel partner** — A company that resells, integrates or services a vendor's products, such as an OEM, distributor or systems integrator, letting the vendor reach customers without its own large sales force. *See also:* [Global systems integrator (GSI)](#gsi), [OEM (original equipment manufacturer)](#oem).
- <a id="checkpoint"></a>**Checkpoint** — A snapshot of a model's weights and optimizer state saved to storage so a training job can restart after a failure without starting over. *See also:* [Goodput](#goodput).
- <a id="compliant-sku"></a>**China-compliant SKU** — A product variant cut down to sit just below an export-control threshold (for example A800, H800, H20), so it can ship without a licence until the rule changes. *See also:* [TPP (total processing performance)](#tpp).
- <a id="chinchilla-optimal"></a>**Chinchilla-optimal** — The 2022 finding that, for a fixed compute budget, parameters and training tokens should grow together, at roughly 20 tokens per parameter. *See also:* [Scaling laws](#scaling-laws), [Over-training](#over-training).
- <a id="chip-hour"></a>**Chip-hour** — One accelerator used for one hour: the unit in which cloud rentals and owner TCO are quoted. Comparing chip-hours across vendors misleads unless throughput per chip is also compared. *See also:* [GPU-hour](#gpu-hour), [TCO (total cost of ownership)](#tco).
- <a id="chiplet"></a>**Chiplet** — A smaller die designed to be combined with others in one package, instead of building one huge monolithic die. Chiplets improve yield and let different functions use different process nodes. *See also:* [Die](#die), [Interposer](#interposer), [Die-to-die interconnect](#die-to-die-interconnect).
- <a id="circular-financing"></a>**Circular financing** — The critique that a supplier inflates its own demand by investing in, lending to or guaranteeing capacity for customers who then use the money to buy the supplier's products. Applied to NVIDIA's stakes in AI labs and neoclouds and its capacity backstops. *See also:* [Neocloud](#neocloud), [Purchase obligations](#purchase-obligations).
- <a id="cloud-credits"></a>**Cloud credits** — Prepaid usage that a cloud provider grants to start-ups (for example up to $350,000 at Google Cloud for AI-first start-ups) to win their workloads early.
- <a id="co-design"></a>**Co-design (hardware-software)** — Designing chips together with the compilers, libraries and models that run on them, so a new feature such as an FP4 number format is usable on launch day. NVIDIA's main silicon advantage in 2026 is co-design speed rather than raw specifications. *See also:* [NVFP4](#nvfp4), [CUDA](#cuda).
- <a id="co-packaged-optics"></a>**Co-packaged optics (CPO)** — Placing the optical engines that turn electrical signals into light right next to the switch chip on the same package, instead of in pluggable modules at the front panel. It shortens the electrical path and cuts power per bit. *See also:* [Pluggable transceiver](#pluggable-transceiver), [Micro-ring modulator](#micro-ring-modulator), [External laser source](#external-laser-source).
- <a id="cold-plate"></a>**Cold plate** — A metal block with internal channels that sits directly on a GPU or CPU; liquid flowing through it carries heat away (direct-to-chip liquid cooling). *See also:* [Coolant distribution unit (CDU)](#cdu), [Liquid cooling](#liquid-cooling).
- <a id="collective-operation"></a>**Collective operation** — A communication pattern in which a whole group of GPUs exchanges data at once (all-reduce, all-gather, reduce-scatter, all-to-all, broadcast), as opposed to one GPU sending to another. *See also:* [All-reduce](#all-reduce), [NCCL](#nccl).
- <a id="composable-kernel"></a>**Composable Kernel** — AMD's C++ template library for writing fused GPU kernels on ROCm; AMD's closest analogue to CUTLASS. *See also:* [CUTLASS](#cutlass), [ROCm](#rocm).
- <a id="computational-lithography"></a>**Computational lithography** — Software that pre-distorts chip-design patterns on a photomask (optical proximity correction) so they print accurately on the wafer; one of the largest compute workloads in chip manufacturing. *See also:* [cuLitho](#culitho), [Photomask](#photomask).
- <a id="compute-margin"></a>**Compute margin** — The share of a model lab's revenue left after paying for the compute that serves paying users; it excludes training compute and R&D. *See also:* [Gross margin](#gross-margin).
- <a id="compute-subsystem"></a>**Compute Subsystem (CSS)** — A pre-integrated, pre-verified Arm block of cores, on-chip mesh and I/O that a licensee drops into its chip to save design time. It carries a higher royalty than licensing cores alone. *See also:* [Neoverse](#neoverse), [IP royalty](#ip-royalty).
- <a id="compute-tray"></a>**Compute tray** — One 1U drawer of an NVL72 rack holding two superchip boards (2 CPUs + 4 GPUs), their network cards, local SSDs and cold plates. Eighteen compute trays make up the rack's 72 GPUs. *See also:* [NVL72](#nvl72), [Superchip](#superchip), [NVLink switch tray](#nvlink-switch-tray).
- <a id="compute-bound"></a>**Compute-bound** — A workload whose speed is limited by the chip's arithmetic throughput because it reuses each byte many times; adding memory bandwidth does not help. *See also:* [Memory-bound](#memory-bound), [FLOPS](#flops).
- <a id="compute-in-memory"></a>**Compute-in-memory** — A design that performs multiply-accumulate operations inside or right next to memory arrays, cutting the energy spent moving weights. d-Matrix's digital in-memory compute is an example. *See also:* [Near-memory computing](#near-memory-compute), [Memory wall](#memory-wall).
- <a id="confidential-computing"></a>**Confidential computing** — Running code and data inside a hardware-protected enclave (trusted execution environment) so that even the cloud operator cannot read them; NVIDIA supports it on GPUs from Hopper onwards. *See also:* [DPU (data processing unit)](#dpu).
- <a id="congestion-control"></a>**Congestion control** — The rules senders and switches use to slow traffic before queues overflow, for example by marking packets (ECN) and having NICs cut their sending rate. Good congestion control keeps queues short and tail latency low. *See also:* [ECN (Explicit Congestion Notification)](#ecn), [Incast](#incast), [Adaptive routing](#adaptive-routing).
- <a id="connectx"></a>**ConnectX** — NVIDIA's (originally Mellanox's) family of network adapters for InfiniBand and Ethernet. Reference designs put one ConnectX NIC or SuperNIC beside every GPU, so it ships with GPU orders. *See also:* [SuperNIC](#supernic), [InfiniBand](#infiniband).
- <a id="context-parallelism"></a>**Context parallelism (CP)** — Splitting the tokens of one very long sequence across GPUs, which then exchange attention keys and values (for example around a ring); used for 100K-token-plus training. *See also:* [Sequence parallelism](#sequence-parallelism).
- <a id="continuous-batching"></a>**Continuous batching** — Scheduling at every generation step so requests can join and leave a running batch, instead of waiting for the whole batch to finish. Standard in modern serving engines. *See also:* [Batching](#batching), [PagedAttention](#paged-attention).
- <a id="contracted-power"></a>**Contracted vs active power** — Contracted power is data-center capacity (in MW or GW) a cloud has signed for; active power is what is energised and billing today. The gap is build-out still to be financed and delivered. *See also:* [Neocloud](#neocloud), [Revenue backlog](#revenue-backlog).
- <a id="cdu"></a>**Coolant distribution unit (CDU)** — The pump-and-heat-exchanger unit that circulates liquid coolant to cold plates in a rack and passes the heat to the building's water loop. One CDU serves one or several racks. *See also:* [Cold plate](#cold-plate), [Liquid cooling](#liquid-cooling).
- <a id="copos"></a>**CoPoS (chip-on-panel-on-substrate)** — TSMC's panel-level version of CoWoS that builds packages on large square panels instead of round 300 mm wafers, wasting less area as packages grow. Piloting in 2026; volume not expected before 2H 2028. *See also:* [CoWoS](#cowos), [CoWoS-L](#cowos-l), [Advanced packaging](#advanced-packaging).
- <a id="corporate-venture-capital"></a>**Corporate venture capital** — Minority equity investments made by an operating company in start-ups, usually for strategic information and ecosystem influence as well as financial return. *See also:* [NVentures](#nventures).
- <a id="wacc"></a>**Cost of capital (WACC)** — The annual return investors require on the money tied up in an asset (weighted average cost of capital). In a TCO model it turns upfront capex into a level yearly charge that includes financing, not just depreciation. *See also:* [Capital recovery factor](#capital-recovery-factor), [Useful life (depreciation)](#useful-life).
- <a id="cost-per-million-tokens"></a>**Cost per million tokens** — Owner cost of an accelerator over a period divided by the tokens it produced, scaled to one million. It depends as much on throughput at a chosen speed per user and on utilization as on the hardware price. *See also:* [Owner TCO](#owner-tco), [Interactivity (tokens/s per user)](#interactivity), [Tokens per second per megawatt](#tokens-per-mw).
- <a id="cowos"></a>**CoWoS** — Chip-on-Wafer-on-Substrate: TSMC's 2.5D advanced packaging that places GPU dies and HBM stacks side by side on a silicon interposer (CoWoS-S) or on bridge-based variants (CoWoS-L, CoWoS-R). Capacity has been a key bottleneck for AI accelerators. *See also:* [HBM (high-bandwidth memory)](#hbm).
- <a id="cowos-l"></a>**CoWoS-L** — TSMC's CoWoS variant that replaces one large silicon interposer with a redistribution-layer interposer containing small embedded silicon bridges, allowing packages several reticles in size (used from Blackwell on). *See also:* [CoWoS](#cowos), [Interposer](#interposer).
- <a id="cowos-r"></a>**CoWoS-R** — A TSMC CoWoS variant whose interposer is made only of organic redistribution layers, with no silicon. Cheaper and more flexible but with coarser wiring than CoWoS-S or CoWoS-L. *See also:* [CoWoS](#cowos), [Redistribution layer (RDL)](#redistribution-layer), [CoWoS-L](#cowos-l).
- <a id="cowos-s"></a>**CoWoS-S** — TSMC's original CoWoS variant, which places dies on one monolithic silicon interposer of up to about 3.3 times the reticle area. Used for A100, H100 and H200. *See also:* [CoWoS](#cowos), [CoWoS-L](#cowos-l), [Interposer](#interposer).
- <a id="credit-based-flow-control"></a>**Credit-based flow control** — InfiniBand's way of avoiding drops: a sender may only transmit when the receiver has advertised free buffer space ('credits'). Nothing is sent that cannot be stored, so the link is lossless by construction. *See also:* [InfiniBand](#infiniband), [Priority Flow Control (PFC)](#priority-flow-control).
- <a id="cublas"></a>**cuBLAS** — NVIDIA's GPU library of basic linear-algebra routines, above all matrix multiplication (GEMM). Most AI frameworks send their big matrix multiplies to it. *See also:* [GEMM (general matrix multiply)](#gemm), [CUTLASS](#cutlass).
- <a id="cuda"></a>**CUDA** — NVIDIA's programming platform (language extensions, compiler, runtime, driver and libraries) launched in 2006 that lets developers run general-purpose code on GPUs. The basis of NVIDIA's software moat. *See also:* [CUDA-X](#cuda-x).
- <a id="cuda-core"></a>**CUDA core** — NVIDIA's name for a simple arithmetic lane in an SM that does one scalar operation (such as a 32-bit multiply-add) per clock. Thousands of them handle general parallel code; matrix math goes to the tensor cores instead. *See also:* [Streaming multiprocessor (SM)](#streaming-multiprocessor), [Tensor core](#tensor-core).
- <a id="cuda-graphs"></a>**CUDA Graphs** — A CUDA feature that records a sequence of kernel launches once and replays it with a single launch, cutting CPU launch overhead - important for small, frequent inference steps. *See also:* [CUDA stream](#cuda-stream), [GPU kernel](#gpu-kernel).
- <a id="cuda-stream"></a>**CUDA stream** — An ordered queue of GPU work (copies and kernel launches). Work in one stream runs in order; separate streams can overlap, which hides data transfers behind computation. *See also:* [CUDA Graphs](#cuda-graphs).
- <a id="cuda-q"></a>**CUDA-Q** — NVIDIA's open platform and compiler for hybrid quantum-classical programs that run across quantum processors, GPUs and CPUs. *See also:* [cuQuantum](#cuquantum).
- <a id="cuda-x"></a>**CUDA-X** — NVIDIA's umbrella name for its hundreds of domain libraries built on CUDA (cuBLAS, cuDNN, NCCL, RAPIDS and others). *See also:* [CUDA](#cuda).
- <a id="cudf"></a>**cuDF** — The RAPIDS GPU dataframe library: a pandas-like table engine that also powers GPU back ends for Spark, Polars and Dask. *See also:* [RAPIDS](#rapids), [Dataframe](#dataframe).
- <a id="cudf-pandas"></a>**cudf.pandas** — A cuDF mode that accelerates unchanged pandas code: operations the GPU supports run there, everything else falls back to normal pandas on the CPU. *See also:* [cuDF](#cudf), [Zero-code-change acceleration](#zero-code-change).
- <a id="cudnn"></a>**cuDNN** — NVIDIA's library of tuned deep-learning kernels (convolutions, attention, normalisation), first released in 2014. Frameworks call it instead of writing their own GPU code. *See also:* [CUDA-X](#cuda-x), [GPU kernel](#gpu-kernel).
- <a id="cufft"></a>**cuFFT** — NVIDIA's fast Fourier transform library, used in signal processing, imaging, seismic analysis and physics codes. *See also:* [cuBLAS](#cublas).
- <a id="cugraph"></a>**cuGraph** — The RAPIDS GPU graph-analytics library (PageRank, shortest paths, community detection) for networks with billions of edges. *See also:* [RAPIDS](#rapids).
- <a id="culitho"></a>**cuLitho** — NVIDIA's library for computational lithography: the heavy calculations that shape photomask patterns so chips print correctly. TSMC put it into production with Synopsys in 2024. *See also:* [Computational lithography](#computational-lithography).
- <a id="cuml"></a>**cuML** — The RAPIDS GPU machine-learning library (random forests, clustering, UMAP and similar). Its cuml.accel mode runs unchanged scikit-learn code on the GPU. *See also:* [RAPIDS](#rapids), [Zero-code-change acceleration](#zero-code-change).
- <a id="cuopt"></a>**cuOpt** — NVIDIA's GPU optimization engine for linear programming and vehicle routing, open-sourced under Apache 2.0 in 2025. *See also:* [Linear programming](#linear-programming).
- <a id="cuquantum"></a>**cuQuantum** — NVIDIA's libraries for simulating quantum computers on GPUs (state-vector and tensor-network methods), used to develop and test quantum algorithms. *See also:* [CUDA-Q](#cuda-q).
- <a id="curand"></a>**cuRAND** — NVIDIA's random-number-generation library, used for Monte Carlo simulation, risk models and the random initialisation of neural networks. *See also:* [cuBLAS](#cublas).
- <a id="cusparse"></a>**cuSPARSE** — NVIDIA's library for linear algebra on sparse matrices (mostly zeros), used in simulation, graph analytics and recommendation models. *See also:* [cuBLAS](#cublas).
- <a id="customer-concentration"></a>**Customer concentration** — The share of revenue that comes from a few large customers. High concentration gives those buyers bargaining power and makes revenue sensitive to any one of them changing suppliers. *See also:* [Direct vs indirect customer](#indirect-customer).
- <a id="customer-owned-tooling"></a>**Customer-owned tooling (COT)** — A custom-chip model in which the customer does more of the design itself and buys only specific services or IP, then contracts the foundry directly; it lowers the partner's per-unit margin. *See also:* [Turnkey ASIC](#turnkey-asic), [NRE (non-recurring engineering)](#nre).
- <a id="cute"></a>**CuTe** — The layout-and-tensor abstraction at the core of CUTLASS 3 and 4. It describes how data is tiled across threads and memory, and since CUTLASS 4 it is also available as a Python DSL. *See also:* [CUTLASS](#cutlass), [DSL (domain-specific language)](#dsl).
- <a id="cutlass"></a>**CUTLASS** — NVIDIA's open-source collection of CUDA C++ templates for building custom high-performance matrix-multiply and related kernels, used when the stock cuBLAS routine does not fit (new number formats, fused operations). *See also:* [cuBLAS](#cublas), [CuTe](#cute).
- <a id="cuvs"></a>**cuVS** — NVIDIA's GPU library for vector search (finding the nearest embeddings) and clustering, built into Faiss, Milvus and other vector databases. *See also:* [Vector search](#vector-search), [RAPIDS](#rapids).
- <a id="cxl"></a>**CXL (Compute Express Link)** — An open standard that runs over PCIe wiring and adds cache-coherent memory access, so CPUs can use memory expanders or share memory with accelerators. It is the open-standard alternative to proprietary coherent links such as NVLink-C2C. *See also:* [PCIe (PCI Express)](#pcie), [Cache coherence](#cache-coherence).
## D

- <a id="data-center-segment"></a>**Data center (NVIDIA segment)** — NVIDIA's reporting segment for AI and HPC products sold into datacenters, split into compute (GPUs, systems) and networking (NVLink, InfiniBand, Ethernet, NICs, DPUs).
- <a id="data-loader"></a>**Data loader** — The software pipeline, usually running on host CPU cores, that reads training samples from storage, decodes and augments them and hands batches to the GPUs. If it is slower than the GPUs, they wait. *See also:* [GPU starvation](#gpu-starvation), [NVIDIA DALI](#dali).
- <a id="data-parallelism"></a>**Data parallelism (DP)** — Training on many GPUs that each hold a full copy of the model and process a different slice of the batch, then average their gradients with an all-reduce every step. *See also:* [All-reduce](#all-reduce), [ZeRO (Zero Redundancy Optimizer)](#zero), [FSDP (Fully Sharded Data Parallel)](#fsdp).
- <a id="dataflow-architecture"></a>**Dataflow architecture** — A chip design in which the compiler maps a model's operations onto a grid of compute and memory units and data streams between them, instead of a processor fetching instructions. SambaNova's RDU is an example. *See also:* [SRAM](#sram), [ASIC](#asic).
- <a id="dataframe"></a>**Dataframe** — A table of rows and named columns held in memory, the basic data structure of pandas, Polars and Spark. *See also:* [cuDF](#cudf), [ETL (extract, transform, load)](#etl).
- <a id="day-zero-support"></a>**Day-0 support** — Whether a new model runs well on a given chip and software stack on the day the model is released. It is where software maturity gaps between vendors show up most clearly. *See also:* [vLLM](#vllm), [GPU kernel](#gpu-kernel).
- <a id="dcgm"></a>**DCGM (Data Center GPU Manager)** — NVIDIA's open-source daemon and tools for monitoring and managing data-center GPUs: health checks, diagnostics, error alerts and power policies, exported to schedulers and Kubernetes. *See also:* [Telemetry (network)](#telemetry), [SM utilization](#sm-utilization).
- <a id="decode"></a>**Decode (generation phase)** — The second phase of an inference request: output tokens are produced one at a time, each requiring a full read of the model's weights. Memory-bandwidth-bound. *See also:* [Prefill (context phase)](#prefill), [TPOT / ITL (time per output token / inter-token latency)](#tpot).
- <a id="decode-ceiling"></a>**Decode ceiling** — The most tokens per second memory bandwidth can feed during decode: bandwidth divided by bytes per token. A 70B-parameter FP8 model is capped at about 48 tokens/s per stream on an H100 and about 274 on Rubin. *See also:* [Bytes per token](#bytes-per-token), [Decode (generation phase)](#decode), [Memory wall](#memory-wall).
- <a id="deep-learning-institute"></a>**Deep Learning Institute** — NVIDIA's training arm (DLI), which runs paid and free courses, instructor-led workshops and certifications on GPU programming and AI, often through universities and partners. *See also:* [Developer relations](#developer-relations).
- <a id="deep-buffer-switch"></a>**Deep-buffer switch** — A switch chip with large packet memory (often HBM), such as Broadcom Jericho or Cisco P200, that can absorb bursts over long links. Used for scale-across between data centers and for scheduled AI fabrics. *See also:* [Scale-across](#scale-across).
- <a id="defect-density"></a>**Defect density (D0)** — The average number of random killer defects per square centimetre of wafer, the key quality metric of a fab process. Yield falls roughly exponentially with die area times defect density. *See also:* [Die yield](#die-yield).
- <a id="dense-vs-sparse"></a>**Dense vs. sparse FLOPS** — Vendors often quote 'sparse' peak throughput, which assumes 2:4 structured sparsity (half the weights zero) and is exactly twice the dense figure. Real models rarely run sparse, so this repo uses dense numbers. *See also:* [Sparsity (2:4 structured)](#sparsity), [FLOPS](#flops).
- <a id="design-win"></a>**Design win** — A customer's commitment to use a supplier's chip or design service in a specific product generation. In custom silicon it starts a multi-year program but is not yet revenue. *See also:* [ASIC design partner](#asic-design-partner), [Tape-out](#tape-out).
- <a id="developer-relations"></a>**Developer relations** — The programs a platform company runs to win and keep software developers: free tools and libraries, documentation, training, conferences and support. For NVIDIA it builds the CUDA habit that raises customers' switching costs. *See also:* [CUDA](#cuda), [NVIDIA Inception](#nvidia-inception).
- <a id="dgx"></a>**DGX** — NVIDIA's own branded AI system (DGX-1 in 2016, later DGX-2, DGX A100, DGX H100 and DGX rack systems), sold directly and through partners; it doubles as NVIDIA's reference design. *See also:* [HGX](#hgx), [SuperPoD](#superpod).
- <a id="dgx-cloud"></a>**DGX Cloud** — NVIDIA's own GPU cloud service (2023), hosted inside Oracle, Microsoft, Google and AWS data centers on capacity NVIDIA rents. Most of it was reportedly redirected to NVIDIA's internal research in 2025. *See also:* [DGX Cloud Lepton](#dgx-cloud-lepton), [Neocloud](#neocloud).
- <a id="dgx-cloud-lepton"></a>**DGX Cloud Lepton** — An NVIDIA marketplace (2025) that routes developers to GPU capacity owned by partner clouds such as CoreWeave, Lambda, Nebius and Crusoe; NVIDIA does not own the hardware. *See also:* [DGX Cloud](#dgx-cloud), [GPU marketplace](#gpu-marketplace).
- <a id="die"></a>**Die** — A single piece of silicon cut from a wafer. Modern AI GPUs such as Blackwell put two (and Rubin Ultra four) compute dies in one package. *See also:* [GPU (graphics processing unit)](#gpu), [Reticle limit](#reticle-limit).
- <a id="die-harvesting"></a>**Die harvesting** — Selling dies that contain a defect by disabling the faulty block (for example a few streaming multiprocessors) and shipping the part as a slightly smaller configuration. It raises the effective yield of large GPUs. *See also:* [Die yield](#die-yield).
- <a id="die-yield"></a>**Die yield** — The share of dies on a wafer that work. Big dies have lower yields because each one is more likely to contain a defect, which makes large GPUs disproportionately expensive. *See also:* [Defect density (D0)](#defect-density), [Die harvesting](#die-harvesting).
- <a id="die-to-die-interconnect"></a>**Die-to-die interconnect** — A very short, very wide link between dies in the same package that lets them act as one chip. NVIDIA's Blackwell uses a 10 TB/s link (NV-HBI) between its two compute dies. *See also:* [Chiplet](#chiplet), [NVLink](#nvlink).
- <a id="dies-per-wafer"></a>**Dies per wafer** — How many complete dies fit on one wafer, a geometry calculation that depends on die area and the partial dies lost at the round wafer edge. Roughly 63 for an 814 mm² GPU die on a 300 mm wafer. *See also:* [Die](#die), [Die yield](#die-yield).
- <a id="digital-twin"></a>**Digital twin (datacenter)** — A physics-accurate software model of a datacenter (power, cooling, airflow, racks) used to design and test it before construction; NVIDIA's Omniverse DSX blueprint is one. *See also:* [AI factory](#ai-factory).
- <a id="dilution"></a>**Dilution** — The fall in existing owners' percentage stake when a company issues new shares, for example to pay for an acquisition or to settle a warrant. *See also:* [Warrant](#warrant).
- <a id="indirect-customer"></a>**Direct vs indirect customer** — In NVIDIA's filings a direct customer buys from NVIDIA (mostly OEMs and ODMs); an indirect customer, such as a cloud provider or AI lab, buys the finished systems from them. NVIDIA discloses direct customers above 10% of revenue and estimates large indirect ones. *See also:* [Customer concentration](#customer-concentration), [OEM (original equipment manufacturer)](#oem), [ODM](#odm).
- <a id="direct-attach-copper"></a>**Direct-attach copper (DAC)** — A passive copper cable with connectors on both ends and no electronics inside. It uses almost no power and rarely fails, but at 200 Gb/s per lane a passive cable reaches only about a metre. *See also:* [NVLink spine](#nvlink-spine), [Active electrical cable (AEC)](#active-electrical-cable), [Co-packaged optics (CPO)](#co-packaged-optics).
- <a id="direct-to-chip-cooling"></a>**Direct-to-chip liquid cooling** — Cooling in which liquid flows through cold plates mounted on the hottest chips (GPUs, CPUs, switches), removing most of the heat at the source; the remaining heat is handled by fans or a rear-door exchanger. *See also:* [Cold plate](#cold-plate), [Coolant distribution unit (CDU)](#cdu), [Liquid cooling](#liquid-cooling).
- <a id="direct3d"></a>**Direct3D** — Microsoft's 3D graphics programming interface for Windows (part of DirectX); it standardised on triangles, which made chips built around other primitives incompatible with most games. *See also:* [fixed-function pipeline](#fixed-function-pipeline).
- <a id="disaggregated-serving"></a>**Disaggregated serving** — Running the prefill (prompt-reading) and decode (token-generating) phases of LLM inference on separate GPU pools and moving the KV cache between them; NVIDIA's Dynamo orchestrates this. *See also:* [KV cache](#kv-cache).
- <a id="dispatch-and-combine"></a>**Dispatch and combine** — The two communication steps of every mixture-of-experts layer: dispatch sends each token's activation to the GPUs holding its chosen experts; combine sends the expert outputs back to be summed. Together they form an all-to-all exchange. *See also:* [Mixture-of-experts (MoE)](#mixture-of-experts), [All-to-all](#all-to-all), [Expert parallelism (EP)](#expert-parallelism).
- <a id="doca"></a>**DOCA** — NVIDIA's software development kit and runtime for BlueField DPUs and SuperNICs, the DPU counterpart of CUDA. *See also:* [DPU (data processing unit)](#dpu).
- <a id="domestic-substitution"></a>**Domestic substitution** — China's policy of replacing foreign chips with local ones, for example by steering state-funded data centers to domestic AI accelerators. *See also:* [Export controls](#export-controls), [Huawei Ascend](#huawei-ascend).
- <a id="dominant-resource-fairness"></a>**Dominant resource fairness** — A fair-share rule for clusters with several resources (GPUs, CPUs, memory): each team's share is judged by the resource it uses most of, so no team can starve others by hoarding one resource. *See also:* [Preemption](#preemption).
- <a id="double-ordering"></a>**Double ordering** — Buyers placing the same order with several suppliers, or ordering more than they need, during a shortage to secure allocation; the excess vanishes when supply catches up and can make demand look stronger than it is. *See also:* [Supply-constrained](#supply-constrained).
- <a id="dpu"></a>**DPU (data processing unit)** — A network card with its own processor cores and accelerators that runs networking, storage and security software so the server's main CPU does not have to. *See also:* [SuperNIC](#supernic), [SmartNIC](#smartnic), [IPU (infrastructure processing unit)](#ipu).
- <a id="dsl"></a>**DSL (domain-specific language)** — A small programming language designed for one job. CuTe DSL, Triton and Mojo are DSLs for writing GPU kernels without full C++. *See also:* [CuTe](#cute), [Triton (OpenAI)](#triton).
- <a id="dsx-os"></a>**DSX OS** — An open, modular software portfolio for running multi-tenant AI factories that NVIDIA introduced in 2026, bundling KAI Scheduler, Run:ai, Cloud Functions, Grove and Dynamo among others. *See also:* [NVIDIA Mission Control](#mission-control), [Run:ai](#run-ai).
- <a id="dualpipe"></a>**DualPipe** — DeepSeek's pipeline-parallel schedule that overlaps the forward and backward computation of different micro-batches with the expert-parallel all-to-all communication, hiding most of the network time on bandwidth-limited H800 clusters. *See also:* [Pipeline parallelism (PP)](#pipeline-parallelism), [Expert parallelism (EP)](#expert-parallelism), [All-to-all](#all-to-all).
- <a id="duv-multipatterning"></a>**DUV multi-patterning** — Printing features finer than a deep-ultraviolet scanner can resolve in one pass by exposing the same layer several times. It lets SMIC make 7 nm-class chips without EUV, at lower yield and higher cost. *See also:* [EUV lithography](#euv-lithography), [Lithography](#lithography).
- <a id="dynamo"></a>**Dynamo** — NVIDIA's open-source (Apache 2.0) layer above serving engines that spreads one model across many GPUs: it splits prefill from decode, routes requests to GPUs that already hold the right KV cache and offloads cache to cheaper memory. Version 1.0 shipped in March 2026. *See also:* [Disaggregated serving](#disaggregated-serving), [KV cache](#kv-cache).
## E

- <a id="earn-out"></a>**Earn-out** — Part of an acquisition price paid later only if the acquired business hits agreed milestones, such as revenue targets. Used to bridge valuation gaps, e.g. in Marvell's purchase of Celestial AI. *See also:* [Acquihire](#acquihire).
- <a id="earth-2"></a>**Earth-2** — NVIDIA's platform for AI weather and climate models and digital twins of the Earth; Earth2Studio is its open-source Python package. *See also:* [Omniverse](#omniverse).
- <a id="east-west-traffic"></a>**East-west traffic** — Traffic between servers inside a data center (for example GPU-to-GPU gradient exchange), as opposed to traffic entering or leaving it. AI training is dominated by east-west traffic. *See also:* [North-south traffic](#north-south-traffic), [Back-end network](#back-end-network).
- <a id="ecmp"></a>**ECMP (equal-cost multipath)** — Standard Ethernet load balancing that hashes each flow onto one of several equal-length paths. Large AI flows can collide on the same path while others sit idle, wasting bandwidth. *See also:* [Adaptive routing](#adaptive-routing), [Packet spraying](#packet-spraying).
- <a id="ecn"></a>**ECN (Explicit Congestion Notification)** — A bit a switch sets in packets when its queue starts to fill. The receiver echoes it back and the sender slows down, preventing drops without pausing the link. *See also:* [Congestion control](#congestion-control).
- <a id="economic-life"></a>**Economic life** — How long hardware keeps earning more than its cash running costs. It can be shorter than the accounting useful life when newer chips make tokens much cheaper, which is the core of the GPU-depreciation bear case. *See also:* [Useful life (depreciation)](#useful-life), [Residual value](#residual-value), [Annual cadence](#annual-cadence).
- <a id="eda"></a>**EDA (electronic design automation)** — Software used to design and verify chips, from logic synthesis to physical layout and sign-off; Synopsys and Cadence dominate. Every new chip program pays EDA licences, and NVIDIA holds a $2B Synopsys stake. *See also:* [Tape-out](#tape-out), [NRE (non-recurring engineering)](#nre).
- <a id="edge-to-cloud-continuity"></a>**Edge-to-cloud continuity** — Running one model family, file format and toolchain across devices, edge servers and cloud racks, so a workload can move between tiers without being rewritten. A selling point for vendors with chips at every tier. *See also:* [Hybrid AI](#hybrid-ai), [NPU (neural processing unit)](#npu).
- <a id="efa"></a>**EFA (Elastic Fabric Adapter)** — AWS's network interface for HPC and AI instances, built on Nitro cards and the SRD transport rather than InfiniBand or standard RoCE. *See also:* [SRD (Scalable Reliable Datagram)](#srd), [AWS Nitro](#aws-nitro).
- <a id="effective-training-time"></a>**Effective training time** — The share of a training run's wall-clock time spent making progress, after time lost to failures, restarts and re-computing work since the last checkpoint. Meta reported over 90% for Llama 3. *See also:* [Goodput](#goodput), [Checkpoint](#checkpoint).
- <a id="efficiency-shock"></a>**Efficiency shock** — A sudden fall in the compute (and so cost) needed per unit of AI output, from a new model architecture, training method or software. Whether it lowers or raises total compute spend depends on the price elasticity of demand. *See also:* [Jevons paradox](#jevons-paradox), [Price elasticity of demand](#price-elasticity).
- <a id="elastic-fabric-adapter"></a>**Elastic Fabric Adapter (EFA)** — AWS's network interface for HPC and AI instances, built on its Nitro hardware and the SRD protocol, which sprays packets over many paths and tolerates out-of-order delivery. *See also:* [Packet spraying](#packet-spraying).
- <a id="emib"></a>**EMIB / EMIB-T** — Intel's Embedded Multi-die Interconnect Bridge: small silicon bridges set into the package substrate to link dies and memory, offered as an alternative to TSMC's CoWoS; EMIB-T adds through-silicon vias for HBM. *See also:* [CoWoS](#cowos), [Advanced packaging](#advanced-packaging).
- <a id="ems"></a>**EMS (electronics manufacturing services)** — A contract manufacturer that builds electronics to another company's design (for example Sanmina, Celestica, Foxconn). In AI servers EMS firms and ODMs assemble and test racks at thin margins. *See also:* [ODM](#odm), [OEM (original equipment manufacturer)](#oem).
- <a id="engineer-year"></a>**Engineer-year** — One engineer working for one year; a standard unit for sizing software efforts. Multiplying engineer-years by a loaded cost per engineer gives a dollar estimate. *See also:* [Software port](#software-port).
- <a id="entity-list"></a>**Entity List** — A US Commerce Department list of foreign companies that need a licence to receive US-origin technology. Huawei, SMIC and several Chinese GPU designers are on it. *See also:* [Export controls](#export-controls), [BIS (Bureau of Industry and Security)](#bis).
- <a id="equity-for-capacity"></a>**Equity-for-capacity** — A deal that ties shares to a purchase commitment. Either the vendor grants the customer equity (AMD's warrant to OpenAI) or the vendor buys the customer's equity (NVIDIA's OpenAI investment), so supplier and buyer share the upside of the build-out. *See also:* [Warrant](#warrant), [Vendor financing](#vendor-financing), [Circular financing](#circular-financing).
- <a id="esun"></a>**ESUN (Ethernet for Scale-Up Networking)** — An Open Compute Project workstream, launched in 2025, that defines how to run scale-up traffic over Ethernet switches, including a compact header to cut overhead. It builds on Broadcom's Scale-Up Ethernet contribution. *See also:* [Scale-Up Ethernet (SUE)](#scale-up-ethernet), [UALink (Ultra Accelerator Link)](#ualink), [Ultra Ethernet (UEC)](#ultra-ethernet).
- <a id="etl"></a>**ETL (extract, transform, load)** — The data-preparation work of pulling raw data from sources, cleaning and joining it, and loading it into a warehouse or training set; often the largest analytics bill in an enterprise. *See also:* [Apache Spark](#apache-spark), [Dataframe](#dataframe).
- <a id="euv-lithography"></a>**EUV lithography** — Extreme-ultraviolet lithography: printing with 13.5 nm light so the finest layers can be exposed in one pass instead of several. EUV scanners are made only by ASML; High-NA EUV is the next generation, with a field half the size of today's. *See also:* [Lithography](#lithography), [High-NA EUV](#high-na-euv).
- <a id="expert-parallelism"></a>**Expert parallelism (EP)** — Placing the different experts of a mixture-of-experts model on different GPUs, so tokens must be sent to their chosen experts and back with all-to-all exchanges every MoE layer. *See also:* [Mixture-of-experts (MoE)](#mixture-of-experts), [All-to-all](#all-to-all).
- <a id="export-controls"></a>**Export controls** — Government rules that require a licence to sell certain technologies abroad. US rules on advanced GPUs decide which countries and buyers can receive NVIDIA's top chips and in what volume. *See also:* [Sovereign AI](#sovereign-ai).
- <a id="export-revenue-share"></a>**Export revenue share** — A licence condition under which the exporter pays part of its sales revenue to the US government: 15% on H20 (Aug 2025) and 25% on H200 (Dec 2025) China sales. *See also:* [Export controls](#export-controls).
- <a id="external-laser-source"></a>**External laser source** — In CPO designs, the lasers sit in separate replaceable modules on the front panel and feed light to the optical engines by fiber, because lasers are the part most likely to fail and dislike the heat next to a switch chip. *See also:* [Co-packaged optics (CPO)](#co-packaged-optics).
## F

- <a id="fabless"></a>**fabless** — A chip company that designs semiconductors but pays a foundry such as TSMC to manufacture them; NVIDIA has been fabless since its founding. *See also:* [Foundry](#foundry).
- <a id="facility-capex"></a>**Facility capex** — Spending on the building, electrical plant, cooling and land around the IT equipment, usually quoted per MW of power (roughly $11-13M per MW for new AI halls in this repo's estimates). It lasts longer than the servers inside. *See also:* [AI factory](#ai-factory), [PUE (power usage effectiveness)](#pue), [Time to power](#time-to-power).
- <a id="falcon-transport"></a>**Falcon (transport)** — Google's hardware-assisted network transport for data-center Ethernet, contributed to the Open Compute Project in 2023; Intel's IPU E2000 was its first hardware platform. *See also:* [IPU (infrastructure processing unit)](#ipu).
- <a id="fat-tree"></a>**Fat tree (Clos network)** — A multi-tier switch topology in which links get 'fatter' toward the top so that any endpoint can talk to any other at full speed. With switches of radix R, two tiers connect R²/2 endpoints and three tiers R³/4. *See also:* [Switch radix](#switch-radix), [Bisection bandwidth](#bisection-bandwidth), [Oversubscription](#oversubscription).
- <a id="fatbinary"></a>**Fatbinary** — The bundle a CUDA application ships: SASS machine code for each GPU generation it was built for, plus PTX that a newer driver can compile for GPUs that did not exist at build time. *See also:* [PTX (Parallel Thread Execution)](#ptx), [JIT compilation](#jit-compilation).
- <a id="feynman"></a>**Feynman** — NVIDIA's GPU architecture planned for 2028, shown with a Rosa CPU, an LP40 decode chip, BlueField-5 and ConnectX-10 and a Kyber NVL1152 rack mixing copper and co-packaged optics; specifications not yet published. *See also:* [Rubin Ultra](#rubin-ultra), [Co-packaged optics (CPO)](#co-packaged-optics).
- <a id="fixed-function-pipeline"></a>**fixed-function pipeline** — An early graphics-chip design in which each rendering stage is hard-wired circuitry with a few settings, rather than a processor that runs programs. *See also:* [programmable shader](#programmable-shader).
- <a id="flashattention"></a>**FlashAttention** — A family of attention kernels (v1 2022 to v4 2026) that compute attention in tiles held in on-chip memory instead of writing the full attention matrix to HBM. Each version was written first for NVIDIA GPUs. *See also:* [Attention](#attention), [GPU kernel](#gpu-kernel).
- <a id="flops"></a>**FLOPS** — Floating-point operations per second: the rate at which a chip does arithmetic. Quoted at a given number format (FP64, BF16, FP8, FP4) and as dense or sparse peak; 1 PFLOPS = 10^15 operations per second. 'FLOPs' (lower-case s) is a count of operations, not a rate. *See also:* [Tensor core](#tensor-core).
- <a id="flywheel"></a>**Flywheel** — A set of reinforcing loops in which each turn makes the next one easier, so momentum builds over time. In this repo NVIDIA's flywheel has four loops (developer, scale/R&D, full-stack, capital) that share one hub: revenue and gross profit. *See also:* [Installed base](#installed-base), [Circular financing](#circular-financing).
- <a id="forward-pe"></a>**Forward P/E** — Share price divided by the next twelve months' or next fiscal year's expected earnings per share (equivalently market value divided by expected net income). *See also:* [Reverse DCF](#reverse-dcf).
- <a id="forward-pass"></a>**Forward pass** — Running inputs through every layer of the model to produce a prediction. Costs about 2 FLOPs per parameter per token. *See also:* [Backward pass (backpropagation)](#backward-pass), [Activation](#activation).
- <a id="foundry"></a>**Foundry** — A company that manufactures chips designed by others (TSMC, Samsung Foundry, Intel Foundry, SMIC). NVIDIA, AMD, Google and Qualcomm are 'fabless': they design chips and buy wafers from foundries. *See also:* [Wafer](#wafer), [OSAT](#osat).
- <a id="foveros"></a>**Foveros** — Intel's 3D packaging technology that stacks logic dies face to face. Offered with EMIB as an alternative to TSMC's packaging for multi-die AI chips. *See also:* [EMIB / EMIB-T](#emib), [Advanced packaging](#advanced-packaging), [Hybrid bonding](#hybrid-bonding).
- <a id="fp4"></a>**FP4** — A 4-bit floating-point format (1 sign, 2 exponent and 1 mantissa bit) that can represent only eight magnitudes from 0 to 6; usable only with block scale factors such as MXFP4 or NVFP4. *See also:* [NVFP4](#nvfp4), [Microscaling (MX formats)](#microscaling).
- <a id="fp8"></a>**FP8** — An 8-bit (1-byte) floating-point format supported by tensor cores since Hopper. It halves memory and roughly doubles tensor throughput versus BF16, with care needed to preserve accuracy. *See also:* [BF16 (bfloat16)](#bf16), [NVFP4](#nvfp4).
- <a id="fractional-gpu"></a>**Fractional GPU** — Giving a job less than a whole GPU, by hardware partitioning (MIG), space sharing (MPS) or time-slicing. It raises utilization for small jobs such as notebooks and light inference, at some cost in isolation. *See also:* [MIG (Multi-Instance GPU)](#mig), [GPU time-slicing](#gpu-time-slicing).
- <a id="free-cash-flow"></a>**Free cash flow** — Operating cash flow minus capital expenditure: the cash a company generates that it can return to shareholders, use for acquisitions or invest in other companies.
- <a id="free-chip-test"></a>**Free-chip test** — A thought experiment: if a rival's accelerator system cost nothing, would its cost per token still be higher than NVIDIA's at full price? It holds only where the throughput gap is larger than the share of cost that is chip capex. *See also:* [Cost per million tokens](#cost-per-million-tokens), [Owner TCO](#owner-tco).
- <a id="front-end-network"></a>**Front-end network** — The conventional data-center network that connects servers to storage, users, management systems and the internet. *See also:* [Back-end network](#back-end-network).
- <a id="frontier-lab"></a>**Frontier lab** — A company training the largest general-purpose AI models (for example OpenAI, Anthropic, xAI, Google DeepMind); each buys compute at gigawatt scale.
- <a id="fsdp"></a>**FSDP (Fully Sharded Data Parallel)** — PyTorch's built-in implementation of fully sharded data parallelism (ZeRO stage 3 style): weights are all-gathered just before use and gradients reduce-scattered after. *See also:* [ZeRO (Zero Redundancy Optimizer)](#zero), [All-gather](#all-gather), [Reduce-scatter](#reduce-scatter).
- <a id="full-stack-merchant"></a>**Full-stack merchant** — A vendor that sells the whole AI system (chips, interconnect, racks and software) to any buyer. NVIDIA is the archetype; AMD is building toward it with Helios and ROCm. *See also:* [Merchant silicon](#merchant-silicon), [Vertical integration](#vertical-integration).
- <a id="fma"></a>**Fused multiply-add (FMA)** — One operation that computes a × b + c in a single step; it counts as two floating-point operations. Matrix multiplication is almost entirely FMAs. *See also:* [FLOPS](#flops), [GEMM (general matrix multiply)](#gemm).
## G

- <a id="gang-scheduling"></a>**Gang scheduling** — Starting all parts of a distributed job at the same time or not at all, so that 1,000 GPUs do not sit idle waiting for the 1,001st. Schedulers such as Slurm, Kueue and KAI Scheduler support it. *See also:* [Slurm](#slurm), [Kubernetes](#kubernetes).
- <a id="gap-trend"></a>**Gap trend** — Whether NVIDIA's lead over the strongest challenger in a layer has been widening, stable or narrowing over roughly the last twelve months, as judged on that layer's competition page. *See also:* [Moat score](#moat-score).
- <a id="gate-all-around"></a>**Gate-all-around (GAA)** — A transistor design in which the gate surrounds stacked silicon nanosheets on all sides, cutting leakage versus the older FinFET. TSMC's N2 is its first GAA node. *See also:* [Process node](#process-node).
- <a id="gddr"></a>**GDDR (graphics DRAM)** — Graphics memory chips soldered around a processor on the board. Cheaper and simpler than HBM but with far less bandwidth per watt and per square millimetre; NVIDIA's data-center GPUs used it before P100. *See also:* [HBM (high-bandwidth memory)](#hbm), [LPDDR](#lpddr).
- <a id="gemm"></a>**GEMM (general matrix multiply)** — The matrix-multiplication operation that accounts for most of the arithmetic in neural networks. Large GEMMs have high arithmetic intensity and run near a GPU's peak FLOPS. *See also:* [Tensor core](#tensor-core), [Arithmetic intensity](#arithmetic-intensity).
- <a id="gigawatt-of-compute"></a>**Gigawatt of compute** — The unit AI-infrastructure deals are now sized in: the electrical power drawn by the accelerators, servers and networking (1 GW ≈ several hundred thousand current GPUs). Buyers commit to power because power and sites, not chips, are the binding constraint. *See also:* [AI factory](#ai-factory), [Contracted vs active power](#contracted-power).
- <a id="gsi"></a>**Global systems integrator (GSI)** — A large IT services firm (for example Accenture) that designs, builds and runs technology projects for enterprises. GSIs decide much of what hardware and software a client deploys. *See also:* [OEM (original equipment manufacturer)](#oem), [Channel partner](#channel-partner).
- <a id="global-systems-integrator"></a>**Global systems integrator (GSI)** — A large IT services firm (Accenture, Deloitte, Infosys and others) that designs and deploys technology for enterprises and so acts as a sales channel for platforms like NVIDIA's.
- <a id="gloo"></a>**Gloo** — Meta's open-source collective-communication library, a PyTorch back end mainly used for CPU tensors and as a fallback when NCCL is unavailable. *See also:* [NCCL](#nccl).
- <a id="goodput"></a>**Goodput** — The useful output of a system after losses: in training, the share of GPU-hours that actually advance the model; in serving, the throughput that still meets latency targets. *See also:* [MFU (model FLOPs utilization)](#mfu), [Checkpoint](#checkpoint).
- <a id="gpgpu"></a>**GPGPU (general-purpose GPU computing)** — Using a graphics chip for non-graphics maths such as physics, finance or neural networks. Before CUDA it meant disguising calculations as pixel-shading jobs. *See also:* [CUDA](#cuda), [Brook](#brook).
- <a id="gpu"></a>**GPU (graphics processing unit)** — A processor with thousands of simple cores that run the same instruction on many pieces of data at once, which suits the matrix multiplications at the heart of neural networks. In this repo 'GPU' usually means the whole package a customer buys (e.g. a B200), which can contain more than one die. *See also:* [Die](#die), [Tensor core](#tensor-core).
- <a id="gpu-fragmentation"></a>**GPU fragmentation** — Idle GPUs scattered across many servers or racks in pieces too small for the next job. The cluster looks partly free, yet a large job cannot start. *See also:* [Bin-packing (scheduling)](#bin-packing), [Topology-aware scheduling](#topology-aware-scheduling).
- <a id="gpu-kernel"></a>**GPU kernel** — A small function that runs on thousands of GPU threads at once, such as one matrix multiply or one attention step. Frameworks stitch thousands of kernels into a model; their speed decides how fast the model runs. *See also:* [CUDA](#cuda), [cuDNN](#cudnn).
- <a id="gpu-marketplace"></a>**GPU marketplace** — A platform that lists GPU capacity from many providers and lets buyers rent it by the hour or week (for example Vast.ai, SF Compute or NVIDIA's Lepton). It competes on price and flexibility rather than service. *See also:* [DGX Cloud Lepton](#dgx-cloud-lepton), [Neocloud](#neocloud).
- <a id="gpu-starvation"></a>**GPU starvation** — GPUs sitting idle because the host cannot supply data, launch kernels or return tool results fast enough; it shows up as low GPU utilization even though the GPUs themselves are not the bottleneck. *See also:* [Data loader](#data-loader), [Host CPU](#host-cpu).
- <a id="gpu-time-slicing"></a>**GPU time-slicing** — Letting several workloads take turns on one GPU. Cheap and flexible, but with no memory or fault isolation: if one workload crashes, all sharing the GPU go down. *See also:* [Fractional GPU](#fractional-gpu), [MIG (Multi-Instance GPU)](#mig).
- <a id="gpu-backed-loan"></a>**GPU-backed loan** — Debt secured by a fleet of GPUs and the customer contracts that rent them out, often drawn in stages as hardware is delivered (a delayed-draw term loan). The lender's risk depends on contract quality and GPU resale value. *See also:* [Take-or-pay contract](#take-or-pay), [Neocloud](#neocloud).
- <a id="gpu-hour"></a>**GPU-hour** — One GPU used (or rented) for one hour: the unit in which GPU clouds price capacity and in which utilization economics are measured. *See also:* [TCO (total cost of ownership)](#tco).
- <a id="gpu-initiated-networking"></a>**GPU-initiated networking** — Letting a GPU kernel post network transfers itself instead of waiting for the CPU to do it; NCCL 2.28 added this (GIN) to cut latency for MoE and inference traffic. *See also:* [NCCL](#nccl), [RDMA (remote direct memory access)](#rdma).
- <a id="gpudirect-rdma"></a>**GPUDirect RDMA** — An NVIDIA feature that lets the network card read and write GPU memory directly, skipping a copy through CPU memory. *See also:* [RDMA (remote direct memory access)](#rdma).
- <a id="gpudirect-storage"></a>**GPUDirect Storage** — NVIDIA technology that moves data directly between storage (local NVMe or over the network) and GPU memory, bypassing a copy through CPU memory. *See also:* [RDMA (remote direct memory access)](#rdma).
- <a id="gradient"></a>**Gradient** — For each parameter, the direction and size of the change that would reduce the loss. Gradients from all GPUs are averaged every training step. *See also:* [Backward pass (backpropagation)](#backward-pass), [All-reduce](#all-reduce).
- <a id="gpc"></a>**Graphics processing cluster (GPC)** — A group of SMs that share some scheduling and routing hardware. Rubin has eight GPCs holding 224 SMs; Hopper's H100 enables 132 SMs across its GPCs. *See also:* [Streaming multiprocessor (SM)](#streaming-multiprocessor).
- <a id="graviton"></a>**Graviton** — AWS's in-house Arm server CPU line (Annapurna Labs), first launched in 2018; Graviton5 (2026) has 192 cores. *See also:* [Annapurna Labs](#annapurna-labs), [Neoverse](#neoverse).
- <a id="cuda-grid"></a>**Grid (CUDA)** — All the thread blocks created by one kernel launch. The hardware hands blocks to SMs as they free up, which lets the same code scale across GPUs of different sizes. *See also:* [Thread block](#thread-block), [GPU kernel](#gpu-kernel).
- <a id="gross-margin"></a>**Gross margin** — Revenue minus cost of goods sold, as a share of revenue. NVIDIA's GAAP gross margin was about 75% in mid-2026; the chip-only margin on a GPU is estimated nearer 80%. *See also:* [Bill of materials (BOM)](#bill-of-materials).
- <a id="grouped-query-attention"></a>**Grouped-query attention (GQA)** — An attention design in which several query heads share one key/value head, shrinking the KV cache (8x for Llama 3.1 70B) with little quality loss. *See also:* [KV cache](#kv-cache), [Multi-head latent attention (MLA)](#multi-head-latent-attention).
- <a id="grove"></a>**Grove** — An open-source Kubernetes API from NVIDIA's Dynamo project that describes a whole multi-component inference system as one resource and schedules it with hierarchical gang and topology-aware placement. *See also:* [Dynamo](#dynamo), [Gang scheduling](#gang-scheduling).
- <a id="gtc"></a>**GTC** — NVIDIA's GPU Technology Conference. The spring event in San Jose (first held in 2009) is NVIDIA's main roadmap keynote and partner launch window; regional editions run elsewhere during the year. *See also:* [Developer relations](#developer-relations).
## H

- <a id="h20"></a>**H20** — A China-market Hopper GPU (2024) with much lower compute than the H100 but full HBM capacity, designed to fit the October 2023 export rules; it became subject to a US licence requirement in April 2025. *See also:* [Export controls](#export-controls), [H800](#h800).
- <a id="h800"></a>**H800** — A China-market version of NVIDIA's H100 (2023) with the same compute but cut-down NVLink bandwidth, designed to fit the October 2022 US export rules; it was itself restricted from November 2023. DeepSeek-V3 was trained on 2,048 of them. *See also:* [Export controls](#export-controls), [H20](#h20), [NVLink](#nvlink).
- <a id="hardware-plugin"></a>**Hardware plugin** — A separately maintained backend that lets a serving engine such as vLLM run on a new accelerator without changing the engine's core code. *See also:* [vLLM](#vllm).
- <a id="pull-through"></a>**Hardware pull-through** — Monetising free software indirectly: the software is given away so that customers buy more of the hardware it runs best on. CUDA is NVIDIA's main example. *See also:* [CUDA](#cuda), [Switching cost](#switching-cost).
- <a id="root-of-trust"></a>**Hardware root of trust** — A small, immutable security block on a chip that holds identity keys and verifies firmware at boot; everything else in the chain of trust is checked against it. *See also:* [Attestation](#attestation).
- <a id="hbm"></a>**HBM (high-bandwidth memory)** — Stacked DRAM placed millimetres from the GPU on a silicon interposer and connected through a very wide bus, giving terabytes per second of bandwidth. HBM capacity and bandwidth often limit AI performance more than raw compute. *See also:* [CoWoS](#cowos), [Memory wall](#memory-wall).
- <a id="hbm-base-die"></a>**HBM base die** — The bottom logic die of an HBM stack that talks to the GPU and manages the DRAM layers above. From HBM4 it can be made on a logic process (e.g. TSMC N3P or N12), letting buyers customise it. *See also:* [HBM (high-bandwidth memory)](#hbm), [HBM4E](#hbm4e), [Near-memory computing](#near-memory-compute).
- <a id="hbm-qualification"></a>**HBM qualification** — The months-long process in which a GPU maker tests a supplier's HBM stacks for speed, heat, power and yield inside its own package before buying in volume. Failing it can lock a supplier out of a generation. *See also:* [HBM (high-bandwidth memory)](#hbm), [Capacity allocation](#capacity-allocation).
- <a id="hbm4e"></a>**HBM4E** — The enhanced version of HBM4 expected in volume from 2027, with faster pins (targets up to ~12.8 Gb/s), up to 16-high stacks of ~48-64 GB and increasingly customer-specific base dies. *See also:* [HBM (high-bandwidth memory)](#hbm), [HBM base die](#hbm-base-die), [Pin speed](#pin-speed).
- <a id="heat-flux"></a>**Heat flux** — Heat leaving a surface per unit area, here watts per square centimetre of chip. Higher flux needs a coolant that carries more heat per unit volume: water holds roughly 3,500 times more heat per litre than air. *See also:* [Direct-to-chip liquid cooling](#direct-to-chip-cooling).
- <a id="hgx"></a>**HGX** — NVIDIA's standard GPU baseboard (typically eight GPUs plus NVLink switches) that server makers such as Dell, HPE, Supermicro and Lenovo build their own servers around. HGX-1 (2017) set the pattern. *See also:* [DGX](#dgx), [MGX](#mgx), [OEM (original equipment manufacturer)](#oem).
- <a id="high-bandwidth-compute"></a>**High Bandwidth Compute (HBC)** — Qualcomm's name for the memory architecture of its 2028 Dragonfly AI300 inference accelerator, which Qualcomm claims gives 54x the memory bandwidth of the AI200 (vendor claim). *See also:* [Near-memory computing](#near-memory-compute).
- <a id="high-na-euv"></a>**High-NA EUV** — The next generation of EUV scanners with a larger numerical aperture (0.55) for finer features. Its anamorphic optics halve the maximum exposure field to about 429 mm², which pushes large chips toward multi-die designs. *See also:* [EUV lithography](#euv-lithography), [Reticle limit](#reticle-limit).
- <a id="hip"></a>**HIP** — AMD's C++ GPU programming interface, deliberately designed to mirror CUDA's API so code can be ported by renaming calls. HIP code can also be compiled for NVIDIA GPUs. *See also:* [ROCm](#rocm), [HIPIFY](#hipify).
- <a id="hipify"></a>**HIPIFY** — AMD tools that automatically translate CUDA source code into HIP source code. They handle the bulk of a port; hand-tuned kernels and inline PTX still need manual work. *See also:* [HIP](#hip), [Translation layer](#translation-layer).
- <a id="host-cpu"></a>**Host CPU** — The general-purpose processor in an accelerated server that boots the system, runs the operating system, schedules work and moves data to and from the GPUs. *See also:* [Superchip](#superchip), [NVLink-C2C](#nvlink-c2c).
- <a id="hot-spare"></a>**Hot spare** — A powered, idle GPU or node kept ready to replace a failed one so a training job can continue. Spares raise reliability but lower utilization. *See also:* [MTBI (mean time between interruptions)](#mtbi).
- <a id="huawei-ascend"></a>**Huawei Ascend** — Huawei's family of AI accelerators (910B/910C, 950PR/950DT, 960, 970), sold mainly in China with the CANN software stack and SuperPoD rack-scale systems. *See also:* [CANN](#cann).
- <a id="hugging-face"></a>**Hugging Face** — The largest public hub for sharing AI models, datasets and demos, and the maker of widely used open-source model libraries. NVIDIA agreed in 2026 to acquire it (pending regulatory review). *See also:* [Nemotron](#nemotron).
- <a id="hybrid-ai"></a>**Hybrid AI** — Splitting AI inference between a device (phone, PC, car) and the cloud: small or private requests run on the device's NPU, larger ones go to datacenter accelerators. *See also:* [Edge-to-cloud continuity](#edge-to-cloud-continuity), [Inference](#inference).
- <a id="hybrid-bonding"></a>**Hybrid bonding** — Joining two dies directly copper-to-copper and oxide-to-oxide, with no solder bumps. It allows denser, thinner and cooler stacks and is being explored for 16-high HBM4E and beyond. *See also:* [Micro-bump](#microbump), [Through-silicon via (TSV)](#through-silicon-via), [Stack height](#stack-height).
- <a id="hyperscaler"></a>**Hyperscaler** — One of the largest cloud operators (AWS, Microsoft Azure, Google Cloud, Meta, Oracle) that buy accelerators by the hundreds of thousands and increasingly design their own chips. *See also:* [XPU (custom accelerator)](#xpu), [Neocloud](#neocloud).
- <a id="hypervisor"></a>**Hypervisor** — The software layer that splits one physical server into many virtual machines; offloading it to a DPU or Nitro card frees host CPU cores and hardens isolation. *See also:* [AWS Nitro](#aws-nitro), [DPU (data processing unit)](#dpu).
## I

- <a id="io-die"></a>**I/O die** — A separate die in a multi-chip package that handles input/output (memory controllers, SerDes, chip-to-chip links) so the compute die can use the leading-edge node. Design partners can supply only the I/O die. *See also:* [Chiplet](#chiplet), [SerDes](#serdes).
- <a id="ici"></a>**ICI (inter-chip interconnect)** — Google's TPU-to-TPU links. Each chip has four or six ICI links to neighbouring chips, forming a 2D or 3D torus; Ironwood has six links at 200 GB/s each (bidirectional). *See also:* [Torus topology](#torus-topology), [Optical circuit switch (OCS)](#optical-circuit-switch).
- <a id="immersion-cooling"></a>**Immersion cooling** — Cooling in which whole servers sit in a tank of non-conductive fluid (single-phase) or a fluid that boils on the chips (two-phase). Very dense, but it changes how hardware is serviced and qualified. *See also:* [Direct-to-chip liquid cooling](#direct-to-chip-cooling), [Liquid cooling](#liquid-cooling).
- <a id="in-network-computing"></a>**In-network computing** — Doing simple computation, such as summing gradients, inside the network switches instead of on the endpoints. It cuts the data that crosses the network and frees GPU time. *See also:* [SHARP (in-network reduction)](#sharp).
- <a id="incast"></a>**Incast** — Many senders transmitting to one receiver at the same moment, overflowing the switch port in front of it. Collective operations create incast by design, which is why AI fabrics need congestion control. *See also:* [Congestion control](#congestion-control), [Priority Flow Control (PFC)](#priority-flow-control).
- <a id="inference"></a>**Inference** — Running a trained model to produce outputs (answers, code, images). Unlike training it is continuous, latency-sensitive and priced per token. *See also:* [Prefill (context phase)](#prefill), [Decode (generation phase)](#decode).
- <a id="context-memory-storage"></a>**Inference context memory storage** — NVIDIA's BlueField-4-based storage tier, launched at CES 2026, that holds and shares KV-cache blocks across inference nodes so long conversations can be reloaded instead of recomputed. *See also:* [KV-cache offload](#kv-cache-offload), [KV cache](#kv-cache), [Disaggregated serving](#disaggregated-serving).
- <a id="inference-provider"></a>**Inference provider** — A company that sells model outputs by the token or GPU time for serving (e.g. Together AI, Fireworks AI, Baseten, GroqCloud, Cerebras Cloud), usually on rented or owned GPUs. *See also:* [Neocloud](#neocloud).
- <a id="inferencex"></a>**InferenceX** — SemiAnalysis's open-source, continuously re-run inference benchmark that maps throughput per GPU against interactivity and cost per million tokens across NVIDIA, AMD and Google hardware. *See also:* [MLPerf](#mlperf), [Throughput-interactivity Pareto frontier](#pareto-frontier).
- <a id="infiniband"></a>**InfiniBand** — A low-latency, lossless networking standard used for scale-out AI clusters; NVIDIA became its leading supplier through the 2020 Mellanox acquisition (Quantum switches, ConnectX adapters). *See also:* [Scale-out](#scale-out), [Spectrum-X](#spectrum-x).
- <a id="infinity-fabric"></a>**Infinity Fabric** — AMD's coherent interconnect family, used inside its chips and between MI300/MI350-series GPUs (as xGMI links) in a switchless eight-GPU mesh. AMD's 72-GPU Helios rack moves scale-up to UALink over Ethernet instead. *See also:* [UALink over Ethernet (UALoE)](#ualoe), [UALink (Ultra Accelerator Link)](#ualink).
- <a id="infrastructure-tax"></a>**Infrastructure tax** — The share of a server's CPU cycles spent on the provider's plumbing (virtual switching, storage protocols, encryption, telemetry, management) rather than the customer's work. Published estimates cluster around 19-33%; also called the datacenter tax. *See also:* [DPU (data processing unit)](#dpu).
- <a id="installed-base"></a>**Installed base** — The number of a vendor's products already in use. A large installed base of CUDA-capable GPUs (over 1 billion by 2020, per NVIDIA) makes CUDA the default target for developers and researchers. *See also:* [CUDA](#cuda), [Flywheel](#flywheel).
- <a id="intel-18a"></a>**Intel 18A** — Intel's 2025–26 process node with gate-all-around transistors (RibbonFET) and backside power delivery (PowerVia). It is the base of Intel's foundry pitch. *See also:* [Gate-all-around (GAA)](#gate-all-around), [Backside power delivery](#backside-power-delivery), [Foundry](#foundry).
- <a id="intel-tdx"></a>**Intel TDX** — Intel Trust Domain Extensions: Intel's confidential-VM technology for Xeon CPUs. TDX Connect extends it to PCIe devices via TDISP. *See also:* [Trusted execution environment (TEE)](#trusted-execution-environment), [TDISP](#tdisp).
- <a id="interactivity"></a>**Interactivity (tokens/s per user)** — How fast each user receives generated tokens. Serving more users at once raises tokens per GPU but lowers interactivity, so throughput figures are only comparable at the same interactivity. *See also:* [Throughput-interactivity Pareto frontier](#pareto-frontier), [Tokens per second per megawatt](#tokens-per-megawatt).
- <a id="interconnection-queue"></a>**Interconnection queue** — The line of projects waiting for a grid operator to study and approve a connection to the transmission network. In the US the median wait from request to operation for new generation exceeds four years. *See also:* [Time to power](#time-to-power), [Behind-the-meter generation](#behind-the-meter).
- <a id="interposer"></a>**Interposer** — A thin layer of silicon (or silicon bridges in an organic layer) on which GPU dies and HBM stacks sit side by side, carrying tens of thousands of fine wires between them. It is what makes HBM's terabytes-per-second bandwidth possible. *See also:* [CoWoS](#cowos), [Advanced packaging](#advanced-packaging).
- <a id="intrinsic-value"></a>**Intrinsic value** — What an option or warrant would be worth if exercised today: the share price minus the strike price, times the number of shares (zero if the price is below the strike). It ignores time value. *See also:* [At the money](#at-the-money), [Purchase-vested warrant](#purchase-vested-warrant).
- <a id="ip-royalty"></a>**IP royalty** — A per-chip payment to the owner of licensed technology, usually a percentage of the chip's selling price or a fixed fee per unit, on top of an upfront licence fee. Arm earns most of its revenue this way. *See also:* [Arm (instruction set)](#arm-isa), [Compute Subsystem (CSS)](#compute-subsystem).
- <a id="ipsec"></a>**IPsec** — A standard for encrypting and authenticating network traffic at the IP layer. Doing it in software at hundreds of Gb/s consumes many CPU cores; DPUs and NICs encrypt inline. *See also:* [DPU (data processing unit)](#dpu).
- <a id="ipu"></a>**IPU (infrastructure processing unit)** — Intel's (and Google's) term for a DPU: a programmable network device that runs cloud infrastructure functions off the host CPU. *See also:* [DPU (data processing unit)](#dpu).
- <a id="ironwood"></a>**Ironwood** — Google's seventh-generation TPU (TPU v7, 2025): 4.6 PFLOPS dense FP8 and 192 GB of HBM3E per chip in pods of up to 9,216 chips; Google's first TPU built mainly for inference. *See also:* [TPU (Tensor Processing Unit)](#tpu), [ICI (inter-chip interconnect)](#ici).
- <a id="isa"></a>**ISA (instruction set architecture)** — The vocabulary of machine instructions a processor understands, such as x86 or Arm. Software compiled for one ISA does not run natively on another, which is why ISA choice locks in ecosystems. *See also:* [x86](#x86), [Arm (instruction set)](#arm-isa), [RISC-V](#risc-v).
- <a id="it-load"></a>**IT load** — The power drawn by the servers, storage and network equipment themselves, excluding cooling and power-conversion losses. Facility power = IT load × PUE. *See also:* [PUE (power usage effectiveness)](#pue).
## J

- <a id="jax"></a>**JAX** — Google's numerical-computing library for machine learning, compiled through XLA. It runs natively on TPUs and NVIDIA GPUs and is the main way frontier labs train on TPUs. *See also:* [XLA](#xla).
- <a id="jevons-paradox"></a>**Jevons paradox** — When something gets cheaper to use, total consumption can rise enough that total spending grows; applied to AI, cheaper tokens may raise total compute demand. *See also:* [Token price deflation](#token-price-deflation).
- <a id="jit-compilation"></a>**JIT compilation** — Just-in-time compilation: turning code into machine instructions when a program loads or runs instead of ahead of time. The CUDA driver JIT-compiles PTX for new GPUs; Triton and DeepGEMM JIT-compile kernels for the exact shapes in use. *See also:* [PTX (Parallel Thread Execution)](#ptx), [Fatbinary](#fatbinary).
- <a id="job-completion-time"></a>**Job completion time (JCT)** — Wall-clock time to finish a training job or step. Network vendors quote JCT gains because they capture both bandwidth and tail-latency effects. *See also:* [Tail latency](#tail-latency).
## K

- <a id="kai-scheduler"></a>**KAI Scheduler** — The Kubernetes GPU scheduler from Run:ai that NVIDIA open-sourced in 2025 (Apache 2.0); it handles GPU sharing, queues, fairness and topology-aware placement. *See also:* [Kubernetes](#kubernetes), [Run:ai](#run-ai).
- <a id="kernel-fusion"></a>**Kernel fusion** — Merging several small GPU programs (kernels) into one so intermediate results stay in on-chip memory instead of being written to and re-read from HBM. It cuts memory traffic and launch overhead. *See also:* [GPU kernel](#gpu-kernel), [TensorRT](#tensorrt).
- <a id="kernelbench"></a>**KernelBench** — A public benchmark of PyTorch operations, grouped in three difficulty levels, used to test whether AI models can write GPU kernels that are correct and faster than PyTorch's own. *See also:* [Triton (OpenAI)](#triton).
- <a id="distillation"></a>**Knowledge distillation** — Training a smaller 'student' model to imitate a larger 'teacher' model's outputs. It transfers much of the teacher's ability at a fraction of the serving cost. *See also:* [Reasoning model](#reasoning-model), [Open-weight model](#open-weight-model).
- <a id="known-good-die"></a>**Known good die (KGD)** — A die (or HBM stack) that has been fully tested before packaging. Because a finished package cannot be reworked, testing each part first avoids scrapping expensive good parts with a bad one. *See also:* [Chiplet](#chiplet), [Advanced packaging](#advanced-packaging).
- <a id="kubernetes"></a>**Kubernetes** — The open-source system that runs containerised software across a cluster of machines; the default control plane of cloud computing. Add-ons such as Kueue and KAI Scheduler teach it to share GPUs. *See also:* [Slurm](#slurm), [KAI Scheduler](#kai-scheduler).
- <a id="kvbm"></a>**KV block manager (KVBM)** — Dynamo's component that stores KV-cache blocks across tiers (GPU memory, CPU memory, SSD, remote storage) and moves them back to the GPU when a conversation resumes. *See also:* [KV-cache offload](#kv-cache-offload), [Dynamo](#dynamo), [NIXL](#nixl).
- <a id="kv-cache"></a>**KV cache** — The keys and values of every earlier token, stored in GPU memory so attention does not recompute them. Grows with context length and number of users; often the binding memory constraint in serving. *See also:* [Attention](#attention), [PagedAttention](#paged-attention).
- <a id="kv-aware-routing"></a>**KV-aware routing** — Sending each new request to the server that already holds the largest part of its conversation or prompt in its KV cache, so less of the prompt has to be recomputed. It shortens time to first token. *See also:* [KV cache](#kv-cache), [Dynamo](#dynamo), [TTFT (time to first token)](#ttft).
- <a id="kv-cache-offload"></a>**KV-cache offload** — Moving the attention cache (KV cache) of idle or long conversations out of scarce GPU HBM into cheaper CPU memory or storage, then reloading it when the user returns instead of recomputing it from scratch. *See also:* [KV cache](#kv-cache), [NVLink-C2C](#nvlink-c2c).
- <a id="kyber"></a>**Kyber** — NVIDIA's next rack design for Rubin Ultra: 144 GPU packages on vertical blades joined through a printed-circuit midplane, at roughly 600 kW. NVIDIA targets H2 2027; a slip to 2028 has been reported. *See also:* [Midplane](#midplane), [NVL72](#nvl72), [Oberon](#oberon).
- <a id="kyber-rack"></a>**Kyber rack** — NVIDIA's next rack architecture after Oberon (the NVL72 rack): vertical compute blades around a midplane, 144 GPU packages in one NVLink domain and ~600 kW per rack, planned for Rubin Ultra. *See also:* [Rack-scale system](#rack-scale-system), [800 V DC power architecture](#hvdc-800v).
## L

- <a id="l2-cache"></a>**L2 cache** — The last on-chip memory level, shared by all SMs: 50 MB on H100 and ~126 MB on B200. It catches data on its way from HBM so repeated reads do not use scarce HBM bandwidth. *See also:* [Shared memory (L1)](#shared-memory), [HBM (high-bandwidth memory)](#hbm).
- <a id="l6-l10-l11"></a>**L6 / L10 / L11 integration** — Industry shorthand for how complete a server build is: L6 is a populated board or module, L10 a complete tested server or tray, and L11 a whole rack with networking, power and cooling, validated as one unit. *See also:* [ODM](#odm), [OEM (original equipment manufacturer)](#oem).
- <a id="lpu"></a>**Language processing unit (LPU)** — Groq's inference chip design, licensed by NVIDIA in December 2025, that keeps model weights in on-chip SRAM (about 500 MB per chip) instead of HBM, trading capacity for very high bandwidth and low latency during decode. *See also:* [Decode (generation phase)](#decode), [HBM (high-bandwidth memory)](#hbm).
- <a id="leading-indicator"></a>**Leading indicator** — A measurable signal that tends to move before the outcome you care about, such as hyperscaler capex guidance moving before NVIDIA's orders do. *See also:* [Risk heatmap](#risk-heatmap).
- <a id="letter-of-intent"></a>**Letter of intent (LOI)** — A non-binding document setting out the intended terms of a deal before definitive agreements are signed. NVIDIA's up-to-$100B OpenAI LOI (2025) was later replaced by a smaller equity investment. *See also:* [Acquihire](#acquihire).
- <a id="licence-plus-acquihire"></a>**Licence plus acquihire** — A deal structure in which a buyer pays for a non-exclusive licence to a start-up's technology and hires its founders and engineers, while the start-up survives as a separate company; it can avoid formal merger review. *See also:* [Acquihire](#acquihire), [Merger review](#merger-review).
- <a id="linear-pluggable-optics"></a>**Linear pluggable optics (LPO)** — A pluggable module without its own DSP chip, relying on the switch's SerDes to drive the signal. Roughly halves module power but shortens reach and tightens interoperability. *See also:* [Pluggable transceiver](#pluggable-transceiver), [Co-packaged optics (CPO)](#co-packaged-optics).
- <a id="linear-programming"></a>**Linear programming** — Finding the best value of a linear objective (cost, profit) subject to linear constraints; the workhorse of logistics, scheduling and supply-chain planning. *See also:* [cuOpt](#cuopt).
- <a id="link-layer-retry"></a>**Link-layer retry (LLR)** — A mechanism that resends a corrupted frame between two directly connected ports instead of relying on end-to-end retransmission. It keeps scale-up links lossless with very low added latency. *See also:* [Scale-Up Ethernet (SUE)](#scale-up-ethernet), [Credit-based flow control](#credit-based-flow-control).
- <a id="liquid-cooling"></a>**Liquid cooling** — Removing heat with liquid circulated through cold plates on the chips rather than with air; required for racks of roughly 100 kW and above such as the GB200 NVL72. *See also:* [800 V DC power architecture](#hvdc-800v).
- <a id="liquid-to-air-cooling"></a>**Liquid-to-air (L2A) cooling** — A transitional setup in which a rack's coolant loop dumps its heat into room air through a sidecar radiator, so liquid-cooled racks can run in halls without facility water. *See also:* [Coolant distribution unit (CDU)](#cdu), [Direct-to-chip liquid cooling](#direct-to-chip-cooling).
- <a id="lithography"></a>**Lithography** — The printing step of chipmaking: a scanner projects light through a patterned mask onto a light-sensitive coating on the wafer, defining one layer of the circuit. A modern chip needs dozens of such layers. *See also:* [EUV lithography](#euv-lithography), [Photomask](#photomask).
- <a id="llm-d"></a>**llm-d** — An open-source Kubernetes project (CNCF sandbox, founded by Red Hat, Google Cloud, IBM Research, CoreWeave and NVIDIA) that adds Dynamo-like routing and prefill/decode splitting on top of vLLM and SGLang across GPU and TPU fleets. *See also:* [Dynamo](#dynamo), [vLLM](#vllm).
- <a id="load-factor"></a>**Load factor** — The average share of full power a facility actually draws. Idle accelerators still draw some power, so a TCO model charges a floor plus the busy share. *See also:* [PUE (power usage effectiveness)](#pue), [Utilization (fleet)](#utilization).
- <a id="load-store-semantics"></a>**Load/store semantics** — Communication in which one processor reads or writes another's memory directly with ordinary memory instructions, as NVLink allows, instead of packaging data into network messages. It cuts software overhead and latency for small, frequent transfers. *See also:* [NVLink](#nvlink), [RDMA (remote direct memory access)](#rdma), [Scale-up](#scale-up).
- <a id="local-silicon-interconnect"></a>**Local silicon interconnect (LSI) bridge** — A small piece of silicon with very fine wiring, embedded under the edges of neighbouring dies in a CoWoS-L package, so that silicon is used only where dense connections are needed. *See also:* [CoWoS-L](#cowos-l), [EMIB / EMIB-T](#emib), [Interposer](#interposer).
- <a id="long-term-agreement"></a>**Long-term agreement (LTA)** — A multi-year supply contract that fixes volumes and often prices or price formulas, sometimes with prepayments; memory makers used them in 2026 to book HBM and DRAM output years ahead. *See also:* [Supply prepayment](#prepayment), [Purchase obligations](#purchase-obligations).
- <a id="loss-function"></a>**Loss function** — The single number that measures how wrong the model's predictions were on a batch; training tries to push it down. *See also:* [Gradient](#gradient).
- <a id="lpddr"></a>**LPDDR** — Low-power DRAM originally designed for phones, sold as chips or modules. Much cheaper per gigabyte and denser than HBM but with far lower bandwidth; used for large-capacity inference cards such as Qualcomm's AI200. *See also:* [LPDDR5X](#lpddr5x), [SOCAMM](#socamm), [HBM (high-bandwidth memory)](#hbm).
- <a id="lpddr5x"></a>**LPDDR5X** — Low-power DRAM originally made for phones, used by Grace and Vera instead of standard server DIMMs because it delivers more bandwidth per watt; it is soldered or mounted close to the CPU. *See also:* [SOCAMM](#socamm).
## M

- <a id="maia"></a>**Maia** — Microsoft's in-house AI accelerator line for Azure: Maia 100 (2024), Maia 200 (2026, inference, runs Copilot) and Maia 300 (announced for 2027). *See also:* [Azure Cobalt](#azure-cobalt), [Captive silicon](#captive-silicon).
- <a id="mamba"></a>**Mamba (state-space layer)** — A neural-network layer that carries a fixed-size running state through a sequence instead of attending to every earlier token, so its memory does not grow with context length. Used alongside attention in hybrid models. *See also:* [Attention](#attention), [KV cache](#kv-cache).
- <a id="mark-to-market"></a>**Mark-to-market gain** — A profit recorded because an investment's market or appraised value rose, without selling it. It lifts reported earnings but is not cash and reverses if prices fall. *See also:* [Non-marketable equity security](#non-marketable-equity).
- <a id="modular-max"></a>**MAX (Modular)** — Modular's inference framework and kernel library written in Mojo, offering an OpenAI-compatible serving endpoint on NVIDIA and AMD GPUs. *See also:* [Mojo](#mojo).
- <a id="mttr"></a>**Mean time to recovery (MTTR)** — Average time from a failure to the job running productively again: detection, isolating the bad node, restarting and re-doing work since the last checkpoint. *See also:* [Effective training time](#effective-training-time), [Checkpoint](#checkpoint).
- <a id="memory-pooling"></a>**Memory pooling** — Sharing a large bank of memory among many processors over a fabric such as CXL or Ethernet, so capacity can be added without buying more GPUs or HBM. *See also:* [CXL (Compute Express Link)](#cxl), [KV cache](#kv-cache).
- <a id="memory-supercycle"></a>**Memory supercycle** — A period when memory demand outruns supply and prices and margins rise sharply across DRAM and HBM, as in 2026 when DRAM industry revenue rose 81% in one quarter. *See also:* [HBM (high-bandwidth memory)](#hbm), [Long-term agreement (LTA)](#long-term-agreement).
- <a id="memory-wall"></a>**Memory wall** — The gap between how fast processors compute and how fast memory can feed them data. In LLM inference (especially the decode phase) performance is often bound by memory bandwidth, not FLOPS. *See also:* [HBM (high-bandwidth memory)](#hbm).
- <a id="memory-bound"></a>**Memory-bound** — A workload whose speed is limited by how fast data can be read from memory rather than by how fast the chip can calculate; adding FLOPS does not help, adding bandwidth does. *See also:* [Compute-bound](#compute-bound), [Memory wall](#memory-wall).
- <a id="merchant-silicon"></a>**Merchant silicon** — Chips sold on the open market to any buyer (NVIDIA GPUs, AMD Instinct), as opposed to custom chips a company designs for its own use (Google TPU, AWS Trainium). *See also:* [XPU (custom accelerator)](#xpu).
- <a id="merger-review"></a>**Merger review** — Antitrust screening of acquisitions by agencies such as the US FTC/DOJ (Hart-Scott-Rodino filings), the European Commission, the UK CMA and China's SAMR; reviews can take a year or more and can block deals, as with NVIDIA-Arm. *See also:* [Licence plus acquihire](#licence-plus-acquihire).
- <a id="mfu"></a>**MFU (model FLOPs utilization)** — The share of a GPU's theoretical peak FLOPS that turns into useful model arithmetic during training. Large training runs typically achieve about 35-45%. *See also:* [FLOPS](#flops), [Goodput](#goodput).
- <a id="mgx"></a>**MGX** — NVIDIA's modular reference architecture for servers and racks, which partners use to build systems around NVIDIA or partner chips. AWS plans to place Trainium4 in MGX racks with NVLink. *See also:* [NVLink Fusion](#nvlink-fusion), [NVL72](#nvl72).
- <a id="micro-batch"></a>**Micro-batch** — A small slice of a training batch processed as one unit through a pipeline; more micro-batches per step shrink the pipeline bubble. *See also:* [Pipeline bubble](#pipeline-bubble).
- <a id="microbump"></a>**Micro-bump** — A tiny solder joint, tens of micrometres across, that connects one stacked die to the next or a die to an interposer. HBM stacks use thousands per layer. *See also:* [Through-silicon via (TSV)](#through-silicon-via), [Hybrid bonding](#hybrid-bonding), [Interposer](#interposer).
- <a id="micro-ring-modulator"></a>**Micro-ring modulator** — A tiny ring-shaped silicon-photonics device that switches light on and off to encode data. Very small and low-power, it is the modulator NVIDIA uses in its CPO engines (built on TSMC's COUPE process), but it is sensitive to temperature. *See also:* [Co-packaged optics (CPO)](#co-packaged-optics).
- <a id="microscaling"></a>**Microscaling (MX formats)** — An industry standard (Open Compute Project, 2023) in which each block of 32 low-precision values shares one 8-bit power-of-two scale factor. MXFP8, MXFP6 and MXFP4 are the main members; NVIDIA's NVFP4 is a variant with 16-value blocks. *See also:* [NVFP4](#nvfp4), [FP4](#fp4).
- <a id="mid-cycle-refresh"></a>**mid-cycle refresh** — An upgraded version of a GPU generation released about a year after the original, such as Blackwell Ultra (B300) after Blackwell or Rubin Ultra after Rubin, usually adding memory and compute on the same architecture. *See also:* [Annual cadence](#annual-cadence).
- <a id="midplane"></a>**Midplane** — A large printed-circuit board in the middle of a rack or chassis into which compute and switch blades plug from both sides, replacing cables. NVIDIA's Kyber rack uses a midplane instead of the NVL72's cable spine. *See also:* [Kyber](#kyber), [NVLink spine](#nvlink-spine).
- <a id="mig"></a>**MIG (Multi-Instance GPU)** — A hardware feature (since NVIDIA Ampere) that splits one data-center GPU into up to seven isolated mini-GPUs, each with its own slice of memory and compute, so several small jobs can share a GPU without interfering. *See also:* [Fractional GPU](#fractional-gpu), [GPU time-slicing](#gpu-time-slicing).
- <a id="mixed-precision"></a>**Mixed-precision training** — Doing the heavy arithmetic in a compact number format (BF16 or FP8) while keeping a full-precision (FP32) master copy of the weights so small updates are not lost. *See also:* [BF16 (bfloat16)](#bf16), [FP8](#fp8), [Adam optimizer](#adam).
- <a id="mixture-of-experts"></a>**Mixture-of-experts (MoE)** — A model design that routes each token to a few of many expert sub-networks, so only a fraction of parameters is active per token (DeepSeek-V3: 37B of 671B). Saves compute but still needs memory for all experts and fast all-to-all networking. *See also:* [Expert parallelism (EP)](#expert-parallelism), [NVLink](#nvlink).
- <a id="mlir"></a>**MLIR** — Multi-Level Intermediate Representation: open compiler infrastructure (from the LLVM project) used to build AI compilers such as Mojo, IREE, Triton and NKI. *See also:* [XLA](#xla), [Mojo](#mojo).
- <a id="mlperf"></a>**MLPerf** — Industry benchmark suites run by MLCommons; MLPerf Inference measures audited throughput per system on fixed models and accuracy targets. *See also:* [InferenceX](#inferencex).
- <a id="moat"></a>**Moat** — A durable advantage that keeps competitors from taking a business's customers or margins, such as switching costs, scale economies, supply access or network effects. In this repo a moat is judged by how long and how much it would cost a buyer or rival to get around it. *See also:* [Moat score](#moat-score).
- <a id="moat-score"></a>**Moat score** — This repo's 1-5 judgement of how hard it is to get around NVIDIA in one stack layer: 1 = commoditised or NVIDIA behind, 3 = rivals at parity on some dimensions while NVIDIA leads on integration, 5 = no rival close and switching takes years. A synthesis of each layer page's verdicts, not a measured quantity. *See also:* [Gap trend](#gap-trend).
- <a id="model-hub"></a>**Model hub** — A platform where developers find, download and deploy models and datasets; Hugging Face is the largest and is being acquired by NVIDIA (pending). *See also:* [Open-weight model](#open-weight-model).
- <a id="model-specific-asic"></a>**Model-specific ASIC** — A chip hard-wired for one model family, such as Etched's transformer-only Sohu. It can be very efficient if the architecture stays stable and becomes stranded if it changes. *See also:* [ASIC](#asic), [Transformer](#transformer).
- <a id="moe-router"></a>**MoE router** — The small learned network in a mixture-of-experts layer that scores the experts for each token and picks which few will process it. *See also:* [Mixture-of-experts (MoE)](#mixture-of-experts).
- <a id="mojo"></a>**Mojo** — A Python-superset programming language from Modular (now part of Qualcomm) designed to write high-performance kernels that run on CPUs and GPUs from several vendors; open-sourced under Apache 2.0 in 2026. *See also:* [MAX (Modular)](#modular-max), [MLIR](#mlir).
- <a id="monte-carlo-simulation"></a>**Monte Carlo simulation** — Re-running a model thousands of times with inputs drawn at random from their plausible ranges, then reporting percentiles (e.g. P10-P90) of the output instead of a single number. *See also:* [Tornado chart](#tornado-chart).
- <a id="mpi"></a>**MPI (Message Passing Interface)** — The decades-old standard for communication between processes in supercomputing; NCCL can run inside MPI applications, and MPI libraries can call NCCL for GPU data. *See also:* [NCCL](#nccl), [UCC (Unified Collective Communication)](#ucc).
- <a id="mrdimm"></a>**MRDIMM** — Multiplexed-rank DIMM: a server memory module that interleaves two ranks to roughly double the data rate per channel (e.g. 8,800 MT/s), raising CPU memory bandwidth without more channels. *See also:* [LPDDR5X](#lpddr5x).
- <a id="msccl"></a>**MSCCL++** — Microsoft's open-source GPU communication stack that lets developers write custom collective algorithms with one-sided GPU-driven primitives; it runs on NVIDIA and AMD GPUs. *See also:* [NCCL](#nccl), [RCCL](#rccl).
- <a id="mtbi"></a>**MTBI (mean time between interruptions)** — Average GPU-hours a large training job runs before a hardware or software fault interrupts it. Higher MTBI means less work lost to restarts. *See also:* [Hot spare](#hot-spare).
- <a id="mtia"></a>**MTIA** — Meta Training and Inference Accelerator: Meta's in-house chip line, first for ranking and recommendation models, now extended to generative-AI inference (MTIA 300-500). *See also:* [Recommendation model](#recommendation-model), [Captive silicon](#captive-silicon).
- <a id="multi-head-latent-attention"></a>**Multi-head latent attention (MLA)** — DeepSeek's attention design that caches a small compressed latent vector per token instead of full keys and values, cutting KV-cache memory by over 90%. *See also:* [KV cache](#kv-cache), [Grouped-query attention (GQA)](#grouped-query-attention).
- <a id="multi-plane-network"></a>**Multi-plane network** — A fabric built as several independent parallel networks ('planes'), with each GPU's NIC split across them. Lower-radix ports per plane let two tiers reach more GPUs, and a failed plane only removes part of the bandwidth. *See also:* [Fat tree (Clos network)](#fat-tree), [Switch radix](#switch-radix).
- <a id="multi-tenancy"></a>**Multi-tenancy** — Several customers sharing the same physical infrastructure while being kept isolated from one another in performance, network reachability and data. *See also:* [Bare-metal instance](#bare-metal), [Zero-trust isolation](#zero-trust).
- <a id="multi-token-prediction"></a>**Multi-token prediction (MTP)** — A model feature, used by DeepSeek, that drafts several future tokens per step so the server can verify them together: a built-in form of speculative decoding that can raise throughput several-fold at the same speed per user. *See also:* [Speculative decoding](#speculative-decoding), [Decode (generation phase)](#decode).
- <a id="cloud-service-agreement"></a>**Multi-year cloud service agreement** — NVIDIA's disclosed commitments to pay cloud providers for capacity over several years (used for DGX Cloud and its own research). They appear in its filings as purchase commitments, not as revenue. *See also:* [DGX Cloud](#dgx-cloud), [Capacity backstop](#capacity-backstop).
## N

- <a id="national-champion"></a>**National champion** — A domestic chip supplier that a government backs to replace foreign technology, usually behind export controls or procurement rules; Huawei's Ascend in China is the main example. *See also:* [Export controls](#export-controls), [Huawei Ascend](#huawei-ascend).
- <a id="nccl"></a>**NCCL** — NVIDIA Collective Communications Library: the software that runs all-reduce, all-gather and similar operations across GPUs over NVLink, InfiniBand or Ethernet. *See also:* [All-reduce](#all-reduce), [CUDA-X](#cuda-x).
- <a id="near-memory-compute"></a>**Near-memory computing** — Placing compute logic inside or right next to memory so data travels a shorter distance, raising effective bandwidth and cutting energy per operation; Qualcomm's AI250 and d-Matrix use variants of the idea. *See also:* [Memory wall](#memory-wall).
- <a id="nemo"></a>**NeMo** — NVIDIA's open-source family of tools for building and adapting AI models: data curation, training and fine-tuning, reinforcement learning, evaluation and guardrails. *See also:* [Nemotron](#nemotron), [NeMo Guardrails](#nemo-guardrails).
- <a id="nemo-guardrails"></a>**NeMo Guardrails** — An open-source NVIDIA toolkit that adds programmable rules around a language model's inputs and outputs, for example blocking off-topic answers or enforcing a dialogue flow. *See also:* [NeMo](#nemo), [NVIDIA NIM](#nim).
- <a id="nemotron"></a>**Nemotron** — NVIDIA's family of open-weight AI models, released with much of their training data and recipes. The 2025-26 Nemotron 3 models are sparse hybrid Mamba-Transformer mixture-of-experts designs. *See also:* [NeMo](#nemo), [Mixture-of-experts (MoE)](#mixture-of-experts), [Mamba (state-space layer)](#mamba).
- <a id="neocloud"></a>**Neocloud** — A cloud provider specialised in renting GPU capacity for AI (for example CoreWeave, Lambda, Nebius, Crusoe), as opposed to a general-purpose hyperscaler. Several are NVIDIA investees or partners. *See also:* [Circular financing](#circular-financing).
- <a id="neoverse"></a>**Neoverse** — Arm's family of datacenter CPU core designs (N-series for efficiency, V-series for performance). Grace and Graviton4 both use Neoverse V2 cores. *See also:* [Arm (instruction set)](#arm-isa), [Compute Subsystem (CSS)](#compute-subsystem).
- <a id="network-operating-system"></a>**Network operating system (NOS)** — The software that runs a switch: routing, telemetry, configuration. Examples are Arista EOS, Cisco NX-OS, NVIDIA Cumulus Linux and the open-source SONiC. *See also:* [White-box switch](#white-box-switch).
- <a id="neural-network"></a>**Neural network** — A stack of layers, each multiplying its input by a matrix of learned numbers (parameters) and applying a simple non-linear function. The matrix multiplications are what GPUs accelerate. *See also:* [Transformer](#transformer), [Parameter (weight)](#parameter).
- <a id="neuron-sdk"></a>**Neuron SDK** — AWS's software stack for its Trainium and Inferentia chips: compiler, runtime, PyTorch integration (TorchNeuron) and the NKI kernel language. *See also:* [NKI (Neuron Kernel Interface)](#nki).
- <a id="neuronlink"></a>**NeuronLink** — AWS's scale-up interconnect for Trainium chips. NeuronLink-v3 joins 64 Trainium2 in a torus; NeuronLink-v4 with NeuronSwitch-v1 joins 144 Trainium3 all-to-all at about 2 TB/s per chip. *See also:* [Scale-up](#scale-up), [NVLink](#nvlink).
- <a id="npi"></a>**New product introduction (NPI)** — The engineering phase where a new design is turned into a manufacturable, tested product on a factory line; for AI racks this includes thermal, power and cable validation before volume ramp. *See also:* [EMS (electronics manufacturing services)](#ems), [ODM](#odm).
- <a id="nixl"></a>**NIXL** — NVIDIA Inference Xfer Library: open-source software that moves KV-cache blocks and other data point-to-point between GPUs, CPU memory and storage over NVLink or RDMA, used by Dynamo for disaggregated serving. *See also:* [Dynamo](#dynamo), [Disaggregated serving](#disaggregated-serving), [RDMA (remote direct memory access)](#rdma).
- <a id="nki"></a>**NKI (Neuron Kernel Interface)** — AWS's Python-based language for writing custom kernels for Trainium, with an open-source MLIR-based compiler. *See also:* [Neuron SDK](#neuron-sdk), [Triton (OpenAI)](#triton).
- <a id="non-marketable-equity"></a>**Non-marketable equity security** — A stake in a private company (for example OpenAI or Anthropic) with no quoted price; it is carried at cost and adjusted when new funding rounds reveal a different price. *See also:* [Mark-to-market gain](#mark-to-market).
- <a id="north-south-traffic"></a>**North-south traffic** — Traffic between a data center and the outside world: users, the internet and other sites. *See also:* [East-west traffic](#east-west-traffic), [Front-end network](#front-end-network).
- <a id="npu"></a>**NPU (neural processing unit)** — A processor built specifically for neural-network math, usually with large matrix engines and less general-purpose control logic than a GPU. Huawei's Ascend and Qualcomm's Cloud AI parts are NPUs. *See also:* [ASIC](#asic), [GPU (graphics processing unit)](#gpu).
- <a id="nre"></a>**NRE (non-recurring engineering)** — The one-time cost of designing a chip, including engineering time, EDA tools, IP licences and photomasks, before any unit is sold. Estimates for a large leading-edge chip run to roughly $0.5-0.7B. *See also:* [Tape-out](#tape-out), [EDA (electronic design automation)](#eda).
- <a id="nv-hbi"></a>**NV-HBI (high-bandwidth interface)** — NVIDIA's die-to-die link that joins the two reticle-sized compute dies of a Blackwell or Rubin GPU at 10 TB/s, fast enough that software sees one GPU. *See also:* [Die-to-die interconnect](#die-to-die-interconnect), [Chiplet](#chiplet).
- <a id="nvcc"></a>**nvcc** — NVIDIA's CUDA compiler driver. It splits a program into CPU code (passed to the host compiler) and GPU code, which it compiles to PTX and then to SASS machine code. *See also:* [PTX (Parallel Thread Execution)](#ptx), [SASS](#sass).
- <a id="nventures"></a>**NVentures** — NVIDIA's venture-capital arm, which buys minority equity in start-up funding rounds. It is separate from Inception (free membership) and from the large strategic stakes NVIDIA holds directly. *See also:* [NVIDIA Inception](#nvidia-inception), [Corporate venture capital](#corporate-venture-capital).
- <a id="nvfp4"></a>**NVFP4** — NVIDIA's 4-bit floating-point format for Blackwell and Rubin: 4-bit values with an FP8 scale per block of 16 plus a per-tensor scale, about 4.5 bits per value in total. *See also:* [FP8](#fp8), [Quantization](#quantization).
- <a id="nvidia-ai-enterprise"></a>**NVIDIA AI Enterprise** — NVIDIA's paid software subscription (enterprise support, security patches and certified versions of CUDA-X libraries, NIM and frameworks), priced at about $4,500 per GPU per year in 2024. *See also:* [CUDA-X](#cuda-x).
- <a id="ai-enterprise"></a>**NVIDIA AI Enterprise** — NVIDIA's paid software subscription (list ~$4,500 per GPU per year) that bundles NIM, NeMo and enterprise support for its AI software stack. *See also:* [NVIDIA NIM](#nim).
- <a id="dali"></a>**NVIDIA DALI** — NVIDIA's Data Loading Library, which moves image, video and audio decoding and augmentation from the host CPU onto the GPU to prevent data-loading bottlenecks. *See also:* [Data loader](#data-loader).
- <a id="nvidia-inception"></a>**NVIDIA Inception** — NVIDIA's free membership program for start-ups (launched 2016). Members get technical help, training and introductions to investors and partners; NVIDIA takes no equity through the program. *See also:* [NVentures](#nventures), [Corporate venture capital](#corporate-venture-capital).
- <a id="mission-control"></a>**NVIDIA Mission Control** — NVIDIA's operations software for AI factories (2025): provisions and monitors DGX racks, diagnoses failures and schedules jobs by combining Base Command Manager with Run:ai. *See also:* [AI factory](#ai-factory), [SuperPoD](#superpod).
- <a id="nim"></a>**NVIDIA NIM** — NVIDIA Inference Microservices: pre-built containers that package a model with an optimised engine and a standard API; production use requires an NVIDIA AI Enterprise licence. *See also:* [NVIDIA AI Enterprise](#ai-enterprise).
- <a id="nvidia-warp"></a>**NVIDIA Warp** — An open-source Python framework from NVIDIA that compiles ordinary Python functions into GPU kernels for physics simulation, robotics and differentiable programming. Not to be confused with a GPU warp of 32 threads. *See also:* [PhysX](#physx), [Warp](#warp).
- <a id="nvl-naming"></a>**NVL naming** — NVIDIA's rack names give the number of GPUs in one NVLink domain; from CES 2026 the number counts GPU packages rather than dies, so 'Vera Rubin NVL144' became Vera Rubin NVL72 and 'Rubin Ultra NVL576' became Kyber NVL144. *See also:* [NVL72](#nvl72), [Kyber](#kyber).
- <a id="nvl72"></a>**NVL72** — NVIDIA's rack-scale system in which 72 GPU packages share one NVLink domain through 18 (Blackwell) or 36 (Vera Rubin) NVLink switch chips. The number counts GPU packages; NVIDIA briefly counted dies ('NVL144') before reverting in 2026. *See also:* [NVLink domain](#nvlink-domain), [NVLink spine](#nvlink-spine), [Oberon](#oberon).
- <a id="nvlink"></a>**NVLink** — NVIDIA's proprietary high-speed GPU-to-GPU link used for scale-up. NVLink 5 (Blackwell) provides 1.8 TB/s per GPU, many times a PCIe slot. *See also:* [NVSwitch](#nvswitch), [Scale-up](#scale-up).
- <a id="nvlink-domain"></a>**NVLink domain** — The set of GPUs that can reach each other directly over NVLink, without going through a network card. Inside it GPUs read and write each other's memory at NVLink speed; outside it traffic falls back to the much slower scale-out network. *See also:* [Scale-up](#scale-up), [NVL72](#nvl72), [NVSwitch](#nvswitch).
- <a id="nvlink-fusion"></a>**NVLink Fusion** — NVIDIA's 2025 program that licenses NVLink so partners' custom CPUs and accelerators can join an NVLink scale-up domain alongside NVIDIA GPUs. Announced partners include Qualcomm, Fujitsu, MediaTek, Marvell and AWS (Trainium4). *See also:* [NVLink](#nvlink), [Scale-up](#scale-up).
- <a id="nvlink-sharp"></a>**NVLink SHARP (NVLS)** — In-network reduction inside NVLink switches: the switch adds up data from all GPUs and multicasts the result, so an all-reduce sends each GPU's data about once instead of about twice. *See also:* [SHARP (in-network reduction)](#sharp), [NCCL](#nccl), [NVSwitch](#nvswitch).
- <a id="nvlink-spine"></a>**NVLink spine** — The bundle of copper twin-axial cables at the back of an NVL72 rack that joins every GPU tray to every switch tray. NVIDIA describes about 5,000 cables totalling about two miles in GB200 NVL72. *See also:* [NVL72](#nvl72), [Direct-attach copper (DAC)](#direct-attach-copper), [NVLink switch tray](#nvlink-switch-tray).
- <a id="nvlink-switch-tray"></a>**NVLink switch tray** — A 1U tray in an NVL72 rack that holds NVLink switch chips (two per tray in GB200 NVL72), a management controller and rear connectors that plug into the copper spine. Nine trays switch all 72 GPUs. *See also:* [NVSwitch](#nvswitch), [NVLink spine](#nvlink-spine), [Blind-mate connector](#blind-mate-connector).
- <a id="nvlink-c2c"></a>**NVLink-C2C** — NVIDIA's chip-to-chip link joining a Grace or Vera CPU to its GPUs at 900 GB/s (Grace) or 1.8 TB/s (Vera), several times a PCIe slot, with cache coherence so the GPU can use CPU memory directly. *See also:* [Cache coherence](#cache-coherence), [NVLink](#nvlink), [Superchip](#superchip).
- <a id="nvme"></a>**NVMe** — The command protocol flash SSDs use over PCIe. It allows tens of thousands of parallel queues, which is why one modern SSD can deliver several GB/s. *See also:* [NVMe over Fabrics (NVMe-oF)](#nvme-of).
- <a id="nvme-of"></a>**NVMe over Fabrics (NVMe-oF)** — NVMe commands carried over a network (RDMA, TCP or Fibre Channel) so a server can use remote flash as if it were a local drive. DPUs can run the initiator or target in hardware. *See also:* [NVMe](#nvme), [RDMA (remote direct memory access)](#rdma).
- <a id="nvqlink"></a>**NVQLink** — NVIDIA's 2025 interconnect architecture linking quantum processors and their control systems to GPU supercomputers for real-time error correction; launched with 17 quantum hardware builders. *See also:* [CUDA-Q](#cuda-q).
- <a id="nvswitch"></a>**NVSwitch** — A switch chip that connects many GPUs' NVLink ports so every GPU can talk to every other at full NVLink speed, forming one scale-up domain (e.g. 72 GPUs in an NVL72 rack). *See also:* [NVLink](#nvlink), [Scale-up](#scale-up).
## O

- <a id="oberon"></a>**Oberon** — The internal name for the rack design used by GB200, GB300 and Vera Rubin NVL72: horizontal compute and switch trays joined by a rear copper NVLink spine. *See also:* [NVL72](#nvl72), [Kyber](#kyber), [NVLink spine](#nvlink-spine).
- <a id="object-storage"></a>**Object storage** — Storage that keeps data as whole objects addressed by key over HTTP (S3 API), scaling to exabytes cheaply but with higher latency than a parallel file system; usually holds raw datasets and archives. *See also:* [Parallel file system](#parallel-file-system).
- <a id="odm"></a>**ODM** — Original design manufacturer: contract manufacturers (Foxconn, Quanta, Wistron and others) that design and build servers, trays and racks to a customer's or NVIDIA's reference design.
- <a id="oem"></a>**OEM (original equipment manufacturer)** — A company that sells servers under its own brand, often built partly by ODMs, and adds sales, service and financing; in AI servers, for example Dell, HPE and Supermicro. *See also:* [ODM](#odm), [L6 / L10 / L11 integration](#l6-l10-l11).
- <a id="offtake-agreement"></a>**Offtake agreement** — A long-term commitment by a large buyer (for example Microsoft or Meta) to rent a provider's future capacity. It lets the provider raise capital before the data center is built. *See also:* [Take-or-pay contract](#take-or-pay), [Capacity backstop](#capacity-backstop).
- <a id="omniverse"></a>**Omniverse** — NVIDIA's platform for building 3D simulations and digital twins of factories, robots and data centers, built on OpenUSD and PhysX. *See also:* [PhysX](#physx).
- <a id="oneapi"></a>**oneAPI** — Intel's cross-vendor programming model and libraries built on SYCL, now governed by the Linux Foundation's UXL Foundation (founding members include Intel, Arm, Google Cloud and Qualcomm). *See also:* [SYCL](#sycl).
- <a id="ocp"></a>**Open Compute Project (OCP)** — An industry foundation, started by Facebook (Meta) in 2011, where hyperscalers and vendors publish open hardware designs for servers, racks and power. NVIDIA contributed its GB200 NVL72 rack design; AMD's Helios uses an OCP rack. *See also:* [Open Rack Wide (ORW)](#open-rack-wide), [MGX](#mgx).
- <a id="open-rack-wide"></a>**Open Rack Wide (ORW)** — A double-width OCP rack specification for very heavy, high-power AI racks; AMD's Helios is built on it. *See also:* [Open Compute Project (OCP)](#ocp), [Rack-scale system](#rack-scale-system).
- <a id="open-weight-model"></a>**Open-weight model** — A model whose trained parameters are published for anyone to download and serve (e.g. Llama, DeepSeek, Qwen, Nemotron), so any provider can compete to serve it. *See also:* [Inference provider](#inference-provider).
- <a id="opencl"></a>**OpenCL** — An open, royalty-free standard for programming GPUs and other processors, backed by Apple, AMD and Intel from the late 2000s. It lost developer mindshare to CUDA in AI because NVIDIA's libraries and tools were better. *See also:* [CUDA](#cuda), [SYCL](#sycl).
- <a id="operating-leverage"></a>**Operating leverage** — When revenue grows faster than costs, so each extra dollar of sales adds more than a dollar's share of profit. NVIDIA's R&D rose 14× from FY2016 to FY2026 yet fell from 27% to about 9% of revenue. *See also:* [Flywheel](#flywheel).
- <a id="operating-point"></a>**Operating point** — The speed per user (tokens per second per user) at which a system is run. Throughput and cost per token change sharply along the throughput-interactivity frontier, so any cost comparison must name its operating point. *See also:* [Interactivity (tokens/s per user)](#interactivity), [Throughput-interactivity Pareto frontier](#pareto-frontier), [Cost per million tokens](#cost-per-million-tokens).
- <a id="optical-circuit-switch"></a>**Optical circuit switch (OCS)** — A switch that steers light beams with tiny mirrors to reconnect fibers without converting to electrical signals. Google uses OCS in place of spine switches in Jupiter and in TPU pods. *See also:* [Fat tree (Clos network)](#fat-tree).
- <a id="optical-dsp"></a>**Optical DSP** — The digital signal processor inside a pluggable transceiver that cleans up and retimes the high-speed signal. Supplied mainly by Marvell and Broadcom; removing it (linear optics) saves power at the cost of reach. *See also:* [Pluggable transceiver](#pluggable-transceiver).
- <a id="optical-io"></a>**Optical I/O chiplet** — A small die, packaged next to a processor, that converts its electrical signals to light so data can leave the package on fibre. It promises scale-up links that span many racks at lower power than pluggable optics; Ayar Labs and Lightmatter build them. *See also:* [Co-packaged optics (CPO)](#co-packaged-optics), [SerDes](#serdes).
- <a id="optimizer"></a>**Optimizer** — The algorithm that turns gradients into parameter updates. It often keeps extra running statistics per parameter, which costs memory. *See also:* [Adam optimizer](#adam), [Gradient](#gradient).
- <a id="osat"></a>**OSAT** — Outsourced semiconductor assembly and test: companies such as ASE and Amkor that package and test chips for fabless designers and foundries. *See also:* [Advanced packaging](#advanced-packaging), [Foundry](#foundry).
- <a id="osborne-effect"></a>**Osborne effect** — The risk that announcing a better future product makes customers stop buying the current one while they wait; named after a 1980s computer maker whose early announcement reportedly froze its sales. *See also:* [Annual cadence](#annual-cadence).
- <a id="over-training"></a>**Over-training** — Deliberately training a model on far more tokens than the Chinchilla-optimal ratio so a smaller model reaches high quality and is cheaper to serve. *See also:* [Chinchilla-optimal](#chinchilla-optimal), [Inference](#inference).
- <a id="overlay-network"></a>**Overlay network** — A virtual network for each tenant built on top of the physical one by wrapping packets in an outer header (for example VXLAN), so many customers can share the same switches without seeing each other. *See also:* [Virtual switch](#virtual-switch), [Multi-tenancy](#multi-tenancy).
- <a id="oversubscription"></a>**Oversubscription** — Having more downlink than uplink bandwidth at a switch tier (for example 3:1), which saves switches and optics but means not every endpoint can send across the tier at full speed at once. *See also:* [Fat tree (Clos network)](#fat-tree), [Bisection bandwidth](#bisection-bandwidth).
- <a id="owner-tco"></a>**Owner TCO** — The all-in yearly cost of owning and running an accelerator (capital charge on the hardware, network, facility, power and operations) divided by its hours. It is what a GPU-hour costs the owner, as opposed to the rental price a customer pays. *See also:* [TCO (total cost of ownership)](#tco), [GPU-hour](#gpu-hour), [Capital recovery factor](#capital-recovery-factor).
## P

- <a id="p4-language"></a>**P4 (programming language)** — A language for programming how a network chip parses and forwards packets, used by AMD Pensando and Intel IPU pipelines. *See also:* [DPU (data processing unit)](#dpu).
- <a id="packet-spraying"></a>**Packet spraying** — Spreading the packets of a single flow across many paths at once. It uses the whole fabric evenly but packets arrive out of order, so the receiving NIC must put them back in sequence. *See also:* [Adaptive routing](#adaptive-routing), [SuperNIC](#supernic).
- <a id="paged-attention"></a>**PagedAttention** — A technique (from vLLM) that stores the KV cache in fixed-size pages like virtual memory, avoiding fragmentation and letting requests share cached prefixes. *See also:* [KV cache](#kv-cache), [Continuous batching](#continuous-batching).
- <a id="pallas"></a>**Pallas** — JAX's kernel language for writing custom TPU (and GPU) kernels when the XLA compiler's output is not fast enough; Google's counterpart to Triton or CUTLASS. *See also:* [XLA](#xla), [CUTLASS](#cutlass).
- <a id="pam4"></a>**PAM4** — Four-level pulse-amplitude modulation: each symbol on the wire carries two bits instead of one, doubling the data rate at the same symbol rate. NVLink moved to PAM4 with Hopper; it is more sensitive to noise, which shortens copper reach. *See also:* [SerDes](#serdes), [Direct-attach copper (DAC)](#direct-attach-copper).
- <a id="panel-level-packaging"></a>**Panel-level packaging** — Building advanced packages on large rectangular panels instead of round 300 mm wafers. Rectangles waste less edge area when each package spans several reticles, but panels warp more. *See also:* [CoPoS (chip-on-panel-on-substrate)](#copos), [CoWoS](#cowos), [Advanced packaging](#advanced-packaging).
- <a id="parabricks"></a>**Parabricks** — NVIDIA's GPU-accelerated genomics software, which runs standard DNA-sequencing pipelines (alignment, variant calling) many times faster than CPU tools. *See also:* [Variant calling](#variant-calling).
- <a id="parallel-file-system"></a>**Parallel file system** — A file system that stripes each file across many storage servers so thousands of clients can read and write at once (for example Lustre/DDN EXAScaler, IBM Storage Scale, WEKA). Suited to checkpoints and training I/O. *See also:* [Object storage](#object-storage).
- <a id="parameter"></a>**Parameter (weight)** — One learned number inside a model. 'A 405B model' has 405 billion of them; training adjusts them and inference reads them for every token generated. *See also:* [Neural network](#neural-network), [Mixed-precision training](#mixed-precision).
- <a id="pat-algorithm"></a>**PAT (Parallel Aggregated Trees)** — An NCCL algorithm (2024) for all-gather and reduce-scatter at very large scale that uses a logarithmic number of steps, cutting latency when each GPU sends little data. *See also:* [Tree all-reduce](#tree-all-reduce), [NCCL](#nccl).
- <a id="payback-period"></a>**Payback period** — The time until cumulative profit or cash from an investment equals the price paid. A discounted payback first grows the price at a cost of capital, so it takes longer.
- <a id="pcie"></a>**PCIe (PCI Express)** — The standard expansion bus that connects GPUs, network cards and SSDs to a host CPU. A 16-lane (x16) link carries about 64 GB/s in total on Gen4, 128 GB/s on Gen5 and 256 GB/s on Gen6, both directions combined. *See also:* [NVLink-C2C](#nvlink-c2c), [CXL (Compute Express Link)](#cxl).
- <a id="pcie-switch"></a>**PCIe switch** — A chip that fans one PCIe connection out to several devices (GPUs, NICs, SSDs) and lets them exchange data peer-to-peer without going through the CPU. ConnectX-8 builds one in. *See also:* [PCIe (PCI Express)](#pcie), [GPUDirect RDMA](#gpudirect-rdma).
- <a id="perf-per-watt"></a>**Perf/W (performance per watt)** — Useful work per unit of power, e.g. FP8 TFLOPS per watt or tokens per second per megawatt. In power-capped data centers it decides how much a site can sell. *See also:* [TCO (total cost of ownership)](#tco).
- <a id="performance-density"></a>**Performance density** — TPP divided by die area in mm². Added by the October 2023 rule so a vendor cannot dodge the TPP line by spreading the same compute over more silicon. *See also:* [TPP (total processing performance)](#tpp).
- <a id="perf-per-dollar"></a>**Performance per dollar** — Useful work (e.g. tokens per second) per dollar of owner cost or rental price; the metric custom ASICs compete on when they trail on peak performance. *See also:* [TCO (total cost of ownership)](#tco), [Perf/W (performance per watt)](#perf-per-watt).
- <a id="photomask"></a>**Photomask** — A quartz plate carrying the pattern of one circuit layer, used as a stencil in lithography. A full set for a leading-edge chip costs millions of dollars, one reason chip designs are expensive to change. *See also:* [Lithography](#lithography).
- <a id="physx"></a>**PhysX** — The physics engine NVIDIA gained with Ageia in 2008, used in games, robotics simulation and Omniverse; now open source. *See also:* [Omniverse](#omniverse), [NVIDIA Warp](#nvidia-warp).
- <a id="picojoules-per-bit"></a>**Picojoules per bit (pJ/bit)** — Energy needed to move one bit across a link; watts divided by bits per second. A DSP-based optical module uses about 15-19 pJ/bit, co-packaged optics about 5 pJ/bit and a passive copper cable adds almost nothing beyond the chips' own SerDes. *See also:* [Co-packaged optics (CPO)](#co-packaged-optics), [Linear pluggable optics (LPO)](#linear-pluggable-optics), [SerDes](#serdes).
- <a id="pin-speed"></a>**Pin speed** — How many billions of bits each wire of a memory interface carries per second (Gb/s). HBM bandwidth per stack = interface width x pin speed / 8; Rubin's HBM4 revision traces to lower-than-targeted pin speeds. *See also:* [HBM (high-bandwidth memory)](#hbm), [HBM4E](#hbm4e).
- <a id="pipeline-bubble"></a>**Pipeline bubble** — The idle time in pipeline parallelism while stages wait for the line to fill and drain; for p stages and m micro-batches it is about (p − 1)/(m + p − 1) of each step. *See also:* [Pipeline parallelism (PP)](#pipeline-parallelism), [Micro-batch](#micro-batch).
- <a id="pipeline-parallelism"></a>**Pipeline parallelism (PP)** — Cutting a model's layers into consecutive stages on different GPUs and streaming micro-batches through them like an assembly line; only activations cross stage boundaries. *See also:* [Pipeline bubble](#pipeline-bubble), [Micro-batch](#micro-batch).
- <a id="pluggable-transceiver"></a>**Pluggable transceiver** — A removable optical module (for example an 800G or 1.6T OSFP) that plugs into a switch or NIC port and converts electrical signals to light. Easy to replace, but it needs a power-hungry DSP to drive signals across the circuit board. *See also:* [Co-packaged optics (CPO)](#co-packaged-optics), [Linear pluggable optics (LPO)](#linear-pluggable-optics).
- <a id="post-training"></a>**Post-training** — Everything done to a model after pre-training on raw text: instruction tuning, preference tuning and reinforcement learning. A growing share of total training compute. *See also:* [Reinforcement learning (RL)](#reinforcement-learning), [Reasoning model](#reasoning-model).
- <a id="power-shelf"></a>**Power shelf** — A 1U drawer of power supplies that converts the building's AC power into low-voltage DC for a rack; in a GB200 NVL72 each shelf holds six 5.5 kW supplies (up to 33 kW). *See also:* [Busbar](#busbar), [800 V DC power architecture](#hvdc-800v).
- <a id="pre-announcement-horizon"></a>**pre-announcement horizon** — How far ahead of volume availability a vendor publicly dates a product (name plus target year); in this repo measured in months from the first dated mention to planned availability. *See also:* [Annual cadence](#annual-cadence), [Osborne effect](#osborne-effect).
- <a id="preemption"></a>**Preemption** — A scheduler stopping (and usually requeuing) a lower-priority job to give its GPUs to a higher-priority one. It lets clusters lend idle capacity without blocking urgent work. *See also:* [Gang scheduling](#gang-scheduling).
- <a id="prefill"></a>**Prefill (context phase)** — The first phase of an inference request: the whole prompt is processed in parallel to build the KV cache and produce the first token. Compute-bound. *See also:* [Decode (generation phase)](#decode), [TTFT (time to first token)](#ttft).
- <a id="price-elasticity"></a>**Price elasticity of demand** — The percentage change in quantity bought for a 1% change in price. Above 1 (elastic), a price cut raises total spending; below 1 (inelastic), it lowers it. *See also:* [Jevons paradox](#jevons-paradox).
- <a id="price-umbrella"></a>**Price umbrella** — The room created when a market leader keeps prices well above cost: rivals can price below it and still earn a return, and the leader can cut prices selectively to squeeze them. NVIDIA's ~75% gross margin is the umbrella over AI accelerators. *See also:* [Gross margin](#gross-margin), [Free-chip test](#free-chip-test).
- <a id="pricing-power"></a>**Pricing power** — The ability to raise or hold prices without losing volume. For NVIDIA it shows up as a ~75% gross margin; rivals and in-house chips limit it first at the largest buyers. *See also:* [Price umbrella](#price-umbrella).
- <a id="priority-flow-control"></a>**Priority Flow Control (PFC)** — An Ethernet mechanism that tells the upstream device to pause a traffic class when a buffer fills, so packets are not dropped. It makes Ethernet 'lossless' for RoCE but can spread pauses through the fabric if overused. *See also:* [RoCE (RDMA over Converged Ethernet)](#roce), [Credit-based flow control](#credit-based-flow-control).
- <a id="process-node"></a>**Process node** — A generation of chip-manufacturing technology (e.g. TSMC N7, N4, N3, N2, A16). The names are marketing labels rather than physical dimensions; each new node packs more transistors per area at a higher price per wafer. *See also:* [Wafer](#wafer), [Foundry](#foundry).
- <a id="programmable-shader"></a>**programmable shader** — A small program that a GPU runs once per vertex or per pixel; once shaders became programmable (GeForce 3, 2001) the GPU became a general parallel processor, the precursor to CUDA. *See also:* [GPGPU (general-purpose GPU computing)](#gpgpu).
- <a id="ptx"></a>**PTX (Parallel Thread Execution)** — NVIDIA's virtual instruction set. CUDA code is compiled to PTX, and the driver translates PTX into each GPU generation's native code, which is why old CUDA programs run on new GPUs. *See also:* [CUDA](#cuda), [GPU kernel](#gpu-kernel).
- <a id="pue"></a>**PUE (power usage effectiveness)** — Total facility power divided by the power used by the IT equipment; 1.0 would mean zero overhead for cooling and power conversion. *See also:* [Liquid cooling](#liquid-cooling).
- <a id="purchase-obligations"></a>**Purchase obligations** — Binding commitments to buy inventory, components or manufacturing capacity in the future, disclosed in a company's filings. NVIDIA's supply and capacity commitments reached $279B in Q2 FY2027; they secure scarce supply but must be paid even if demand falls. *See also:* [Flywheel](#flywheel).
- <a id="purchase-vested-warrant"></a>**Purchase-vested warrant** — A warrant that vests in tranches only as the holder buys a set dollar amount of the issuer's products; a supplier uses it to share upside with a large customer. *See also:* [Warrant](#warrant), [Equity-for-capacity](#equity-for-capacity).
- <a id="pytorch"></a>**PyTorch** — The open-source deep-learning framework created at Meta (2016-17) and now the default in AI research. Models are written once in Python; vendor backends (CUDA first, then ROCm, TPU and others) run them. *See also:* [Triton (OpenAI)](#triton), [XLA](#xla).
## Q

- <a id="quadratic-surfaces"></a>**quadratic surfaces** — A way of drawing 3D shapes from curved patches described by second-order equations, used by NVIDIA's first chip (NV1) instead of the flat triangles the industry standardised on. *See also:* [Direct3D](#direct3d).
- <a id="quantization"></a>**Quantization** — Storing and computing with fewer bits per number (e.g. FP8 or FP4 instead of BF16). Cuts memory and bandwidth per token, at some risk to accuracy. *See also:* [FP8](#fp8), [NVFP4](#nvfp4).
## R

- <a id="rack-scale-system"></a>**Rack-scale system** — An AI computer sold and engineered as a whole rack (compute trays, switch trays, power shelves, cabling and liquid cooling) rather than as individual servers, so that dozens of accelerators behave like one machine. NVIDIA's NVL72, AMD's Helios and AWS's UltraServers are examples. *See also:* [Scale-up](#scale-up), [NVLink](#nvlink), [Liquid cooling](#liquid-cooling).
- <a id="rail-optimized"></a>**Rail-optimized topology** — A cluster wiring pattern in which NIC number k of every server connects to the same 'rail' leaf switch, so same-numbered GPUs across servers are one switch hop apart. It matches how collective libraries move data. *See also:* [Fat tree (Clos network)](#fat-tree), [NCCL](#nccl).
- <a id="rapids"></a>**RAPIDS** — NVIDIA's open-source suite of GPU data-science libraries launched in 2018 (cuDF, cuML, cuGraph, cuVS and others) that mirror popular Python tools such as pandas and scikit-learn. *See also:* [cuDF](#cudf), [cuML](#cuml).
- <a id="rccl"></a>**RCCL** — AMD's ROCm Communication Collectives Library, derived from NCCL's code and API, which runs collectives on Instinct GPUs over Infinity Fabric and networks. *See also:* [NCCL](#nccl), [ROCm](#rocm).
- <a id="rdma"></a>**RDMA (remote direct memory access)** — A way for one machine's network card to read or write another machine's memory directly, without either operating system copying the data. It cuts latency and CPU work, which is why AI clusters use it for GPU-to-GPU traffic. *See also:* [RoCE (RDMA over Converged Ethernet)](#roce), [GPUDirect RDMA](#gpudirect-rdma), [InfiniBand](#infiniband).
- <a id="reasoning-model"></a>**Reasoning model** — A model trained (usually with reinforcement learning) to generate a hidden chain of thought before answering. Better answers on hard problems at the cost of many more generated tokens. *See also:* [Test-time compute](#test-time-compute), [Reinforcement learning (RL)](#reinforcement-learning).
- <a id="recommendation-model"></a>**Recommendation model** — A model that ranks ads, posts or products for each user (e.g. DLRM). It is dominated by huge embedding-table lookups rather than the dense matrix maths of LLMs, so it rewards different chip designs. *See also:* [MTIA](#mtia).
- <a id="redistribution-layer"></a>**Redistribution layer (RDL)** — Thin layers of metal wiring built on top of an organic or silicon base to route signals between dies and to the package's connections; coarser than wiring inside a chip but far finer than a circuit board. *See also:* [CoWoS-R](#cowos-r), [CoWoS-L](#cowos-l), [Interposer](#interposer).
- <a id="reduce-scatter"></a>**Reduce-scatter** — A collective in which GPUs sum their vectors but each GPU keeps only its own slice of the result; the first half of a ring all-reduce. *See also:* [All-reduce](#all-reduce), [All-gather](#all-gather).
- <a id="reference-architecture"></a>**Reference architecture** — A vendor-specified, tested bill of materials and configuration (servers, network, storage, software) that partners can quote and support as a complete system. NVIDIA's enterprise version is called a validated design. *See also:* [NVIDIA AI Enterprise](#nvidia-ai-enterprise), [RTX PRO server](#rtx-pro-server).
- <a id="reference-design"></a>**Reference design** — A complete, documented design that a platform owner publishes so partners can build compatible products quickly (NVIDIA's HGX, MGX and DGX SuperPOD architectures are reference designs). *See also:* [MGX](#mgx), [HGX](#hgx).
- <a id="register-file"></a>**Register file** — The fastest storage on a GPU: 256 KB of registers per SM holding the values threads are working on right now. It sits next to the arithmetic units and feeds them every clock. *See also:* [Shared memory (L1)](#shared-memory), [Streaming multiprocessor (SM)](#streaming-multiprocessor).
- <a id="registered-developer"></a>**Registered developer** — Someone who has signed up to NVIDIA's developer programme. The count is cumulative and self-reported, so it measures reach rather than how many people actively write CUDA code today. *See also:* [CUDA](#cuda).
- <a id="reinforcement-learning"></a>**Reinforcement learning (RL)** — Training by trial and reward: the model generates many candidate answers, they are scored (e.g. by checking a math result or running code), and the model is updated toward the better ones. RL runs contain large inference workloads. *See also:* [Post-training](#post-training), [Reasoning model](#reasoning-model).
- <a id="residual-value"></a>**Residual value** — What an asset can be sold for at the end of its use. Positive resale prices for old GPUs lower their true cost; falling rental prices lower residual values and can force impairments. *See also:* [Economic life](#economic-life), [GPU-backed loan](#gpu-backed-loan).
- <a id="reticle-limit"></a>**Reticle limit** — The maximum area a lithography scanner can expose in one shot (~858 mm² for today's EUV tools), which caps the size of a single die and pushes designers to multi-die packages. *See also:* [Die](#die).
- <a id="retimer"></a>**Retimer** — A chip that receives a weakened high-speed signal, recovers the data and retransmits it cleanly, extending how far a copper link can run. Common on PCIe and CXL links; Astera Labs is a leading supplier. *See also:* [Active electrical cable (AEC)](#active-electrical-cable), [SerDes](#serdes).
- <a id="revenue-backlog"></a>**Revenue backlog** — Revenue a company has under signed contract but not yet delivered (often called remaining performance obligations). It shows demand visibility, not cash: contracts can be delayed or renegotiated. *See also:* [Take-or-pay contract](#take-or-pay).
- <a id="revenue-by-customer-hq"></a>**Revenue by customer headquarters** — Geographic revenue assigned to the country where the customer is headquartered rather than where it is billed. NVIDIA switched to this basis in Q3 FY2026, which raised China's reported share. *See also:* [Export controls](#export-controls).
- <a id="reverse-dcf"></a>**Reverse DCF** — Working backwards from today's market value to the growth or margins it implies, instead of forecasting cash flows and deriving a value; in its simplest form P/E = 1 / (cost of equity - growth). *See also:* [Forward P/E](#forward-pe).
- <a id="ridge-point"></a>**Ridge point** — The arithmetic intensity at which a chip switches from memory-bound to compute-bound: peak FLOPS divided by memory bandwidth. About 295 FLOPs per byte for an H100 in dense BF16. *See also:* [Roofline model](#roofline-model), [Arithmetic intensity](#arithmetic-intensity).
- <a id="ring-all-reduce"></a>**Ring all-reduce** — An all-reduce algorithm that passes chunks around a ring of GPUs; each GPU sends about twice the data size regardless of how many GPUs take part. *See also:* [All-reduce](#all-reduce).
- <a id="risc-v"></a>**RISC-V** — An open, royalty-free instruction set that anyone can implement. Start-ups such as Ventana, Rivos, Tenstorrent and Akeana design high-performance RISC-V cores as an alternative to Arm. *See also:* [ISA (instruction set architecture)](#isa), [Arm (instruction set)](#arm-isa).
- <a id="risk-heatmap"></a>**Risk heatmap** — A grid that places each risk by its likelihood (x-axis) and impact (y-axis), usually scored 1-5 each; the product of the two ranks which risks deserve attention first. *See also:* [Leading indicator](#leading-indicator).
- <a id="roce"></a>**RoCE (RDMA over Converged Ethernet)** — RDMA carried inside Ethernet packets (RoCEv2 uses UDP/IP). It brings InfiniBand-style direct memory transfers to Ethernet, but needs careful congestion control because Ethernet was designed to drop packets when busy. *See also:* [RDMA (remote direct memory access)](#rdma), [Priority Flow Control (PFC)](#priority-flow-control), [Congestion control](#congestion-control).
- <a id="rocm"></a>**ROCm** — AMD's open-source GPU software stack (drivers, compilers, libraries, HIP), first released in 2016. It is AMD's answer to CUDA. *See also:* [HIP](#hip), [CUDA](#cuda).
- <a id="roofline-model"></a>**Roofline model** — A simple chart of a chip's attainable speed: the lower of its peak compute (a flat roof) and its memory bandwidth times the work's arithmetic intensity (a sloped line). It shows at a glance whether a workload is limited by compute or by memory. *See also:* [Arithmetic intensity](#arithmetic-intensity), [Ridge point](#ridge-point).
- <a id="rtx-pro-server"></a>**RTX PRO server** — An air-cooled x86 server with NVIDIA RTX PRO 6000 Blackwell Server Edition GPUs, sold by OEMs from 2025 for enterprises that cannot host liquid-cooled rack-scale systems. *See also:* [Reference architecture](#reference-architecture).
- <a id="rubin-cpx"></a>**Rubin CPX** — An NVIDIA GPU announced in September 2025 for the prefill (context) phase of inference, with 128 GB of GDDR7 instead of HBM. It was absent from the March 2026 roadmap; a revival with HBM4 is reported but unconfirmed. *See also:* [Prefill (context phase)](#prefill), [Disaggregated serving](#disaggregated-serving), [GDDR (graphics DRAM)](#gddr).
- <a id="rubin-ultra"></a>**Rubin Ultra** — NVIDIA's 2027 GPU generation, announced with four reticle-sized dies, about 100 PFLOPS of FP4 and 1 TB of HBM4E per package for the Kyber rack; reports in 2026 describe a two-die version and 768 GB. *See also:* [Kyber](#kyber), [HBM4E](#hbm4e).
- <a id="run-ai"></a>**Run:ai** — An Israeli GPU-orchestration software company NVIDIA bought in 2024 (about $700M reported); its platform pools GPUs across teams and was fully open-sourced in October 2026. *See also:* [KAI Scheduler](#kai-scheduler), [NVIDIA Mission Control](#mission-control).
## S

- <a id="same-year-flagship"></a>**Same-year flagship** — Repo convention for gap charts: the NVIDIA data-center GPU shipping in volume in a given calendar year (2023 H100, 2024 H200, 2025 GB300, 2026 Rubin), used as the 100% reference.
- <a id="samr"></a>**SAMR** — China's State Administration for Market Regulation. Its anti-monopoly bureau reviews mergers between companies with sizeable China sales and can approve them with conditions, delay them or block them. *See also:* [Behavioural remedy](#behavioural-remedy).
- <a id="sass"></a>**SASS** — The real machine code of one NVIDIA GPU family (for example sm_90 for Hopper). The ptxas assembler turns PTX into SASS; unlike PTX, SASS for one generation generally does not run on the next. *See also:* [PTX (Parallel Thread Execution)](#ptx), [nvcc](#nvcc).
- <a id="scale-across"></a>**Scale-across** — Linking AI clusters in different datacenters (tens to thousands of kilometres apart) so they can work on one job; NVIDIA's Spectrum-XGS targets this. *See also:* [Scale-out](#scale-out).
- <a id="scale-out"></a>**Scale-out** — Connecting many scale-up domains or servers across a datacenter network (InfiniBand or Ethernet) to train or serve at cluster scale. *See also:* [Scale-up](#scale-up), [Scale-across](#scale-across).
- <a id="scale-up"></a>**Scale-up** — Tightly coupling a group of accelerators with a very fast memory-semantic fabric (NVLink, ICI, Infinity Fabric) so they behave like one large GPU. *See also:* [Scale-out](#scale-out), [NVLink](#nvlink).
- <a id="scale-up-ethernet"></a>**Scale-Up Ethernet (SUE)** — Broadcom's framework, contributed to OCP in 2025, for using Ethernet switches such as Tomahawk Ultra as a scale-up fabric. It adds link-layer retry and credit-based flow control so short, lossless transfers work over Ethernet. *See also:* [ESUN (Ethernet for Scale-Up Networking)](#esun), [Link-layer retry (LLR)](#link-layer-retry), [Credit-based flow control](#credit-based-flow-control).
- <a id="scaling-laws"></a>**Scaling laws** — Empirical findings that model quality improves predictably (as a power law) with more parameters, data and compute. They justify ever-larger training budgets. *See also:* [Chinchilla-optimal](#chinchilla-optimal), [Over-training](#over-training).
- <a id="second-source"></a>**Second source** — A qualified alternative supplier for the same job. Buyers keep one to win price concessions and to protect supply if the main vendor is short or late; it only works if the second product is good enough to absorb real volume. *See also:* [Switching cost](#switching-cost), [Share of wallet](#share-of-wallet).
- <a id="sequence-parallelism"></a>**Sequence parallelism** — NVIDIA's companion to tensor parallelism that splits operations such as LayerNorm along the sequence dimension to save activation memory at no extra communication; distinct from context parallelism. *See also:* [Tensor parallelism (TP)](#tensor-parallelism), [Context parallelism (CP)](#context-parallelism).
- <a id="serdes"></a>**SerDes** — Serializer/deserializer: the circuit that turns many parallel on-chip signals into a few very fast serial lanes (today 100–200 Gb/s each) and back. Port speed = lanes × lane rate. *See also:* [Switch radix](#switch-radix).
- <a id="serving-engine"></a>**Serving engine** — The software that runs a trained model for users: it batches requests, manages the KV cache and calls GPU kernels. Examples are vLLM, SGLang and NVIDIA TensorRT-LLM. *See also:* [vLLM](#vllm), [SGLang](#sglang), [TensorRT-LLM](#tensorrt-llm).
- <a id="sglang"></a>**SGLang** — An open-source LLM serving engine competing with vLLM, strong on structured generation and large mixture-of-experts models; supports NVIDIA, AMD, TPU and Ascend hardware. *See also:* [vLLM](#vllm).
- <a id="share-of-wallet"></a>**Share of wallet** — The fraction of a customer's total spending in a category that goes to one vendor. Selling racks, networking, CPUs and software rather than only GPUs raises NVIDIA's share of each data-center dollar. *See also:* [NVLink Fusion](#nvlink-fusion).
- <a id="shared-memory"></a>**Shared memory (L1)** — Fast on-chip SRAM inside each SM (256 KB on H100 and B200, split between L1 cache and programmer-managed shared memory) where a kernel stages tiles of a matrix so the tensor cores can reuse them many times. *See also:* [Register file](#register-file), [L2 cache](#l2-cache).
- <a id="sharp"></a>**SHARP (in-network reduction)** — NVIDIA's Scalable Hierarchical Aggregation and Reduction Protocol: switches add up the data from many GPUs as it passes through, so each GPU sends its data once instead of about twice during an all-reduce. Available in Quantum InfiniBand and NVLink switches. *See also:* [All-reduce](#all-reduce), [In-network computing](#in-network-computing).
- <a id="signpost"></a>**Signpost** — A pre-agreed observable event or metric threshold that tells you which scenario is unfolding, such as custom-ASIC revenue passing 25% of NVIDIA's Data Center revenue. Signposts turn scenarios into review triggers. *See also:* [Leading indicator](#leading-indicator).
- <a id="silicon-photonics"></a>**Silicon photonics** — Building optical components (modulators, waveguides, detectors) on silicon wafers with chip-making tools, so light-based links can be made in volume and placed next to electronic chips. *See also:* [Co-packaged optics (CPO)](#co-packaged-optics).
- <a id="smt"></a>**Simultaneous multithreading (SMT)** — A CPU feature that runs two (or more) hardware threads on one core by letting them share its execution units, raising total throughput at the cost of less predictable per-thread speed. Intel calls it Hyper-Threading. *See also:* [Spatial Multithreading](#spatial-multithreading).
- <a id="slurm"></a>**Slurm** — The open-source batch scheduler that queues and places jobs on most supercomputers and many AI training clusters. Its developer SchedMD was acquired by NVIDIA in December 2025. *See also:* [Kubernetes](#kubernetes), [Gang scheduling](#gang-scheduling).
- <a id="sm-utilization"></a>**SM utilization** — How busy the GPU's streaming multiprocessors actually are, as measured by telemetry such as DCGM. A GPU can be allocated and report 100% 'utilization' in simple tools while its SMs are mostly idle. *See also:* [Allocation ratio](#allocation-ratio), [MFU (model FLOPs utilization)](#mfu), [DCGM (Data Center GPU Manager)](#dcgm).
- <a id="smartnic"></a>**SmartNIC** — A network card that offloads some packet processing (for example virtual switching or encryption) from the CPU; a DPU is a SmartNIC with general-purpose cores. *See also:* [DPU (data processing unit)](#dpu).
- <a id="socamm"></a>**SOCAMM** — A compact, replaceable memory module carrying LPDDR5X chips, used with Vera so that low-power memory can be serviced like a normal DIMM. *See also:* [LPDDR5X](#lpddr5x).
- <a id="software-port"></a>**Software port** — A re-implementation of another vendor's library behind a compatible interface (e.g. RCCL for NCCL, hipDF for cuDF). Ports cut adoption friction but trail the original by the time it takes to copy each release. *See also:* [HIP](#hip), [RCCL](#rccl).
- <a id="solid-state-transformer"></a>**Solid-state transformer (SST)** — A power-electronics converter (built from SiC or GaN switches) that replaces a bulky copper-and-iron transformer, converting medium-voltage grid power directly to the 800 V DC used by next-generation AI racks. *See also:* [800 V DC power architecture](#hvdc-800v).
- <a id="sovereign-ai"></a>**Sovereign AI** — AI infrastructure built or funded by a nation (or for it) so that data, models and compute stay under national control; often delivered through local neoclouds or telecom operators. *See also:* [ACIE (AI clouds; industrial and enterprise)](#acie), [Neocloud](#neocloud).
- <a id="sparsity"></a>**Sparsity (2:4 structured)** — A hardware trick in which two of every four weights are zero so the tensor cores can skip them, doubling quoted peak FLOPS. Headline NVIDIA figures often assume it; dense figures do not. *See also:* [FLOPS](#flops), [Tensor core](#tensor-core).
- <a id="spatial-multithreading"></a>**Spatial Multithreading** — NVIDIA's name for the two-threads-per-core scheme in its Vera CPU; NVIDIA describes it as dividing each core's resources between the two threads to make per-thread performance more predictable than conventional SMT. *See also:* [Simultaneous multithreading (SMT)](#smt).
- <a id="spectrum-x"></a>**Spectrum-X** — NVIDIA's Ethernet platform for AI clusters, pairing Spectrum switches with SuperNICs and adaptive routing to approach InfiniBand-like performance on Ethernet. *See also:* [InfiniBand](#infiniband), [Scale-out](#scale-out).
- <a id="spectrum-xgs"></a>**Spectrum-XGS** — NVIDIA's 2025 extension of Spectrum-X Ethernet for 'scale-across': algorithms for distance-aware congestion control and latency management that let GPU fabrics in different data centers act as one. *See also:* [Spectrum-X](#spectrum-x), [Scale-across](#scale-across).
- <a id="speculative-decoding"></a>**Speculative decoding** — A small draft model proposes several tokens and the large model verifies them in one pass, keeping the correct ones. Produces identical output 2-3x faster when decode is memory-bound. *See also:* [Decode (generation phase)](#decode).
- <a id="spv-financing"></a>**SPV financing** — Funding a data center through a special-purpose vehicle or joint venture owned largely by outside investors, so most of the debt sits off the operator's balance sheet (e.g. Meta's Hyperion). *See also:* [Circular financing](#circular-financing).
- <a id="sram"></a>**SRAM** — Static RAM: very fast memory built into the processor die itself. It offers huge bandwidth but little capacity per square millimetre, so SRAM-first chips (Groq, Cerebras, d-Matrix) trade capacity for speed. *See also:* [HBM (high-bandwidth memory)](#hbm), [Language processing unit (LPU)](#lpu), [Wafer-scale engine](#wafer-scale).
- <a id="srd"></a>**SRD (Scalable Reliable Datagram)** — AWS's own transport protocol, used by EFA, that sprays packets across many network paths and recovers losses in hardware. *See also:* [EFA (Elastic Fabric Adapter)](#efa), [Packet spraying](#packet-spraying).
- <a id="stack-breadth"></a>**Stack breadth** — In this repo, the number of NVIDIA's twelve stack layers (02-13) in which a competitor scores at least 3 of 5. Depth is how strong it is in its best layers. *See also:* [Vertical integration](#vertical-integration).
- <a id="stack-height"></a>**Stack height** — How many DRAM dies are stacked in one HBM stack (8-, 12- or 16-high). Height times die density sets capacity: twelve 24 Gb dies give 36 GB, sixteen 32 Gb dies give 64 GB. *See also:* [HBM (high-bandwidth memory)](#hbm), [Pin speed](#pin-speed), [Through-silicon via (TSV)](#through-silicon-via).
- <a id="steelman"></a>**Steelman** — The strongest honest version of an argument you may disagree with, built from the best available evidence, as opposed to a 'straw man' that is easy to knock down. *See also:* [Risk heatmap](#risk-heatmap).
- <a id="storage-tiering"></a>**Storage tiering** — Placing data on a ladder of memories, from small and fast (HBM) to large and slow (shared flash), and moving it up and down as it is needed; NVIDIA labels KV-cache tiers G1 to G4. *See also:* [KV-cache offload](#kv-cache-offload), [Inference context memory storage](#context-memory-storage).
- <a id="straggler"></a>**Straggler** — A GPU, link or flow that finishes late and makes every other participant in a synchronous step wait. Causes include congested paths, slow or failing hardware and uneven work. *See also:* [Tail latency](#tail-latency).
- <a id="straight-line-depreciation"></a>**Straight-line depreciation** — Spreading an asset's cost evenly over its useful life (for example a $70K GPU over six years = ~$11.7K a year). It ignores financing cost, which a capital recovery factor adds. *See also:* [Useful life (depreciation)](#useful-life), [Capital recovery factor](#capital-recovery-factor).
- <a id="streaming-multiprocessor"></a>**Streaming multiprocessor (SM)** — The repeating building block of an NVIDIA GPU: a cluster of CUDA cores, four tensor cores, a register file and its own L1/shared memory. An H100 has 132 SMs and a Rubin GPU 224. *See also:* [Tensor core](#tensor-core), [CUDA core](#cuda-core), [Graphics processing cluster (GPC)](#gpc).
- <a id="subnet-manager"></a>**Subnet manager** — The InfiniBand control software that discovers every switch and adapter, assigns addresses and computes the routing tables for the whole fabric. It makes InfiniBand centrally managed rather than self-organizing like Ethernet. *See also:* [InfiniBand](#infiniband).
- <a id="superchip"></a>**Superchip** — NVIDIA's name for a CPU and one or two GPUs joined by NVLink-C2C on one module, such as GH200 (one Grace, one Hopper) or GB200 (one Grace, two Blackwell). *See also:* [NVLink-C2C](#nvlink-c2c).
- <a id="supernic"></a>**SuperNIC** — NVIDIA's name for a network adapter tuned for GPU-to-GPU traffic (ConnectX-8/9, BlueField-3 SuperNIC): RDMA, congestion control and reordering of sprayed packets in hardware, typically one per GPU. *See also:* [RDMA (remote direct memory access)](#rdma), [Packet spraying](#packet-spraying), [Spectrum-X](#spectrum-x).
- <a id="superpod"></a>**SuperPoD** — A vendor name for a multi-rack AI system sold as one unit: NVIDIA's DGX SuperPOD (for example eight GB200 NVL72 racks) or Huawei's Atlas SuperPoD (thousands of Ascend chips in one scale-up domain). *See also:* [DGX](#dgx), [Scale-up](#scale-up).
- <a id="prepayment"></a>**Supply prepayment** — Cash a buyer pays a supplier in advance to reserve future capacity or output; it sits on the buyer's balance sheet as a prepaid asset and can be lost if demand collapses. *See also:* [Purchase obligations](#purchase-obligations), [Long-term agreement (LTA)](#long-term-agreement).
- <a id="supply-constrained"></a>**Supply-constrained** — A market where a vendor can sell everything it can make. A lost customer then costs little in the short run, because the capacity is resold to others. *See also:* [Gross margin](#gross-margin).
- <a id="switch-radix"></a>**Switch radix** — The number of ports on a switch at a given speed. Higher radix means more endpoints per tier, fewer tiers, fewer hops and fewer optics for the same cluster. *See also:* [Fat tree (Clos network)](#fat-tree).
- <a id="switching-cost"></a>**Switching cost** — The money, time and risk a customer bears to move to a rival product, here porting and re-validating kernels, tools and team skills from CUDA to another stack. *See also:* [Hardware pull-through](#pull-through), [Translation layer](#translation-layer).
- <a id="sycl"></a>**SYCL** — An open Khronos standard for writing C++ code that runs on CPUs, GPUs and accelerators from different vendors. Intel's oneAPI is built on it. *See also:* [oneAPI](#oneapi).
- <a id="system-on-chip"></a>**system-on-chip** — A single chip that integrates CPU cores, graphics, memory controllers and other functions, as used in phones and tablets (for example NVIDIA's Tegra). *See also:* [baseband modem](#baseband-modem).
- <a id="systolic-array"></a>**Systolic array** — A grid of multiply-accumulate cells through which data flows in a fixed rhythm, each cell passing results to its neighbour. Google's TPU matrix units are 128×128 or 256×256 systolic arrays: very efficient for large matrices, less flexible for odd shapes. *See also:* [ASIC](#asic).
## T

- <a id="tail-latency"></a>**Tail latency** — The delay of the slowest messages (for example the 99th or 99.9th percentile), not the average. In synchronous AI training the whole step waits for the slowest transfer, so the tail, not the mean, sets the pace. *See also:* [Straggler](#straggler), [Collective operation](#collective-operation).
- <a id="take-or-pay"></a>**Take-or-pay contract** — A contract in which the buyer pays for reserved capacity whether or not it uses it. Neoclouds sign multi-year take-or-pay deals with AI labs and hyperscalers and then borrow against them. *See also:* [Revenue backlog](#revenue-backlog), [GPU-backed loan](#gpu-backed-loan).
- <a id="tape-out"></a>**Tape-out** — The moment a finished chip design is handed to the foundry to make photomasks and first wafers. A failed tape-out costs months and tens of millions of dollars in masks. *See also:* [NRE (non-recurring engineering)](#nre), [Photomask](#photomask).
- <a id="tco"></a>**TCO (total cost of ownership)** — All-in cost of running infrastructure over its life: capital cost (depreciated) plus power, cooling, space, networking, software and operations. In AI it is often normalised to $ per million tokens.
- <a id="tdisp"></a>**TDISP** — PCI-SIG's TEE Device Interface Security Protocol: a standard way to bring a PCIe device (GPU, NIC, SSD) inside a CPU's confidential VM with authenticated, encrypted links instead of software bounce buffers. *See also:* [Trusted execution environment (TEE)](#trusted-execution-environment), [AMD SEV-SNP](#sev-snp), [Intel TDX](#intel-tdx).
- <a id="telemetry"></a>**Telemetry (network)** — Continuous measurement of flows, congestion, errors and latency inside the network and NICs, used to find stragglers and tune congestion control. *See also:* [DPU (data processing unit)](#dpu).
- <a id="tensor-core"></a>**Tensor core** — A specialised unit inside an NVIDIA GPU that multiplies small matrices in one step, delivering most of the GPU's AI throughput. Introduced with Volta (2017). *See also:* [GPU (graphics processing unit)](#gpu), [FLOPS](#flops).
- <a id="tensor-memory"></a>**Tensor memory (TMEM)** — A 256 KB per-SM scratchpad introduced with Blackwell that holds tensor-core accumulators and operands, freeing registers and keeping the larger tensor cores fed. *See also:* [Tensor core](#tensor-core), [Register file](#register-file).
- <a id="tma"></a>**Tensor Memory Accelerator (TMA)** — A Hopper-era hardware unit that copies whole tiles of a tensor between HBM/L2 and shared memory in the background, so threads can keep computing instead of issuing individual loads. *See also:* [Shared memory (L1)](#shared-memory).
- <a id="tensor-parallelism"></a>**Tensor parallelism (TP)** — Splitting each layer's weight matrices across several GPUs so they compute one layer together; it needs an all-reduce inside every layer, so it is kept within a fast NVLink domain. *See also:* [NVLink](#nvlink), [All-reduce](#all-reduce).
- <a id="tensorrt"></a>**TensorRT** — NVIDIA's inference optimizer and runtime: it takes a trained model, fuses and quantizes its operations and produces an engine tuned for a specific NVIDIA GPU. TensorRT-LLM is its large-language-model branch. *See also:* [cuDNN](#cudnn), [GPU kernel](#gpu-kernel).
- <a id="tensorrt-llm"></a>**TensorRT-LLM** — NVIDIA's open-source library for running large language models fast on NVIDIA GPUs: custom kernels plus runtime features such as continuous batching, a paged KV cache, FP8/FP4 quantization and speculative decoding. *See also:* [TensorRT](#tensorrt), [Dynamo](#dynamo), [Continuous batching](#continuous-batching).
- <a id="test-time-compute"></a>**Test-time compute** — Spending more inference computation per query (longer reasoning, multiple attempts, search) to get a better answer, rather than training a bigger model. *See also:* [Reasoning model](#reasoning-model), [Agentic AI (agents)](#agentic-ai).
- <a id="tf32"></a>**TF32 (TensorFloat-32)** — A 19-bit tensor-core format introduced with Ampere that keeps FP32's range but only 10 mantissa bits, so FP32 code can use tensor cores without changes; values are still stored as 32 bits. *See also:* [BF16 (bfloat16)](#bf16), [FP8](#fp8).
- <a id="thread-block"></a>**Thread block** — A group of up to 1,024 GPU threads that run on the same SM, share fast on-chip memory and can synchronise with each other. A kernel launch is a grid of thread blocks. *See also:* [Grid (CUDA)](#cuda-grid), [Warp](#warp), [Shared memory (L1)](#shared-memory).
- <a id="through-silicon-via"></a>**Through-silicon via (TSV)** — A vertical copper wire etched through a thinned silicon die so that stacked dies can pass data, power and ground straight up and down. Thousands of TSVs per die make HBM stacks possible. *See also:* [HBM (high-bandwidth memory)](#hbm), [HBM base die](#hbm-base-die), [Micro-bump](#microbump).
- <a id="pareto-frontier"></a>**Throughput-interactivity Pareto frontier** — The curve of best achievable tokens/s per GPU (throughput) at each tokens/s per user (interactivity). Hardware and software generations are compared by how far they push the whole curve. *See also:* [Batching](#batching), [TPOT / ITL (time per output token / inter-token latency)](#tpot).
- <a id="tilelang"></a>**TileLang** — An open-source Python kernel language from the tile-ai project, used for DeepSeek's attention kernels. It targets NVIDIA CUDA, AMD ROCm and Apple Metal and, since September 2026, Huawei Ascend 950. *See also:* [Triton (OpenAI)](#triton), [MLIR](#mlir).
- <a id="time-to-power"></a>**Time to power** — How long it takes a datacenter site to obtain the electricity it needs, from utility request to energized capacity. For AI builds it is often longer than constructing the building. *See also:* [Interconnection queue](#interconnection-queue), [Behind-the-meter generation](#behind-the-meter).
- <a id="time-to-train"></a>**Time to train** — Calendar days a training run takes on a given cluster. Faster chips or larger clusters shorten it; for a frontier lab, earlier model release can be worth more than the compute bill. *See also:* [MFU (model FLOPs utilization)](#mfu), [Goodput](#goodput).
- <a id="token"></a>**Token** — The unit of text a language model reads or writes, roughly three-quarters of an English word. AI economics are increasingly quoted in tokens per second and dollars per million tokens.
- <a id="token-price-deflation"></a>**Token price deflation** — The rapid fall in the price of reaching a fixed model quality per million tokens, estimated at 9x to 900x per year depending on the task; frontier list prices do not always fall. *See also:* [Blended token price](#blended-token-price).
- <a id="token-parity-rent"></a>**Token-parity rent** — The hourly price at which renting an older accelerator yields the same cost per token as the newest generation. When new chips cut cost per token, the parity rent of old ones falls, dragging rental prices down. *See also:* [Economic life](#economic-life), [Token price deflation](#token-price-deflation).
- <a id="tokens-per-megawatt"></a>**Tokens per second per megawatt** — An AI-factory output metric: how many tokens a fleet generates each second for every megawatt of power it draws, at a stated speed per user. It turns a fixed power budget into revenue capacity. *See also:* [AI factory](#ai-factory), [Throughput-interactivity Pareto frontier](#pareto-frontier), [Token](#token).
- <a id="tokens-per-mw"></a>**Tokens per second per megawatt** — Tokens an AI system generates each second for every megawatt of power it draws, usually at a stated speed per user. Because sites are power-limited it measures how much revenue a datacenter can produce. *See also:* [AI factory](#ai-factory), [Interactivity (tokens/s per user)](#interactivity), [Perf/W (performance per watt)](#perf-per-watt).
- <a id="topology-aware-scheduling"></a>**Topology-aware scheduling** — Placing the GPUs of a job according to the physical network: for example keeping a tensor-parallel group inside one NVLink domain or one rack, so its heavy traffic never crosses slower links. *See also:* [Gang scheduling](#gang-scheduling), [GPU fragmentation](#gpu-fragmentation).
- <a id="torch-compile"></a>**torch.compile** — PyTorch 2's compiler: it captures a model's operations and generates fused kernels (by default via Triton) instead of calling pre-written ones, which makes hardware back-ends easier to swap. *See also:* [Triton (OpenAI)](#triton).
- <a id="torchinductor"></a>**TorchInductor** — The default compiler back end of PyTorch 2's torch.compile. It fuses operations and generates Triton kernels for GPUs and C++ for CPUs. *See also:* [torch.compile](#torch-compile), [Triton (OpenAI)](#triton).
- <a id="torchtpu"></a>**TorchTPU** — Google's native PyTorch stack for TPUs, open-sourced with Meta in October 2026 to replace PyTorch/XLA, so PyTorch models can run on TPUs without rewriting them in JAX. *See also:* [PyTorch](#pytorch), [JAX](#jax), [XLA](#xla).
- <a id="tornado-chart"></a>**Tornado chart** — A sensitivity chart that changes one input at a time between a low and a high value and sorts the inputs by how far they move the result, so the widest bars show which assumptions matter most. *See also:* [Monte Carlo simulation](#monte-carlo-simulation).
- <a id="torus-topology"></a>**Torus topology** — A network in which each chip connects only to its neighbours along each dimension, with the ends wrapped around into rings. It scales to thousands of chips cheaply, but a message to a distant chip crosses many hops and shares bandwidth along the way. *See also:* [ICI (inter-chip interconnect)](#ici), [Optical circuit switch (OCS)](#optical-circuit-switch), [All-to-all](#all-to-all).
- <a id="tpc-ds"></a>**TPC-DS** — A standard decision-support benchmark of about 100 SQL queries over retail-style data. Vendor tests 'derived from' it are not official, audited TPC results. *See also:* [Apache Spark](#apache-spark).
- <a id="tpot"></a>**TPOT / ITL (time per output token / inter-token latency)** — The gap between successive streamed tokens; 1/TPOT is tokens per second per user. Driven mainly by decode bandwidth and batch size. *See also:* [Decode (generation phase)](#decode), [TTFT (time to first token)](#ttft).
- <a id="tpp"></a>**TPP (total processing performance)** — The US export-control measure of an AI chip's compute: roughly dense TFLOPS (or TOPS) times the bit width of the operation. Chips at or above 4,800 TPP need a licence to ship to China. *See also:* [Performance density](#performance-density).
- <a id="tpu"></a>**TPU (Tensor Processing Unit)** — Google's in-house family of AI accelerator chips, from the 2015 inference card (v1) to Ironwood (v7, 2025) and the 2026 TPU 8t/8i. Each chip is built around large matrix-multiply units and chips are wired into pods of up to ~9,600. *See also:* [ASIC](#asic), [ICI (inter-chip interconnect)](#ici), [Systolic array](#systolic-array).
- <a id="trainium"></a>**Trainium** — AWS's in-house AI accelerator for training and inference, sold only as AWS cloud capacity; generations Trn1 (2022), Trn2 (2024), Trn3 (2025) and Trainium4 (announced). *See also:* [UltraServer](#ultraserver), [Neuron SDK](#neuron-sdk).
- <a id="transform-and-lighting"></a>**transform and lighting** — The steps that position each 3D vertex on screen and compute how light falls on it; GeForce 256 (1999) moved them from the CPU into graphics hardware. *See also:* [fixed-function pipeline](#fixed-function-pipeline).
- <a id="transformer"></a>**Transformer** — The neural-network design behind modern language models: a stack of identical layers, each with an attention block (tokens look at earlier tokens) and a feed-forward block where most parameters live. *See also:* [Attention](#attention), [Neural network](#neural-network).
- <a id="transformer-engine"></a>**Transformer Engine** — NVIDIA's combination of tensor-core hardware and software libraries that picks number formats (FP8 from Hopper, FP4/NVFP4 from Blackwell) and per-tensor or per-block scale factors automatically so models can run in lower precision without losing accuracy. *See also:* [FP8](#fp8), [NVFP4](#nvfp4), [Microscaling (MX formats)](#microscaling).
- <a id="translation-layer"></a>**Translation layer** — Software that lets programs built for one platform run on another without recompiling, for example ZLUDA running unmodified CUDA binaries on non-NVIDIA GPUs. NVIDIA's CUDA licence restricts this use. *See also:* [HIPIFY](#hipify), [CUDA](#cuda).
- <a id="tree-all-reduce"></a>**Tree all-reduce** — An all-reduce that sums data up a tree of nodes and broadcasts it back down. It needs about 2·log2(N) hops instead of a ring's 2(N−1), so it has far lower latency at scale. *See also:* [Ring all-reduce](#ring-all-reduce), [NCCL](#nccl).
- <a id="triton"></a>**Triton (OpenAI)** — An open-source Python-like language and compiler for writing GPU kernels, started at OpenAI. PyTorch's compiler generates Triton code, and Triton has backends for NVIDIA, AMD and others, so kernels need not be written in CUDA. *See also:* [torch.compile](#torch-compile), [GPU kernel](#gpu-kernel).
- <a id="triton-inference-server"></a>**Triton Inference Server** — NVIDIA's general-purpose open-source model server (2018, then called TensorRT Inference Server), now branded Dynamo-Triton; serves many model types and frameworks behind one API. *See also:* [Dynamo](#dynamo).
- <a id="trusted-execution-environment"></a>**Trusted execution environment (TEE)** — A hardware-isolated region (a confidential VM on the CPU, a GPU in confidential mode) whose memory and state the host OS, hypervisor and cloud operator cannot read or alter. *See also:* [Confidential computing](#confidential-computing), [Attestation](#attestation).
- <a id="ttft"></a>**TTFT (time to first token)** — How long a user waits between sending a request and seeing the first token. Driven mainly by prefill compute and queueing. *See also:* [Prefill (context phase)](#prefill), [TPOT / ITL (time per output token / inter-token latency)](#tpot).
- <a id="turnkey-asic"></a>**Turnkey ASIC** — A custom-chip model in which the design partner owns physical design, IP, packaging, test and foundry supply, and sells finished chips to the customer at a per-unit price. *See also:* [Customer-owned tooling (COT)](#customer-owned-tooling), [ASIC design partner](#asic-design-partner).
- <a id="tying"></a>**Tying (antitrust)** — Making the sale of one product conditional on buying another, for example GPUs only with the vendor's own networking; it can breach competition law when the seller has market power in the first product. *See also:* [Behavioural remedy](#behavioural-remedy).
## U

- <a id="ualink"></a>**UALink (Ultra Accelerator Link)** — An open scale-up interconnect standard from a consortium founded in 2024 (AMD, Intel, Google, Microsoft, Meta, AWS and others). It lets accelerators read and write each other's memory through UALink switches, using 200G lanes, in pods of up to 1,024 devices. *See also:* [NVLink](#nvlink), [ESUN (Ethernet for Scale-Up Networking)](#esun), [Scale-up](#scale-up).
- <a id="ualoe"></a>**UALink over Ethernet (UALoE)** — Carrying UALink's memory-style protocol across ordinary Ethernet switch chips instead of dedicated UALink switches. AMD's Helios rack uses it with Broadcom Tomahawk 6 switches while native UALink silicon is not yet available. *See also:* [UALink (Ultra Accelerator Link)](#ualink), [Scale-Up Ethernet (SUE)](#scale-up-ethernet).
- <a id="ucc"></a>**UCC (Unified Collective Communication)** — An open-source collective library from the Unified Communication Framework consortium that targets HPC and AI and treats hardware-offloaded collectives as first-class. *See also:* [MPI (Message Passing Interface)](#mpi), [NCCL](#nccl).
- <a id="ucie"></a>**UCIe (Universal Chiplet Interconnect Express)** — An open standard for connecting chiplets inside one package. Reports suggest third-party chips could attach an NVLink chiplet over UCIe under NVLink Fusion. *See also:* [Chiplet](#chiplet), [NVLink Fusion](#nvlink-fusion).
- <a id="ultra-ethernet"></a>**Ultra Ethernet (UEC)** — An industry specification from the Ultra Ethernet Consortium (version 1.0 in June 2025) that adds AI-oriented transport, packet spraying, congestion control and other features to standard Ethernet, so any vendor's NICs and switches can match proprietary AI fabrics. *See also:* [RoCE (RDMA over Converged Ethernet)](#roce), [Packet spraying](#packet-spraying).
- <a id="ultraserver"></a>**UltraServer** — AWS's name for a group of Trainium chips joined by its NeuronLink scale-up fabric into one domain: 64 Trainium2 or up to 144 Trainium3 chips. *See also:* [NeuronLink](#neuronlink), [Scale-up](#scale-up).
- <a id="unified-memory"></a>**Unified memory** — A programming model in which CPU and GPU share one virtual address space, so the same pointer works on both. With a coherent link (NVLink-C2C) the GPU reads CPU memory directly; over PCIe the driver must migrate pages, which is much slower. *See also:* [Cache coherence](#cache-coherence), [NVLink-C2C](#nvlink-c2c).
- <a id="unified-shader-architecture"></a>**Unified shader architecture** — A GPU design, introduced by NVIDIA's G80 in 2006, in which one pool of identical programmable cores handles every graphics stage. Those general-purpose cores are what CUDA exposed for non-graphics work. *See also:* [GPGPU (general-purpose GPU computing)](#gpgpu), [CUDA](#cuda).
- <a id="unifiedbus"></a>**UnifiedBus (UB)** — Huawei's scale-up interconnect (also called Lingqu) used in CloudMatrix 384 and Atlas SuperPoDs. It links hundreds to thousands of Ascend NPUs through UB switches, largely over optics. *See also:* [Scale-up](#scale-up), [Optical circuit switch (OCS)](#optical-circuit-switch).
- <a id="useful-life"></a>**Useful life (depreciation)** — The number of years over which a company spreads the cost of an asset such as a GPU server; a longer life lowers annual depreciation and raises reported profit. *See also:* [GPU-hour](#gpu-hour).
- <a id="utilization"></a>**Utilization (fleet)** — The share of installed accelerator-hours that do paid or useful work. Because most of an accelerator's cost is fixed, cost per useful hour scales with 1 ÷ utilization. *See also:* [Allocation ratio](#allocation-ratio), [MFU (model FLOPs utilization)](#mfu), [Goodput](#goodput).
- <a id="uxl-foundation"></a>**UXL Foundation** — A Linux Foundation consortium formed in 2023 that stewards the oneAPI specification and libraries as a vendor-neutral alternative to CUDA; founding members included Intel, Arm, Google Cloud and Qualcomm, and AMD reportedly joined in 2026. *See also:* [oneAPI](#oneapi).
## V

- <a id="value-pool"></a>**Value pool** — The profit available in one part of an industry's value chain (for example HBM, switch silicon or rack assembly), and who captures it. A layer can be strategically vital yet a small value pool for the company that controls it. *See also:* [Pricing power](#pricing-power).
- <a id="variant-calling"></a>**Variant calling** — The step in genome analysis that finds where a person's DNA differs from the reference genome; the compute-heavy core of clinical sequencing pipelines. *See also:* [Parabricks](#parabricks).
- <a id="vector-search"></a>**Vector search** — Finding the stored items whose embeddings (lists of numbers that encode meaning) are closest to a query; the retrieval step in RAG and recommendation systems. *See also:* [cuVS](#cuvs).
- <a id="vendor-financing"></a>**Vendor financing** — When a supplier lends to, invests in or guarantees its own customers so they can buy its products. Common in telecom equipment around 1999–2001, where it amplified the bust. *See also:* [Circular financing](#circular-financing), [Capacity backstop](#capacity-backstop).
- <a id="vertical-integration"></a>**Vertical integration** — Owning successive layers of a value chain (chip, network, compiler, datacenter, model) so they can be designed together and no supplier margin is paid between them. *See also:* [Co-design (hardware-software)](#co-design).
- <a id="vesting-milestone"></a>**Vesting milestone** — A condition that must be met before a tranche of a warrant or stock award can be exercised, such as a gigawatt deployed or a share price reached. *See also:* [Warrant](#warrant), [Dilution](#dilution).
- <a id="virtual-switch"></a>**Virtual switch** — Software (for example Open vSwitch, OVS) that forwards packets between virtual machines or containers and the physical network, applying tenant rules. Running it on the host costs CPU cores; a DPU runs it in hardware. *See also:* [Overlay network](#overlay-network), [DPU (data processing unit)](#dpu).
- <a id="vllm"></a>**vLLM** — The most widely used open-source LLM inference engine (PagedAttention, continuous batching). It runs in-tree on NVIDIA and AMD GPUs and via plugins on TPU, Gaudi, Ascend, Trainium and Qualcomm Cloud AI. *See also:* [SGLang](#sglang), [Inference](#inference).
## W

- <a id="wafer"></a>**Wafer** — A thin disc of ultra-pure silicon, 300 mm across for leading-edge chips, on which hundreds of identical dies are printed and later cut apart. Foundries price their output per processed wafer. *See also:* [Die](#die), [Foundry](#foundry).
- <a id="wafer-scale"></a>**Wafer-scale engine** — A processor built from an entire silicon wafer rather than a single die, as in Cerebras' WSE-3 (46,225 mm², 44 GB of on-chip SRAM). It avoids chip-to-chip links but needs special packaging, power and cooling. *See also:* [Die](#die), [Reticle limit](#reticle-limit).
- <a id="warp"></a>**Warp** — A group of 32 GPU threads that execute the same instruction in lockstep on an SM. It is the unit the hardware schedules, so code that keeps all 32 threads busy runs fastest. *See also:* [Streaming multiprocessor (SM)](#streaming-multiprocessor).
- <a id="warrant"></a>**Warrant** — A right to buy a company's shares at a fixed price (AMD's OpenAI warrant: $0.01 per share), usually vesting only when conditions are met. It costs the issuer no cash but dilutes existing shareholders. *See also:* [Dilution](#dilution).
- <a id="white-box-switch"></a>**White-box switch** — A switch built by an ODM (e.g. Celestica, Accton) on merchant silicon, sold without a vendor operating system; the buyer runs SONiC, FBOSS or its own software. *See also:* [Merchant silicon](#merchant-silicon), [Network operating system (NOS)](#network-operating-system).
- <a id="wide-ep"></a>**Wide expert parallelism (wide EP)** — Spreading a mixture-of-experts model's experts across many GPUs (for example 64-144) so each GPU holds only a few. It frees memory for larger batches and caches, but makes dispatch and combine traffic cross more GPUs. *See also:* [Expert parallelism (EP)](#expert-parallelism), [Dispatch and combine](#dispatch-and-combine), [NVLink domain](#nvlink-domain).
## X

- <a id="x86"></a>**x86** — The instruction set used by Intel and AMD processors since the 1970s-80s. Only Intel and AMD hold the licences to build x86 server CPUs, and most legacy enterprise software is compiled for it. *See also:* [ISA (instruction set architecture)](#isa), [Arm (instruction set)](#arm-isa).
- <a id="xla"></a>**XLA** — Accelerated Linear Algebra: a compiler that turns a whole model graph into optimised code for TPUs, GPUs or CPUs. Used by JAX and, formerly, PyTorch on TPU. *See also:* [JAX](#jax), [MLIR](#mlir).
- <a id="xpu"></a>**XPU (custom accelerator)** — Industry shorthand for a custom AI accelerator designed by or for one customer, such as Google's TPU, AWS Trainium, Microsoft Maia or Meta MTIA. *See also:* [ASIC](#asic), [ASIC design partner](#asic-design-partner).
## Z

- <a id="zero"></a>**ZeRO (Zero Redundancy Optimizer)** — Microsoft's technique for sharding optimizer states (stage 1), gradients (stage 2) and weights (stage 3) across data-parallel GPUs instead of replicating them, cutting memory per GPU. *See also:* [FSDP (Fully Sharded Data Parallel)](#fsdp), [Data parallelism (DP)](#data-parallelism).
- <a id="zero-code-change"></a>**Zero-code-change acceleration** — Running existing code (pandas, scikit-learn, Polars, Spark) on GPUs by swapping the engine underneath, with no rewrite and automatic CPU fallback for unsupported operations. *See also:* [cudf.pandas](#cudf-pandas), [cuML](#cuml).
- <a id="zero-trust"></a>**Zero-trust isolation** — A security design in which no component (including the host OS) is trusted by default; every access is authenticated and policy is enforced outside the tenant's control, for example on a DPU. *See also:* [Multi-tenancy](#multi-tenancy), [Hardware root of trust](#root-of-trust).
- <a id="zt-systems"></a>**ZT Systems** — US rack-scale server designer AMD bought for $4.9B (closed March 2025); AMD kept the design teams that built Helios and sold the factories to Sanmina. *See also:* [AMD Helios](#amd-helios), [ODM](#odm).
