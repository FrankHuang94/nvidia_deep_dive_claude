## 0–9

- <a id="hvdc-800v"></a>**800 V DC power architecture（800 V 直流供电架构）** — 英伟达的规划（自 2027 年起）：向机架输送 800 伏直流电，减少电能转换环节和铜材用量，使单个机架的功耗可达约 1 兆瓦。*另见：* [液冷](#liquid-cooling)。
## A

- <a id="abf-substrate"></a>**ABF substrate（ABF 基板）** — GPU 封装所承载的多层有机基板（以味之素积层膜 Ajinomoto Build-up Film 制造），负责把数以千计的连接引至电路板；供应商包括揖斐电（Ibiden）和欣兴电子（Unimicron）等。*另见：* [先进封装](#advanced-packaging)、[中介层](#interposer)。
- <a id="acie"></a>**ACIE (AI clouds; industrial and enterprise)（AI 云、工业与企业客户）** — 自 Q1 FY2027 起英伟达数据中心收入中非超大规模云厂商的那一半：AI 云与新兴云服务商（neocloud）、主权项目，以及工业与企业买家。*另见：* [新兴云服务商（neocloud）](#neocloud)、[超大规模云厂商](#hyperscaler)。
- <a id="acquihire"></a>**Acquihire（收购式招聘）** — 一种交易结构：聘用目标公司的团队（通常附带技术授权），而非直接收购整家公司。它比收购更快，且可能绕开并购审查；英伟达与 Groq 和 Enfabrica 的交易即采用这一结构。
- <a id="activation"></a>**Activation（激活值）** — 前向传播中某一层产生、并为反向传播保留的中间结果。激活值所占内存随批大小和序列长度增长；重计算（recomputation）以额外算力换取这部分内存。*另见：* [前向传播](#forward-pass)、[反向传播](#backward-pass)。
- <a id="active-electrical-cable"></a>**Active electrical cable (AEC)（有源电缆）** — 在连接器中内置重定时器（retimer）芯片的铜缆，可在每通道 100-200G 速率下把传输距离延伸至数米；用于机架内及相邻机架互连时，比光学方案更便宜、功耗更低。Credo 是领先供应商。*另见：* [SerDes](#serdes)。
- <a id="activist-investor"></a>**Activist investor（维权投资者）** — 持有相当规模股份、并向管理层施压要求变革（董事会席位、削减成本、出售公司）的股东。Starboard 在 2017-18 年对 Mellanox 发起的维权行动，是该公司后来进行出售竞拍的前奏。
- <a id="adam"></a>**Adam optimizer（Adam 优化器）** — 大模型的标准优化器。它为每个参数维护两个滑动平均值（动量与方差），这正是混合精度训练中每个参数约需 16 字节的原因。*另见：* [优化器](#optimizer)、[混合精度训练](#mixed-precision)。
- <a id="adaptive-routing"></a>**Adaptive routing（自适应路由）** — 依据实时队列深度而非固定哈希，为每个数据包（或一组数据包）选择路径，引导流量绕开拥塞热点。InfiniBand 原生支持这一能力；Spectrum-X 和超以太网（Ultra Ethernet）将其引入以太网。*另见：* [ECMP（等价多路径）](#ecmp)、[数据包喷洒](#packet-spraying)。
- <a id="amx"></a>**Advanced Matrix Extensions (AMX)（高级矩阵扩展）** — 英特尔自 Sapphire Rapids（2023 年）起在 Xeon CPU 核心中加入的矩阵乘法单元；每个核心每个时钟周期最多可执行 1,024 次 BF16 运算，是其向量单元的 16 倍。*另见：* [张量核心](#tensor-core)。
- <a id="advanced-packaging"></a>**Advanced packaging（先进封装）** — 将多个裸片（die）与内存堆栈集成于同一封装、布线密度远高于电路板的技术，例如台积电的 CoWoS（2.5D）和 SoIC（3D 堆叠）。对 AI 加速器而言，先进封装已成为产能瓶颈和主要成本项。*另见：* [CoWoS](#cowos)、[中介层](#interposer)。
- <a id="agent-sandbox"></a>**Agent sandbox（智能体沙箱）** — 一种隔离环境（通常是绑定到某个 CPU 核心的容器或小型虚拟机），用于运行 AI 智能体生成的代码、浏览器会话或工具调用，或用于执行强化学习中的尝试并为其评分。*另见：* [智能体 AI](#agentic-ai)、[强化学习（RL）](#reinforcement-learning)。
- <a id="agentic-ai"></a>**Agentic AI (agents)（智能体 AI）** — 由模型在多个步骤中自主规划、调用工具、读取结果并反复迭代以完成任务的系统。一项任务可能消耗数百次模型调用和数百万个 token（词元）。*另见：* [测试时计算](#test-time-compute)、[推理](#inference)。
- <a id="ai-blueprint"></a>**AI Blueprint（AI 蓝图）** — 英伟达的参考应用（例如研究型智能体或检索管线），由 NIM 微服务和 NeMo 工具构建，作为企业开发的起步代码发布。*另见：* [NVIDIA NIM](#nim)、[NeMo](#nemo)。
- <a id="ai-factory"></a>**AI factory（AI 工厂）** — 英伟达提出的概念，指主要为生产 AI token 而建设和运营的数据中心，从供电、散热到机架、网络和软件均作为一个整体系统来设计。*另见：* [机架级系统](#rack-scale-system)、[800 V 直流供电架构](#hvdc-800v)。
- <a id="ai-head-node"></a>**AI head node（AI 主控节点）** — AI 系统中负责调度任务、运行智能体逻辑并向加速器供给数据的通用服务器 CPU。高通将其 Dragonfly C1000 定位于这一角色。*另见：* [主机 CPU](#host-cpu)。
- <a id="ai-ran"></a>**AI-RAN（AI 无线接入网）** — 在移动基站的同一批加速服务器上同时运行 AI 工作负载和无线网络信号处理。英伟达对诺基亚（Nokia）$1B 的入股正是瞄准这一市场。
- <a id="aiter"></a>**AITER** — AI Tensor Engine for ROCm：AMD 经过调优的大语言模型（LLM）算子库（注意力、MoE、GEMM），以 Triton、Composable Kernel 和汇编语言编写；是 vLLM 在 ROCm 上的默认注意力后端。*另见：* [ROCm](#rocm)、[Composable Kernel](#composable-kernel)。
- <a id="alexnet"></a>**AlexNet** — 2012 年由 Krizhevsky、Sutskever 和 Hinton 提出的神经网络，以大幅领先的成绩赢得 ImageNet 图像识别竞赛。它借助 CUDA 在两块 GeForce GTX 580 游戏 GPU 上完成训练。*另见：* [CUDA](#cuda)。
- <a id="all-gather"></a>**All-gather（全收集）** — 一种集合通信操作：每个 GPU 贡献一个分片，最终每个 GPU 都得到所有分片拼接而成的完整数据。*另见：* [全规约](#all-reduce)、[规约散射](#reduce-scatter)。
- <a id="all-in-power"></a>**All-in power per GPU（单 GPU 全口径功耗）** — 数据中心为运行一块 GPU 所需配置的全部电力中由该 GPU 分摊的部分：GPU 本身、其主机 CPU、交换机和网卡，再加上散热与电能转换损耗。按兆瓦计的指标应除以这一数值，而非 GPU 的 TDP。*另见：* [PUE（电能使用效率）](#pue)、[每兆瓦每秒 token 数](#tokens-per-megawatt)。
- <a id="all-reduce"></a>**All-reduce（全规约）** — 一种集合通信操作：每个 GPU 贡献一组数值（如梯度），每个 GPU 都收到合并后的结果。其速度取决于 GPU 之间的网络。*另见：* [NCCL](#nccl)、[横向扩展（scale-out）](#scale-out)。
- <a id="all-to-all"></a>**All-to-all（全交换）** — 一种集合通信操作：每个 GPU 同时向其他每个 GPU 发送各不相同的数据；这是混合专家层的通信模式，也是对网络要求最苛刻的一种。*另见：* [专家并行（EP）](#expert-parallelism)。
- <a id="allocation-ratio"></a>**Allocation ratio（分配率）** — 某一时刻已分配给某项作业的 GPU 占已装机 GPU 的比例。它并不说明被分配的 GPU 是否真正处于忙碌状态；是最基础、也最宽松的利用率指标。*另见：* [MFU（模型 FLOPs 利用率）](#mfu)、[SM 利用率](#sm-utilization)。
- <a id="amd-helios"></a>**AMD Helios** — AMD 首个机架级 AI 系统（2026 年）：72 块 Instinct MI455X GPU、EPYC Venice CPU 和 Pensando 网卡装于双宽机架内，通过基于以太网的 UALink 互连，对标英伟达的 Vera Rubin NVL72。*另见：* [机架级系统](#rack-scale-system)、[UALoE](#ualoe)、[NVL72](#nvl72)。
- <a id="sev-snp"></a>**AMD SEV-SNP** — AMD 面向 EPYC CPU 的机密虚拟机技术（Secure Encrypted Virtualization with Secure Nested Paging，安全加密虚拟化与安全嵌套分页）：加密每台虚拟机的内存，并阻止虚拟机管理程序（hypervisor）篡改。SEV-TIO 借助 TDISP 将其扩展到 PCIe 设备。*另见：* [可信执行环境（TEE）](#trusted-execution-environment)、[TDISP](#tdisp)。
- <a id="amdahls-law"></a>**Amdahl's law（阿姆达尔定律）** — 该定律指出：任务中无法加速的部分（在 AI 集群中通常是无法与计算重叠的通信）决定了增加处理器所能带来的总加速比的上限。*另见：* [横向扩展（scale-out）](#scale-out)。
- <a id="annapurna-labs"></a>**Annapurna Labs** — 以色列芯片设计初创公司，亚马逊于 2015 年以据报约 $350-370M 将其收购；负责设计 AWS 的 Nitro、Graviton、Inferentia 和 Trainium 芯片。*另见：* [AWS Nitro](#aws-nitro)、[Trainium](#trainium)。
- <a id="annual-cadence"></a>**Annual cadence（一年一代节奏）** — 每年（而非每两年）推出新一代旗舰数据中心 GPU。这抬高了竞争对手和第二供应商的门槛——它们要追赶的是移动靶，而非固定靶。*另见：* [NVL72](#nvl72)。
- <a id="apache-spark"></a>**Apache Spark** — 应用最广泛的开源引擎，用于在服务器集群上进行大规模数据处理和 SQL 查询。*另见：* [ETL](#etl)、[cuDF](#cudf)。
- <a id="architecture-licence"></a>**Architecture licence（架构授权）** — Arm 的一种授权方式，允许企业自行设计实现 Arm 指令集的处理器核心，而不使用 Arm 提供的核心设计。苹果、高通和英伟达（Vera 的 Olympus 核心）均采用这一路线。*另见：* [Arm 指令集](#arm-isa)、[Neoverse](#neoverse)。
- <a id="arithmetic-intensity"></a>**Arithmetic intensity（算术强度）** — 每从内存搬运一个字节所执行的浮点运算次数（FLOPs）。低于芯片“峰值 FLOPS 与内存带宽之比”（即屋脊点）的工作负载受内存带宽限制；小批量下的解码远低于这一水平。*另见：* [解码（decode）](#decode)、[内存墙](#memory-wall)。
- <a id="arm-isa"></a>**Arm (instruction set)（Arm 指令集）** — Arm Holdings 授权给芯片设计商使用的一系列指令集，被授权方需支付授权费和按芯片计收的版税。Grace、Vera、Graviton、Axion 和 Cobalt 均为 Arm CPU。*另见：* [ISA（指令集架构）](#isa)、[Neoverse](#neoverse)、[IP 版税](#ip-royalty)。
- <a id="arm-cca"></a>**Arm CCA（Arm 机密计算架构）** — Arm Confidential Compute Architecture：Armv9 中的“Realm”机制，将虚拟机与主机软件隔离，是 Arm 对标 SEV-SNP 和 TDX 的方案。*另见：* [可信执行环境（TEE）](#trusted-execution-environment)。
- <a id="asic"></a>**ASIC（专用集成电路）** — Application-specific integrated circuit（专用集成电路）：为单一工作负载设计的芯片。在 AI 领域指谷歌 TPU、AWS Trainium 等定制加速器，以灵活性换取效率。*另见：* [GPU](#gpu)。
- <a id="asic-design-partner"></a>**ASIC design partner（ASIC 设计合作伙伴）** — 将客户的芯片架构转化为可量产芯片的公司（如博通、美满电子、联发科、世芯电子（Alchip）、创意电子（GUC）），提供物理设计、高速 SerDes、封装和晶圆代工渠道。超大规模云厂商借助它们打造定制加速器，而无需组建完整的芯片团队。*另见：* [ASIC](#asic)、[XPU（定制加速器）](#xpu)。
- <a id="at-the-money"></a>**At the money（平价）** — 行权价等于授予时股价的期权或认股权证。授予时没有内在价值，只有股价涨过行权价才会产生收益；这与行权价接近零的低价认股权证（penny warrant）不同。*另见：* [内在价值](#intrinsic-value)、[认股权证](#warrant)。
- <a id="attach-rate"></a>**Attach rate（附加率）** — 客户在购买一种产品时连带购买另一种产品的数量，例如每 1 美元 GPU 支出所对应的网络设备支出。附加率上升意味着供应商在每个集群的预算中占取更大份额。*另见：* [装机量](#installed-base)。
- <a id="attention"></a>**Attention（注意力机制）** — Transformer 层中让每个 token 与此前的 token 逐一比对、以获取上下文的部分。其计算成本和内存占用（KV 缓存）随序列长度增长。*另见：* [Transformer](#transformer)、[KV 缓存](#kv-cache)。
- <a id="attestation"></a>**Attestation（远程证明）** — 由烧录在芯片中的密钥签名的密码学证明，证实可信执行环境（TEE）是运行着经批准固件与配置的真实硬件。客户在发送模型权重等机密数据前会先校验该证明。*另见：* [可信执行环境（TEE）](#trusted-execution-environment)、[硬件信任根](#root-of-trust)。
- <a id="autotuning"></a>**Autotuning（自动调优）** — 在实际硬件和实际张量形状上，对内核的多个版本（分块大小、流水线深度、线程数）自动进行基准测试，并保留最快的版本。cuBLAS 的启发式选择、Triton 和 TorchInductor 均采用此法。*另见：* [GPU 内核](#gpu-kernel)、[Triton (OpenAI)](#triton)。
- <a id="aws-nitro"></a>**AWS Nitro** — AWS 自研的卸载卡与虚拟机管理程序系列，将 EC2 的网络、存储、管理和安全功能从主机 CPU 上卸载；源于 2015 年对 Annapurna Labs 的收购。*另见：* [数据处理器（DPU）](#dpu)、[EFA (Elastic Fabric Adapter)](#efa)。
- <a id="azure-cobalt"></a>**Azure Cobalt** — 微软为 Azure 自研的 Arm 服务器 CPU：Cobalt 100（128 个 Neoverse N2 核心）和 Cobalt 200（132 个 Neoverse V3 核心，2025 年）。*另见：* [Maia](#maia)、[Neoverse](#neoverse)。
## B

- <a id="back-end-network"></a>**Back-end network（后端网络）** — 专用于 GPU 之间互连的网络（InfiniBand 或 AI 以太网），承载训练和大规模推理中的集合通信，独立于通用网络之外。*另见：* [前端网络](#front-end-network)、[横向扩展（scale-out）](#scale-out)。
- <a id="backside-power-delivery"></a>**Backside power delivery（背面供电）** — 将芯片的供电线路布设在晶体管下方，而非穿过其上方的信号层，从而腾出布线空间并降低电压损耗。台积电将其方案称为 Super Power Rail（超级电轨），随 A16 节点推出。*另见：* [工艺节点](#process-node)。
- <a id="backward-pass"></a>**Backward pass (backpropagation)（反向传播）** — 沿各层逆向计算每个参数应如何调整以降低误差（即梯度）。其成本约为前向传播的两倍，因此训练总计约为每个参数每个 token 6 次浮点运算。*另见：* [前向传播](#forward-pass)、[梯度](#gradient)。
- <a id="bare-metal"></a>**Bare-metal instance（裸金属实例）** — 不带云服务商虚拟机管理程序（hypervisor）的租用式云服务器：租户掌控整个操作系统。云服务商的控制软件因此必须部署在租户无法触及之处，例如 DPU 上。*另见：* [多租户](#multi-tenancy)、[数据处理器（DPU）](#dpu)。
- <a id="base-command-manager"></a>**Base Command Manager** — 英伟达的集群管理软件（源自 2022 年对 Bright Computing 的收购），用于部署、配置和监控 GPU 集群的服务器、操作系统镜像和调度器；现已并入 Mission Control。*另见：* [NVIDIA Mission Control](#mission-control)、[Slurm](#slurm)。
- <a id="baseband-modem"></a>**baseband modem（基带调制解调器）** — 处理手机蜂窝无线协议的芯片（或芯片模块）；英伟达于 2011 年收购 Icera 以获得这一能力，并于 2015 年关停该业务。*另见：* [片上系统](#system-on-chip)。
- <a id="batching"></a>**Batching（批处理）** — 在同一个 GPU 计算步骤中同时处理多个请求，使一次权重读取由所有请求共享。可提升单 GPU 吞吐量，但会拖慢每个用户的响应速度。*另见：* [连续批处理](#continuous-batching)、[吞吐量-交互速度帕累托前沿](#pareto-frontier)。
- <a id="behavioural-remedy"></a>**Behavioural remedy（行为性救济措施）** — 一种并购附加条件：规范合并后公司的行为方式（例如不得捆绑销售、须继续向竞争对手供货、保持互操作性），而不是强制其剥离资产。*另见：* [SAMR（国家市场监督管理总局）](#samr)。
- <a id="behind-the-meter"></a>**Behind-the-meter generation（表后发电）** — 在数据中心场址内或邻近处建设、直接向其供电而不经过公用电网的发电设施（通常为燃气轮机、内燃机或燃料电池），使数据中心能在电网接入到位之前先行投运。*另见：* [通电时间](#time-to-power)、[并网排队](#interconnection-queue)。
- <a id="bf16"></a>**BF16 (bfloat16)** — 一种 16 位（2 字节）数值格式，数值范围与 32 位浮点数相同、但精度较低；是当前 GPU 上训练和大部分推理的默认格式。*另见：* [FP8](#fp8)、[混合精度训练](#mixed-precision)。
- <a id="bill-of-materials"></a>**Bill of materials (BOM)（物料清单）** — 构成一件产品的全部元器件清单及其成本。就 GPU 封装而言包括：逻辑裸片、HBM、封装、基板和测试。分析师估计 B200 的物料成本约为 $6,400。
- <a id="bin-packing"></a>**Bin-packing (scheduling)（装箱式调度）** — 一种放置策略：先填满一台服务器或一个机架，再启用下一台，从而为大型作业保留完整的空闲单元。与之相反的分散放置可提升容错能力，但会造成容量碎片化。*另见：* [GPU 碎片化](#gpu-fragmentation)。
- <a id="binary-translation"></a>**Binary translation（二进制翻译）** — 在程序运行时将其机器码从一种指令集（或形式）转换为另一种。英伟达的 Denver 核心采用了与之相关的“动态代码优化”方案。*另见：* [ISA（指令集架构）](#isa)。
- <a id="bionemo"></a>**BioNeMo** — 英伟达用于训练和部署生物与化学基础模型（蛋白质、分子、DNA）的框架与模型集合。*另见：* [Parabricks](#parabricks)。
- <a id="bis"></a>**BIS (Bureau of Industry and Security)（美国商务部工业与安全局）** — 美国商务部下属机构，负责制定出口管制规则并审批出口许可，包括针对中国的 AI 芯片规则。*另见：* [出口管制](#export-controls)。
- <a id="bisection-bandwidth"></a>**Bisection bandwidth（对分带宽）** — 将网络切分为相等两半的最窄切面上的总带宽。无阻塞胖树拥有全对分带宽：一半端点能够以线速与另一半端点通信。*另见：* [胖树](#fat-tree)、[超额订阅](#oversubscription)。
- <a id="blended-token-price"></a>**Blended token price（混合 token 价格）** — 将输入价格与输出价格加权平均后得到的单一每百万 token 价格，通常按 3 个输入 token 对 1 个输出 token 加权。*另见：* [token 价格通缩](#token-price-deflation)。
- <a id="blind-mate-connector"></a>**Blind-mate connector（盲插连接器）** — 托盘滑入机架时即自动对接、无需人工插拔线缆的连接器。NVL72 的托盘借此接入 NVLink 背板（spine），使托盘可整体插拔更换，也降低了布线出错的概率。*另见：* [NVLink 线缆背板](#nvlink-spine)、[NVLink 交换托盘](#nvlink-switch-tray)。
- <a id="bluefield"></a>**BlueField** — 英伟达（最初为 Mellanox）的 DPU 产品系列：将 ConnectX 网络适配器与 Arm CPU 核心相结合，把网络、存储和安全任务从主机 CPU 上卸载。*另见：* [数据处理器（DPU）](#dpu)、[ConnectX](#connectx)。
- <a id="bmc"></a>**BMC (baseboard management controller)（基板管理控制器）** — 服务器或交换托盘上的小型服务处理器，通过独立的管理网络监控设备健康、电源和固件状态，即使主芯片断电也能工作。*另见：* [NVLink 交换托盘](#nvlink-switch-tray)。
- <a id="bounce-buffer"></a>**Bounce buffer（中转缓冲区）** — 位于 CPU 内存中的暂存区：数据先落到这里，再复制到真正的目的地（例如从网卡或 SSD 复制到 GPU 显存）。每次中转都会消耗主机内存带宽和 CPU 时间并增加延迟；GPUDirect 免去了这一环节。*另见：* [GPUDirect RDMA](#gpudirect-rdma)、[GPUDirect Storage](#gpudirect-storage)。
- <a id="brook"></a>**Brook** — 斯坦福大学于 2004 年推出、由 Ian Buck 主导的类 C 语言 GPU 流式编程语言。它证明通用代码可以编译到图形硬件上运行，是 CUDA 在研究阶段的前身。*另见：* [GPGPU](#gpgpu)、[CUDA](#cuda)。
- <a id="burn-in"></a>**Burn-in（老化测试）** — 新硬件在正式投入生产前满负荷运行数日，以便在客户依赖它之前提前暴露 GPU、线缆、散热和电源的早期故障。*另见：* [计算托盘](#compute-tray)、[NVL72](#nvl72)。
- <a id="bus-bandwidth"></a>**Bus bandwidth（总线带宽）** — NCCL 基准测试所报告的指标：集合通信期间每块 GPU 的链路实际维持的数据速率，经过归一化处理，以便与硬件链路速度相比较。*另见：* [NCCL](#nccl)、[全规约](#all-reduce)。
- <a id="busbar"></a>**Busbar（母排）** — 纵贯机架高度的粗铜排，把直流电从电源架输送到每个托盘。在约 50 V 电压下，132 kW 的机架需要约 2,600 A 电流，这正是更高电压方案即将到来的原因。*另见：* [电源架](#power-shelf)、[800 V 直流供电架构](#hvdc-800v)。
- <a id="bytes-per-token"></a>**Bytes per token（每 token 字节数）** — GPU 生成一个 token 必须从内存读取的数据量：大致为模型权重（每个解码步骤读取一次，由整个批次共享）加上每个用户的 KV 缓存。用内存带宽除以该数值，即得到解码速度上限。*另见：* [解码速度上限](#decode-ceiling)、[内存受限](#memory-bound)、[KV 缓存](#kv-cache)。
## C

- <a id="cache-coherence"></a>**Cache coherence（缓存一致性）** — 由硬件保证各处理器缓存中的共享内存副本彼此一致，使 CPU 和 GPU 能用普通指针读写同一份数据，而无需显式复制。*另见：* [NVLink-C2C](#nvlink-c2c)。
- <a id="cann"></a>**CANN** — 华为的神经网络计算架构（Compute Architecture for Neural Networks）：昇腾（Ascend）NPU 的驱动、编译器和内核层，相当于华为版的 CUDA；已于 2025 年开源。*另见：* [CUDA](#cuda)。
- <a id="capacity-allocation"></a>**Capacity allocation（产能分配）** — 台积电或 HBM 厂商等供应商在客户之间分配稀缺产出的方式，通常偏向规模最大、下单最早、最可靠的买家。在 AI 硬件领域，拿到产能可能比拥有更好的设计更重要。*另见：* [CoWoS](#cowos)、[高带宽内存（HBM）](#hbm)、[采购义务](#purchase-obligations)。
- <a id="capacity-backstop"></a>**Capacity backstop（算力兜底承诺）** — 由第三方（此处通常为英伟达或谷歌）作出的承诺：若运营方未能把数据中心容量卖给客户，由其购买或付费。这降低了运营方的融资风险和借贷成本。*另见：* [循环融资](#circular-financing)、[新兴云服务商（neocloud）](#neocloud)。
- <a id="capacity-market"></a>**Capacity market（容量市场）** — 一种电力市场：电网运营方提前数年向发电方付费（以每兆瓦·日美元计），换取其届时可供电的承诺；PJM 的拍卖价格是衡量美国最大数据中心区域稳定电力稀缺程度的公开指标。*另见：* [并网排队](#interconnection-queue)。
- <a id="capital-recovery-factor"></a>**Capital recovery factor（资本回收系数）** — 在资产寿命期内每年须赚取的投资比例，以连本带息收回投资：r / (1 - (1 + r)^-n)。用于把资本开支折算为年度成本。*另见：* [总拥有成本（TCO）](#tco)。
- <a id="capital-for-capacity"></a>**Capital-for-capacity deal（以资本换产能交易）** — 芯片厂商向客户提供资金或股权（现金入股、认股权证、兜底承诺），以换取客户承诺部署一定规模的该厂商算力（通常以吉瓦计）的交易。*另见：* [循环融资](#circular-financing)、[认股权证](#warrant)。
- <a id="captive-silicon"></a>**Captive silicon（自用芯片）** — 企业自行设计、仅供自用而不对外销售的芯片（例如 AWS Nitro 或微软的 Azure Boost DPU），与商用芯片相对。*另见：* [商用芯片](#merchant-silicon)。
- <a id="cdna"></a>**CDNA** — AMD 的数据中心 GPU 架构系列（Compute DNA），独立于其 RDNA 游戏产品线。CDNA 3 用于 MI300X/MI325X，CDNA 4 用于 MI350 系列；据报道 MI500 将采用 CDNA 6。*另见：* [ROCm](#rocm)、[AMD Helios](#amd-helios)。
- <a id="channel-partner"></a>**Channel partner（渠道合作伙伴）** — 转售、集成或服务某厂商产品的公司，例如 OEM、分销商或系统集成商，使厂商无需自建庞大的销售团队即可触达客户。*另见：* [全球系统集成商（GSI）](#gsi)、[OEM](#oem)。
- <a id="checkpoint"></a>**Checkpoint（检查点）** — 保存到存储中的模型权重与优化器状态快照，使训练作业在发生故障后可以从断点恢复，而不必从头开始。*另见：* [有效吞吐量](#goodput)。
- <a id="compliant-sku"></a>**China-compliant SKU（中国合规版 SKU）** — 为恰好低于出口管制门槛而削减规格的产品型号（例如 A800、H800、H20），从而在规则变化之前无需许可证即可出货。*另见：* [TPP（总处理性能）](#tpp)。
- <a id="chinchilla-optimal"></a>**Chinchilla-optimal（Chinchilla 最优）** — 2022 年的一项研究结论：在算力预算固定的情况下，参数量与训练 token 数应同步增长，比例约为每个参数 20 个 token。*另见：* [缩放定律](#scaling-laws)、[过度训练](#over-training)。
- <a id="chip-hour"></a>**Chip-hour（芯片小时）** — 一个加速器使用一小时：云租赁价格和自有总拥有成本（TCO）的计价单位。跨厂商比较芯片小时时，若不同时比较单芯片吞吐量，就会产生误导。*另见：* [GPU 小时](#gpu-hour)、[总拥有成本（TCO）](#tco)。
- <a id="chiplet"></a>**Chiplet（芯粒）** — 为与其他裸片组合封装而设计的较小裸片，以取代单一的巨型单体裸片。芯粒能提升良率，并允许不同功能采用不同的工艺节点。*另见：* [裸片](#die)、[中介层](#interposer)、[裸片间互连](#die-to-die-interconnect)。
- <a id="circular-financing"></a>**Circular financing（循环融资）** — 一种批评观点：供应商通过投资客户、向客户放贷或为客户的产能提供担保来抬高自身需求，而客户再用这些资金购买供应商的产品。此说法被用于评论英伟达对 AI 实验室和新兴云服务商的入股及其算力兜底承诺。*另见：* [新兴云服务商（neocloud）](#neocloud)、[采购义务](#purchase-obligations)。
- <a id="cloud-credits"></a>**Cloud credits（云积分）** — 云服务商赠予初创企业的预付使用额度（例如谷歌云为 AI 原生初创企业提供最高 $350,000），以便尽早赢得其工作负载。
- <a id="co-design"></a>**Co-design (hardware-software)（软硬件协同设计）** — 将芯片与运行于其上的编译器、库和模型一并设计，使 FP4 数值格式等新特性在产品发布当天即可投入使用。2026 年英伟达在芯片上的主要优势在于协同设计的速度，而非纸面规格。*另见：* [NVFP4](#nvfp4)、[CUDA](#cuda)。
- <a id="co-packaged-optics"></a>**Co-packaged optics (CPO)（共封装光学）** — 把将电信号转换为光信号的光引擎直接放在交换芯片旁边、置于同一封装内，而不是放在前面板的可插拔光模块中。这缩短了电气路径，降低了每比特功耗。*另见：* [可插拔光模块](#pluggable-transceiver)、[微环调制器](#micro-ring-modulator)、[外置激光光源](#external-laser-source)。
- <a id="cold-plate"></a>**Cold plate（冷板）** — 直接贴装在 GPU 或 CPU 上、内部带有流道的金属块；流经其中的液体将热量带走（直触芯片液冷）。*另见：* [冷却液分配单元（CDU）](#cdu)、[液冷](#liquid-cooling)。
- <a id="collective-operation"></a>**Collective operation（集合通信操作）** — 整组 GPU 同时交换数据的通信模式（全规约、全收集、规约散射、全交换、广播），与单个 GPU 向另一个 GPU 发送数据相对。*另见：* [全规约](#all-reduce)、[NCCL](#nccl)。
- <a id="composable-kernel"></a>**Composable Kernel** — AMD 用于在 ROCm 上编写融合 GPU 内核的 C++ 模板库；是 AMD 最接近 CUTLASS 的对应产品。*另见：* [CUTLASS](#cutlass)、[ROCm](#rocm)。
- <a id="computational-lithography"></a>**Computational lithography（计算光刻）** — 对光掩模上的芯片设计图形进行预先畸变处理（光学邻近效应修正）的软件，使图形能准确地印制在晶圆上；是芯片制造中规模最大的计算工作负载之一。*另见：* [cuLitho](#culitho)、[光掩模](#photomask)。
- <a id="compute-margin"></a>**Compute margin（算力利润率）** — 模型实验室的收入在扣除为付费用户提供服务的算力成本后剩余的比例；不含训练算力和研发支出。*另见：* [毛利率](#gross-margin)。
- <a id="compute-subsystem"></a>**Compute Subsystem (CSS)（计算子系统）** — Arm 预先集成并验证的模块，包含处理器核心、片上互连网格和 I/O，被授权方可直接将其放入自家芯片以节省设计时间。其版税高于单独授权核心。*另见：* [Neoverse](#neoverse)、[IP 版税](#ip-royalty)。
- <a id="compute-tray"></a>**Compute tray（计算托盘）** — NVL72 机架中的一个 1U 抽屉，容纳两块超级芯片板（2 个 CPU + 4 个 GPU）及其网卡、本地 SSD 和冷板。十八个计算托盘构成机架的 72 块 GPU。*另见：* [NVL72](#nvl72)、[超级芯片](#superchip)、[NVLink 交换托盘](#nvlink-switch-tray)。
- <a id="compute-bound"></a>**Compute-bound（计算受限）** — 速度受芯片算术吞吐量限制的工作负载，因为它会对每个字节重复使用多次；增加内存带宽无济于事。*另见：* [内存受限](#memory-bound)、[FLOPS](#flops)。
- <a id="compute-in-memory"></a>**Compute-in-memory（存内计算）** — 在存储阵列内部或紧邻处执行乘累加运算的设计，减少搬运权重所耗费的能量。d-Matrix 的数字存内计算即为一例。*另见：* [近存计算](#near-memory-compute)、[内存墙](#memory-wall)。
- <a id="confidential-computing"></a>**Confidential computing（机密计算）** — 在受硬件保护的隔离区（可信执行环境）中运行代码和数据，使云运营方本身也无法读取；英伟达自 Hopper 起在 GPU 上支持该功能。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="congestion-control"></a>**Congestion control（拥塞控制）** — 发送端和交换机在队列溢出前降低流量的规则，例如对数据包打标记（ECN）并由网卡降低发送速率。良好的拥塞控制能保持队列短、尾延迟低。*另见：* [ECN（显式拥塞通知）](#ecn)、[多对一拥塞](#incast)、[自适应路由](#adaptive-routing)。
- <a id="connectx"></a>**ConnectX** — 英伟达（最初为 Mellanox）面向 InfiniBand 和以太网的网络适配器系列。参考设计为每块 GPU 配一块 ConnectX 网卡或 SuperNIC，因此它随 GPU 订单一同出货。*另见：* [SuperNIC](#supernic)、[InfiniBand](#infiniband)。
- <a id="context-parallelism"></a>**Context parallelism (CP)（上下文并行）** — 将一个超长序列的 token 拆分到多个 GPU 上，各 GPU 再交换注意力的键和值（例如以环形方式）；用于 100K token 以上的长序列训练。*另见：* [序列并行](#sequence-parallelism)。
- <a id="continuous-batching"></a>**Continuous batching（连续批处理）** — 在每个生成步骤都进行调度，使请求可以随时加入或离开正在运行的批次，而不必等整个批次完成。现代推理服务引擎的标配。*另见：* [批处理](#batching)、[PagedAttention](#paged-attention)。
- <a id="contracted-power"></a>**Contracted vs active power（签约电力与在用电力）** — 签约电力指云厂商已签约锁定的数据中心容量（以 MW 或 GW 计）；在用电力指当前已通电并在计费的容量。二者之差是仍待融资和交付的建设量。*另见：* [新兴云服务商（neocloud）](#neocloud)、[收入积压](#revenue-backlog)。
- <a id="cdu"></a>**Coolant distribution unit (CDU)（冷却液分配单元）** — 由水泵和换热器组成的单元，将液态冷却剂循环输送至机架内的冷板，并把热量传递给建筑的水循环系统。一台 CDU 可服务一个或多个机架。*另见：* [冷板](#cold-plate)、[液冷](#liquid-cooling)。
- <a id="copos"></a>**CoPoS (chip-on-panel-on-substrate)（面板级 CoWoS）** — 台积电 CoWoS 的面板级版本，在大型方形面板而非 300 mm 圆形晶圆上制作封装，随着封装尺寸增大可减少面积浪费。2026 年试产；预计 2H 2028 之前不会量产。*另见：* [CoWoS](#cowos)、[CoWoS-L](#cowos-l)、[先进封装](#advanced-packaging)。
- <a id="corporate-venture-capital"></a>**Corporate venture capital（企业风险投资）** — 实体经营企业对初创公司进行的少数股权投资，通常兼顾获取战略信息、扩大生态影响力和财务回报。*另见：* [NVentures](#nventures)。
- <a id="wacc"></a>**Cost of capital (WACC)（资本成本）** — 投资者对占用在某项资产上的资金所要求的年回报率（加权平均资本成本）。在 TCO 模型中，它把前期资本开支转化为包含融资成本（而不仅是折旧）的均等年度费用。*另见：* [资本回收系数](#capital-recovery-factor)、[使用寿命](#useful-life)。
- <a id="cost-per-million-tokens"></a>**Cost per million tokens（每百万 token 成本）** — 加速器在一段时期内的自有成本除以其产出的 token 数，再折算到一百万个 token。它既取决于硬件价格，也同样取决于在选定的单用户速度下的吞吐量以及利用率。*另见：* [自有 TCO](#owner-tco)、[交互速度（每用户 tokens/s）](#interactivity)、[每兆瓦每秒 token 数](#tokens-per-megawatt)。
- <a id="cowos"></a>**CoWoS** — Chip-on-Wafer-on-Substrate（晶圆上芯片再上基板）：台积电的 2.5D 先进封装，将 GPU 裸片和 HBM 堆栈并排置于硅中介层（CoWoS-S）或基于桥接的变体（CoWoS-L、CoWoS-R）上。其产能一直是 AI 加速器的关键瓶颈。*另见：* [高带宽内存（HBM）](#hbm)。
- <a id="cowos-l"></a>**CoWoS-L** — 台积电的 CoWoS 变体，以内嵌小型硅桥的重布线层中介层取代单一大型硅中介层，可支持数倍光罩尺寸的封装（自 Blackwell 起采用）。*另见：* [CoWoS](#cowos)、[中介层](#interposer)。
- <a id="cowos-r"></a>**CoWoS-R** — 台积电的 CoWoS 变体，其中介层仅由有机重布线层构成、不含硅。成本更低、更灵活，但布线精度低于 CoWoS-S 或 CoWoS-L。*另见：* [CoWoS](#cowos)、[重布线层（RDL）](#redistribution-layer)、[CoWoS-L](#cowos-l)。
- <a id="cowos-s"></a>**CoWoS-S** — 台积电最初的 CoWoS 变体，将裸片置于单一的单体硅中介层上，中介层面积最大约为光罩面积的 3.3 倍。用于 A100、H100 和 H200。*另见：* [CoWoS](#cowos)、[CoWoS-L](#cowos-l)、[中介层](#interposer)。
- <a id="cpu"></a>**CPU (central processing unit)（中央处理器）** — 一种通用处理器，拥有几十到几百个强大的核心，专为低延迟运行多样化、分支繁多的代码而设计。在 AI 服务器中，它是负责启动系统、运行操作系统并向 GPU 供给数据的主机。*另见：* [主机 CPU](#host-cpu)、[GPU](#gpu)、[超级芯片](#superchip)。
- <a id="credit-based-flow-control"></a>**Credit-based flow control（基于信用的流量控制）** — InfiniBand 避免丢包的机制：只有在接收端通告有空闲缓冲区（“信用”）时，发送端才能发送。无法存储的数据一律不发，因此链路在设计上就是无损的。*另见：* [InfiniBand](#infiniband)、[PFC（基于优先级的流量控制）](#priority-flow-control)。
- <a id="cublas"></a>**cuBLAS** — 英伟达的 GPU 基础线性代数例程库，核心是矩阵乘法（GEMM）。大多数 AI 框架都把大型矩阵乘法交由它执行。*另见：* [GEMM](#gemm)、[CUTLASS](#cutlass)。
- <a id="cuda"></a>**CUDA** — 英伟达于 2006 年推出的编程平台（语言扩展、编译器、运行时、驱动和库），让开发者能在 GPU 上运行通用代码。是英伟达软件护城河的基础。*另见：* [CUDA-X](#cuda-x)。
- <a id="cuda-core"></a>**CUDA core（CUDA 核心）** — 英伟达对 SM 中简单算术通道的称呼，每个时钟周期执行一次标量运算（例如一次 32 位乘加）。数以千计的 CUDA 核心负责通用并行代码；矩阵运算则交由张量核心处理。*另见：* [流式多处理器（SM）](#streaming-multiprocessor)、[张量核心](#tensor-core)。
- <a id="cuda-graphs"></a>**CUDA Graphs** — CUDA 的一项功能：将一系列内核启动录制一次，之后以单次启动整体重放，从而降低 CPU 的启动开销——这对小而频繁的推理步骤很重要。*另见：* [CUDA 流](#cuda-stream)、[GPU 内核](#gpu-kernel)。
- <a id="cuda-stream"></a>**CUDA stream（CUDA 流）** — GPU 工作（数据复制和内核启动）的有序队列。同一个流内的工作按顺序执行；不同的流可以重叠执行，从而把数据传输隐藏在计算之后。*另见：* [CUDA Graphs](#cuda-graphs)。
- <a id="cuda-q"></a>**CUDA-Q** — 英伟达面向量子-经典混合程序的开放平台和编译器，程序可跨量子处理器、GPU 和 CPU 运行。*另见：* [cuQuantum](#cuquantum)。
- <a id="cuda-x"></a>**CUDA-X** — 英伟达对其基于 CUDA 构建的数百个领域库（cuBLAS、cuDNN、NCCL、RAPIDS 等）的统称。*另见：* [CUDA](#cuda)。
- <a id="cudf"></a>**cuDF** — RAPIDS 的 GPU 数据框（dataframe）库：类似 pandas 的表格引擎，也为 Spark、Polars 和 Dask 提供 GPU 后端。*另见：* [RAPIDS](#rapids)、[数据框](#dataframe)。
- <a id="cudf-pandas"></a>**cudf.pandas** — cuDF 的一种模式，可加速未经修改的 pandas 代码：GPU 支持的操作在 GPU 上运行，其余操作回退到 CPU 上的普通 pandas。*另见：* [cuDF](#cudf)、[零代码改动加速](#zero-code-change)。
- <a id="cudnn"></a>**cuDNN** — 英伟达经调优的深度学习内核库（卷积、注意力、归一化），2014 年首次发布。各框架直接调用它，而无需自行编写 GPU 代码。*另见：* [CUDA-X](#cuda-x)、[GPU 内核](#gpu-kernel)。
- <a id="cufft"></a>**cuFFT** — 英伟达的快速傅里叶变换库，用于信号处理、成像、地震分析和物理计算程序。*另见：* [cuBLAS](#cublas)。
- <a id="cugraph"></a>**cuGraph** — RAPIDS 的 GPU 图分析库（PageRank、最短路径、社区发现），适用于拥有数十亿条边的网络。*另见：* [RAPIDS](#rapids)。
- <a id="culitho"></a>**cuLitho** — 英伟达的计算光刻库：完成为光掩模图形塑形的繁重计算，使芯片能被正确印制。台积电于 2024 年与新思科技（Synopsys）将其投入生产。*另见：* [计算光刻](#computational-lithography)。
- <a id="cuml"></a>**cuML** — RAPIDS 的 GPU 机器学习库（随机森林、聚类、UMAP 等）。其 cuml.accel 模式可在 GPU 上运行未经修改的 scikit-learn 代码。*另见：* [RAPIDS](#rapids)、[零代码改动加速](#zero-code-change)。
- <a id="cuopt"></a>**cuOpt** — 英伟达用于线性规划和车辆路径规划的 GPU 优化引擎，2025 年以 Apache 2.0 许可开源。*另见：* [线性规划](#linear-programming)。
- <a id="cuquantum"></a>**cuQuantum** — 英伟达在 GPU 上模拟量子计算机的库（态矢量法和张量网络法），用于开发和测试量子算法。*另见：* [CUDA-Q](#cuda-q)。
- <a id="curand"></a>**cuRAND** — 英伟达的随机数生成库，用于蒙特卡洛模拟、风险模型以及神经网络的随机初始化。*另见：* [cuBLAS](#cublas)。
- <a id="cusparse"></a>**cuSPARSE** — 英伟达用于稀疏矩阵（大部分元素为零）线性代数运算的库，用于仿真、图分析和推荐模型。*另见：* [cuBLAS](#cublas)。
- <a id="customer-concentration"></a>**Customer concentration（客户集中度）** — 来自少数大客户的收入占比。集中度高意味着这些买家拥有议价能力，且收入对其中任何一家更换供应商都十分敏感。*另见：* [直接客户与间接客户](#indirect-customer)。
- <a id="customer-owned-tooling"></a>**Customer-owned tooling (COT)（客户自有工具模式）** — 一种定制芯片模式：客户自己承担更多设计工作，只采购特定服务或 IP，再直接与晶圆代工厂签约；这会压低合作伙伴的单位利润率。*另见：* [交钥匙 ASIC](#turnkey-asic)、[NRE（一次性工程费用）](#nre)。
- <a id="cute"></a>**CuTe** — CUTLASS 3 和 4 核心的布局与张量抽象。它描述数据如何在线程和内存之间分块；自 CUTLASS 4 起也以 Python 领域专用语言（DSL）形式提供。*另见：* [CUTLASS](#cutlass)、[DSL（领域专用语言）](#dsl)。
- <a id="cutlass"></a>**CUTLASS** — 英伟达开源的 CUDA C++ 模板集合，用于构建定制的高性能矩阵乘法及相关内核，在现成的 cuBLAS 例程不适用时使用（新数值格式、融合操作）。*另见：* [cuBLAS](#cublas)、[CuTe](#cute)。
- <a id="cuvs"></a>**cuVS** — 英伟达用于向量搜索（查找最近邻嵌入向量）和聚类的 GPU 库，已内置于 Faiss、Milvus 等向量数据库中。*另见：* [向量搜索](#vector-search)、[RAPIDS](#rapids)。
- <a id="cxl"></a>**CXL (Compute Express Link)** — 一种运行在 PCIe 线路之上的开放标准，增加了缓存一致的内存访问，使 CPU 能使用内存扩展器或与加速器共享内存。它是 NVLink-C2C 等专有一致性互连的开放标准替代方案。*另见：* [PCIe (PCI Express)](#pcie)、[缓存一致性](#cache-coherence)。
## D

- <a id="data-center-segment"></a>**Data center (NVIDIA segment)（数据中心分部）** — 英伟达针对销往数据中心的 AI 和 HPC 产品设立的报告分部，分为计算（GPU、系统）和网络（NVLink、InfiniBand、以太网、网卡、DPU）两部分。
- <a id="data-loader"></a>**Data loader（数据加载器）** — 通常在主机 CPU 核心上运行的软件管线，负责从存储读取训练样本、进行解码和数据增强，再把批数据交给 GPU。若其速度慢于 GPU，GPU 就只能空等。*另见：* [GPU 饥饿](#gpu-starvation)、[NVIDIA DALI](#dali)。
- <a id="data-parallelism"></a>**Data parallelism (DP)（数据并行）** — 在多块 GPU 上进行训练：每块 GPU 持有完整的模型副本、处理批次中不同的切片，并在每一步通过全规约对梯度求平均。*另见：* [全规约](#all-reduce)、[ZeRO（零冗余优化器）](#zero)、[FSDP](#fsdp)。
- <a id="dataflow-architecture"></a>**Dataflow architecture（数据流架构）** — 一种芯片设计：由编译器把模型的运算映射到计算与存储单元构成的网格上，数据在各单元之间流动，而不是由处理器逐条读取指令执行。SambaNova 的 RDU 即为一例。*另见：* [SRAM](#sram)、[ASIC](#asic)。
- <a id="dataframe"></a>**Dataframe（数据框）** — 驻留在内存中、由行和具名列组成的表格，是 pandas、Polars 和 Spark 的基本数据结构。*另见：* [cuDF](#cudf)、[ETL](#etl)。
- <a id="day-zero-support"></a>**Day-0 support（首日支持）** — 新模型发布当天，能否在某款芯片及其软件栈上良好运行。厂商之间软件成熟度的差距在这一点上体现得最为明显。*另见：* [vLLM](#vllm)、[GPU 内核](#gpu-kernel)。
- <a id="dcgm"></a>**DCGM (Data Center GPU Manager)（数据中心 GPU 管理器）** — 英伟达开源的守护进程和工具集，用于监控和管理数据中心 GPU：健康检查、诊断、错误告警和功耗策略，并将数据输出给调度器和 Kubernetes。*另见：* [网络遥测](#telemetry)、[SM 利用率](#sm-utilization)。
- <a id="decode"></a>**Decode (generation phase)（解码）** — 推理请求的第二阶段：逐个生成输出 token，每生成一个都需要完整读取一遍模型权重。受内存带宽限制。*另见：* [预填充（prefill）](#prefill)、[TPOT/ITL](#tpot)。
- <a id="decode-ceiling"></a>**Decode ceiling（解码速度上限）** — 解码阶段内存带宽所能支撑的最高每秒 token 数：带宽除以每个 token 需读取的字节数。一个 70B 参数的 FP8 模型，在 H100 上每个流的上限约为 48 tokens/s，在 Rubin 上约为 274。*另见：* [每 token 字节数](#bytes-per-token)、[解码（decode）](#decode)、[内存墙](#memory-wall)。
- <a id="deep-learning-institute"></a>**Deep Learning Institute（深度学习学院）** — 英伟达的培训部门（DLI），提供有关 GPU 编程和 AI 的付费及免费课程、讲师指导的工作坊和认证，通常通过高校和合作伙伴开展。*另见：* [开发者关系](#developer-relations)。
- <a id="deep-buffer-switch"></a>**Deep-buffer switch（深缓冲交换机）** — 配备大容量数据包缓存（通常为 HBM）的交换芯片，如博通 Jericho 或思科（Cisco）P200，能够吸收长距离链路上的突发流量。用于数据中心之间的跨数据中心扩展（scale-across）以及调度式 AI 网络。*另见：* [跨数据中心扩展（scale-across）](#scale-across)。
- <a id="defect-density"></a>**Defect density (D0)（缺陷密度）** — 晶圆上每平方厘米随机致命缺陷的平均数量，是晶圆厂工艺的关键质量指标。良率大致随“裸片面积 × 缺陷密度”呈指数下降。*另见：* [裸片良率](#die-yield)。
- <a id="dense-vs-sparse"></a>**Dense vs. sparse FLOPS（稠密与稀疏 FLOPS）** — 厂商常引用“稀疏”峰值吞吐量，它假定采用 2:4 结构化稀疏（一半权重为零），恰为稠密数值的两倍。实际模型很少以稀疏方式运行，因此本资料库采用稠密数值。*另见：* [2:4 结构化稀疏](#sparsity)、[FLOPS](#flops)。
- <a id="design-win"></a>**Design win（设计导入）** — 客户承诺在某一代具体产品中采用某供应商的芯片或设计服务。在定制芯片领域，它标志着一个多年期项目的开始，但尚未形成收入。*另见：* [ASIC 设计合作伙伴](#asic-design-partner)、[流片](#tape-out)。
- <a id="developer-relations"></a>**Developer relations（开发者关系）** — 平台型公司为赢得并留住软件开发者而开展的各类项目：免费工具和库、文档、培训、会议和技术支持。对英伟达而言，它培养了开发者使用 CUDA 的习惯，从而抬高了客户的转换成本。*另见：* [CUDA](#cuda)、[NVIDIA Inception](#nvidia-inception)。
- <a id="dgx"></a>**DGX** — 英伟达自有品牌的 AI 系统（2016 年的 DGX-1，此后有 DGX-2、DGX A100、DGX H100 以及 DGX 机架系统），既直接销售，也经合作伙伴销售；同时充当英伟达的参考设计。*另见：* [HGX](#hgx)、[超节点](#superpod)。
- <a id="dgx-cloud"></a>**DGX Cloud** — 英伟达自营的 GPU 云服务（2023 年），托管在甲骨文、微软、谷歌和 AWS 的数据中心内、由英伟达租用的容量之上。据报道，其大部分容量已于 2025 年转用于英伟达内部研究。*另见：* [DGX Cloud Lepton](#dgx-cloud-lepton)、[新兴云服务商（neocloud）](#neocloud)。
- <a id="dgx-cloud-lepton"></a>**DGX Cloud Lepton** — 英伟达的算力交易平台（2025 年），把开发者引导至 CoreWeave、Lambda、Nebius 和 Crusoe 等合作云厂商所拥有的 GPU 容量；英伟达本身不拥有这些硬件。*另见：* [DGX Cloud](#dgx-cloud)、[GPU 交易平台](#gpu-marketplace)。
- <a id="die"></a>**Die（裸片）** — 从晶圆上切割下来的单块硅片。Blackwell 等现代 AI GPU 在一个封装内放置两颗（Rubin Ultra 为四颗）计算裸片。*另见：* [GPU](#gpu)、[光罩尺寸极限](#reticle-limit)。
- <a id="die-harvesting"></a>**Die harvesting（裸片降级利用）** — 将含有缺陷的裸片屏蔽其故障模块（例如几个流式多处理器）后，作为规格略低的型号出售。这提高了大型 GPU 的有效良率。*另见：* [裸片良率](#die-yield)。
- <a id="die-yield"></a>**Die yield（裸片良率）** — 晶圆上可正常工作的裸片所占比例。裸片越大良率越低，因为每颗裸片含有缺陷的可能性更大，这使大型 GPU 的成本不成比例地升高。*另见：* [缺陷密度（D0）](#defect-density)、[裸片降级利用](#die-harvesting)。
- <a id="die-to-die-interconnect"></a>**Die-to-die interconnect（裸片间互连）** — 同一封装内裸片之间极短、极宽的连接，使它们能像一颗芯片那样协同工作。英伟达 Blackwell 的两颗计算裸片之间采用 10 TB/s 的互连（NV-HBI）。*另见：* [芯粒](#chiplet)、[NVLink](#nvlink)。
- <a id="dies-per-wafer"></a>**Dies per wafer（每片晶圆裸片数）** — 一片晶圆上可容纳的完整裸片数量。这是一个几何计算，取决于裸片面积以及圆形晶圆边缘损失的不完整裸片。在 300 mm 晶圆上，814 mm² 的 GPU 裸片约为 63 颗。*另见：* [裸片](#die)、[裸片良率](#die-yield)。
- <a id="digital-twin"></a>**Digital twin (datacenter)（数字孪生）** — 以物理精度模拟数据中心（供电、散热、气流、机架）的软件模型，用于在施工前进行设计和测试；英伟达的 Omniverse DSX 蓝图即为一例。*另见：* [AI 工厂](#ai-factory)。
- <a id="dilution"></a>**Dilution（稀释）** — 公司发行新股（例如为支付收购对价或结算认股权证）时，原有股东持股比例的下降。*另见：* [认股权证](#warrant)。
- <a id="indirect-customer"></a>**Direct vs indirect customer（直接客户与间接客户）** — 在英伟达的财报中，直接客户是直接向英伟达采购的客户（主要是 OEM 和 ODM）；间接客户（如云服务商或 AI 实验室）则从直接客户处购买整机系统。英伟达披露收入占比超过 10% 的直接客户，并对大型间接客户作出估计。*另见：* [客户集中度](#customer-concentration)、[OEM](#oem)、[ODM](#odm)。
- <a id="direct-attach-copper"></a>**Direct-attach copper (DAC)（直连铜缆）** — 两端带连接器、内部没有任何电子器件的无源铜缆。几乎不耗电、极少故障，但在每通道 200 Gb/s 的速率下，无源铜缆的传输距离仅约一米。*另见：* [NVLink 线缆背板](#nvlink-spine)、[有源电缆（AEC）](#active-electrical-cable)、[共封装光学（CPO）](#co-packaged-optics)。
- <a id="direct-to-chip-cooling"></a>**Direct-to-chip liquid cooling（直触芯片液冷）** — 让液体流经安装在发热最高的芯片（GPU、CPU、交换芯片）上的冷板，从源头带走大部分热量；剩余热量由风扇或后门换热器处理。*另见：* [冷板](#cold-plate)、[冷却液分配单元（CDU）](#cdu)、[液冷](#liquid-cooling)。
- <a id="direct3d"></a>**Direct3D** — 微软面向 Windows 的 3D 图形编程接口（DirectX 的组成部分）；它以三角形为标准图元，使围绕其他图元设计的芯片无法兼容大多数游戏。*另见：* [固定功能管线](#fixed-function-pipeline)。
- <a id="disaggregated-serving"></a>**Disaggregated serving（分离式推理服务）** — 将 LLM 推理的预填充（prefill，读取提示词）和解码（decode，生成 token）两个阶段放在不同的 GPU 池上运行，并在二者之间传送 KV 缓存；由英伟达 Dynamo 负责编排。*另见：* [KV 缓存](#kv-cache)。
- <a id="dispatch-and-combine"></a>**Dispatch and combine（分发与合并）** — 每个混合专家层的两个通信步骤：分发（dispatch）将每个 token 的激活值发送到持有其所选专家的 GPU；合并（combine）将专家输出发回并求和。二者共同构成一次全交换。*另见：* [混合专家模型（MoE）](#mixture-of-experts)、[全交换](#all-to-all)、[专家并行（EP）](#expert-parallelism)。
- <a id="doca"></a>**DOCA** — 英伟达面向 BlueField DPU 和 SuperNIC 的软件开发工具包和运行时，是 DPU 领域与 CUDA 相对应的平台。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="domestic-substitution"></a>**Domestic substitution（国产替代）** — 中国以本土芯片替代外国芯片的政策，例如引导国资背景的数据中心采用国产 AI 加速器。*另见：* [出口管制](#export-controls)、[华为昇腾](#huawei-ascend)。
- <a id="dominant-resource-fairness"></a>**Dominant resource fairness（主导资源公平）** — 适用于拥有多种资源（GPU、CPU、内存）集群的公平分配规则：每个团队的份额按其使用最多的那种资源来衡量，因此任何团队都无法通过囤积某一种资源来挤占其他团队。*另见：* [抢占](#preemption)。
- <a id="double-ordering"></a>**Double ordering（重复下单）** — 短缺期间，买家为确保拿到配额而向多家供应商下同样的订单，或超出实际需要下单；供应跟上后多余订单随即消失，因而可能让需求显得比实际更强。*另见：* [供给受限](#supply-constrained)。
- <a id="dpu"></a>**DPU (data processing unit)（数据处理器）** — 自带处理器核心和加速器的网卡，负责运行网络、存储和安全软件，从而为服务器的主 CPU 免去这些负担。*另见：* [SuperNIC](#supernic)、[SmartNIC](#smartnic)、[IPU（基础设施处理器）](#ipu)。
- <a id="dram"></a>**DRAM (dynamic random-access memory)（动态随机存取存储器）** — 计算机的主流内存技术：每个比特以电荷形式存储在一个微小电容中，每秒须刷新多次。HBM、DDR、LPDDR 和 GDDR 都是 DRAM，只是封装和连接方式不同。*另见：* [高带宽内存（HBM）](#hbm)、[LPDDR](#lpddr)、[GDDR](#gddr)。
- <a id="dsl"></a>**DSL (domain-specific language)（领域专用语言）** — 为单一任务设计的小型编程语言。CuTe DSL、Triton 和 Mojo 都是无需完整 C++ 即可编写 GPU 内核的 DSL。*另见：* [CuTe](#cute)、[Triton (OpenAI)](#triton)。
- <a id="dsx-os"></a>**DSX OS** — 英伟达于 2026 年推出的开放、模块化软件组合，用于运营多租户 AI 工厂，集成了 KAI Scheduler、Run:ai、Cloud Functions、Grove 和 Dynamo 等组件。*另见：* [NVIDIA Mission Control](#mission-control)、[Run:ai](#run-ai)。
- <a id="dualpipe"></a>**DualPipe** — DeepSeek 的流水线并行调度方案，将不同微批次的前向和反向计算与专家并行的全交换通信相互重叠，在带宽受限的 H800 集群上隐藏了大部分网络时间。*另见：* [流水线并行（PP）](#pipeline-parallelism)、[专家并行（EP）](#expert-parallelism)、[全交换](#all-to-all)。
- <a id="duv-multipatterning"></a>**DUV multi-patterning（DUV 多重曝光）** — 通过对同一层进行多次曝光，印制出深紫外（DUV）光刻机单次曝光无法分辨的精细图形。这使中芯国际（SMIC）能在没有 EUV 的情况下制造 7 nm 级芯片，但良率更低、成本更高。*另见：* [EUV 光刻](#euv-lithography)、[光刻](#lithography)。
- <a id="dynamo"></a>**Dynamo** — 英伟达开源（Apache 2.0）、位于推理服务引擎之上的软件层，可把一个模型分布到大量 GPU 上运行：它将预填充与解码分离，把请求路由到已持有相应 KV 缓存的 GPU，并把缓存卸载到更便宜的存储层。1.0 版于 2026 年 3 月发布。*另见：* [分离式推理服务](#disaggregated-serving)、[KV 缓存](#kv-cache)。
## E

- <a id="earn-out"></a>**Earn-out（业绩对赌付款）** — 收购价款中延后支付的部分，仅在被收购业务达成约定里程碑（如收入目标）时才支付。用于弥合买卖双方的估值分歧，例如美满电子收购 Celestial AI 时即采用此安排。*另见：* [收购式招聘](#acquihire)。
- <a id="earth-2"></a>**Earth-2** — 英伟达面向 AI 天气与气候模型以及地球数字孪生的平台；Earth2Studio 是其开源 Python 软件包。*另见：* [Omniverse](#omniverse)。
- <a id="east-west-traffic"></a>**East-west traffic（东西向流量）** — 数据中心内部服务器之间的流量（例如 GPU 之间的梯度交换），与进出数据中心的流量相对。AI 训练以东西向流量为主。*另见：* [南北向流量](#north-south-traffic)、[后端网络](#back-end-network)。
- <a id="ecmp"></a>**ECMP (equal-cost multipath)（等价多路径）** — 以太网的标准负载均衡方式，把每条流哈希到若干条等长路径之一。大型 AI 流可能挤在同一条路径上，而其他路径闲置，造成带宽浪费。*另见：* [自适应路由](#adaptive-routing)、[数据包喷洒](#packet-spraying)。
- <a id="ecn"></a>**ECN (Explicit Congestion Notification)（显式拥塞通知）** — 交换机在队列开始积压时在数据包中置位的一个比特。接收端将其回传，发送端随即降速，从而在不暂停链路的情况下避免丢包。*另见：* [拥塞控制](#congestion-control)。
- <a id="economic-life"></a>**Economic life（经济寿命）** — 硬件创造的收入持续高于其现金运营成本的时长。当新一代芯片使 token 成本大幅下降时，经济寿命可能短于会计上的使用寿命，这正是 GPU 折旧看空情景的核心论点。*另见：* [使用寿命](#useful-life)、[残值](#residual-value)、[一年一代节奏](#annual-cadence)。
- <a id="eda"></a>**EDA (electronic design automation)（电子设计自动化）** — 用于设计和验证芯片的软件，涵盖从逻辑综合到物理版图和签核的全流程；新思科技（Synopsys）和楷登电子（Cadence）占据主导地位。每个新芯片项目都要支付 EDA 授权费，英伟达持有新思科技 $2B 的股份。*另见：* [流片](#tape-out)、[NRE（一次性工程费用）](#nre)。
- <a id="edge-to-cloud-continuity"></a>**Edge-to-cloud continuity（端云一体）** — 在终端设备、边缘服务器和云端机架上运行同一模型家族、文件格式和工具链，使工作负载能在各层级之间迁移而无需重写。这是在每个层级都拥有芯片的厂商的卖点。*另见：* [混合 AI](#hybrid-ai)、[NPU（神经网络处理器）](#npu)。
- <a id="efa"></a>**EFA (Elastic Fabric Adapter)** — AWS 面向 HPC 和 AI 实例的网络接口，基于 Nitro 卡和 SRD 传输协议构建，而非 InfiniBand 或标准 RoCE。*另见：* [SRD](#srd)、[AWS Nitro](#aws-nitro)、[数据包喷洒](#packet-spraying)。
- <a id="effective-training-time"></a>**Effective training time（有效训练时间）** — 训练运行的挂钟时间中，扣除故障、重启以及从上一个检查点起重算所损失的时间之后，真正用于推进训练的时间占比。Meta 报告 Llama 3 的这一比例超过 90%。*另见：* [有效吞吐量](#goodput)、[检查点](#checkpoint)。
- <a id="efficiency-shock"></a>**Efficiency shock（效率冲击）** — 新的模型架构、训练方法或软件导致单位 AI 产出所需算力（进而成本）骤降。它最终是减少还是增加总算力支出，取决于需求的价格弹性。*另见：* [杰文斯悖论](#jevons-paradox)、[需求价格弹性](#price-elasticity)。
- <a id="emib"></a>**EMIB / EMIB-T** — 英特尔的嵌入式多芯片互连桥（Embedded Multi-die Interconnect Bridge）：嵌入封装基板、用于连接裸片与内存的小型硅桥，作为台积电 CoWoS 的替代方案提供；EMIB-T 增加了面向 HBM 的硅通孔（TSV）。*另见：* [CoWoS](#cowos)、[先进封装](#advanced-packaging)。
- <a id="ems"></a>**EMS (electronics manufacturing services)（电子制造服务）** — 按照其他公司的设计制造电子产品的代工厂商（例如 Sanmina、天弘（Celestica）、富士康）。在 AI 服务器领域，EMS 厂商和 ODM 以微薄的利润承担机架的组装和测试。*另见：* [ODM](#odm)、[OEM](#oem)。
- <a id="engineer-year"></a>**Engineer-year（工程师人年）** — 一名工程师工作一年；衡量软件工作量的标准单位。用工程师人年乘以每名工程师的全口径成本，即可得出以美元计的估算。*另见：* [软件移植版](#software-port)。
- <a id="entity-list"></a>**Entity List（实体清单）** — 美国商务部发布的外国企业名单，名单上的企业须获许可才能获得原产于美国的技术。华为、中芯国际和多家中国 GPU 设计公司均在其列。*另见：* [出口管制](#export-controls)、[BIS（工业与安全局）](#bis)。
- <a id="equity-for-capacity"></a>**Equity-for-capacity（股权换产能）** — 将股权与采购承诺绑定的交易：要么由供应商向客户授予股权（AMD 向 OpenAI 发行的认股权证），要么由供应商购买客户的股权（英伟达对 OpenAI 的投资），使供需双方共享扩建带来的上行收益。*另见：* [认股权证](#warrant)、[供应商融资](#vendor-financing)、[循环融资](#circular-financing)。
- <a id="esun"></a>**ESUN (Ethernet for Scale-Up Networking)** — 开放计算项目（OCP）于 2025 年启动的工作组，定义如何通过以太网交换机承载纵向扩展（scale-up）流量，包括采用精简报头以降低开销。它以博通贡献的 Scale-Up Ethernet 规范为基础。*另见：* [Scale-Up Ethernet（SUE）](#scale-up-ethernet)、[UALink (Ultra Accelerator Link)](#ualink)、[超以太网（UEC）](#ultra-ethernet)。
- <a id="etl"></a>**ETL (extract, transform, load)（抽取、转换、加载）** — 数据准备工作：从各数据源提取原始数据、进行清洗和关联，再加载到数据仓库或训练集中；往往是企业最大的一笔数据分析开支。*另见：* [Apache Spark](#apache-spark)、[数据框](#dataframe)。
- <a id="euv-lithography"></a>**EUV lithography（EUV 光刻）** — 极紫外光刻：使用 13.5 nm 波长的光进行曝光，使最精细的层能一次曝光完成，而不必多次曝光。EUV 光刻机仅由 ASML 制造；高数值孔径（High-NA）EUV 是下一代技术，其曝光视场仅为现有的一半。*另见：* [光刻](#lithography)、[高数值孔径 EUV](#high-na-euv)。
- <a id="expert-parallelism"></a>**Expert parallelism (EP)（专家并行）** — 将混合专家模型的不同专家放在不同 GPU 上，因此在每个 MoE 层，token 都须通过全交换发送至所选专家并返回。*另见：* [混合专家模型（MoE）](#mixture-of-experts)、[全交换](#all-to-all)。
- <a id="export-controls"></a>**Export controls（出口管制）** — 政府要求向境外销售特定技术须取得许可证的规定。美国关于先进 GPU 的规定决定了哪些国家和买家能获得英伟达的顶级芯片，以及数量多少。*另见：* [主权 AI](#sovereign-ai)。
- <a id="export-revenue-share"></a>**Export revenue share（出口收入分成）** — 一种许可条件，出口商须将部分销售收入上缴美国政府：H20 对华销售为 15%（2025 年 8 月），H200 对华销售为 25%（2025 年 12 月）。*另见：* [出口管制](#export-controls)。
- <a id="external-laser-source"></a>**External laser source（外置激光光源）** — 在 CPO 设计中，激光器位于前面板上独立、可更换的模块内，通过光纤向光引擎供光；因为激光器是最容易失效的部件，而且不耐交换芯片旁边的高温。*另见：* [共封装光学（CPO）](#co-packaged-optics)。
## F

- <a id="fabless"></a>**fabless（无晶圆厂）** — 自行设计半导体、但付费委托台积电等晶圆代工厂制造的芯片公司；英伟达自成立以来一直采用无晶圆厂模式。*另见：* [晶圆代工厂](#foundry)。
- <a id="facility-capex"></a>**Facility capex（设施资本开支）** — IT 设备之外的建筑、电力设施、冷却系统和土地支出，通常按每兆瓦电力计（据本资料库估计，新建 AI 机房约为每兆瓦 $11-13M）。其使用寿命长于内部的服务器。*另见：* [AI 工厂](#ai-factory)、[PUE（电能使用效率）](#pue)、[通电时间](#time-to-power)。
- <a id="falcon-transport"></a>**Falcon (transport)（Falcon 传输协议）** — 谷歌面向数据中心以太网的硬件辅助网络传输协议，于 2023 年贡献给开放计算项目（OCP）；英特尔 IPU E2000 是其首个硬件平台。*另见：* [IPU（基础设施处理器）](#ipu)。
- <a id="fat-tree"></a>**Fat tree (Clos network)（胖树）** — 一种多层交换拓扑，越往上层链路越“胖”，使任意端点之间都能全速通信。使用端口数（radix）为 R 的交换机时，两层可连接 R²/2 个端点，三层可连接 R³/4 个。*另见：* [交换机端口数](#switch-radix)、[对分带宽](#bisection-bandwidth)、[超额订阅](#oversubscription)。
- <a id="fatbinary"></a>**Fatbinary（胖二进制）** — CUDA 应用程序随附的二进制包：包含针对构建时所面向的每一代 GPU 的 SASS 机器码，外加 PTX——新版驱动可将 PTX 编译到构建时尚不存在的 GPU 上。*另见：* [PTX (Parallel Thread Execution)](#ptx)、[JIT 编译](#jit-compilation)。
- <a id="feynman"></a>**Feynman** — 英伟达计划于 2028 年推出的 GPU 架构，发布时展示的配套组件包括 Rosa CPU、LP40 解码芯片、BlueField-5、ConnectX-10，以及混用铜缆与共封装光学的 Kyber NVL1152 机架；规格尚未公布。*另见：* [Rubin Ultra](#rubin-ultra)、[共封装光学（CPO）](#co-packaged-optics)。
- <a id="fixed-function-pipeline"></a>**fixed-function pipeline（固定功能管线）** — 早期图形芯片的设计方式：每个渲染阶段都是只有少量可调设置的硬连线电路，而不是运行程序的处理器。*另见：* [可编程着色器](#programmable-shader)。
- <a id="flashattention"></a>**FlashAttention** — 一系列注意力内核（从 2022 年的 v1 到 2026 年的 v4），在片上存储中分块计算注意力，而不把完整的注意力矩阵写入 HBM。每个版本都最先为英伟达 GPU 编写。*另见：* [注意力机制](#attention)、[GPU 内核](#gpu-kernel)。
- <a id="flops"></a>**FLOPS（每秒浮点运算次数）** — Floating-point operations per second（每秒浮点运算次数）：芯片执行算术运算的速率。引用时须注明数值格式（FP64、BF16、FP8、FP4）以及是稠密还是稀疏峰值；1 PFLOPS = 每秒 10^15 次运算。“FLOPs”（小写 s）表示运算次数，而非速率。*另见：* [张量核心](#tensor-core)。
- <a id="flywheel"></a>**Flywheel（飞轮）** — 一组相互强化的循环，每转一圈都让下一圈更容易，从而随时间积累动能。本资料库中，英伟达的飞轮包含四个循环（开发者、规模/研发、全栈、资本），它们共用一个中枢：收入与毛利。*另见：* [装机量](#installed-base)、[循环融资](#circular-financing)。
- <a id="forward-pe"></a>**Forward P/E（远期市盈率）** — 股价除以未来十二个月或下一财年的预期每股收益（等同于市值除以预期净利润）。*另见：* [反向 DCF](#reverse-dcf)。
- <a id="forward-pass"></a>**Forward pass（前向传播）** — 将输入依次通过模型的每一层以产生预测。成本约为每个参数每个 token 2 次浮点运算。*另见：* [反向传播](#backward-pass)、[激活值](#activation)。
- <a id="foundry"></a>**Foundry（晶圆代工厂）** — 制造他人所设计芯片的公司（台积电、三星代工、英特尔代工、中芯国际）。英伟达、AMD、谷歌和高通均为“无晶圆厂”企业：它们设计芯片，并向晶圆代工厂采购晶圆。*另见：* [晶圆](#wafer)、[OSAT（外包封测）](#osat)。
- <a id="foveros"></a>**Foveros** — 英特尔的 3D 封装技术，将逻辑裸片面对面堆叠。与 EMIB 一起作为台积电封装的替代方案，面向多裸片 AI 芯片提供。*另见：* [EMIB / EMIB-T](#emib)、[先进封装](#advanced-packaging)、[混合键合](#hybrid-bonding)。
- <a id="fp16"></a>**FP16 (half precision)（半精度）** — 一种 16 位浮点格式，含 5 位指数和 10 位尾数。其精度高于 BF16，但数值范围窄得多，因此以 FP16 训练需要损失缩放（loss scaling）；它已基本被 BF16 取代。*另见：* [BF16 (bfloat16)](#bf16)、[FP8](#fp8)、[混合精度训练](#mixed-precision)。
- <a id="fp32"></a>**FP32 (single precision)（单精度）** — 32 位浮点格式（8 位指数，23 位尾数）。AI 训练将主权重和许多累加运算保留为 FP32，而大部分矩阵运算以更低精度完成。*另见：* [BF16 (bfloat16)](#bf16)、[混合精度训练](#mixed-precision)、[FLOPS](#flops)。
- <a id="fp4"></a>**FP4** — 一种 4 位浮点格式（1 位符号、2 位指数、1 位尾数），只能表示从 0 到 6 的八个量级；必须搭配 MXFP4 或 NVFP4 等块缩放因子才能使用。*另见：* [NVFP4](#nvfp4)、[微缩放（MX）格式](#microscaling)。
- <a id="fp8"></a>**FP8** — 一种 8 位（1 字节）浮点格式，自 Hopper 起获得张量核心支持。与 BF16 相比，它使内存占用减半、张量吞吐量约翻倍，但需谨慎处理以保持精度。*另见：* [BF16 (bfloat16)](#bf16)、[NVFP4](#nvfp4)。
- <a id="fractional-gpu"></a>**Fractional GPU（GPU 切分）** — 通过硬件分区（MIG）、空间共享（MPS）或时间片轮转，为作业分配不足一整块的 GPU。它能提高 notebook、轻量推理等小型作业的利用率，代价是隔离性有所削弱。*另见：* [MIG（多实例 GPU）](#mig)、[GPU 时间片轮转](#gpu-time-slicing)。
- <a id="free-cash-flow"></a>**Free cash flow（自由现金流）** — 经营现金流减去资本开支：公司产生的、可用于回报股东、进行收购或投资其他公司的现金。
- <a id="free-chip-test"></a>**Free-chip test（免费芯片测试）** — 一个思想实验：即便竞争对手的加速器系统完全免费，其每 token 成本是否仍高于按全价购买的英伟达系统？只有当吞吐量差距大于芯片资本开支在总成本中的占比时，这一结论才成立。*另见：* [每百万 token 成本](#cost-per-million-tokens)、[自有 TCO](#owner-tco)。
- <a id="front-end-network"></a>**Front-end network（前端网络）** — 连接服务器与存储、用户、管理系统和互联网的传统数据中心网络。*另见：* [后端网络](#back-end-network)。
- <a id="frontier-lab"></a>**Frontier lab（前沿实验室）** — 训练规模最大的通用 AI 模型的公司（例如 OpenAI、Anthropic、xAI、谷歌 DeepMind）；每家都以吉瓦级规模采购算力。
- <a id="fsdp"></a>**FSDP (Fully Sharded Data Parallel)（完全分片数据并行）** — PyTorch 内置的完全分片数据并行实现（ZeRO 第 3 阶段风格）：权重在使用前即时全收集，梯度在计算后进行规约散射。*另见：* [ZeRO（零冗余优化器）](#zero)、[全收集](#all-gather)、[规约散射](#reduce-scatter)。
- <a id="full-stack-merchant"></a>**Full-stack merchant（全栈商用供应商）** — 向任何买家出售完整 AI 系统（芯片、互连、机架和软件）的厂商。英伟达是典型代表；AMD 正借助 Helios 和 ROCm 朝这一方向发展。*另见：* [商用芯片](#merchant-silicon)、[垂直整合](#vertical-integration)。
- <a id="fma"></a>**Fused multiply-add (FMA)（融合乘加）** — 一步完成 a × b + c 计算的单条运算，计为两次浮点运算。矩阵乘法几乎完全由 FMA 构成。*另见：* [FLOPS](#flops)、[GEMM](#gemm)。
## G

- <a id="gang-scheduling"></a>**Gang scheduling（成组调度）** — 让分布式作业的所有部分同时启动、否则一个都不启动，避免 1,000 块 GPU 闲置等待第 1,001 块。Slurm、Kueue 和 KAI Scheduler 等调度器均支持此功能。*另见：* [Slurm](#slurm)、[Kubernetes](#kubernetes)。
- <a id="gap-trend"></a>**Gap trend（差距趋势）** — 在某一层中，英伟达相对最强挑战者的领先优势在过去约十二个月内是在扩大、持平还是收窄，以该层竞争页面的判断为准。*另见：* [护城河评分](#moat-score)。
- <a id="gate-all-around"></a>**Gate-all-around (GAA)（全环绕栅极）** — 一种晶体管结构，栅极从四面包围堆叠的硅纳米片，与较早的 FinFET 相比可降低漏电。台积电 N2 是其首个 GAA 节点。*另见：* [工艺节点](#process-node)。
- <a id="gddr"></a>**GDDR (graphics DRAM)（图形 DRAM）** — 焊接在电路板上、环绕处理器分布的图形内存芯片。比 HBM 更便宜、更简单，但每瓦和每平方毫米的带宽要低得多；英伟达的数据中心 GPU 在 P100 之前一直采用它。*另见：* [高带宽内存（HBM）](#hbm)、[LPDDR](#lpddr)。
- <a id="gemm"></a>**GEMM (general matrix multiply)（通用矩阵乘法）** — 占神经网络绝大部分算术运算的矩阵乘法操作。大型 GEMM 具有很高的算术强度，可接近 GPU 的峰值 FLOPS 运行。*另见：* [张量核心](#tensor-core)、[算术强度](#arithmetic-intensity)。
- <a id="gigawatt-of-compute"></a>**Gigawatt of compute（吉瓦算力）** — 如今衡量 AI 基础设施交易规模的单位：加速器、服务器和网络设备所消耗的电力（1 GW ≈ 数十万块当前一代 GPU）。买家以电力作为承诺单位，因为真正的约束是电力和场地，而非芯片。*另见：* [AI 工厂](#ai-factory)、[签约电力与在用电力](#contracted-power)。
- <a id="gsi"></a>**Global systems integrator (GSI)（全球系统集成商）** — 为企业设计、建设和运营技术项目的大型 IT 服务公司（例如埃森哲（Accenture））。客户部署哪些硬件和软件，很大程度上由 GSI 决定。*另见：* [OEM](#oem)、[渠道合作伙伴](#channel-partner)。
- <a id="gloo"></a>**Gloo** — Meta 开源的集合通信库，是 PyTorch 的一个后端，主要用于 CPU 张量，并在 NCCL 不可用时充当备选。*另见：* [NCCL](#nccl)。
- <a id="goodput"></a>**Goodput（有效吞吐量）** — 系统扣除各类损失后的有效产出：在训练中，指真正推进模型训练的 GPU 小时占比；在推理服务中，指仍能满足延迟目标的吞吐量。*另见：* [MFU（模型 FLOPs 利用率）](#mfu)、[检查点](#checkpoint)。
- <a id="gpgpu"></a>**GPGPU (general-purpose GPU computing)（通用 GPU 计算）** — 将图形芯片用于物理、金融或神经网络等非图形计算。在 CUDA 出现之前，这意味着要把计算伪装成像素着色任务。*另见：* [CUDA](#cuda)、[Brook](#brook)。
- <a id="gpu"></a>**GPU (graphics processing unit)（图形处理器）** — 拥有数千个简单核心、可同时对大量数据执行同一条指令的处理器，非常适合神经网络核心的矩阵乘法。在本资料库中，“GPU”通常指客户购买的整个封装（例如一块 B200），其中可能包含不止一颗裸片。*另见：* [裸片](#die)、[张量核心](#tensor-core)。
- <a id="gpu-fragmentation"></a>**GPU fragmentation（GPU 碎片化）** — 空闲 GPU 零散分布在许多服务器或机架上，每处的数量都太少，无法容纳下一个作业。集群看似部分空闲，大型作业却无法启动。*另见：* [装箱式调度](#bin-packing)、[拓扑感知调度](#topology-aware-scheduling)。
- <a id="gpu-kernel"></a>**GPU kernel（GPU 内核）** — 在数千个 GPU 线程上同时运行的小型函数，例如一次矩阵乘法或一个注意力步骤。框架把数千个内核串联成一个模型；内核的速度决定了模型的运行速度。*另见：* [CUDA](#cuda)、[cuDNN](#cudnn)。
- <a id="gpu-marketplace"></a>**GPU marketplace（GPU 交易平台）** — 汇集众多供应商的 GPU 容量、供买家按小时或按周租用的平台（例如 Vast.ai、SF Compute 或英伟达的 Lepton）。它们以价格和灵活性而非服务取胜。*另见：* [DGX Cloud Lepton](#dgx-cloud-lepton)、[新兴云服务商（neocloud）](#neocloud)。
- <a id="gpu-starvation"></a>**GPU starvation（GPU 饥饿）** — 由于主机无法足够快地供给数据、启动内核或返回工具调用结果，GPU 处于闲置状态；表现为 GPU 利用率偏低，尽管 GPU 本身并非瓶颈。*另见：* [数据加载器](#data-loader)、[主机 CPU](#host-cpu)。
- <a id="gpu-time-slicing"></a>**GPU time-slicing（GPU 时间片轮转）** — 让多个工作负载轮流使用同一块 GPU。成本低、灵活，但没有内存或故障隔离：一个工作负载崩溃，共享该 GPU 的所有工作负载都会随之宕掉。*另见：* [GPU 切分](#fractional-gpu)、[MIG（多实例 GPU）](#mig)。
- <a id="gpu-backed-loan"></a>**GPU-backed loan（GPU 抵押贷款）** — 以 GPU 集群及将其对外出租的客户合同作抵押的债务，通常随硬件交付分批提款（延迟提款定期贷款）。贷方的风险取决于合同质量和 GPU 的转售价值。*另见：* [照付不议合同](#take-or-pay)、[新兴云服务商（neocloud）](#neocloud)。
- <a id="gpu-hour"></a>**GPU-hour（GPU 小时）** — 一块 GPU 使用（或租用）一小时：GPU 云为容量定价、以及衡量利用率经济性所用的单位。*另见：* [总拥有成本（TCO）](#tco)。
- <a id="gpu-initiated-networking"></a>**GPU-initiated networking（GPU 发起的网络通信）** — 让 GPU 内核自行发起网络传输，而不必等待 CPU 代劳；NCCL 2.28 加入了这一功能（GIN），以降低 MoE 和推理流量的延迟。*另见：* [NCCL](#nccl)、[RDMA（远程直接内存访问）](#rdma)。
- <a id="gpudirect-rdma"></a>**GPUDirect RDMA** — 英伟达的一项功能，使网卡能直接读写 GPU 显存，省去经由 CPU 内存的一次复制。*另见：* [RDMA（远程直接内存访问）](#rdma)。
- <a id="gpudirect-storage"></a>**GPUDirect Storage** — 英伟达的一项技术，在存储（本地 NVMe 或经网络访问的存储）与 GPU 显存之间直接传输数据，绕过经由 CPU 内存的一次复制。*另见：* [RDMA（远程直接内存访问）](#rdma)。
- <a id="gradient"></a>**Gradient（梯度）** — 对每个参数而言，能够降低损失的调整方向和幅度。每个训练步骤都要对所有 GPU 的梯度求平均。*另见：* [反向传播](#backward-pass)、[全规约](#all-reduce)。
- <a id="gpc"></a>**Graphics processing cluster (GPC)（图形处理簇）** — 共享部分调度和路由硬件的一组 SM。Rubin 有 8 个 GPC，共含 224 个 SM；Hopper 的 H100 在其各 GPC 中共启用 132 个 SM。*另见：* [流式多处理器（SM）](#streaming-multiprocessor)。
- <a id="graviton"></a>**Graviton** — AWS 自研的 Arm 服务器 CPU 产品线（由 Annapurna Labs 设计），2018 年首发；Graviton5（2026 年）拥有 192 个核心。*另见：* [Annapurna Labs](#annapurna-labs)、[Neoverse](#neoverse)。
- <a id="cuda-grid"></a>**Grid (CUDA)（CUDA 网格）** — 一次内核启动所创建的全部线程块。硬件在 SM 空闲时将线程块分派给它们，这使同一份代码能在不同规模的 GPU 上扩展。*另见：* [线程块](#thread-block)、[GPU 内核](#gpu-kernel)。
- <a id="gross-margin"></a>**Gross margin（毛利率）** — 收入减去销售成本后占收入的比例。2026 年年中英伟达的 GAAP 毛利率约为 75%；据估计，单看 GPU 芯片本身的毛利率接近 80%。*另见：* [物料清单](#bill-of-materials)。
- <a id="grouped-query-attention"></a>**Grouped-query attention (GQA)（分组查询注意力）** — 一种注意力设计：多个查询头共享一个键/值头，在质量损失很小的情况下缩小 KV 缓存（Llama 3.1 70B 缩小 8 倍）。*另见：* [KV 缓存](#kv-cache)、[多头潜在注意力（MLA）](#multi-head-latent-attention)。
- <a id="grove"></a>**Grove** — 英伟达 Dynamo 项目中的开源 Kubernetes API，把由多个组件构成的整个推理系统描述为一个资源，并以分层成组调度和拓扑感知放置对其进行调度。*另见：* [Dynamo](#dynamo)、[成组调度](#gang-scheduling)。
- <a id="gtc"></a>**GTC** — 英伟达 GPU 技术大会（GPU Technology Conference）。每年春季在圣何塞举办的大会（2009 年首届）是英伟达发布路线图主题演讲和合作伙伴新品的主要窗口；年内还在其他地区举办区域性大会。*另见：* [开发者关系](#developer-relations)。
## H

- <a id="h20"></a>**H20** — 面向中国市场的 Hopper GPU（2024 年），算力远低于 H100，但 HBM 容量不减，旨在符合 2023 年 10 月的出口规则；2025 年 4 月起被纳入美国出口许可证管理。*另见：* [出口管制](#export-controls)、[H800](#h800)。
- <a id="h800"></a>**H800** — 面向中国市场的英伟达 H100 版本（2023 年），算力相同但 NVLink 带宽被削减，旨在符合 2022 年 10 月的美国出口规则；自 2023 年 11 月起其本身也受到限制。DeepSeek-V3 即使用 2,048 块 H800 训练而成。*另见：* [出口管制](#export-controls)、[H20](#h20)、[NVLink](#nvlink)。
- <a id="hardware-plugin"></a>**Hardware plugin（硬件插件）** — 单独维护的后端，使 vLLM 等推理服务引擎无需修改核心代码即可在新加速器上运行。*另见：* [vLLM](#vllm)。
- <a id="pull-through"></a>**Hardware pull-through（硬件拉动）** — 间接变现免费软件：免费提供软件，以促使客户购买更多在其上运行效果最佳的硬件。CUDA 是英伟达最主要的例子。*另见：* [CUDA](#cuda)、[转换成本](#switching-cost)。
- <a id="root-of-trust"></a>**Hardware root of trust（硬件信任根）** — 芯片上一个小型、不可篡改的安全模块，保存身份密钥并在启动时验证固件；信任链中的其他一切都以它为基准进行校验。*另见：* [远程证明](#attestation)。
- <a id="hbm"></a>**HBM (high-bandwidth memory)（高带宽内存）** — 堆叠式 DRAM，经由硅中介层放置在距 GPU 仅数毫米处，并以极宽的总线连接，提供每秒数 TB 的带宽。HBM 的容量和带宽往往比原始算力更能制约 AI 性能。*另见：* [CoWoS](#cowos)、[内存墙](#memory-wall)。
- <a id="hbm-base-die"></a>**HBM base die（HBM 基础裸片）** — HBM 堆栈最底层的逻辑裸片，负责与 GPU 通信并管理其上方的 DRAM 层。从 HBM4 起可采用逻辑工艺制造（例如台积电 N3P 或 N12），让买家可以对其进行定制。*另见：* [高带宽内存（HBM）](#hbm)、[HBM4E](#hbm4e)、[近存计算](#near-memory-compute)。
- <a id="hbm-qualification"></a>**HBM qualification（HBM 认证）** — GPU 厂商在批量采购前，在自家封装内测试供应商 HBM 堆栈的速度、发热、功耗和良率，整个过程往往历时数月。认证失败可能使供应商错过整整一代产品。*另见：* [高带宽内存（HBM）](#hbm)、[产能分配](#capacity-allocation)。
- <a id="hbm3e"></a>**HBM3E** — 高带宽内存的第五代扩展版本，在 1,024 位接口上引脚速率约 8–10 Gb/s（每个堆栈约 1–1.2 TB/s），堆栈最高 12 层裸片（36 GB）。Blackwell 和 Blackwell Ultra GPU 采用的就是这种内存。*另见：* [高带宽内存（HBM）](#hbm)、[HBM4](#hbm4)、[HBM4E](#hbm4e)。
- <a id="hbm4"></a>**HBM4** — 第六代高带宽内存（JEDEC 标准于 2025 年发布），将每个堆栈的接口加倍至 2,048 位，并使基础裸片转向逻辑工艺。英伟达 Rubin 和 AMD MI455X 采用的就是这种内存。*另见：* [高带宽内存（HBM）](#hbm)、[HBM4E](#hbm4e)、[HBM 基础裸片](#hbm-base-die)。
- <a id="hbm4e"></a>**HBM4E** — HBM4 的增强版本，预计自 2027 年起量产，引脚速率更快（目标最高约 12.8 Gb/s），堆栈最高 16 层、容量约 48-64 GB，基础裸片也越来越多地按客户定制。*另见：* [高带宽内存（HBM）](#hbm)、[HBM 基础裸片](#hbm-base-die)、[引脚速率](#pin-speed)。
- <a id="heat-flux"></a>**Heat flux（热通量）** — 单位面积表面散出的热量，此处指每平方厘米芯片的瓦数。热通量越高，就越需要单位体积载热量更大的冷却剂：每升水的载热量约为空气的 3,500 倍。*另见：* [直触芯片液冷](#direct-to-chip-cooling)。
- <a id="hgx"></a>**HGX** — 英伟达的标准 GPU 基板（通常为八块 GPU 加 NVLink 交换芯片），戴尔、HPE、超微（Supermicro）和联想等服务器厂商围绕它打造各自的服务器。HGX-1（2017 年）确立了这一模式。*另见：* [DGX](#dgx)、[MGX](#mgx)、[OEM](#oem)。
- <a id="high-bandwidth-compute"></a>**High Bandwidth Compute (HBC)（高带宽计算）** — 高通对其 2028 年 Dragonfly AI300 推理加速器内存架构的命名，高通称其内存带宽为 AI200 的 54 倍（厂商宣称）。*另见：* [近存计算](#near-memory-compute)。
- <a id="high-na-euv"></a>**High-NA EUV（高数值孔径 EUV）** — 下一代 EUV 光刻机，数值孔径更大（0.55），可实现更精细的图形。其变形（anamorphic）光学系统将最大曝光视场减半至约 429 mm²，从而推动大型芯片转向多裸片设计。*另见：* [EUV 光刻](#euv-lithography)、[光罩尺寸极限](#reticle-limit)。
- <a id="hip"></a>**HIP** — AMD 的 C++ GPU 编程接口，刻意设计成与 CUDA API 一一对应，使代码只需重命名调用即可移植。HIP 代码也可编译后在英伟达 GPU 上运行。*另见：* [ROCm](#rocm)、[HIPIFY](#hipify)。
- <a id="hipify"></a>**HIPIFY** — AMD 将 CUDA 源代码自动转换为 HIP 源代码的工具。它们能完成移植的大部分工作；手工调优的内核和内联 PTX 仍需人工处理。*另见：* [HIP](#hip)、[转译层](#translation-layer)。
- <a id="host-cpu"></a>**Host CPU（主机 CPU）** — 加速服务器中的通用处理器，负责启动系统、运行操作系统、调度任务，并在 GPU 与外部之间搬运数据。*另见：* [超级芯片](#superchip)、[NVLink-C2C](#nvlink-c2c)。
- <a id="hot-spare"></a>**Hot spare（热备件）** — 保持通电、处于空闲状态、随时可替换故障 GPU 或节点的备用设备，使训练作业得以继续。热备件提高了可靠性，但会降低利用率。*另见：* [MTBI（平均中断间隔时间）](#mtbi)。
- <a id="hpc"></a>**HPC (high-performance computing)（高性能计算）** — 在超级计算机上进行的科学与工程仿真（气象、物理、化学），传统上采用 64 位精度。它是英伟达数据中心 GPU 和 InfiniBand 的第一个市场。*另见：* [InfiniBand](#infiniband)、[FLOPS](#flops)。
- <a id="huawei-ascend"></a>**Huawei Ascend（华为昇腾）** — 华为的 AI 加速器系列（910B/910C、950PR/950DT、960、970），主要在中国销售，配套 CANN 软件栈和超节点（SuperPoD）机架级系统。*另见：* [CANN](#cann)。
- <a id="hugging-face"></a>**Hugging Face** — 全球最大的 AI 模型、数据集和演示共享公共平台，也是广泛使用的开源模型库的开发者。英伟达于 2026 年同意收购该公司（尚待监管审查）。*另见：* [Nemotron](#nemotron)。
- <a id="hybrid-ai"></a>**Hybrid AI（混合 AI）** — 将 AI 推理拆分到终端设备（手机、PC、汽车）和云端：小型或涉及隐私的请求在设备的 NPU 上运行，较大的请求交给数据中心加速器。*另见：* [端云一体](#edge-to-cloud-continuity)、[推理](#inference)。
- <a id="hybrid-bonding"></a>**Hybrid bonding（混合键合）** — 不使用焊料凸块，以铜对铜、氧化物对氧化物的方式直接接合两颗裸片。它能实现更致密、更薄、散热更好的堆叠，正被考虑用于 16 层 HBM4E 及后续产品。*另见：* [微凸块](#microbump)、[硅通孔（TSV）](#through-silicon-via)、[堆叠层数](#stack-height)。
- <a id="hyperscaler"></a>**Hyperscaler（超大规模云厂商）** — 规模最大的云运营商之一（AWS、微软 Azure、谷歌云、Meta、甲骨文），以数十万计的规模采购加速器，并越来越多地自研芯片。*另见：* [XPU（定制加速器）](#xpu)、[新兴云服务商（neocloud）](#neocloud)。
- <a id="hypervisor"></a>**Hypervisor（虚拟机管理程序）** — 将一台物理服务器划分为多台虚拟机的软件层；把它卸载到 DPU 或 Nitro 卡上，可释放主机 CPU 核心并强化隔离。*另见：* [AWS Nitro](#aws-nitro)、[数据处理器（DPU）](#dpu)。
## I

- <a id="io-die"></a>**I/O die（I/O 裸片）** — 多芯片封装中负责输入/输出（内存控制器、SerDes、芯片间互连）的独立裸片，使计算裸片可以采用最先进的工艺节点。设计合作伙伴可以只供应 I/O 裸片。*另见：* [芯粒](#chiplet)、[SerDes](#serdes)。
- <a id="ici"></a>**ICI (inter-chip interconnect)（芯片间互连）** — 谷歌 TPU 之间的互连链路。每颗芯片有四条或六条 ICI 链路连接相邻芯片，构成 2D 或 3D 环面（torus）拓扑；Ironwood 有六条链路，每条 200 GB/s（双向）。*另见：* [环面拓扑](#torus-topology)、[光路交换机（OCS）](#optical-circuit-switch)。
- <a id="immersion-cooling"></a>**Immersion cooling（浸没式冷却）** — 将整台服务器浸入不导电液体槽中（单相），或浸入会在芯片表面沸腾的液体中（两相）进行冷却。密度极高，但会改变硬件的维护和认证方式。*另见：* [直触芯片液冷](#direct-to-chip-cooling)、[液冷](#liquid-cooling)。
- <a id="in-network-computing"></a>**In-network computing（网内计算）** — 在网络交换机内部（而非端点上）完成简单计算，例如梯度求和。它减少了穿越网络的数据量，并释放 GPU 时间。*另见：* [SHARP (in-network reduction)](#sharp)。
- <a id="incast"></a>**Incast（多对一拥塞）** — 多个发送端在同一时刻向一个接收端发送数据，使接收端前方的交换机端口溢出。集合通信操作在设计上就会产生 incast，这正是 AI 网络需要拥塞控制的原因。*另见：* [拥塞控制](#congestion-control)、[PFC（基于优先级的流量控制）](#priority-flow-control)。
- <a id="inference"></a>**Inference（推理）** — 运行已训练好的模型以产生输出（回答、代码、图像）。与训练不同，推理是持续进行的、对延迟敏感，并按 token 计价。*另见：* [预填充（prefill）](#prefill)、[解码（decode）](#decode)。
- <a id="context-memory-storage"></a>**Inference context memory storage（推理上下文内存存储）** — 英伟达在 CES 2026 上推出的、基于 BlueField-4 的存储层，在推理节点之间保存并共享 KV 缓存块，使长对话可以重新加载，而不必重新计算。*另见：* [KV 缓存卸载](#kv-cache-offload)、[KV 缓存](#kv-cache)、[分离式推理服务](#disaggregated-serving)。
- <a id="inference-provider"></a>**Inference provider（推理服务商）** — 按 token 或按推理所用 GPU 时间出售模型输出的公司（例如 Together AI、Fireworks AI、Baseten、GroqCloud、Cerebras Cloud），通常基于租用或自有的 GPU。*另见：* [新兴云服务商（neocloud）](#neocloud)。
- <a id="inferencex"></a>**InferenceX** — SemiAnalysis 开源、持续重跑的推理基准测试，在英伟达、AMD 和谷歌的硬件上描绘单 GPU 吞吐量与交互速度及每百万 token 成本之间的关系。*另见：* [MLPerf](#mlperf)、[吞吐量-交互速度帕累托前沿](#pareto-frontier)。
- <a id="infiniband"></a>**InfiniBand** — 一种低延迟、无损的网络标准，用于横向扩展的 AI 集群；英伟达通过 2020 年收购 Mellanox 成为其主要供应商（Quantum 交换机、ConnectX 适配器）。*另见：* [横向扩展（scale-out）](#scale-out)、[Spectrum-X](#spectrum-x)。
- <a id="infinity-fabric"></a>**Infinity Fabric** — AMD 的一致性互连系列，用于其芯片内部，以及在 MI300/MI350 系列 GPU 之间（作为 xGMI 链路）构成无交换机的八 GPU 网状互连。AMD 的 72 GPU Helios 机架则改用基于以太网的 UALink 实现纵向扩展。*另见：* [UALoE](#ualoe)、[UALink (Ultra Accelerator Link)](#ualink)。
- <a id="infrastructure-tax"></a>**Infrastructure tax（基础设施税）** — 服务器 CPU 周期中耗费在服务商“管道”工作（虚拟交换、存储协议、加密、遥测、管理）而非客户工作上的比例。公开估计大多在 19-33% 之间；也称数据中心税。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="installed-base"></a>**Installed base（装机量）** — 某厂商已投入使用的产品数量。庞大的支持 CUDA 的 GPU 装机量（据英伟达称，到 2020 年已超过 10 亿块）使 CUDA 成为开发者和研究人员的默认目标平台。*另见：* [CUDA](#cuda)、[飞轮](#flywheel)。
- <a id="intel-18a"></a>**Intel 18A** — 英特尔 2025–26 年的工艺节点，采用全环绕栅极晶体管（RibbonFET）和背面供电（PowerVia）。它是英特尔代工业务对外推介的基础。*另见：* [全环绕栅极（GAA）](#gate-all-around)、[背面供电](#backside-power-delivery)、[晶圆代工厂](#foundry)。
- <a id="intel-tdx"></a>**Intel TDX** — 英特尔信任域扩展（Trust Domain Extensions）：英特尔面向 Xeon CPU 的机密虚拟机技术。TDX Connect 借助 TDISP 将其扩展到 PCIe 设备。*另见：* [可信执行环境（TEE）](#trusted-execution-environment)、[TDISP](#tdisp)。
- <a id="interactivity"></a>**Interactivity (tokens/s per user)（交互速度）** — 每个用户接收生成 token 的速度。同时服务更多用户会提高单 GPU 的 token 产出，但会降低交互速度，因此只有在相同交互速度下，吞吐量数据才具有可比性。*另见：* [吞吐量-交互速度帕累托前沿](#pareto-frontier)、[每兆瓦每秒 token 数](#tokens-per-megawatt)。
- <a id="interconnection-queue"></a>**Interconnection queue（并网排队）** — 等待电网运营方研究并批准接入输电网的项目队列。在美国，新增发电项目从提交申请到投运的等待时间中位数超过四年。*另见：* [通电时间](#time-to-power)、[表后发电](#behind-the-meter)。
- <a id="interposer"></a>**Interposer（中介层）** — 一层薄硅片（或嵌有硅桥的有机层），GPU 裸片和 HBM 堆栈并排置于其上，其间承载数以万计的细微连线。正是它让 HBM 实现每秒数 TB 的带宽。*另见：* [CoWoS](#cowos)、[先进封装](#advanced-packaging)。
- <a id="intrinsic-value"></a>**Intrinsic value（内在价值）** — 期权或认股权证若在今日行权所值的金额：股价减去行权价，再乘以股数（若股价低于行权价则为零）。不考虑时间价值。*另见：* [平价](#at-the-money)、[采购挂钩归属认股权证](#purchase-vested-warrant)。
- <a id="ip-royalty"></a>**IP royalty（IP 版税）** — 在前期授权费之外，按芯片向授权技术所有者支付的费用，通常为芯片售价的一定百分比或每颗固定金额。Arm 的大部分收入即来自这种方式。*另见：* [Arm 指令集](#arm-isa)、[计算子系统（CSS）](#compute-subsystem)。
- <a id="ipsec"></a>**IPsec** — 在 IP 层对网络流量进行加密和认证的标准。以数百 Gb/s 的速率用软件实现会消耗大量 CPU 核心；DPU 和网卡可在数据通路上直接加密。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="ipu"></a>**IPU (infrastructure processing unit)（基础设施处理器）** — 英特尔（及谷歌）对 DPU 的称呼：一种可编程网络设备，把云基础设施功能从主机 CPU 上卸载运行。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="ironwood"></a>**Ironwood** — 谷歌第七代 TPU（TPU v7，2025 年）：每颗芯片 4.6 PFLOPS 稠密 FP8 算力和 192 GB HBM3E，单个 pod 最多 9,216 颗芯片；是谷歌首款主要面向推理设计的 TPU。*另见：* [TPU](#tpu)、[ICI（芯片间互连）](#ici)。
- <a id="isa"></a>**ISA (instruction set architecture)（指令集架构）** — 处理器能理解的机器指令“词汇表”，例如 x86 或 Arm。为某一 ISA 编译的软件无法在另一 ISA 上原生运行，这就是 ISA 的选择会锁定生态的原因。*另见：* [x86](#x86)、[Arm 指令集](#arm-isa)、[RISC-V](#risc-v)。
- <a id="it-load"></a>**IT load（IT 负载）** — 服务器、存储和网络设备本身消耗的电力，不含散热和电能转换损耗。设施电力 = IT 负载 × PUE。*另见：* [PUE（电能使用效率）](#pue)。
## J

- <a id="jax"></a>**JAX** — 谷歌面向机器学习的数值计算库，经 XLA 编译。它可原生运行于 TPU 和英伟达 GPU，是前沿实验室在 TPU 上进行训练的主要方式。*另见：* [XLA](#xla)。
- <a id="jedec"></a>**JEDEC** — 半导体标准组织，制定 DDR、LPDDR、GDDR 和 HBM 等内存标准，使三星、SK 海力士和美光的芯片能够互通。*另见：* [高带宽内存（HBM）](#hbm)、[LPDDR](#lpddr)、[DRAM](#dram)。
- <a id="jevons-paradox"></a>**Jevons paradox（杰文斯悖论）** — 当某种东西的使用成本下降时，总消费量可能增长到使总支出反而上升；用于 AI 领域，即更便宜的 token 可能推高总算力需求。*另见：* [token 价格通缩](#token-price-deflation)。
- <a id="jit-compilation"></a>**JIT compilation（即时编译）** — Just-in-time compilation（即时编译）：在程序加载或运行时（而非提前）把代码转换为机器指令。CUDA 驱动会为新 GPU 即时编译 PTX；Triton 和 DeepGEMM 会针对实际使用的张量形状即时编译内核。*另见：* [PTX (Parallel Thread Execution)](#ptx)、[胖二进制](#fatbinary)。
- <a id="job-completion-time"></a>**Job completion time (JCT)（作业完成时间）** — 完成一个训练作业或训练步骤所需的挂钟时间。网络厂商喜欢引用 JCT 的改善，因为它同时反映了带宽和尾延迟的影响。*另见：* [尾延迟](#tail-latency)。
## K

- <a id="kai-scheduler"></a>**KAI Scheduler** — 源自 Run:ai、由英伟达于 2025 年开源（Apache 2.0）的 Kubernetes GPU 调度器；负责 GPU 共享、队列、公平性以及拓扑感知放置。*另见：* [Kubernetes](#kubernetes)、[Run:ai](#run-ai)。
- <a id="kernel-fusion"></a>**Kernel fusion（内核融合）** — 将多个小型 GPU 程序（内核）合并为一个，使中间结果留在片上存储中，而不必写入 HBM 再读回。它减少了内存流量和启动开销。*另见：* [GPU 内核](#gpu-kernel)、[TensorRT](#tensorrt)。
- <a id="kernelbench"></a>**KernelBench** — 一个公开的 PyTorch 操作基准测试，分为三个难度级别，用于检验 AI 模型能否编写出正确且比 PyTorch 自带实现更快的 GPU 内核。*另见：* [Triton (OpenAI)](#triton)。
- <a id="distillation"></a>**Knowledge distillation（知识蒸馏）** — 训练一个较小的“学生”模型去模仿较大“教师”模型的输出。它能以远低于教师模型的推理成本保留其大部分能力。*另见：* [推理型模型](#reasoning-model)、[开放权重模型](#open-weight-model)。
- <a id="known-good-die"></a>**Known good die (KGD)（已知合格裸片）** — 在封装前已经过全面测试的裸片（或 HBM 堆栈）。由于成品封装无法返修，事先逐一测试可避免因一个坏件而报废其他昂贵的合格部件。*另见：* [芯粒](#chiplet)、[先进封装](#advanced-packaging)。
- <a id="kubernetes"></a>**Kubernetes** — 在机器集群上运行容器化软件的开源系统；云计算的默认控制平面。Kueue 和 KAI Scheduler 等插件让它具备了共享 GPU 的能力。*另见：* [Slurm](#slurm)、[KAI Scheduler](#kai-scheduler)。
- <a id="kvbm"></a>**KV block manager (KVBM)（KV 块管理器）** — Dynamo 的组件，将 KV 缓存块分层存储（GPU 显存、CPU 内存、SSD、远端存储），并在对话恢复时将其移回 GPU。*另见：* [KV 缓存卸载](#kv-cache-offload)、[Dynamo](#dynamo)、[NIXL](#nixl)。
- <a id="kv-cache"></a>**KV cache（KV 缓存）** — 此前每个 token 的键（key）和值（value），存储在 GPU 显存中，使注意力计算无需重新计算它们。其规模随上下文长度和用户数增长；往往是推理服务中起决定作用的内存约束。*另见：* [注意力机制](#attention)、[PagedAttention](#paged-attention)。
- <a id="kv-aware-routing"></a>**KV-aware routing（KV 感知路由）** — 把每个新请求发送到 KV 缓存中已保存其对话或提示词最大部分的服务器，从而减少需要重算的提示词部分。它缩短了首 token 时间。*另见：* [KV 缓存](#kv-cache)、[Dynamo](#dynamo)、[TTFT（首 token 时间）](#ttft)。
- <a id="kv-cache-offload"></a>**KV-cache offload（KV 缓存卸载）** — 把闲置对话或长对话的注意力缓存（KV 缓存）从稀缺的 GPU HBM 移到更便宜的 CPU 内存或存储中，待用户回来时重新加载，而不必从头重算。*另见：* [KV 缓存](#kv-cache)、[NVLink-C2C](#nvlink-c2c)。
- <a id="kyber"></a>**Kyber** — 英伟达为 Rubin Ultra 设计的下一代机架：144 个 GPU 封装安装在垂直刀片上，通过印刷电路中板（midplane）互连，功耗约 600 kW。英伟达的目标是 H2 2027；有报道称可能推迟到 2028 年。*另见：* [中板](#midplane)、[NVL72](#nvl72)、[Oberon](#oberon)、[机架级系统](#rack-scale-system)、[800 V 直流供电架构](#hvdc-800v)。
## L

- <a id="l2-cache"></a>**L2 cache（L2 缓存）** — 片上最后一级存储，由所有 SM 共享：H100 为 50 MB，B200 约为 126 MB。它在数据从 HBM 传来的途中将其截留，使重复读取不占用稀缺的 HBM 带宽。*另见：* [共享内存](#shared-memory)、[高带宽内存（HBM）](#hbm)。
- <a id="l6-l10-l11"></a>**L6 / L10 / L11 integration（L6/L10/L11 级集成）** — 业界衡量服务器组装完成度的简称：L6 指已贴装元器件的电路板或模块，L10 指经过测试的完整服务器或托盘，L11 指包含网络、电源和散热、作为一个整体完成验证的整机架。*另见：* [ODM](#odm)、[OEM](#oem)。
- <a id="lpu"></a>**Language processing unit (LPU)（语言处理单元）** — Groq 的推理芯片设计（2025 年 12 月授权给英伟达），将模型权重保存在片上 SRAM（每颗芯片约 500 MB）而非 HBM 中，以容量换取解码时极高的带宽和极低的延迟。*另见：* [解码（decode）](#decode)、[高带宽内存（HBM）](#hbm)。
- <a id="leading-indicator"></a>**Leading indicator（领先指标）** — 往往先于你所关心的结果而变动的可量化信号，例如超大规模云厂商的资本开支指引会先于英伟达的订单发生变化。*另见：* [风险热力图](#risk-heatmap)。
- <a id="letter-of-intent"></a>**Letter of intent (LOI)（意向书）** — 在签署最终协议之前列明交易拟定条款的、不具约束力的文件。英伟达与 OpenAI 最高 $100B 的意向书（2025 年）后来被规模较小的股权投资所取代。*另见：* [收购式招聘](#acquihire)。
- <a id="licence-plus-acquihire"></a>**Licence plus acquihire（授权加收购式招聘）** — 一种交易结构：买方付费取得初创公司技术的非独家授权，并聘用其创始人和工程师，而初创公司仍作为独立公司存续；这可能绕开正式的并购审查。*另见：* [收购式招聘](#acquihire)、[并购审查](#merger-review)。
- <a id="linear-pluggable-optics"></a>**Linear pluggable optics (LPO)（线性可插拔光模块）** — 自身不带 DSP 芯片、依靠交换机的 SerDes 驱动信号的可插拔模块。模块功耗约减半，但传输距离缩短，互操作性要求也更严格。*另见：* [可插拔光模块](#pluggable-transceiver)、[共封装光学（CPO）](#co-packaged-optics)。
- <a id="linear-programming"></a>**Linear programming（线性规划）** — 在线性约束条件下求线性目标（成本、利润）的最优值；是物流、排程和供应链规划的主力工具。*另见：* [cuOpt](#cuopt)。
- <a id="link-layer-retry"></a>**Link-layer retry (LLR)（链路层重传）** — 在两个直连端口之间重发受损帧的机制，而不依赖端到端重传。它使纵向扩展链路保持无损，且增加的延迟极低。*另见：* [Scale-Up Ethernet（SUE）](#scale-up-ethernet)、[基于信用的流量控制](#credit-based-flow-control)。
- <a id="liquid-cooling"></a>**Liquid cooling（液冷）** — 通过在芯片冷板中循环的液体（而非空气）带走热量；功率约 100 kW 及以上的机架（如 GB200 NVL72）必须采用。*另见：* [800 V 直流供电架构](#hvdc-800v)。
- <a id="liquid-to-air-cooling"></a>**Liquid-to-air (L2A) cooling（液-气冷却）** — 一种过渡性方案：机架的冷却液回路通过侧挂式散热器把热量排到室内空气中，使液冷机架能在没有设施冷却水的机房中运行。*另见：* [冷却液分配单元（CDU）](#cdu)、[直触芯片液冷](#direct-to-chip-cooling)。
- <a id="lithography"></a>**Lithography（光刻）** — 芯片制造中的“印刷”步骤：光刻机将光线透过带图形的掩模投射到晶圆表面的感光涂层上，定义出电路的一层。一颗现代芯片需要数十个这样的层。*另见：* [EUV 光刻](#euv-lithography)、[光掩模](#photomask)。
- <a id="llm"></a>**LLM (large language model)（大语言模型）** — 拥有数十亿到数万亿参数的 Transformer 神经网络，在大规模文本语料上训练以预测下一个 token。聊天助手、编程工具和 AI 智能体都构建于 LLM 之上。*另见：* [Transformer](#transformer)、[参数](#parameter)、[token](#token)。
- <a id="llm-d"></a>**llm-d** — 一个开源 Kubernetes 项目（CNCF 沙箱项目，由红帽（Red Hat）、谷歌云、IBM Research、CoreWeave 和英伟达共同发起），在 vLLM 和 SGLang 之上为 GPU 和 TPU 集群增加类似 Dynamo 的路由以及预填充/解码分离功能。*另见：* [Dynamo](#dynamo)、[vLLM](#vllm)。
- <a id="load-factor"></a>**Load factor（负载率）** — 设施实际消耗功率占满载功率的平均比例。闲置的加速器仍会耗电，因此 TCO 模型按“底线功耗 + 忙碌部分”计费。*另见：* [PUE（电能使用效率）](#pue)、[集群利用率](#utilization)。
- <a id="load-store-semantics"></a>**Load/store semantics（加载/存储语义）** — 一个处理器直接用普通内存指令读写另一个处理器内存的通信方式（NVLink 即支持这种方式），而不是把数据打包成网络消息。对小而频繁的传输，它降低了软件开销和延迟。*另见：* [NVLink](#nvlink)、[RDMA（远程直接内存访问）](#rdma)、[纵向扩展（scale-up）](#scale-up)。
- <a id="local-silicon-interconnect"></a>**Local silicon interconnect (LSI) bridge（局部硅互连桥）** — 一小块布线极精细的硅片，嵌在 CoWoS-L 封装中相邻裸片的边缘下方，使硅材料只用在需要密集连接的地方。*另见：* [CoWoS-L](#cowos-l)、[EMIB / EMIB-T](#emib)、[中介层](#interposer)。
- <a id="long-term-agreement"></a>**Long-term agreement (LTA)（长期协议）** — 锁定供货量、并常常锁定价格或定价公式的多年期供应合同，有时附带预付款；2026 年内存厂商借此提前数年锁定 HBM 和 DRAM 产出。*另见：* [供应预付款](#prepayment)、[采购义务](#purchase-obligations)。
- <a id="loss-function"></a>**Loss function（损失函数）** — 衡量模型在一个批次上预测错误程度的单一数值；训练的目标就是把它降下来。*另见：* [梯度](#gradient)。
- <a id="lpddr"></a>**LPDDR** — 最初为手机设计的低功耗 DRAM，以芯片或模块形式销售。每 GB 成本远低于 HBM、密度更高，但带宽要低得多；用于高通 AI200 等大容量推理卡。*另见：* [LPDDR5X](#lpddr5x)、[SOCAMM](#socamm)、[高带宽内存（HBM）](#hbm)。
- <a id="lpddr5x"></a>**LPDDR5X** — 最初为手机设计的低功耗 DRAM，Grace 和 Vera 采用它而非标准服务器 DIMM，因为其每瓦带宽更高；它以焊接或贴装方式紧靠 CPU 放置。*另见：* [SOCAMM](#socamm)。
## M

- <a id="maia"></a>**Maia** — 微软为 Azure 自研的 AI 加速器产品线：Maia 100（2024 年）、Maia 200（2026 年，面向推理，运行 Copilot）以及 Maia 300（宣布于 2027 年推出）。*另见：* [Azure Cobalt](#azure-cobalt)、[自用芯片](#captive-silicon)。
- <a id="mamba"></a>**Mamba (state-space layer)（状态空间层）** — 一种神经网络层，在序列中携带固定大小的滚动状态，而非关注此前的每一个 token，因此其内存不随上下文长度增长。在混合模型中与注意力层搭配使用。*另见：* [注意力机制](#attention)、[KV 缓存](#kv-cache)。
- <a id="mark-to-market"></a>**Mark-to-market gain（按市值计价收益）** — 因投资的市场价值或评估价值上升而入账的利润，并未实际出售。它会抬高报告利润，但并非现金，价格下跌时还会转回。*另见：* [非流通股权证券](#non-marketable-equity)。
- <a id="modular-max"></a>**MAX (Modular)** — Modular 公司以 Mojo 编写的推理框架和内核库，在英伟达和 AMD GPU 上提供兼容 OpenAI 接口的推理服务端点。*另见：* [Mojo](#mojo)。
- <a id="mttr"></a>**Mean time to recovery (MTTR)（平均恢复时间）** — 从故障发生到作业重新有效运行的平均时间：包括检测、隔离故障节点、重启，以及重做自上一个检查点以来的工作。*另见：* [有效训练时间](#effective-training-time)、[检查点](#checkpoint)。
- <a id="memory-pooling"></a>**Memory pooling（内存池化）** — 通过 CXL 或以太网等互连，在众多处理器之间共享一大块内存，使容量可以扩充而无需购买更多 GPU 或 HBM。*另见：* [CXL (Compute Express Link)](#cxl)、[KV 缓存](#kv-cache)。
- <a id="memory-supercycle"></a>**Memory supercycle（内存超级周期）** — 内存需求超过供给、DRAM 和 HBM 价格与利润率全面大幅上升的时期，例如 2026 年 DRAM 行业收入曾在一个季度内增长 81%。*另见：* [高带宽内存（HBM）](#hbm)、[长期协议（LTA）](#long-term-agreement)。
- <a id="memory-wall"></a>**Memory wall（内存墙）** — 处理器计算速度与内存供数速度之间的差距。在 LLM 推理（尤其是解码阶段）中，性能往往受内存带宽而非 FLOPS 的限制。*另见：* [高带宽内存（HBM）](#hbm)。
- <a id="memory-bound"></a>**Memory-bound（内存受限）** — 速度受限于从内存读取数据的速度、而非芯片计算速度的工作负载；增加 FLOPS 无济于事，增加带宽才有效。*另见：* [计算受限](#compute-bound)、[内存墙](#memory-wall)。
- <a id="merchant-silicon"></a>**Merchant silicon（商用芯片）** — 在公开市场上出售给任何买家的芯片（英伟达 GPU、AMD Instinct），与企业为自用而设计的定制芯片（谷歌 TPU、AWS Trainium）相对。*另见：* [XPU（定制加速器）](#xpu)。
- <a id="merger-review"></a>**Merger review（并购审查）** — 由美国 FTC/DOJ（Hart-Scott-Rodino 申报）、欧盟委员会、英国 CMA 和中国国家市场监督管理总局（SAMR）等机构对收购进行的反垄断审查；审查可能历时一年以上，并可能阻止交易，英伟达收购 Arm 一案即是如此。*另见：* [授权加收购式招聘](#licence-plus-acquihire)。
- <a id="mfu"></a>**MFU (model FLOPs utilization)（模型 FLOPs 利用率）** — 训练期间 GPU 理论峰值 FLOPS 中转化为有效模型运算的比例。大型训练任务通常可达约 35-45%。*另见：* [FLOPS](#flops)、[有效吞吐量](#goodput)。
- <a id="mgx"></a>**MGX** — 英伟达面向服务器和机架的模块化参考架构，合作伙伴借此围绕英伟达或合作伙伴的芯片构建系统。AWS 计划将 Trainium4 置于配备 NVLink 的 MGX 机架中。*另见：* [NVLink Fusion](#nvlink-fusion)、[NVL72](#nvl72)。
- <a id="micro-batch"></a>**Micro-batch（微批次）** — 训练批次中的一小片，作为一个单元流经流水线；每一步的微批次越多，流水线气泡越小。*另见：* [流水线气泡](#pipeline-bubble)。
- <a id="microbump"></a>**Micro-bump（微凸块）** — 直径数十微米的微小焊点，用于连接上下堆叠的裸片，或连接裸片与中介层。HBM 堆栈每层使用数千个微凸块。*另见：* [硅通孔（TSV）](#through-silicon-via)、[混合键合](#hybrid-bonding)、[中介层](#interposer)。
- <a id="micro-ring-modulator"></a>**Micro-ring modulator（微环调制器）** — 一种微小的环形硅光器件，通过开关光信号来编码数据。它尺寸极小、功耗很低，是英伟达在其 CPO 光引擎中采用的调制器（基于台积电 COUPE 工艺制造），但对温度敏感。*另见：* [共封装光学（CPO）](#co-packaged-optics)。
- <a id="microscaling"></a>**Microscaling (MX formats)（微缩放格式）** — 一项行业标准（开放计算项目，2023 年）：每 32 个低精度数值组成一块，共享一个 8 位、2 的幂次的缩放因子。主要成员为 MXFP8、MXFP6 和 MXFP4；英伟达的 NVFP4 是采用 16 值分块的变体。*另见：* [NVFP4](#nvfp4)、[FP4](#fp4)。
- <a id="mid-cycle-refresh"></a>**mid-cycle refresh（中期升级版）** — 在原版发布约一年后推出的同代 GPU 升级版本，例如 Blackwell 之后的 Blackwell Ultra（B300）、Rubin 之后的 Rubin Ultra，通常在同一架构上增加内存和算力。*另见：* [一年一代节奏](#annual-cadence)。
- <a id="midplane"></a>**Midplane（中板）** — 位于机架或机箱中部的大型印刷电路板，计算刀片和交换刀片从两侧插入，取代线缆。英伟达的 Kyber 机架采用中板，取代 NVL72 的线缆背板。*另见：* [Kyber](#kyber)、[NVLink 线缆背板](#nvlink-spine)。
- <a id="mig"></a>**MIG (Multi-Instance GPU)（多实例 GPU）** — 一项硬件功能（自英伟达 Ampere 起），可将一块数据中心 GPU 划分为最多七个相互隔离的迷你 GPU，各自拥有独立的内存和计算资源，使多个小作业能共享一块 GPU 而互不干扰。*另见：* [GPU 切分](#fractional-gpu)、[GPU 时间片轮转](#gpu-time-slicing)。
- <a id="mixed-precision"></a>**Mixed-precision training（混合精度训练）** — 以紧凑的数值格式（BF16 或 FP8）完成繁重的算术运算，同时保留一份全精度（FP32）的主权重副本，以免丢失微小的更新。*另见：* [BF16 (bfloat16)](#bf16)、[FP8](#fp8)、[Adam 优化器](#adam)。
- <a id="mixture-of-experts"></a>**Mixture-of-experts (MoE)（混合专家模型）** — 一种模型设计，把每个 token 路由到众多专家子网络中的少数几个，因此每个 token 只激活一小部分参数（DeepSeek-V3：671B 中的 37B）。可节省算力，但仍需为所有专家提供内存，并需要快速的全交换网络。*另见：* [专家并行（EP）](#expert-parallelism)、[NVLink](#nvlink)。
- <a id="mlir"></a>**MLIR** — Multi-Level Intermediate Representation（多级中间表示）：开放的编译器基础设施（源自 LLVM 项目），用于构建 Mojo、IREE、Triton 和 NKI 等 AI 编译器。*另见：* [XLA](#xla)、[Mojo](#mojo)。
- <a id="mlperf"></a>**MLPerf** — 由 MLCommons 运营的行业基准测试套件；MLPerf Inference 在固定模型和精度目标下，测量经审计的单系统吞吐量。*另见：* [InferenceX](#inferencex)。
- <a id="moat"></a>**Moat（护城河）** — 使竞争对手无法夺走企业客户或利润的持久优势，例如转换成本、规模经济、供应渠道或网络效应。本资料库以买家或竞争对手绕开护城河所需的时间和成本来评判其强弱。*另见：* [护城河评分](#moat-score)。
- <a id="moat-score"></a>**Moat score（护城河评分）** — 本资料库对在某一技术栈层级中绕开英伟达难度的 1-5 分判断：1 = 已商品化或英伟达落后，3 = 竞争对手在部分维度上持平、英伟达在集成上领先，5 = 无对手接近且切换需要数年。它综合了各层页面的结论，而非实测数值。*另见：* [差距趋势](#gap-trend)。
- <a id="model-hub"></a>**Model hub（模型中心）** — 开发者查找、下载和部署模型与数据集的平台；Hugging Face 是其中最大的一家，正被英伟达收购（尚待完成）。*另见：* [开放权重模型](#open-weight-model)。
- <a id="model-specific-asic"></a>**Model-specific ASIC（模型专用 ASIC）** — 为单一模型家族硬连线设计的芯片，例如 Etched 仅支持 Transformer 的 Sohu。若模型架构保持稳定，其效率可以非常高；一旦架构改变，就会沦为搁浅资产。*另见：* [ASIC](#asic)、[Transformer](#transformer)。
- <a id="moe-router"></a>**MoE router（MoE 路由器）** — 混合专家层中经训练得到的小型网络，为每个 token 给各专家打分，并选出由哪几个专家处理它。*另见：* [混合专家模型（MoE）](#mixture-of-experts)。
- <a id="mojo"></a>**Mojo** — Modular 公司（现属高通）推出的 Python 超集编程语言，用于编写能在多家厂商 CPU 和 GPU 上运行的高性能内核；2026 年以 Apache 2.0 许可开源。*另见：* [MAX (Modular)](#modular-max)、[MLIR](#mlir)。
- <a id="monte-carlo-simulation"></a>**Monte Carlo simulation（蒙特卡洛模拟）** — 将模型重复运行数千次，每次从各输入的合理区间中随机抽取数值，然后报告输出的百分位数（如 P10-P90），而非单一数值。*另见：* [龙卷风图](#tornado-chart)。
- <a id="mpi"></a>**MPI (Message Passing Interface)（消息传递接口）** — 超级计算领域沿用数十年的进程间通信标准；NCCL 可在 MPI 应用中运行，MPI 库也可调用 NCCL 处理 GPU 数据。*另见：* [NCCL](#nccl)、[UCC (Unified Collective Communication)](#ucc)。
- <a id="mrdimm"></a>**MRDIMM** — 多路复用 Rank DIMM（Multiplexed-rank DIMM）：一种服务器内存模块，交错使用两个 rank，使每通道数据速率约翻倍（例如 8,800 MT/s），在不增加通道数的情况下提升 CPU 内存带宽。*另见：* [LPDDR5X](#lpddr5x)。
- <a id="msccl"></a>**MSCCL++** — 微软开源的 GPU 通信栈，让开发者用单边、由 GPU 驱动的原语编写自定义集合通信算法；可在英伟达和 AMD GPU 上运行。*另见：* [NCCL](#nccl)、[RCCL](#rccl)。
- <a id="mtbi"></a>**MTBI (mean time between interruptions)（平均中断间隔时间）** — 大型训练作业在被硬件或软件故障中断之前平均运行的 GPU 小时数。MTBI 越高，因重启而损失的工作越少。*另见：* [热备件](#hot-spare)。
- <a id="mtia"></a>**MTIA** — Meta Training and Inference Accelerator（Meta 训练与推理加速器）：Meta 自研的芯片产品线，最初用于排序和推荐模型，现已扩展到生成式 AI 推理（MTIA 300-500）。*另见：* [推荐模型](#recommendation-model)、[自用芯片](#captive-silicon)。
- <a id="multi-head-latent-attention"></a>**Multi-head latent attention (MLA)（多头潜在注意力）** — DeepSeek 的注意力设计，为每个 token 缓存一个经压缩的小型潜在向量，而非完整的键和值，使 KV 缓存内存减少 90% 以上。*另见：* [KV 缓存](#kv-cache)、[分组查询注意力（GQA）](#grouped-query-attention)。
- <a id="multi-plane-network"></a>**Multi-plane network（多平面网络）** — 由若干相互独立的并行网络（“平面”）构成的网络，每块 GPU 的网卡分拆接入各个平面。每个平面采用更低 radix 的端口，使两层网络即可覆盖更多 GPU；某个平面故障也只会损失部分带宽。*另见：* [胖树](#fat-tree)、[交换机端口数](#switch-radix)。
- <a id="multi-tenancy"></a>**Multi-tenancy（多租户）** — 多个客户共享同一物理基础设施，同时在性能、网络可达性和数据方面彼此隔离。*另见：* [裸金属实例](#bare-metal)、[零信任隔离](#zero-trust)。
- <a id="multi-token-prediction"></a>**Multi-token prediction (MTP)（多 token 预测）** — DeepSeek 采用的一种模型特性，每一步预先起草若干个未来 token，由服务器一并验证：这是一种内置的推测解码，可在单用户速度相同的情况下将吞吐量提升数倍。*另见：* [推测解码](#speculative-decoding)、[解码（decode）](#decode)。
- <a id="cloud-service-agreement"></a>**Multi-year cloud service agreement（多年期云服务协议）** — 英伟达披露的、在数年内向云服务商支付容量费用的承诺（用于 DGX Cloud 及其自身研究）。它们在财报中列为采购承诺，而非收入。*另见：* [DGX Cloud](#dgx-cloud)、[算力兜底承诺](#capacity-backstop)。
- <a id="mxfp4"></a>**MXFP4** — 开放计算项目的 4 位微缩放格式：每 32 个 FP4 数值组成一块，共享一个 8 位、2 的幂次的缩放因子。英伟达的 NVFP4 采用更小的 16 值分块和更精细的 FP8 缩放因子；AMD 等厂商支持 MXFP4。*另见：* [FP4](#fp4)、[NVFP4](#nvfp4)。
## N

- <a id="national-champion"></a>**National champion（国家冠军企业）** — 政府为替代外国技术而扶持的本土芯片供应商，通常受出口管制或采购规则的保护；中国的华为昇腾是主要例子。*另见：* [出口管制](#export-controls)、[华为昇腾](#huawei-ascend)。
- <a id="nccl"></a>**NCCL** — NVIDIA Collective Communications Library（英伟达集合通信库）：通过 NVLink、InfiniBand 或以太网在 GPU 之间执行全规约、全收集等操作的软件。*另见：* [全规约](#all-reduce)、[CUDA-X](#cuda-x)。
- <a id="near-memory-compute"></a>**Near-memory computing（近存计算）** — 将计算逻辑放在内存内部或紧邻处，使数据传输距离更短，从而提高有效带宽并降低每次运算的能耗；高通 AI250 和 d-Matrix 采用了这一思路的不同变体。*另见：* [内存墙](#memory-wall)。
- <a id="nemo"></a>**NeMo** — 英伟达开源的 AI 模型构建与适配工具家族：数据整理、训练和微调、强化学习、评估以及护栏。*另见：* [Nemotron](#nemotron)、[NeMo Guardrails](#nemo-guardrails)。
- <a id="nemo-guardrails"></a>**NeMo Guardrails** — 英伟达开源的工具包，在语言模型的输入和输出周围添加可编程规则，例如拦截离题回答或强制执行对话流程。*另见：* [NeMo](#nemo)、[NVIDIA NIM](#nim)。
- <a id="nemotron"></a>**Nemotron** — 英伟达的开放权重 AI 模型家族，发布时公开了大部分训练数据和训练方法。2025-26 年的 Nemotron 3 模型采用稀疏的 Mamba-Transformer 混合专家架构。*另见：* [NeMo](#nemo)、[混合专家模型（MoE）](#mixture-of-experts)、[Mamba（状态空间层）](#mamba)。
- <a id="neocloud"></a>**Neocloud（新兴云服务商）** — 专门出租 AI 用 GPU 容量的云服务商（例如 CoreWeave、Lambda、Nebius、Crusoe），与通用型超大规模云厂商相对。其中数家是英伟达的被投企业或合作伙伴。*另见：* [循环融资](#circular-financing)。
- <a id="neoverse"></a>**Neoverse** — Arm 的数据中心 CPU 核心设计系列（N 系列侧重能效，V 系列侧重性能）。Grace 和 Graviton4 均采用 Neoverse V2 核心。*另见：* [Arm 指令集](#arm-isa)、[计算子系统（CSS）](#compute-subsystem)。
- <a id="network-operating-system"></a>**Network operating system (NOS)（网络操作系统）** — 运行交换机的软件：路由、遥测、配置。例如 Arista EOS、思科 NX-OS、英伟达 Cumulus Linux 以及开源的 SONiC。*另见：* [白盒交换机](#white-box-switch)。
- <a id="neural-network"></a>**Neural network（神经网络）** — 由多层堆叠而成，每一层将输入乘以一个由学习得到的数值（参数）构成的矩阵，再施加一个简单的非线性函数。GPU 加速的正是其中的矩阵乘法。*另见：* [Transformer](#transformer)、[参数](#parameter)。
- <a id="neuron-sdk"></a>**Neuron SDK** — AWS 面向 Trainium 和 Inferentia 芯片的软件栈：编译器、运行时、PyTorch 集成（TorchNeuron）以及 NKI 内核语言。*另见：* [NKI (Neuron Kernel Interface)](#nki)。
- <a id="neuronlink"></a>**NeuronLink** — AWS 面向 Trainium 芯片的纵向扩展互连。NeuronLink-v3 以环面拓扑连接 64 颗 Trainium2；NeuronLink-v4 配合 NeuronSwitch-v1 以全互连方式连接 144 颗 Trainium3，每颗芯片约 2 TB/s。*另见：* [纵向扩展（scale-up）](#scale-up)、[NVLink](#nvlink)。
- <a id="npi"></a>**New product introduction (NPI)（新产品导入）** — 将新设计在工厂产线上转化为可制造、经测试产品的工程阶段；对 AI 机架而言，包括在批量爬坡前完成散热、供电和线缆验证。*另见：* [EMS（电子制造服务）](#ems)、[ODM](#odm)。
- <a id="nic"></a>**NIC (network interface card)（网卡）** — 将服务器或 GPU 连接到网络的适配器。AI 服务器通常为每块 GPU 配备一块 400–800 Gb/s 的网卡，用于横向扩展网络；SuperNIC 和 DPU 是能力更强的网卡类型。*另见：* [SuperNIC](#supernic)、[SmartNIC](#smartnic)、[数据处理器（DPU）](#dpu)。
- <a id="nixl"></a>**NIXL** — NVIDIA Inference Xfer Library（英伟达推理传输库）：开源软件，通过 NVLink 或 RDMA 在 GPU、CPU 内存和存储之间点对点传输 KV 缓存块等数据，被 Dynamo 用于分离式推理服务。*另见：* [Dynamo](#dynamo)、[分离式推理服务](#disaggregated-serving)、[RDMA（远程直接内存访问）](#rdma)。
- <a id="nki"></a>**NKI (Neuron Kernel Interface)** — AWS 基于 Python 的语言，用于为 Trainium 编写自定义内核，配有基于 MLIR 的开源编译器。*另见：* [Neuron SDK](#neuron-sdk)、[Triton (OpenAI)](#triton)。
- <a id="non-marketable-equity"></a>**Non-marketable equity security（非流通股权证券）** — 对私营公司（例如 OpenAI 或 Anthropic）的持股，没有公开报价；按成本入账，并在新一轮融资显示出不同价格时进行调整。*另见：* [按市值计价收益](#mark-to-market)。
- <a id="north-south-traffic"></a>**North-south traffic（南北向流量）** — 数据中心与外部世界之间的流量：用户、互联网以及其他站点。*另见：* [东西向流量](#east-west-traffic)、[前端网络](#front-end-network)。
- <a id="npu"></a>**NPU (neural processing unit)（神经网络处理器）** — 专为神经网络运算打造的处理器，通常配备大型矩阵引擎，通用控制逻辑少于 GPU。华为昇腾和高通的 Cloud AI 产品都属于 NPU。*另见：* [ASIC](#asic)、[GPU](#gpu)。
- <a id="nre"></a>**NRE (non-recurring engineering)（一次性工程费用）** — 芯片在售出任何一颗之前的一次性设计成本，包括工程人力、EDA 工具、IP 授权和光掩模。大型先进制程芯片的估算约为 $0.5-0.7B。*另见：* [流片](#tape-out)、[EDA（电子设计自动化）](#eda)。
- <a id="nv-hbi"></a>**NV-HBI (high-bandwidth interface)** — 英伟达的裸片间互连，以 10 TB/s 的速率连接 Blackwell 或 Rubin GPU 中两颗光罩尺寸的计算裸片，速度之快使软件将其视为一块 GPU。*另见：* [裸片间互连](#die-to-die-interconnect)、[芯粒](#chiplet)。
- <a id="nvcc"></a>**nvcc** — 英伟达的 CUDA 编译器驱动程序。它将程序拆分为 CPU 代码（交给主机编译器）和 GPU 代码，后者先编译为 PTX，再编译为 SASS 机器码。*另见：* [PTX (Parallel Thread Execution)](#ptx)、[SASS](#sass)。
- <a id="nventures"></a>**NVentures** — 英伟达的风险投资部门，在初创企业融资轮中购买少数股权。它独立于 Inception（免费会员计划），也独立于英伟达直接持有的大额战略股份。*另见：* [NVIDIA Inception](#nvidia-inception)、[企业风险投资](#corporate-venture-capital)。
- <a id="nvfp4"></a>**NVFP4** — 英伟达面向 Blackwell 和 Rubin 的 4 位浮点格式：4 位数值，每 16 个数值一块共享一个 FP8 缩放因子，另加一个张量级缩放因子，合计每个数值约 4.5 位。*另见：* [FP8](#fp8)、[量化](#quantization)。
- <a id="nvidia-ai-enterprise"></a>**NVIDIA AI Enterprise** — 英伟达的付费软件订阅（企业级支持、安全补丁以及经认证版本的 CUDA-X 库、NIM 和框架），2024 年定价约为每 GPU 每年 $4,500。*另见：* [CUDA-X](#cuda-x)。
- <a id="dali"></a>**NVIDIA DALI** — 英伟达的数据加载库（Data Loading Library），将图像、视频和音频的解码与增强从主机 CPU 转移到 GPU 上，以避免数据加载瓶颈。*另见：* [数据加载器](#data-loader)。
- <a id="nvidia-inception"></a>**NVIDIA Inception** — 英伟达面向初创企业的免费会员计划（2016 年推出）。会员可获得技术帮助、培训以及与投资者和合作伙伴的对接；英伟达不通过该计划获取股权。*另见：* [NVentures](#nventures)、[企业风险投资](#corporate-venture-capital)。
- <a id="mission-control"></a>**NVIDIA Mission Control** — 英伟达面向 AI 工厂的运维软件（2025 年）：结合 Base Command Manager 与 Run:ai，负责部署和监控 DGX 机架、诊断故障并调度作业。*另见：* [AI 工厂](#ai-factory)、[超节点](#superpod)。
- <a id="nim"></a>**NVIDIA NIM** — NVIDIA Inference Microservices（英伟达推理微服务）：预先构建的容器，将模型与经优化的引擎及标准 API 打包在一起；生产环境使用须取得 NVIDIA AI Enterprise 许可。*另见：* [NVIDIA AI Enterprise](#nvidia-ai-enterprise)。
- <a id="nvidia-warp"></a>**NVIDIA Warp** — 英伟达的开源 Python 框架，可将普通 Python 函数编译为 GPU 内核，用于物理仿真、机器人和可微编程。不要与由 32 个线程组成的 GPU warp（线程束）混淆。*另见：* [PhysX](#physx)、[线程束](#warp)。
- <a id="nvl-naming"></a>**NVL naming（NVL 命名规则）** — 英伟达的机架名称标明一个 NVLink 域中的 GPU 数量；自 CES 2026 起，该数字按 GPU 封装而非裸片计算，因此“Vera Rubin NVL144”更名为 Vera Rubin NVL72，“Rubin Ultra NVL576”更名为 Kyber NVL144。*另见：* [NVL72](#nvl72)、[Kyber](#kyber)。
- <a id="nvl72"></a>**NVL72** — 英伟达的机架级系统，72 个 GPU 封装通过 18 颗（Blackwell）或 36 颗（Vera Rubin）NVLink 交换芯片共享一个 NVLink 域。该数字按 GPU 封装计算；英伟达曾短暂改按裸片计数（“NVL144”），2026 年又改了回来。*另见：* [NVLink 域](#nvlink-domain)、[NVLink 线缆背板](#nvlink-spine)、[Oberon](#oberon)。
- <a id="nvlink"></a>**NVLink** — 英伟达专有的高速 GPU 间互连，用于纵向扩展。NVLink 5（Blackwell）为每块 GPU 提供 1.8 TB/s 带宽，是 PCIe 插槽的许多倍。*另见：* [NVSwitch](#nvswitch)、[纵向扩展（scale-up）](#scale-up)。
- <a id="nvlink-domain"></a>**NVLink domain（NVLink 域）** — 无需经过网卡、可通过 NVLink 直接互访的一组 GPU。在域内，GPU 以 NVLink 速度读写彼此的内存；域外的流量则只能退回到慢得多的横向扩展网络。*另见：* [纵向扩展（scale-up）](#scale-up)、[NVL72](#nvl72)、[NVSwitch](#nvswitch)。
- <a id="nvlink-fusion"></a>**NVLink Fusion** — 英伟达 2025 年推出的计划，对外授权 NVLink，使合作伙伴的定制 CPU 和加速器能与英伟达 GPU 一同接入 NVLink 纵向扩展域。已公布的合作伙伴包括高通、富士通、联发科、美满电子和 AWS（Trainium4）。*另见：* [NVLink](#nvlink)、[纵向扩展（scale-up）](#scale-up)。
- <a id="nvlink-sharp"></a>**NVLink SHARP (NVLS)** — NVLink 交换机内部的网内规约：交换机将所有 GPU 的数据相加并组播结果，使一次全规约中每块 GPU 的数据只需发送约一次，而非约两次。*另见：* [SHARP (in-network reduction)](#sharp)、[NCCL](#nccl)、[NVSwitch](#nvswitch)。
- <a id="nvlink-spine"></a>**NVLink spine（NVLink 线缆背板）** — NVL72 机架后部的铜质双轴线缆束，将每个 GPU 托盘与每个交换托盘相连。英伟达称 GB200 NVL72 中约有 5,000 根线缆，总长约两英里。*另见：* [NVL72](#nvl72)、[直连铜缆（DAC）](#direct-attach-copper)、[NVLink 交换托盘](#nvlink-switch-tray)。
- <a id="nvlink-switch-tray"></a>**NVLink switch tray（NVLink 交换托盘）** — NVL72 机架中的一个 1U 托盘，装有 NVLink 交换芯片（GB200 NVL72 中每个托盘两颗）、一个管理控制器，以及插入铜缆背板的后部连接器。九个托盘即可完成全部 72 块 GPU 的交换。*另见：* [NVSwitch](#nvswitch)、[NVLink 线缆背板](#nvlink-spine)、[盲插连接器](#blind-mate-connector)。
- <a id="nvlink-c2c"></a>**NVLink-C2C** — 英伟达的芯片间互连，以 900 GB/s（Grace）或 1.8 TB/s（Vera）的速率将 Grace 或 Vera CPU 与其 GPU 相连，是 PCIe 插槽的数倍，并具备缓存一致性，使 GPU 可以直接使用 CPU 内存。*另见：* [缓存一致性](#cache-coherence)、[NVLink](#nvlink)、[超级芯片](#superchip)。
- <a id="nvme"></a>**NVMe** — 闪存 SSD 通过 PCIe 使用的命令协议。它支持数万个并行队列，这就是一块现代 SSD 能提供数 GB/s 速率的原因。*另见：* [NVMe over Fabrics (NVMe-oF)](#nvme-of)。
- <a id="nvme-of"></a>**NVMe over Fabrics (NVMe-oF)** — 通过网络（RDMA、TCP 或光纤通道）承载 NVMe 命令，使服务器能像使用本地硬盘一样使用远端闪存。DPU 可在硬件中运行发起端或目标端。*另见：* [NVMe](#nvme)、[RDMA（远程直接内存访问）](#rdma)。
- <a id="nvqlink"></a>**NVQLink** — 英伟达 2025 年推出的互连架构，将量子处理器及其控制系统与 GPU 超级计算机相连，以实现实时纠错；发布时有 17 家量子硬件厂商参与。*另见：* [CUDA-Q](#cuda-q)。
- <a id="nvswitch"></a>**NVSwitch** — 连接众多 GPU 的 NVLink 端口的交换芯片，使每块 GPU 都能以 NVLink 全速与其他任何 GPU 通信，构成一个纵向扩展域（例如 NVL72 机架中的 72 块 GPU）。*另见：* [NVLink](#nvlink)、[纵向扩展（scale-up）](#scale-up)。
## O

- <a id="oberon"></a>**Oberon** — GB200、GB300 和 Vera Rubin NVL72 所用机架设计的内部代号：水平放置的计算托盘和交换托盘，通过后部的铜质 NVLink 线缆背板互连。*另见：* [NVL72](#nvl72)、[Kyber](#kyber)、[NVLink 线缆背板](#nvlink-spine)。
- <a id="object-storage"></a>**Object storage（对象存储）** — 以完整对象形式保存数据、通过 HTTP（S3 API）按键寻址的存储，能以低成本扩展到 EB 级，但延迟高于并行文件系统；通常存放原始数据集和归档数据。*另见：* [并行文件系统](#parallel-file-system)。
- <a id="odm"></a>**ODM（原始设计制造商）** — Original design manufacturer（原始设计制造商）：按照客户或英伟达的参考设计来设计和制造服务器、托盘和机架的代工厂商（富士康、广达、纬创等）。
- <a id="oem"></a>**OEM (original equipment manufacturer)（原始设备制造商）** — 以自有品牌销售服务器的公司，其产品往往部分由 ODM 代工，并附加销售、服务和融资；在 AI 服务器领域，例如戴尔、HPE 和超微。*另见：* [ODM](#odm)、[L6/L10/L11 级集成](#l6-l10-l11)。
- <a id="offtake-agreement"></a>**Offtake agreement（包销协议）** — 大型买家（例如微软或 Meta）长期租用某服务商未来容量的承诺。它使服务商能在数据中心建成之前筹集资金。*另见：* [照付不议合同](#take-or-pay)、[算力兜底承诺](#capacity-backstop)。
- <a id="omniverse"></a>**Omniverse** — 英伟达用于构建工厂、机器人和数据中心 3D 仿真与数字孪生的平台，基于 OpenUSD 和 PhysX 构建。*另见：* [PhysX](#physx)。
- <a id="oneapi"></a>**oneAPI** — 英特尔基于 SYCL 的跨厂商编程模型和库，现由 Linux 基金会旗下的 UXL 基金会管理（创始成员包括英特尔、Arm、谷歌云和高通）。*另见：* [SYCL](#sycl)。
- <a id="ocp"></a>**Open Compute Project (OCP)（开放计算项目）** — 由 Facebook（Meta）于 2011 年发起的行业基金会，超大规模云厂商和供应商在此发布服务器、机架和供电的开放硬件设计。英伟达贡献了其 GB200 NVL72 机架设计；AMD 的 Helios 采用 OCP 机架。*另见：* [Open Rack Wide (ORW)](#open-rack-wide)、[MGX](#mgx)。
- <a id="open-rack-wide"></a>**Open Rack Wide (ORW)** — 面向超重、高功率 AI 机架的 OCP 双宽机架规范；AMD 的 Helios 即基于该规范打造。*另见：* [开放计算项目（OCP）](#ocp)、[机架级系统](#rack-scale-system)。
- <a id="open-weight-model"></a>**Open-weight model（开放权重模型）** — 训练好的参数公开发布、任何人都可下载并部署的模型（例如 Llama、DeepSeek、Qwen、Nemotron），因此任何服务商都可以竞相提供该模型的推理服务。*另见：* [推理服务商](#inference-provider)。
- <a id="opencl"></a>**OpenCL** — 一项开放、免版税的 GPU 及其他处理器编程标准，自 2000 年代末起获得苹果、AMD 和英特尔的支持。由于英伟达的库和工具更胜一筹，它在 AI 领域的开发者心智份额输给了 CUDA。*另见：* [CUDA](#cuda)、[SYCL](#sycl)。
- <a id="operating-leverage"></a>**Operating leverage（经营杠杆）** — 收入增速快于成本增速，使每增加一美元销售额所带来的利润高于平均水平。英伟达的研发支出从 FY2016 到 FY2026 增长了 14 倍，但占收入的比例却从 27% 降至约 9%。*另见：* [飞轮](#flywheel)。
- <a id="operating-point"></a>**Operating point（工作点）** — 系统运行时设定的单用户速度（每用户每秒 token 数）。沿吞吐量-交互速度前沿，吞吐量和每 token 成本变化剧烈，因此任何成本比较都必须注明其工作点。*另见：* [交互速度（每用户 tokens/s）](#interactivity)、[吞吐量-交互速度帕累托前沿](#pareto-frontier)、[每百万 token 成本](#cost-per-million-tokens)。
- <a id="optical-circuit-switch"></a>**Optical circuit switch (OCS)（光路交换机）** — 利用微小镜面引导光束、无需转换为电信号即可重新连接光纤的交换机。谷歌在 Jupiter 网络和 TPU pod 中用 OCS 取代了脊层（spine）交换机。*另见：* [胖树](#fat-tree)。
- <a id="optical-dsp"></a>**Optical DSP（光模块 DSP）** — 可插拔光模块内部的数字信号处理器，负责清理并重定时高速信号。主要由美满电子和博通供应；去掉它（线性光学）可以省电，代价是传输距离缩短。*另见：* [可插拔光模块](#pluggable-transceiver)。
- <a id="optical-io"></a>**Optical I/O chiplet（光 I/O 芯粒）** — 封装在处理器旁边的小型裸片，将其电信号转换为光信号，使数据能通过光纤离开封装。它有望以低于可插拔光模块的功耗实现跨越多个机架的纵向扩展链路；Ayar Labs 和 Lightmatter 在开发此类产品。*另见：* [共封装光学（CPO）](#co-packaged-optics)、[SerDes](#serdes)。
- <a id="optimizer"></a>**Optimizer（优化器）** — 将梯度转化为参数更新的算法。它通常为每个参数额外维护滑动统计量，这会占用内存。*另见：* [Adam 优化器](#adam)、[梯度](#gradient)。
- <a id="osat"></a>**OSAT（外包封测）** — Outsourced semiconductor assembly and test（外包半导体封装与测试）：为无晶圆厂设计公司和晶圆代工厂提供芯片封装与测试服务的企业，例如日月光（ASE）和安靠（Amkor）。*另见：* [先进封装](#advanced-packaging)、[晶圆代工厂](#foundry)。
- <a id="osborne-effect"></a>**Osborne effect（奥斯本效应）** — 提前宣布更好的未来产品，导致客户停止购买现有产品、转而观望的风险；得名于 1980 年代的一家计算机厂商，据称其过早发布新品导致销售停滞。*另见：* [一年一代节奏](#annual-cadence)。
- <a id="over-training"></a>**Over-training（过度训练）** — 有意用远超 Chinchilla 最优比例的 token 数训练模型，使较小的模型也能达到高质量，且推理成本更低。*另见：* [Chinchilla 最优](#chinchilla-optimal)、[推理](#inference)。
- <a id="overlay-network"></a>**Overlay network（叠加网络）** — 通过给数据包封装外层报头（例如 VXLAN），在物理网络之上为每个租户构建的虚拟网络，使众多客户能共享同一批交换机而彼此不可见。*另见：* [虚拟交换机](#virtual-switch)、[多租户](#multi-tenancy)。
- <a id="oversubscription"></a>**Oversubscription（超额订阅）** — 某一交换层的下行带宽大于上行带宽（例如 3:1 的收敛比），可节省交换机和光模块，但意味着并非所有端点都能同时以全速跨层发送数据。*另见：* [胖树](#fat-tree)、[对分带宽](#bisection-bandwidth)。
- <a id="owner-tco"></a>**Owner TCO（自有 TCO）** — 拥有并运营一个加速器的全口径年度成本（硬件、网络、设施的资本费用，以及电力和运维）除以其小时数。它是 GPU 小时对所有者而言的成本，与客户支付的租赁价格相对。*另见：* [总拥有成本（TCO）](#tco)、[GPU 小时](#gpu-hour)、[资本回收系数](#capital-recovery-factor)。
## P

- <a id="p4-language"></a>**P4 (programming language)（P4 编程语言）** — 用于编程网络芯片如何解析和转发数据包的语言，AMD Pensando 和英特尔 IPU 的处理管线采用该语言。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="packet-spraying"></a>**Packet spraying（数据包喷洒）** — 将单条流的数据包同时分散到多条路径上。它能均匀利用整个网络，但数据包会乱序到达，因此接收端网卡必须将其重新排序。*另见：* [自适应路由](#adaptive-routing)、[SuperNIC](#supernic)。
- <a id="paged-attention"></a>**PagedAttention** — 一种技术（源自 vLLM），像虚拟内存那样以固定大小的页存储 KV 缓存，避免碎片化，并让请求之间共享已缓存的前缀。*另见：* [KV 缓存](#kv-cache)、[连续批处理](#continuous-batching)。
- <a id="pallas"></a>**Pallas** — JAX 的内核语言，用于在 XLA 编译器的输出不够快时编写自定义 TPU（及 GPU）内核；是谷歌对标 Triton 或 CUTLASS 的工具。*另见：* [XLA](#xla)、[CUTLASS](#cutlass)。
- <a id="pam4"></a>**PAM4** — 四电平脉冲幅度调制：线路上每个符号携带两个比特而非一个，在符号速率不变的情况下使数据速率翻倍。NVLink 自 Hopper 起改用 PAM4；它对噪声更敏感，因而缩短了铜缆的传输距离。*另见：* [SerDes](#serdes)、[直连铜缆（DAC）](#direct-attach-copper)。
- <a id="panel-level-packaging"></a>**Panel-level packaging（面板级封装）** — 在大型矩形面板而非 300 mm 圆形晶圆上制作先进封装。当每个封装跨越数个光罩尺寸时，矩形面板的边缘浪费更少，但面板更容易翘曲。*另见：* [CoPoS](#copos)、[CoWoS](#cowos)、[先进封装](#advanced-packaging)。
- <a id="parabricks"></a>**Parabricks** — 英伟达的 GPU 加速基因组学软件，运行标准 DNA 测序流程（比对、变异检测）的速度比 CPU 工具快许多倍。*另见：* [变异检测](#variant-calling)。
- <a id="parallel-file-system"></a>**Parallel file system（并行文件系统）** — 将每个文件条带化分布到众多存储服务器上、使数千个客户端能同时读写的文件系统（例如 Lustre/DDN EXAScaler、IBM Storage Scale、WEKA）。适合检查点和训练 I/O。*另见：* [对象存储](#object-storage)。
- <a id="parameter"></a>**Parameter (weight)（参数）** — 模型内部一个经学习得到的数值。“405B 模型”拥有 4,050 亿个参数；训练调整它们，推理则在每生成一个 token 时读取它们。*另见：* [神经网络](#neural-network)、[混合精度训练](#mixed-precision)。
- <a id="pat-algorithm"></a>**PAT (Parallel Aggregated Trees)（并行聚合树）** — NCCL 的一种算法（2024 年），用于超大规模下的全收集和规约散射，所需步数呈对数增长，可在每块 GPU 发送数据量很小时降低延迟。*另见：* [树形全规约](#tree-all-reduce)、[NCCL](#nccl)。
- <a id="payback-period"></a>**Payback period（投资回收期）** — 投资带来的累计利润或现金等于所付价格所需的时间。折现回收期先按资本成本对价格进行复利增长，因此耗时更长。
- <a id="pcie"></a>**PCIe (PCI Express)** — 将 GPU、网卡和 SSD 连接到主机 CPU 的标准扩展总线。一条 16 通道（x16）链路的总带宽（双向合计）在 Gen4 上约为 64 GB/s，Gen5 上为 128 GB/s，Gen6 上为 256 GB/s。*另见：* [NVLink-C2C](#nvlink-c2c)、[CXL (Compute Express Link)](#cxl)。
- <a id="pcie-switch"></a>**PCIe switch（PCIe 交换芯片）** — 将一路 PCIe 连接扇出到多个设备（GPU、网卡、SSD）的芯片，使这些设备无需经过 CPU 即可点对点交换数据。ConnectX-8 内置了一颗 PCIe 交换芯片。*另见：* [PCIe (PCI Express)](#pcie)、[GPUDirect RDMA](#gpudirect-rdma)。
- <a id="perf-per-watt"></a>**Perf/W (performance per watt)（每瓦性能）** — 单位功率所完成的有效工作，例如每瓦 FP8 TFLOPS 或每兆瓦每秒 token 数。在电力受限的数据中心，它决定了一个站点能卖出多少算力。*另见：* [总拥有成本（TCO）](#tco)。
- <a id="performance-density"></a>**Performance density（性能密度）** — TPP 除以以 mm² 计的裸片面积。由 2023 年 10 月的规则新增，以防厂商把同样的算力分散到更多硅面积上来规避 TPP 门槛。*另见：* [TPP（总处理性能）](#tpp)。
- <a id="perf-per-dollar"></a>**Performance per dollar（每美元性能）** — 每美元自有成本或租赁价格所对应的有效工作量（例如每秒 token 数）；当定制 ASIC 在峰值性能上落后时，就以这一指标参与竞争。*另见：* [总拥有成本（TCO）](#tco)、[每瓦性能](#perf-per-watt)。
- <a id="photomask"></a>**Photomask（光掩模）** — 承载某一电路层图形的石英板，在光刻中用作模版。一颗先进制程芯片的全套光掩模耗资数百万美元，这也是芯片设计修改成本高昂的原因之一。*另见：* [光刻](#lithography)。
- <a id="physx"></a>**PhysX** — 英伟达于 2008 年通过收购 Ageia 获得的物理引擎，用于游戏、机器人仿真和 Omniverse；现已开源。*另见：* [Omniverse](#omniverse)、[NVIDIA Warp](#nvidia-warp)。
- <a id="picojoules-per-bit"></a>**Picojoules per bit (pJ/bit)（皮焦每比特）** — 通过链路传输一个比特所需的能量，即瓦数除以每秒比特数。基于 DSP 的光模块约为 15-19 pJ/bit，共封装光学约为 5 pJ/bit，而无源铜缆在芯片自身 SerDes 之外几乎不增加功耗。*另见：* [共封装光学（CPO）](#co-packaged-optics)、[线性可插拔光模块（LPO）](#linear-pluggable-optics)、[SerDes](#serdes)。
- <a id="pin-speed"></a>**Pin speed（引脚速率）** — 内存接口每根导线每秒传输的比特数（以 Gb/s 计）。每个堆栈的 HBM 带宽 = 接口宽度 x 引脚速率 / 8；Rubin 的 HBM4 规格修订源于引脚速率低于目标。*另见：* [高带宽内存（HBM）](#hbm)、[HBM4E](#hbm4e)。
- <a id="pipeline-bubble"></a>**Pipeline bubble（流水线气泡）** — 流水线并行中，各阶段等待流水线填满和排空时的空闲时间；对于 p 个阶段和 m 个微批次，约占每一步的 (p − 1)/(m + p − 1)。*另见：* [流水线并行（PP）](#pipeline-parallelism)、[微批次](#micro-batch)。
- <a id="pipeline-parallelism"></a>**Pipeline parallelism (PP)（流水线并行）** — 将模型的各层切分为连续的阶段放在不同 GPU 上，让微批次像装配线一样依次流过；只有激活值跨越阶段边界。*另见：* [流水线气泡](#pipeline-bubble)、[微批次](#micro-batch)。
- <a id="pluggable-transceiver"></a>**Pluggable transceiver（可插拔光模块）** — 插入交换机或网卡端口、将电信号转换为光信号的可拆卸光学模块（例如 800G 或 1.6T OSFP）。易于更换，但需要一颗高功耗 DSP 来驱动信号穿过电路板。*另见：* [共封装光学（CPO）](#co-packaged-optics)、[线性可插拔光模块（LPO）](#linear-pluggable-optics)。
- <a id="post-training"></a>**Post-training（后训练）** — 在原始文本预训练之后对模型所做的一切工作：指令微调、偏好微调和强化学习。在总训练算力中所占比例日益上升。*另见：* [强化学习（RL）](#reinforcement-learning)、[推理型模型](#reasoning-model)。
- <a id="power-shelf"></a>**Power shelf（电源架）** — 一个 1U 的电源抽屉，将建筑的交流电转换为供机架使用的低压直流电；在 GB200 NVL72 中，每个电源架装有六个 5.5 kW 电源模块（最高 33 kW）。*另见：* [母排](#busbar)、[800 V 直流供电架构](#hvdc-800v)。
- <a id="pre-announcement-horizon"></a>**pre-announcement horizon（提前公布期）** — 厂商在产品批量上市前多久公开为其标注日期（名称加目标年份）；本资料库以从首次带日期的提及到计划上市之间的月数来衡量。*另见：* [一年一代节奏](#annual-cadence)、[奥斯本效应](#osborne-effect)。
- <a id="preemption"></a>**Preemption（抢占）** — 调度器停止（通常是重新排队）较低优先级的作业，把其 GPU 让给更高优先级的作业。这使集群可以出借闲置容量，而不会阻塞紧急工作。*另见：* [成组调度](#gang-scheduling)。
- <a id="prefill"></a>**Prefill (context phase)（预填充）** — 推理请求的第一阶段：并行处理整个提示词，以构建 KV 缓存并生成第一个 token。受计算能力限制。*另见：* [解码（decode）](#decode)、[TTFT（首 token 时间）](#ttft)。
- <a id="price-elasticity"></a>**Price elasticity of demand（需求价格弹性）** — 价格变动 1% 时购买量变动的百分比。大于 1（富有弹性）时，降价会增加总支出；小于 1（缺乏弹性）时，降价会减少总支出。*另见：* [杰文斯悖论](#jevons-paradox)。
- <a id="price-umbrella"></a>**Price umbrella（价格保护伞）** — 市场领导者将价格维持在远高于成本的水平所形成的空间：竞争对手可以定价低于它而仍获得回报，领导者则可以有选择地降价来挤压对手。英伟达约 75% 的毛利率就是笼罩 AI 加速器市场的价格保护伞。*另见：* [毛利率](#gross-margin)、[免费芯片测试](#free-chip-test)。
- <a id="pricing-power"></a>**Pricing power（定价权）** — 提价或维持价格而不损失销量的能力。对英伟达而言，它体现为约 75% 的毛利率；竞争对手和自研芯片首先在最大的买家处对其形成制约。*另见：* [价格保护伞](#price-umbrella)。
- <a id="priority-flow-control"></a>**Priority Flow Control (PFC)（基于优先级的流量控制）** — 一种以太网机制：缓冲区填满时通知上游设备暂停某一流量类别，以免丢包。它使以太网能为 RoCE 提供“无损”传输，但若过度使用，暂停可能在整个网络中扩散。*另见：* [RoCE (RDMA over Converged Ethernet)](#roce)、[基于信用的流量控制](#credit-based-flow-control)。
- <a id="process-node"></a>**Process node（工艺节点）** — 一代芯片制造技术（例如台积电 N7、N4、N3、N2、A16）。这些名称是营销标签而非物理尺寸；每个新节点单位面积可容纳更多晶体管，但每片晶圆的价格也更高。*另见：* [晶圆](#wafer)、[晶圆代工厂](#foundry)。
- <a id="programmable-shader"></a>**programmable shader（可编程着色器）** — GPU 对每个顶点或每个像素运行一次的小程序；着色器变得可编程后（GeForce 3，2001 年），GPU 就成为通用并行处理器，这是 CUDA 的前身。*另见：* [GPGPU](#gpgpu)。
- <a id="ptx"></a>**PTX (Parallel Thread Execution)** — 英伟达的虚拟指令集。CUDA 代码先编译为 PTX，再由驱动将 PTX 翻译为每一代 GPU 的原生代码，这就是旧 CUDA 程序能在新 GPU 上运行的原因。*另见：* [CUDA](#cuda)、[GPU 内核](#gpu-kernel)。
- <a id="pue"></a>**PUE (power usage effectiveness)（电能使用效率）** — 设施总电力除以 IT 设备所用电力；1.0 意味着散热和电能转换的开销为零。*另见：* [液冷](#liquid-cooling)。
- <a id="purchase-obligations"></a>**Purchase obligations（采购义务）** — 在公司财报中披露的、未来购买存货、元器件或制造产能的约束性承诺。英伟达的供应与产能承诺在 Q2 FY2027 达到 $279B；它们锁定了稀缺供应，但即使需求下降也必须支付。*另见：* [飞轮](#flywheel)。
- <a id="purchase-vested-warrant"></a>**Purchase-vested warrant（采购挂钩归属认股权证）** — 仅在持有人购买发行人一定金额的产品后才按批次归属的认股权证；供应商借此与大客户分享上行收益。*另见：* [认股权证](#warrant)、[股权换产能](#equity-for-capacity)。
- <a id="pytorch"></a>**PyTorch** — 由 Meta 创建（2016-17 年）的开源深度学习框架，现为 AI 研究的默认框架。模型用 Python 编写一次，再由各厂商后端（首先是 CUDA，其后是 ROCm、TPU 等）运行。*另见：* [Triton (OpenAI)](#triton)、[XLA](#xla)。
## Q

- <a id="quadratic-surfaces"></a>**quadratic surfaces（二次曲面）** — 一种用二阶方程描述的曲面片来绘制 3D 形状的方法，英伟达首款芯片（NV1）采用了这一方法，而非业界后来标准化的平面三角形。*另见：* [Direct3D](#direct3d)。
- <a id="quantization"></a>**Quantization（量化）** — 以更少的比特数存储和计算每个数值（例如以 FP8 或 FP4 取代 BF16）。可降低每个 token 的内存和带宽需求，但存在一定的精度风险。*另见：* [FP8](#fp8)、[NVFP4](#nvfp4)。
## R

- <a id="rack-scale-system"></a>**Rack-scale system（机架级系统）** — 作为整个机架（计算托盘、交换托盘、电源架、布线和液冷）而非单台服务器来设计和销售的 AI 计算机，使数十个加速器像一台机器那样协同工作。英伟达的 NVL72、AMD 的 Helios 和 AWS 的 UltraServer 都是例子。*另见：* [纵向扩展（scale-up）](#scale-up)、[NVLink](#nvlink)、[液冷](#liquid-cooling)。
- <a id="rail-optimized"></a>**Rail-optimized topology（轨道优化拓扑）** — 一种集群布线方式：每台服务器的第 k 号网卡都连接到同一个“轨道”叶交换机，使不同服务器上编号相同的 GPU 之间只隔一跳交换。这与集合通信库搬运数据的方式相匹配。*另见：* [胖树](#fat-tree)、[NCCL](#nccl)。
- <a id="rapids"></a>**RAPIDS** — 英伟达于 2018 年推出的开源 GPU 数据科学库套件（cuDF、cuML、cuGraph、cuVS 等），对应 pandas 和 scikit-learn 等流行的 Python 工具。*另见：* [cuDF](#cudf)、[cuML](#cuml)。
- <a id="rccl"></a>**RCCL** — AMD 的 ROCm 集合通信库（ROCm Communication Collectives Library），源自 NCCL 的代码和 API，通过 Infinity Fabric 及网络在 Instinct GPU 上执行集合通信。*另见：* [NCCL](#nccl)、[ROCm](#rocm)。
- <a id="rdma"></a>**RDMA (remote direct memory access)（远程直接内存访问）** — 一台机器的网卡直接读写另一台机器内存的方式，双方操作系统都无需复制数据。它降低了延迟和 CPU 负担，这正是 AI 集群用它承载 GPU 间流量的原因。*另见：* [RoCE (RDMA over Converged Ethernet)](#roce)、[GPUDirect RDMA](#gpudirect-rdma)、[InfiniBand](#infiniband)。
- <a id="reasoning-model"></a>**Reasoning model（推理型模型）** — 经训练（通常借助强化学习）在作答前先生成一段隐藏思维链的模型。在难题上回答质量更高，代价是生成的 token 大幅增加。*另见：* [测试时计算](#test-time-compute)、[强化学习（RL）](#reinforcement-learning)。
- <a id="recommendation-model"></a>**Recommendation model（推荐模型）** — 为每个用户对广告、帖子或商品进行排序的模型（例如 DLRM）。其主要负载是大规模嵌入表查找，而非 LLM 的稠密矩阵运算，因此青睐不同的芯片设计。*另见：* [MTIA](#mtia)。
- <a id="redistribution-layer"></a>**Redistribution layer (RDL)（重布线层）** — 在有机或硅基底之上制作的薄层金属布线，用于在裸片之间以及向封装连接点传递信号；比芯片内部布线粗，但远比电路板精细。*另见：* [CoWoS-R](#cowos-r)、[CoWoS-L](#cowos-l)、[中介层](#interposer)。
- <a id="reduce-scatter"></a>**Reduce-scatter（规约散射）** — 一种集合通信操作：各 GPU 对各自的向量求和，但每块 GPU 只保留结果中属于自己的那一片；是环形全规约的前半部分。*另见：* [全规约](#all-reduce)、[全收集](#all-gather)。
- <a id="reference-architecture"></a>**Reference architecture（参考架构）** — 由厂商指定并经测试的物料清单和配置（服务器、网络、存储、软件），合作伙伴可将其作为完整系统报价和提供支持。英伟达的企业版称为“验证设计”（validated design）。*另见：* [NVIDIA AI Enterprise](#nvidia-ai-enterprise)、[RTX PRO 服务器](#rtx-pro-server)。
- <a id="reference-design"></a>**Reference design（参考设计）** — 平台所有者发布的完整、有文档的设计，使合作伙伴能迅速打造兼容产品（英伟达的 HGX、MGX 和 DGX SuperPOD 架构都是参考设计）。*另见：* [MGX](#mgx)、[HGX](#hgx)。
- <a id="register-file"></a>**Register file（寄存器堆）** — GPU 上最快的存储：每个 SM 有 256 KB 寄存器，保存线程当前正在处理的数值。它紧邻算术单元，每个时钟周期为其供数。*另见：* [共享内存](#shared-memory)、[流式多处理器（SM）](#streaming-multiprocessor)。
- <a id="registered-developer"></a>**Registered developer（注册开发者）** — 已加入英伟达开发者计划的人员。该数字是累计且自行申报的，因此衡量的是覆盖面，而非当前有多少人在积极编写 CUDA 代码。*另见：* [CUDA](#cuda)。
- <a id="reinforcement-learning"></a>**Reinforcement learning (RL)（强化学习）** — 通过试错和奖励进行训练：模型生成许多候选答案，对其评分（例如检查数学结果或运行代码），再朝更好的答案更新模型。强化学习运行包含大量推理工作负载。*另见：* [后训练](#post-training)、[推理型模型](#reasoning-model)。
- <a id="residual-value"></a>**Residual value（残值）** — 资产在使用期结束时可出售的价格。旧 GPU 若仍有正的转售价格，其真实成本就会降低；租赁价格下跌会压低残值，并可能导致资产减值。*另见：* [经济寿命](#economic-life)、[GPU 抵押贷款](#gpu-backed-loan)。
- <a id="reticle-limit"></a>**Reticle limit（光罩尺寸极限）** — 光刻机单次曝光的最大面积（现有 EUV 设备约为 858 mm²），它限制了单颗裸片的尺寸，迫使设计者转向多裸片封装。*另见：* [裸片](#die)。
- <a id="retimer"></a>**Retimer（重定时器）** — 接收衰减后的高速信号、恢复数据并重新干净地发送的芯片，可延长铜缆链路的传输距离。常见于 PCIe 和 CXL 链路；Astera Labs 是领先供应商。*另见：* [有源电缆（AEC）](#active-electrical-cable)、[SerDes](#serdes)。
- <a id="revenue-backlog"></a>**Revenue backlog（收入积压）** — 公司已签合同但尚未交付的收入（常称剩余履约义务）。它体现的是需求可见度，而非现金：合同可能被推迟或重新谈判。*另见：* [照付不议合同](#take-or-pay)。
- <a id="revenue-by-customer-hq"></a>**Revenue by customer headquarters（按客户总部所在地划分的收入）** — 按客户总部所在国家（而非开票地）划分的地区收入。英伟达在 Q3 FY2026 改用这一口径，使中国的报告占比上升。*另见：* [出口管制](#export-controls)。
- <a id="reverse-dcf"></a>**Reverse DCF（反向 DCF）** — 从当前市值倒推其隐含的增长率或利润率，而非预测现金流再推导估值；最简单的形式是 P/E = 1 / (股权成本 - 增长率)。*另见：* [远期市盈率](#forward-pe)。
- <a id="ridge-point"></a>**Ridge point（屋脊点）** — 芯片从内存受限转为计算受限时的算术强度：峰值 FLOPS 除以内存带宽。H100 在稠密 BF16 下约为每字节 295 FLOPs。*另见：* [屋顶线模型](#roofline-model)、[算术强度](#arithmetic-intensity)。
- <a id="ring-all-reduce"></a>**Ring all-reduce（环形全规约）** — 一种全规约算法，在 GPU 组成的环上依次传递数据块；无论参与的 GPU 有多少，每块 GPU 发送的数据量约为数据大小的两倍。*另见：* [全规约](#all-reduce)。
- <a id="risc-v"></a>**RISC-V** — 任何人都可实现的开放、免版税指令集。Ventana、Rivos、Tenstorrent 和 Akeana 等初创公司设计高性能 RISC-V 核心，作为 Arm 的替代方案。*另见：* [ISA（指令集架构）](#isa)、[Arm 指令集](#arm-isa)。
- <a id="risk-heatmap"></a>**Risk heatmap（风险热力图）** — 按可能性（x 轴）和影响（y 轴）为每项风险定位的网格，两项通常各按 1-5 分打分；二者的乘积决定哪些风险最值得优先关注。*另见：* [领先指标](#leading-indicator)。
- <a id="roce"></a>**RoCE (RDMA over Converged Ethernet)** — 承载于以太网数据包中的 RDMA（RoCEv2 使用 UDP/IP）。它将 InfiniBand 式的直接内存传输带到以太网上，但由于以太网在繁忙时本就设计为丢包，因此需要精心的拥塞控制。*另见：* [RDMA（远程直接内存访问）](#rdma)、[PFC（基于优先级的流量控制）](#priority-flow-control)、[拥塞控制](#congestion-control)。
- <a id="rocm"></a>**ROCm** — AMD 的开源 GPU 软件栈（驱动、编译器、库、HIP），2016 年首次发布。是 AMD 对标 CUDA 的方案。*另见：* [HIP](#hip)、[CUDA](#cuda)。
- <a id="roofline-model"></a>**Roofline model（屋顶线模型）** — 描述芯片可达速度的简单图表：取峰值算力（平顶）与“内存带宽 × 工作负载算术强度”（斜线）中的较小者。它让人一眼看出工作负载受计算还是受内存限制。*另见：* [算术强度](#arithmetic-intensity)、[屋脊点](#ridge-point)。
- <a id="rtx-pro-server"></a>**RTX PRO server（RTX PRO 服务器）** — 搭载英伟达 RTX PRO 6000 Blackwell Server Edition GPU 的风冷 x86 服务器，自 2025 年起由 OEM 销售，面向无法部署液冷机架级系统的企业。*另见：* [参考架构](#reference-architecture)。
- <a id="rubin-cpx"></a>**Rubin CPX** — 英伟达于 2025 年 9 月发布、面向推理预填充（上下文）阶段的 GPU，配备 128 GB GDDR7 而非 HBM。它未出现在 2026 年 3 月的路线图中；有报道称其将以 HBM4 版本回归，但尚未证实。*另见：* [预填充（prefill）](#prefill)、[分离式推理服务](#disaggregated-serving)、[GDDR](#gddr)。
- <a id="rubin-ultra"></a>**Rubin Ultra** — 英伟达 2027 年的 GPU 世代，发布时宣称每个封装含四颗光罩尺寸裸片、约 100 PFLOPS FP4 算力和 1 TB HBM4E，用于 Kyber 机架；2026 年的报道描述的是双裸片、768 GB 的版本。*另见：* [Kyber](#kyber)、[HBM4E](#hbm4e)。
- <a id="run-ai"></a>**Run:ai** — 以色列 GPU 编排软件公司，英伟达于 2024 年将其收购（据报约 $700M）；其平台在团队之间池化 GPU，并于 2026 年 10 月完全开源。*另见：* [KAI Scheduler](#kai-scheduler)、[NVIDIA Mission Control](#mission-control)。
## S

- <a id="same-year-flagship"></a>**Same-year flagship（同年旗舰）** — 本资料库差距图表采用的约定：某一日历年中批量出货的英伟达数据中心 GPU（2023 年 H100、2024 年 H200、2025 年 GB300、2026 年 Rubin），作为 100% 基准。
- <a id="samr"></a>**SAMR（国家市场监督管理总局）** — 中国国家市场监督管理总局。其反垄断局审查在华销售额较大的公司之间的合并，可附条件批准、拖延或否决交易。*另见：* [行为性救济措施](#behavioural-remedy)。
- <a id="sass"></a>**SASS** — 某一英伟达 GPU 家族的真实机器码（例如 Hopper 的 sm_90）。ptxas 汇编器将 PTX 转换为 SASS；与 PTX 不同，某一代的 SASS 通常无法在下一代上运行。*另见：* [PTX (Parallel Thread Execution)](#ptx)、[nvcc](#nvcc)。
- <a id="scale-across"></a>**Scale-across（跨数据中心扩展）** — 连接位于不同数据中心（相距数十到数千公里）的 AI 集群，使其能协同完成同一作业；英伟达的 Spectrum-XGS 瞄准的正是这一需求。*另见：* [横向扩展（scale-out）](#scale-out)。
- <a id="scale-out"></a>**Scale-out（横向扩展）** — 通过数据中心网络（InfiniBand 或以太网）连接大量纵向扩展域或服务器，以集群规模进行训练或推理。*另见：* [纵向扩展（scale-up）](#scale-up)、[跨数据中心扩展（scale-across）](#scale-across)。
- <a id="scale-up"></a>**Scale-up（纵向扩展）** — 以极快的内存语义互连（NVLink、ICI、Infinity Fabric）将一组加速器紧密耦合，使其表现得像一块大型 GPU。*另见：* [横向扩展（scale-out）](#scale-out)、[NVLink](#nvlink)。
- <a id="scale-up-ethernet"></a>**Scale-Up Ethernet (SUE)（纵向扩展以太网）** — 博通于 2025 年贡献给 OCP 的框架，用于把 Tomahawk Ultra 等以太网交换机用作纵向扩展网络。它增加了链路层重传和基于信用的流量控制，使短小、无损的传输能够在以太网上运行。*另见：* [ESUN (Ethernet for Scale-Up Networking)](#esun)、[链路层重传（LLR）](#link-layer-retry)、[基于信用的流量控制](#credit-based-flow-control)。
- <a id="scaling-laws"></a>**Scaling laws（缩放定律）** — 经验性发现：随着参数、数据和算力的增加，模型质量会以可预测的方式（幂律）提升。它为不断扩大的训练预算提供了依据。*另见：* [Chinchilla 最优](#chinchilla-optimal)、[过度训练](#over-training)。
- <a id="second-source"></a>**Second source（第二供应商）** — 承担同一任务的合格替代供应商。买家保留第二供应商以争取价格让步，并在主供应商缺货或延期时保障供应；只有当第二供应商的产品足够好、能承接实际销量时，这一策略才奏效。*另见：* [转换成本](#switching-cost)、[钱包份额](#share-of-wallet)。
- <a id="sequence-parallelism"></a>**Sequence parallelism（序列并行）** — 英伟达与张量并行配套的技术，沿序列维度拆分 LayerNorm 等操作，在不增加通信的情况下节省激活值内存；与上下文并行不同。*另见：* [张量并行（TP）](#tensor-parallelism)、[上下文并行（CP）](#context-parallelism)。
- <a id="serdes"></a>**SerDes** — 串行器/解串器（Serializer/deserializer）：将大量片上并行信号转换为少数几条极高速串行通道（目前每条 100–200 Gb/s）并反向转换的电路。端口速率 = 通道数 × 单通道速率。*另见：* [交换机端口数](#switch-radix)。
- <a id="serving-engine"></a>**Serving engine（推理服务引擎）** — 为用户运行已训练模型的软件：它对请求进行批处理、管理 KV 缓存并调用 GPU 内核。例如 vLLM、SGLang 和英伟达 TensorRT-LLM。*另见：* [vLLM](#vllm)、[SGLang](#sglang)、[TensorRT-LLM](#tensorrt-llm)。
- <a id="sglang"></a>**SGLang** — 与 vLLM 竞争的开源 LLM 推理服务引擎，擅长结构化生成和大型混合专家模型；支持英伟达、AMD、TPU 和昇腾硬件。*另见：* [vLLM](#vllm)。
- <a id="share-of-wallet"></a>**Share of wallet（钱包份额）** — 客户在某一类别的总支出中流向某一家供应商的比例。销售机架、网络、CPU 和软件（而不仅是 GPU）提高了英伟达在每一美元数据中心支出中的份额。*另见：* [NVLink Fusion](#nvlink-fusion)。
- <a id="shared-memory"></a>**Shared memory (L1)（共享内存）** — 每个 SM 内部的高速片上 SRAM（H100 和 B200 上为 256 KB，在 L1 缓存与程序员管理的共享内存之间分配），内核在此暂存矩阵分块，使张量核心能重复使用多次。*另见：* [寄存器堆](#register-file)、[L2 缓存](#l2-cache)。
- <a id="sharp"></a>**SHARP (in-network reduction)** — 英伟达的可扩展分层聚合与规约协议（Scalable Hierarchical Aggregation and Reduction Protocol）：交换机在数据经过时将多块 GPU 的数据相加，使全规约中每块 GPU 只需发送一次数据，而非约两次。Quantum InfiniBand 和 NVLink 交换机均支持该功能。*另见：* [全规约](#all-reduce)、[网内计算](#in-network-computing)。
- <a id="signpost"></a>**Signpost（路标）** — 预先约定的可观察事件或指标阈值，用于判断正在展开的是哪种情景，例如定制 ASIC 收入超过英伟达数据中心收入的 25%。路标把情景分析转化为复盘的触发条件。*另见：* [领先指标](#leading-indicator)。
- <a id="silicon-photonics"></a>**Silicon photonics（硅光子）** — 用芯片制造工具在硅晶圆上制作光学元件（调制器、波导、探测器），使光链路能够批量制造，并紧邻电子芯片放置。*另见：* [共封装光学（CPO）](#co-packaged-optics)。
- <a id="smt"></a>**Simultaneous multithreading (SMT)（同时多线程）** — 一种 CPU 功能，让两个（或更多）硬件线程共享同一核心的执行单元，从而在一个核心上同时运行，以单线程速度的可预测性下降为代价提高总吞吐量。英特尔称之为超线程（Hyper-Threading）。*另见：* [空间多线程](#spatial-multithreading)。
- <a id="slurm"></a>**Slurm** — 开源的批处理调度器，在大多数超级计算机和许多 AI 训练集群上负责作业排队和放置。其开发商 SchedMD 于 2025 年 12 月被英伟达收购。*另见：* [Kubernetes](#kubernetes)、[成组调度](#gang-scheduling)。
- <a id="sm-utilization"></a>**SM utilization（SM 利用率）** — GPU 流式多处理器实际的繁忙程度，由 DCGM 等遥测工具测量。一块 GPU 可能已被分配，并在简单工具中显示 100%“利用率”，而其 SM 大部分时间却处于空闲。*另见：* [分配率](#allocation-ratio)、[MFU（模型 FLOPs 利用率）](#mfu)、[DCGM](#dcgm)。
- <a id="smartnic"></a>**SmartNIC（智能网卡）** — 将部分数据包处理（例如虚拟交换或加密）从 CPU 上卸载的网卡；DPU 是带有通用处理器核心的 SmartNIC。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="socamm"></a>**SOCAMM** — 一种紧凑、可更换的内存模块，承载 LPDDR5X 芯片，与 Vera 搭配使用，使低功耗内存能像普通 DIMM 一样维护更换。*另见：* [LPDDR5X](#lpddr5x)。
- <a id="software-port"></a>**Software port（软件移植版）** — 在兼容接口之后重新实现另一厂商的库（例如对应 NCCL 的 RCCL、对应 cuDF 的 hipDF）。移植版降低了采用门槛，但每次都要在原版发布后才能跟进复制，因而总是落后一步。*另见：* [HIP](#hip)、[RCCL](#rccl)。
- <a id="solid-state-transformer"></a>**Solid-state transformer (SST)（固态变压器）** — 由 SiC 或 GaN 开关器件构成的电力电子变换器，取代笨重的铜铁变压器，将中压电网电力直接转换为下一代 AI 机架所用的 800 V 直流电。*另见：* [800 V 直流供电架构](#hvdc-800v)。
- <a id="sovereign-ai"></a>**Sovereign AI（主权 AI）** — 由国家建设或出资（或为国家建设）的 AI 基础设施，使数据、模型和算力处于本国掌控之下；通常通过本土新兴云服务商或电信运营商交付。*另见：* [ACIE](#acie)、[新兴云服务商（neocloud）](#neocloud)。
- <a id="sparsity"></a>**Sparsity (2:4 structured)（2:4 结构化稀疏）** — 一种硬件技巧：每四个权重中有两个为零，使张量核心可以跳过它们，从而使标称峰值 FLOPS 翻倍。英伟达的宣传数字常以此为前提；稠密数字则不然。*另见：* [FLOPS](#flops)、[张量核心](#tensor-core)。
- <a id="spatial-multithreading"></a>**Spatial Multithreading（空间多线程）** — 英伟达对其 Vera CPU 每核双线程方案的命名；英伟达称它在两个线程之间划分每个核心的资源，使单线程性能比传统 SMT 更可预测。*另见：* [同时多线程（SMT）](#smt)。
- <a id="spectrum-x"></a>**Spectrum-X** — 英伟达面向 AI 集群的以太网平台，将 Spectrum 交换机与 SuperNIC 及自适应路由相结合，在以太网上逼近 InfiniBand 级别的性能。*另见：* [InfiniBand](#infiniband)、[横向扩展（scale-out）](#scale-out)。
- <a id="spectrum-xgs"></a>**Spectrum-XGS** — 英伟达 2025 年对 Spectrum-X 以太网的扩展，面向“跨数据中心扩展”（scale-across）：提供距离感知的拥塞控制和延迟管理算法，使不同数据中心的 GPU 网络能像一个整体那样运作。*另见：* [Spectrum-X](#spectrum-x)、[跨数据中心扩展（scale-across）](#scale-across)。
- <a id="speculative-decoding"></a>**Speculative decoding（推测解码）** — 由小型草稿模型提出若干个 token，大模型一次性验证并保留正确的部分。在解码受内存限制时，可在输出完全相同的情况下提速 2-3 倍。*另见：* [解码（decode）](#decode)。
- <a id="spv-financing"></a>**SPV financing（SPV 融资）** — 通过主要由外部投资者持有的特殊目的载体或合资企业为数据中心融资，使大部分债务不进入运营方的资产负债表（例如 Meta 的 Hyperion）。*另见：* [循环融资](#circular-financing)。
- <a id="sram"></a>**SRAM** — 静态随机存取存储器（Static RAM）：直接集成在处理器裸片上的极高速存储器。它带宽极高，但每平方毫米的容量很小，因此以 SRAM 为主的芯片（Groq、Cerebras、d-Matrix）以容量换速度。*另见：* [高带宽内存（HBM）](#hbm)、[语言处理单元（LPU）](#lpu)、[晶圆级引擎](#wafer-scale)。
- <a id="srd"></a>**SRD (Scalable Reliable Datagram)（可扩展可靠数据报）** — AWS 自研的传输协议，供 EFA 使用，将数据包喷洒到多条网络路径上，并在硬件中恢复丢包。*另见：* [EFA (Elastic Fabric Adapter)](#efa)、[数据包喷洒](#packet-spraying)。
- <a id="stack-breadth"></a>**Stack breadth（技术栈广度）** — 在本资料库中，指竞争对手在英伟达十二个技术栈层级（02-13）中得分不低于 3 分（满分 5 分）的层数。深度则指其在最强层级中的实力。*另见：* [垂直整合](#vertical-integration)。
- <a id="stack-height"></a>**Stack height（堆叠层数）** — 一个 HBM 堆栈中堆叠的 DRAM 裸片数量（8 层、12 层或 16 层）。层数乘以裸片密度决定容量：十二颗 24 Gb 裸片为 36 GB，十六颗 32 Gb 裸片为 64 GB。*另见：* [高带宽内存（HBM）](#hbm)、[引脚速率](#pin-speed)、[硅通孔（TSV）](#through-silicon-via)。
- <a id="steelman"></a>**Steelman（钢人论证）** — 对你可能不认同的观点，以现有最佳证据构建出的最有力、最诚实的版本，与容易驳倒的“稻草人”相对。*另见：* [风险热力图](#risk-heatmap)。
- <a id="storage-tiering"></a>**Storage tiering（存储分层）** — 把数据放在一个由小而快（HBM）到大而慢（共享闪存）的存储阶梯上，并按需在各层之间上下移动；英伟达将 KV 缓存的各层标记为 G1 到 G4。*另见：* [KV 缓存卸载](#kv-cache-offload)、[推理上下文内存存储](#context-memory-storage)。
- <a id="straggler"></a>**Straggler（掉队者）** — 完成得较晚、使同步步骤中其他所有参与者都必须等待的 GPU、链路或数据流。原因包括路径拥塞、硬件缓慢或故障，以及工作量分配不均。*另见：* [尾延迟](#tail-latency)。
- <a id="straight-line-depreciation"></a>**Straight-line depreciation（直线折旧）** — 将资产成本在其使用寿命内平均分摊（例如一块 $70K 的 GPU 分六年折旧 = 每年约 $11.7K）。它忽略了融资成本，而资本回收系数会将其计入。*另见：* [使用寿命](#useful-life)、[资本回收系数](#capital-recovery-factor)。
- <a id="streaming-multiprocessor"></a>**Streaming multiprocessor (SM)（流式多处理器）** — 英伟达 GPU 中重复出现的基本构建单元：一组 CUDA 核心、四个张量核心、一个寄存器堆以及自有的 L1/共享内存。H100 有 132 个 SM，Rubin GPU 有 224 个。*另见：* [张量核心](#tensor-core)、[CUDA 核心](#cuda-core)、[图形处理簇（GPC）](#gpc)。
- <a id="subnet-manager"></a>**Subnet manager（子网管理器）** — InfiniBand 的控制软件，负责发现每台交换机和适配器、分配地址并计算整个网络的路由表。这使 InfiniBand 成为集中管理的网络，而不像以太网那样自组织。*另见：* [InfiniBand](#infiniband)。
- <a id="superchip"></a>**Superchip（超级芯片）** — 英伟达对以 NVLink-C2C 将一颗 CPU 与一到两块 GPU 连接在同一模块上的产品的称呼，例如 GH200（一颗 Grace、一块 Hopper）或 GB200（一颗 Grace、两块 Blackwell）。*另见：* [NVLink-C2C](#nvlink-c2c)。
- <a id="supernic"></a>**SuperNIC** — 英伟达对专为 GPU 间流量调优的网络适配器的称呼（ConnectX-8/9、BlueField-3 SuperNIC）：在硬件中实现 RDMA、拥塞控制以及对喷洒数据包的重排序，通常每块 GPU 配一块。*另见：* [RDMA（远程直接内存访问）](#rdma)、[数据包喷洒](#packet-spraying)、[Spectrum-X](#spectrum-x)。
- <a id="superpod"></a>**SuperPoD（超节点）** — 厂商对作为一个整体销售的多机架 AI 系统的称呼：英伟达的 DGX SuperPOD（例如八个 GB200 NVL72 机架）或华为的 Atlas 超节点（SuperPoD，在一个纵向扩展域中集成数千颗昇腾芯片）。*另见：* [DGX](#dgx)、[纵向扩展（scale-up）](#scale-up)。
- <a id="prepayment"></a>**Supply prepayment（供应预付款）** — 买方为预留未来产能或产出而预先支付给供应商的现金；在买方资产负债表上列为预付资产，若需求崩塌则可能无法收回。*另见：* [采购义务](#purchase-obligations)、[长期协议（LTA）](#long-term-agreement)。
- <a id="supply-constrained"></a>**Supply-constrained（供给受限）** — 供应商能卖出其全部产出的市场。在这种情况下，失去一个客户短期内损失不大，因为产能会转售给其他客户。*另见：* [毛利率](#gross-margin)。
- <a id="switch-radix"></a>**Switch radix（交换机端口数）** — 交换机在给定速率下的端口数量（radix）。端口数越高，每层可连接的端点越多，同等规模的集群所需的层数、跳数和光模块都越少。*另见：* [胖树](#fat-tree)。
- <a id="switching-cost"></a>**Switching cost（转换成本）** — 客户转向竞争对手产品所承担的资金、时间和风险，此处指把内核、工具和团队技能从 CUDA 移植并重新验证到另一技术栈。*另见：* [硬件拉动](#pull-through)、[转译层](#translation-layer)。
- <a id="sycl"></a>**SYCL** — Khronos 组织的开放标准，用于编写可在不同厂商的 CPU、GPU 和加速器上运行的 C++ 代码。英特尔的 oneAPI 即基于它构建。*另见：* [oneAPI](#oneapi)。
- <a id="system-on-chip"></a>**system-on-chip（片上系统）** — 在单颗芯片上集成 CPU 核心、图形、内存控制器及其他功能，用于手机和平板电脑（例如英伟达的 Tegra）。*另见：* [基带调制解调器](#baseband-modem)。
- <a id="systolic-array"></a>**Systolic array（脉动阵列）** — 由乘累加单元组成的网格，数据以固定节拍流经其中，每个单元把结果传给相邻单元。谷歌 TPU 的矩阵单元是 128×128 或 256×256 的脉动阵列：处理大矩阵极其高效，但对不规则形状不够灵活。*另见：* [ASIC](#asic)。
## T

- <a id="tail-latency"></a>**Tail latency（尾延迟）** — 最慢那部分消息的延迟（例如第 99 或第 99.9 百分位），而非平均值。在同步 AI 训练中，整个步骤都要等待最慢的传输完成，因此决定节奏的是尾部而非均值。*另见：* [掉队者](#straggler)、[集合通信操作](#collective-operation)。
- <a id="take-or-pay"></a>**Take-or-pay contract（照付不议合同）** — 买方无论是否使用都须为预留容量付费的合同。新兴云服务商与 AI 实验室和超大规模云厂商签订多年期照付不议合同，再以此为担保借款。*另见：* [收入积压](#revenue-backlog)、[GPU 抵押贷款](#gpu-backed-loan)。
- <a id="tape-out"></a>**Tape-out（流片）** — 完成的芯片设计交付晶圆代工厂制作光掩模和首批晶圆的时刻。流片失败会耽误数月，并在掩模上损失数千万美元。*另见：* [NRE（一次性工程费用）](#nre)、[光掩模](#photomask)。
- <a id="tco"></a>**TCO (total cost of ownership)（总拥有成本）** — 基础设施在整个生命周期内的全口径运行成本：资本成本（折旧）加上电力、散热、空间、网络、软件和运维。在 AI 领域常折算为每百万 token 的美元成本。
- <a id="tdisp"></a>**TDISP** — PCI-SIG 的 TEE 设备接口安全协议（TEE Device Interface Security Protocol）：以经认证的加密链路（而非软件中转缓冲区）将 PCIe 设备（GPU、网卡、SSD）纳入 CPU 机密虚拟机的标准方式。*另见：* [可信执行环境（TEE）](#trusted-execution-environment)、[AMD SEV-SNP](#sev-snp)、[Intel TDX](#intel-tdx)。
- <a id="telemetry"></a>**Telemetry (network)（网络遥测）** — 持续测量网络和网卡内部的流量、拥塞、错误和延迟，用于发现掉队者并调优拥塞控制。*另见：* [数据处理器（DPU）](#dpu)。
- <a id="tensor-core"></a>**Tensor core（张量核心）** — 英伟达 GPU 内部的专用单元，一步完成小矩阵乘法，提供 GPU 的大部分 AI 吞吐量。随 Volta（2017 年）推出。*另见：* [GPU](#gpu)、[FLOPS](#flops)。
- <a id="tensor-memory"></a>**Tensor memory (TMEM)（张量内存）** — Blackwell 引入的每个 SM 256 KB 的暂存存储，保存张量核心的累加器和操作数，从而释放寄存器，并持续为更大的张量核心供数。*另见：* [张量核心](#tensor-core)、[寄存器堆](#register-file)。
- <a id="tma"></a>**Tensor Memory Accelerator (TMA)（张量内存加速器）** — Hopper 时代引入的硬件单元，在后台于 HBM/L2 与共享内存之间复制张量的整个分块，使线程能继续计算，而不必逐个发出加载指令。*另见：* [共享内存](#shared-memory)。
- <a id="tensor-parallelism"></a>**Tensor parallelism (TP)（张量并行）** — 将每层的权重矩阵拆分到多块 GPU 上，由它们共同计算同一层；每层内部都需要一次全规约，因此通常限制在高速的 NVLink 域内。*另见：* [NVLink](#nvlink)、[全规约](#all-reduce)。
- <a id="tensorrt"></a>**TensorRT** — 英伟达的推理优化器和运行时：接收训练好的模型，融合并量化其运算，生成针对特定英伟达 GPU 调优的引擎。TensorRT-LLM 是其大语言模型分支。*另见：* [cuDNN](#cudnn)、[GPU 内核](#gpu-kernel)。
- <a id="tensorrt-llm"></a>**TensorRT-LLM** — 英伟达用于在其 GPU 上高速运行大语言模型的开源库：定制内核，加上连续批处理、分页 KV 缓存、FP8/FP4 量化和推测解码等运行时功能。*另见：* [TensorRT](#tensorrt)、[Dynamo](#dynamo)、[连续批处理](#continuous-batching)。
- <a id="test-time-compute"></a>**Test-time compute（测试时计算）** — 为每个查询投入更多推理计算（更长的推理链、多次尝试、搜索）以获得更好的答案，而非训练更大的模型。*另见：* [推理型模型](#reasoning-model)、[智能体 AI](#agentic-ai)。
- <a id="tf32"></a>**TF32 (TensorFloat-32)** — Ampere 引入的 19 位张量核心格式，保留 FP32 的数值范围，但只有 10 位尾数，使 FP32 代码无需修改即可使用张量核心；数值仍以 32 位存储。*另见：* [BF16 (bfloat16)](#bf16)、[FP8](#fp8)。
- <a id="thread-block"></a>**Thread block（线程块）** — 最多 1,024 个 GPU 线程组成的一组，在同一个 SM 上运行，共享高速片上存储，并可相互同步。一次内核启动即由线程块构成的网格。*另见：* [CUDA 网格](#cuda-grid)、[线程束](#warp)、[共享内存](#shared-memory)。
- <a id="through-silicon-via"></a>**Through-silicon via (TSV)（硅通孔）** — 蚀刻穿过减薄硅裸片的垂直铜导线，使堆叠的裸片能直接上下传递数据、电源和接地。每颗裸片上数以千计的 TSV 使 HBM 堆栈成为可能。*另见：* [高带宽内存（HBM）](#hbm)、[HBM 基础裸片](#hbm-base-die)、[微凸块](#microbump)。
- <a id="pareto-frontier"></a>**Throughput-interactivity Pareto frontier（吞吐量-交互速度帕累托前沿）** — 在每个单用户 tokens/s（交互速度）下所能达到的最佳单 GPU tokens/s（吞吐量）所构成的曲线。比较硬件和软件代际时，看的是它们把整条曲线向外推了多远。*另见：* [批处理](#batching)、[TPOT/ITL](#tpot)。
- <a id="tilelang"></a>**TileLang** — tile-ai 项目推出的开源 Python 内核语言，用于 DeepSeek 的注意力内核。它支持英伟达 CUDA、AMD ROCm 和苹果 Metal，并自 2026 年 9 月起支持华为昇腾 950。*另见：* [Triton (OpenAI)](#triton)、[MLIR](#mlir)。
- <a id="time-to-power"></a>**Time to power（通电时间）** — 数据中心站点从向电力公司提出申请到获得通电容量所需的时间。对 AI 项目而言，它往往比建造厂房本身还要长。*另见：* [并网排队](#interconnection-queue)、[表后发电](#behind-the-meter)。
- <a id="time-to-train"></a>**Time to train（训练时长）** — 一次训练运行在给定集群上所需的日历天数。更快的芯片或更大的集群可以缩短它；对前沿实验室而言，提早发布模型的价值可能高于算力账单。*另见：* [MFU（模型 FLOPs 利用率）](#mfu)、[有效吞吐量](#goodput)。
- <a id="token"></a>**Token（词元）** — 语言模型读写文本的基本单位，大约相当于四分之三个英文单词。AI 经济学越来越多地以每秒 token 数和每百万 token 的美元成本来计量。
- <a id="token-price-deflation"></a>**Token price deflation（token 价格通缩）** — 达到固定模型质量所需的每百万 token 价格快速下降，视任务不同估计每年下降 9 倍至 900 倍；前沿模型的标价并不总是下降。*另见：* [混合 token 价格](#blended-token-price)。
- <a id="token-parity-rent"></a>**Token-parity rent（token 平价租金）** — 租用旧款加速器时，使其每 token 成本与最新一代持平的小时价格。当新芯片降低每 token 成本时，旧芯片的平价租金随之下降，从而拉低租赁价格。*另见：* [经济寿命](#economic-life)、[token 价格通缩](#token-price-deflation)。
- <a id="tokens-per-megawatt"></a>**Tokens per second per megawatt（每兆瓦每秒 token 数）** — AI 工厂的产出指标：在给定单用户速度下，集群每消耗一兆瓦电力每秒生成多少 token。它把固定的电力预算转化为收入产能。*另见：* [AI 工厂](#ai-factory)、[吞吐量-交互速度帕累托前沿](#pareto-frontier)、[token](#token)、[交互速度（每用户 tokens/s）](#interactivity)、[每瓦性能](#perf-per-watt)。
- <a id="topology-aware-scheduling"></a>**Topology-aware scheduling（拓扑感知调度）** — 依据物理网络放置作业的 GPU：例如把一个张量并行组保持在同一个 NVLink 域或同一个机架内，使其大流量永远不必经过较慢的链路。*另见：* [成组调度](#gang-scheduling)、[GPU 碎片化](#gpu-fragmentation)。
- <a id="tops"></a>**TOPS (tera-operations per second)（每秒万亿次运算）** — 每秒万亿次运算，通常指整数（INT8）运算；是 NPU 和边缘 AI 芯片的标称指标。它与按浮点格式标注的 FLOPS 不能直接比较。*另见：* [FLOPS](#flops)。
- <a id="torch-compile"></a>**torch.compile** — PyTorch 2 的编译器：捕获模型的运算并生成融合内核（默认通过 Triton），而不是调用预先编写好的内核，这使硬件后端更易替换。*另见：* [Triton (OpenAI)](#triton)。
- <a id="torchinductor"></a>**TorchInductor** — PyTorch 2 中 torch.compile 的默认编译器后端。它融合运算，为 GPU 生成 Triton 内核，为 CPU 生成 C++ 代码。*另见：* [torch.compile](#torch-compile)、[Triton (OpenAI)](#triton)。
- <a id="torchtpu"></a>**TorchTPU** — 谷歌面向 TPU 的原生 PyTorch 软件栈，2026 年 10 月与 Meta 共同开源，以取代 PyTorch/XLA，使 PyTorch 模型无需用 JAX 重写即可在 TPU 上运行。*另见：* [PyTorch](#pytorch)、[JAX](#jax)、[XLA](#xla)。
- <a id="tornado-chart"></a>**Tornado chart（龙卷风图）** — 一种敏感性分析图表：每次只让一个输入在低值和高值之间变动，并按其对结果的影响幅度对输入排序，最宽的横条即显示最关键的假设。*另见：* [蒙特卡洛模拟](#monte-carlo-simulation)。
- <a id="torus-topology"></a>**Torus topology（环面拓扑）** — 一种网络，每颗芯片只与各维度上的相邻芯片相连，两端首尾相接成环。它能以低成本扩展到数千颗芯片，但发往远端芯片的消息需经过许多跳，并沿途共享带宽。*另见：* [ICI（芯片间互连）](#ici)、[光路交换机（OCS）](#optical-circuit-switch)、[全交换](#all-to-all)。
- <a id="tpc-ds"></a>**TPC-DS** — 一项标准的决策支持基准测试，包含约 100 个基于零售类数据的 SQL 查询。厂商“源自”该基准的测试并非官方经审计的 TPC 结果。*另见：* [Apache Spark](#apache-spark)。
- <a id="tpot"></a>**TPOT / ITL (time per output token / inter-token latency)（每输出 token 时间 / token 间延迟）** — 流式输出中相邻两个 token 之间的间隔；1/TPOT 即每用户每秒 token 数。主要由解码带宽和批大小决定。*另见：* [解码（decode）](#decode)、[TTFT（首 token 时间）](#ttft)。
- <a id="tpp"></a>**TPP (total processing performance)（总处理性能）** — 美国出口管制衡量 AI 芯片算力的指标：大致为稠密 TFLOPS（或 TOPS）乘以运算的位宽。TPP 达到或超过 4,800 的芯片须获许可证才能运往中国。*另见：* [性能密度](#performance-density)。
- <a id="tpu"></a>**TPU (Tensor Processing Unit)（张量处理器）** — 谷歌自研的 AI 加速器芯片系列，从 2015 年的推理卡（v1）到 Ironwood（v7，2025 年）以及 2026 年的 TPU 8t/8i。每颗芯片都围绕大型矩阵乘法单元构建，芯片互连组成最多约 9,600 颗的 pod。*另见：* [ASIC](#asic)、[ICI（芯片间互连）](#ici)、[脉动阵列](#systolic-array)。
- <a id="trainium"></a>**Trainium** — AWS 自研的 AI 加速器，用于训练和推理，仅以 AWS 云容量形式出售；已有 Trn1（2022 年）、Trn2（2024 年）、Trn3（2025 年）三代，Trainium4 已宣布。*另见：* [UltraServer](#ultraserver)、[Neuron SDK](#neuron-sdk)。
- <a id="transform-and-lighting"></a>**transform and lighting（变换与光照）** — 确定每个 3D 顶点在屏幕上的位置、并计算光线如何照射到它的步骤；GeForce 256（1999 年）把这些步骤从 CPU 转移到了图形硬件中。*另见：* [固定功能管线](#fixed-function-pipeline)。
- <a id="transformer"></a>**Transformer** — 现代语言模型背后的神经网络设计：由一系列相同的层堆叠而成，每层包含一个注意力模块（token 关注此前的 token）和一个前馈模块（大部分参数位于其中）。*另见：* [注意力机制](#attention)、[神经网络](#neural-network)。
- <a id="transformer-engine"></a>**Transformer Engine** — 英伟达将张量核心硬件与软件库相结合的方案，自动选择数值格式（自 Hopper 起支持 FP8，自 Blackwell 起支持 FP4/NVFP4）以及张量级或块级缩放因子，使模型能以更低精度运行而不损失准确性。*另见：* [FP8](#fp8)、[NVFP4](#nvfp4)、[微缩放（MX）格式](#microscaling)。
- <a id="translation-layer"></a>**Translation layer（转译层）** — 使为某一平台构建的程序无需重新编译即可在另一平台上运行的软件，例如让未经修改的 CUDA 二进制文件在非英伟达 GPU 上运行的 ZLUDA。英伟达的 CUDA 许可协议限制此类用途。*另见：* [HIPIFY](#hipify)、[CUDA](#cuda)。
- <a id="tree-all-reduce"></a>**Tree all-reduce（树形全规约）** — 一种全规约算法，沿节点树向上求和，再向下广播结果。它约需 2·log2(N) 跳，而环形算法需要 2(N−1) 跳，因此在大规模下延迟低得多。*另见：* [环形全规约](#ring-all-reduce)、[NCCL](#nccl)。
- <a id="triton"></a>**Triton (OpenAI)** — 一种开源的类 Python 语言和编译器，用于编写 GPU 内核，最初由 OpenAI 开发。PyTorch 的编译器会生成 Triton 代码，且 Triton 拥有英伟达、AMD 等后端，因此内核不必用 CUDA 编写。*另见：* [torch.compile](#torch-compile)、[GPU 内核](#gpu-kernel)。
- <a id="triton-inference-server"></a>**Triton Inference Server** — 英伟达的通用开源模型服务器（2018 年推出，当时名为 TensorRT Inference Server），现更名为 Dynamo-Triton；通过统一的 API 服务多种模型类型和框架。*另见：* [Dynamo](#dynamo)。
- <a id="trusted-execution-environment"></a>**Trusted execution environment (TEE)（可信执行环境）** — 硬件隔离的区域（CPU 上的机密虚拟机、处于机密模式的 GPU），其内存和状态无法被主机操作系统、虚拟机管理程序和云运营方读取或篡改。*另见：* [机密计算](#confidential-computing)、[远程证明](#attestation)。
- <a id="ttft"></a>**TTFT (time to first token)（首 token 时间）** — 用户从发送请求到看到第一个 token 之间的等待时间。主要由预填充计算和排队时间决定。*另见：* [预填充（prefill）](#prefill)、[TPOT/ITL](#tpot)。
- <a id="turnkey-asic"></a>**Turnkey ASIC（交钥匙 ASIC）** — 一种定制芯片模式：设计合作伙伴负责物理设计、IP、封装、测试和晶圆代工供应，并按单价向客户出售成品芯片。*另见：* [客户自有工具模式（COT）](#customer-owned-tooling)、[ASIC 设计合作伙伴](#asic-design-partner)。
- <a id="tying"></a>**Tying (antitrust)（搭售）** — 以购买另一产品作为销售某一产品的条件，例如只有搭配厂商自家的网络设备才出售 GPU；当卖方在第一种产品上拥有市场支配力时，这可能违反竞争法。*另见：* [行为性救济措施](#behavioural-remedy)。
## U

- <a id="ualink"></a>**UALink (Ultra Accelerator Link)** — 一项开放的纵向扩展互连标准，由 2024 年成立的联盟（AMD、英特尔、谷歌、微软、Meta、AWS 等）制定。它让加速器通过 UALink 交换机读写彼此的内存，采用 200G 通道，单个 pod 最多 1,024 个设备。*另见：* [NVLink](#nvlink)、[ESUN (Ethernet for Scale-Up Networking)](#esun)、[纵向扩展（scale-up）](#scale-up)。
- <a id="ualoe"></a>**UALink over Ethernet (UALoE)（基于以太网的 UALink）** — 通过普通以太网交换芯片、而非专用 UALink 交换机承载 UALink 的内存式协议。在原生 UALink 芯片尚未问世之际，AMD 的 Helios 机架搭配博通 Tomahawk 6 交换机采用了这一方案。*另见：* [UALink (Ultra Accelerator Link)](#ualink)、[Scale-Up Ethernet（SUE）](#scale-up-ethernet)。
- <a id="ucc"></a>**UCC (Unified Collective Communication)** — Unified Communication Framework 联盟推出的开源集合通信库，面向 HPC 和 AI，并把硬件卸载的集合通信作为一等公民来支持。*另见：* [MPI（消息传递接口）](#mpi)、[NCCL](#nccl)。
- <a id="ucie"></a>**UCIe (Universal Chiplet Interconnect Express)** — 在同一封装内连接芯粒的开放标准。有报道称，在 NVLink Fusion 框架下，第三方芯片可经由 UCIe 接入 NVLink 芯粒。*另见：* [芯粒](#chiplet)、[NVLink Fusion](#nvlink-fusion)。
- <a id="ultra-ethernet"></a>**Ultra Ethernet (UEC)（超以太网）** — 超以太网联盟（Ultra Ethernet Consortium）发布的行业规范（1.0 版于 2025 年 6 月发布），在标准以太网上增加面向 AI 的传输层、数据包喷洒、拥塞控制等功能，使任何厂商的网卡和交换机都能比肩专有 AI 网络。*另见：* [RoCE (RDMA over Converged Ethernet)](#roce)、[数据包喷洒](#packet-spraying)。
- <a id="ultraserver"></a>**UltraServer** — AWS 对通过 NeuronLink 纵向扩展互连组成一个域的一组 Trainium 芯片的称呼：64 颗 Trainium2，或最多 144 颗 Trainium3。*另见：* [NeuronLink](#neuronlink)、[纵向扩展（scale-up）](#scale-up)。
- <a id="unified-memory"></a>**Unified memory（统一内存）** — CPU 和 GPU 共享同一虚拟地址空间的编程模型，同一个指针在两者上都有效。借助一致性互连（NVLink-C2C），GPU 可以直接读取 CPU 内存；若经由 PCIe，则须由驱动迁移内存页，速度要慢得多。*另见：* [缓存一致性](#cache-coherence)、[NVLink-C2C](#nvlink-c2c)。
- <a id="unified-shader-architecture"></a>**Unified shader architecture（统一着色器架构）** — 英伟达于 2006 年随 G80 推出的 GPU 设计，由一池相同的可编程核心处理所有图形阶段。CUDA 正是把这些通用核心开放给非图形工作使用。*另见：* [GPGPU](#gpgpu)、[CUDA](#cuda)。
- <a id="unifiedbus"></a>**UnifiedBus (UB)（灵衢）** — 华为的纵向扩展互连（中文名“灵衢”），用于 CloudMatrix 384 和 Atlas 超节点。它通过 UB 交换机连接数百至数千颗昇腾 NPU，主要采用光互连。*另见：* [纵向扩展（scale-up）](#scale-up)、[光路交换机（OCS）](#optical-circuit-switch)。
- <a id="useful-life"></a>**Useful life (depreciation)（使用寿命）** — 公司分摊 GPU 服务器等资产成本的年限；使用寿命越长，年度折旧越低，报告利润越高。*另见：* [GPU 小时](#gpu-hour)。
- <a id="utilization"></a>**Utilization (fleet)（集群利用率）** — 已装机加速器小时中用于付费或有效工作的比例。由于加速器的大部分成本是固定的，每个有效小时的成本与 1 ÷ 利用率成正比。*另见：* [分配率](#allocation-ratio)、[MFU（模型 FLOPs 利用率）](#mfu)、[有效吞吐量](#goodput)。
- <a id="uxl-foundation"></a>**UXL Foundation（UXL 基金会）** — Linux 基金会于 2023 年成立的联盟，负责管理 oneAPI 规范和库，作为与厂商无关的 CUDA 替代方案；创始成员包括英特尔、Arm、谷歌云和高通，据报道 AMD 已于 2026 年加入。*另见：* [oneAPI](#oneapi)。
## V

- <a id="value-pool"></a>**Value pool（价值池）** — 产业价值链某一环节（例如 HBM、交换芯片或机架组装）中可获取的利润，以及由谁获取。某一层级可能在战略上至关重要，但对掌控它的公司而言却只是一个很小的价值池。*另见：* [定价权](#pricing-power)。
- <a id="variant-calling"></a>**Variant calling（变异检测）** — 基因组分析中找出个人 DNA 与参考基因组差异位置的步骤；是临床测序流程中计算最密集的核心环节。*另见：* [Parabricks](#parabricks)。
- <a id="vector-search"></a>**Vector search（向量搜索）** — 查找嵌入向量（编码语义的数值列表）与查询最接近的已存储条目；是 RAG 和推荐系统中的检索步骤。*另见：* [cuVS](#cuvs)。
- <a id="vendor-financing"></a>**Vendor financing（供应商融资）** — 供应商向自己的客户放贷、投资或提供担保，使其能购买自家产品。在 1999–2001 年前后的电信设备行业很常见，并放大了随后的崩盘。*另见：* [循环融资](#circular-financing)、[算力兜底承诺](#capacity-backstop)。
- <a id="vertical-integration"></a>**Vertical integration（垂直整合）** — 拥有价值链上相继的多个层级（芯片、网络、编译器、数据中心、模型），使它们能被一体化设计，且各层之间无需支付供应商利润。*另见：* [软硬件协同设计](#co-design)。
- <a id="vesting-milestone"></a>**Vesting milestone（归属里程碑）** — 认股权证或股票奖励的某一批次可以行权之前必须满足的条件，例如部署达到一定吉瓦数，或股价达到某一水平。*另见：* [认股权证](#warrant)、[稀释](#dilution)。
- <a id="virtual-switch"></a>**Virtual switch（虚拟交换机）** — 在虚拟机或容器与物理网络之间转发数据包并执行租户规则的软件（例如 Open vSwitch，即 OVS）。在主机上运行它会占用 CPU 核心；DPU 则在硬件中运行它。*另见：* [叠加网络](#overlay-network)、[数据处理器（DPU）](#dpu)。
- <a id="vllm"></a>**vLLM** — 使用最广泛的开源 LLM 推理引擎（PagedAttention、连续批处理）。它在主代码树中原生支持英伟达和 AMD GPU，并通过插件支持 TPU、Gaudi、昇腾、Trainium 和高通 Cloud AI。*另见：* [SGLang](#sglang)、[推理](#inference)。
## W

- <a id="wafer"></a>**Wafer（晶圆）** — 超高纯度硅制成的薄圆片，先进制程芯片所用晶圆直径为 300 mm，其上印制数百颗相同的裸片，随后切割分离。晶圆代工厂按加工完成的晶圆片数为产出定价。*另见：* [裸片](#die)、[晶圆代工厂](#foundry)。
- <a id="wafer-scale"></a>**Wafer-scale engine（晶圆级引擎）** — 以整片硅晶圆而非单颗裸片构建的处理器，例如 Cerebras 的 WSE-3（46,225 mm²，44 GB 片上 SRAM）。它免去了芯片间互连，但需要特殊的封装、供电和散热。*另见：* [裸片](#die)、[光罩尺寸极限](#reticle-limit)。
- <a id="warp"></a>**Warp（线程束）** — 在一个 SM 上以锁步方式执行同一条指令的 32 个 GPU 线程。它是硬件调度的单位，因此能让全部 32 个线程保持忙碌的代码运行最快。*另见：* [流式多处理器（SM）](#streaming-multiprocessor)。
- <a id="warrant"></a>**Warrant（认股权证）** — 以固定价格购买公司股份的权利（AMD 给 OpenAI 的认股权证：每股 $0.01），通常仅在满足条件时才归属。发行人无需支付现金，但会稀释现有股东。*另见：* [稀释](#dilution)。
- <a id="white-box-switch"></a>**White-box switch（白盒交换机）** — 由 ODM（例如天弘（Celestica）、智邦（Accton））基于商用芯片制造、不预装厂商操作系统出售的交换机；买家自行运行 SONiC、FBOSS 或自有软件。*另见：* [商用芯片](#merchant-silicon)、[网络操作系统（NOS）](#network-operating-system)。
- <a id="wide-ep"></a>**Wide expert parallelism (wide EP)（大规模专家并行）** — 将混合专家模型的专家分散到大量 GPU 上（例如 64-144 块），使每块 GPU 只承载少数几个专家。它为更大的批次和缓存腾出内存，但使分发与合并流量需跨越更多 GPU。*另见：* [专家并行（EP）](#expert-parallelism)、[分发与合并](#dispatch-and-combine)、[NVLink 域](#nvlink-domain)。
## X

- <a id="x86"></a>**x86** — 英特尔和 AMD 处理器自 1970-80 年代以来使用的指令集。只有英特尔和 AMD 持有制造 x86 服务器 CPU 的授权，大多数传统企业软件都是为其编译的。*另见：* [ISA（指令集架构）](#isa)、[Arm 指令集](#arm-isa)。
- <a id="xla"></a>**XLA** — Accelerated Linear Algebra（加速线性代数）：将整个模型计算图编译为面向 TPU、GPU 或 CPU 的优化代码的编译器。被 JAX 以及（此前）TPU 上的 PyTorch 所采用。*另见：* [JAX](#jax)、[MLIR](#mlir)。
- <a id="xpu"></a>**XPU (custom accelerator)（定制加速器）** — 业界对由某一客户自行设计或为其定制的 AI 加速器的简称，例如谷歌 TPU、AWS Trainium、微软 Maia 或 Meta MTIA。*另见：* [ASIC](#asic)、[ASIC 设计合作伙伴](#asic-design-partner)。
## Z

- <a id="zero"></a>**ZeRO (Zero Redundancy Optimizer)（零冗余优化器）** — 微软的技术，把优化器状态（第 1 阶段）、梯度（第 2 阶段）和权重（第 3 阶段）分片分布到数据并行的各 GPU 上，而非在每块 GPU 上复制，从而降低每块 GPU 的内存占用。*另见：* [FSDP](#fsdp)、[数据并行（DP）](#data-parallelism)。
- <a id="zero-code-change"></a>**Zero-code-change acceleration（零代码改动加速）** — 通过替换底层引擎，在 GPU 上运行现有代码（pandas、scikit-learn、Polars、Spark），无需重写，遇到不支持的操作时自动回退到 CPU。*另见：* [cudf.pandas](#cudf-pandas)、[cuML](#cuml)。
- <a id="zero-trust"></a>**Zero-trust isolation（零信任隔离）** — 一种安全设计，默认不信任任何组件（包括主机操作系统）；每次访问都需认证，策略在租户无法控制之处执行，例如在 DPU 上。*另见：* [多租户](#multi-tenancy)、[硬件信任根](#root-of-trust)。
- <a id="zt-systems"></a>**ZT Systems** — 美国机架级服务器设计公司，AMD 以 $4.9B 将其收购（2025 年 3 月完成）；AMD 保留了打造 Helios 的设计团队，并将工厂出售给 Sanmina。*另见：* [AMD Helios](#amd-helios)、[ODM](#odm)。
